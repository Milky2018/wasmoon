# Wasmoon 0.18.0

This minor release updates all 12 workspace modules together. It contains the
native GC/compiler work from #577, the bounded large-initializer compilation
repair from #578, owned uncaught JIT exceptions from #579, and original Wasm
source offsets from #580. It does not change the guest Wasm binary format.

This document describes the release candidate; preparing it does not publish
packages. Registry publication remains a separate step after release review.

## Embedding migration

Use matching versions for the Wasmoon runtime, JIT and compiler modules.
The [Core embedding guide](../core-embedding.md) documents validated modules,
Store-owned handles, rooted values, resource ownership and explicit exceptions.

### Trap source positions

`WasmTrapFrame.wasm_offset` changes from `Int64` to `Int64?`.
`TrapReport.wasm_offset` and frame offsets now mean absolute byte positions in
the original input Wasm module. They are not native instruction displacements.
Handle `None` explicitly; never substitute zero or use `native_offset` as a
Wasm source-map address.

`TrapReport` and `WasmTrapFrame` add `native_offset : Int64?` for the separate
function-relative machine-code displacement. `SourceLocation` adds
`byte_offset : Int64?`. Existing calls to `SourceLocation::new` remain valid;
callers constructing public records directly must supply the additional fields.

Binary compilation retains original positions, including custom sections and
non-canonical LEB encodings. AST/WAT input without binary provenance, synthetic
prologues/epilogues and ambiguous shared failure blocks may have no source
position. `JITFunction::wasm_offset(native_displacement)` performs a bounded
lookup without requiring a trap. Caller and resumed frames preserve the same
position contract.

### Uncaught guest exceptions

Legacy native call APIs retain their trap-only behavior. Embedders needing the
tag and payload of an escaping guest exception should use
`call_core_func_with_exception`, `call_core_func_resumable_with_exception`, or
`call_core_func_async_with_exception` on `JITModuleContext`.

Their `Thrown` result owns a `RootedValue` in the originating Store. Keep it
alive while inspecting or transferring the exception, and close it when done.
Do not use a raw exception index as an independently owned reference or move it
between Stores. Ordinary traps, host errors, cancellation and quota failures
remain distinct from guest exceptions. These rules also apply to suspended,
resumed and reentrant native calls.

## Compiled artifacts and caches

The artifact format and persistent cache namespace are version 12. Native JIT
ABI version 8 is unchanged. Old `.cwasm` artifacts are rejected; recompile them
from the original Wasm rather than changing their version fields. Persistent
cache entries with the old identity are not reused. The runtime can create new
entries automatically when original source bytes are available; deleting a
user's entire cache is unnecessary.

The [artifact contract](../../modules/wasmoon_jit/artifact/README.mbt.md)
describes validation and bounded source ranges. Artifact compatibility is not
determined by the package version alone.

## Performance and support boundaries

GC access, root transport and allocation improvements remain guarded by type,
layout, alias, safepoint, quota and rollback checks. The large-initializer repair
bounds compiler work without omitting root-mask initialization. Interpreter
semantics remain shared between native and wasm targets.

Performance varies by workload. The remaining #568 throughput and compilation
targets are deferred and are not release acceptance requirements. Historical
measurements are documented in the [performance checkpoint](../perf/parse-double-gc.md);
they do not establish timings for this release candidate or another platform.

The native CLI supports AArch64 and AMD64 JIT execution. The portable
`wasmoon_runtime` interpreter also supports the MoonBit `wasm` target under
`moonrun`; that target does not execute native JIT code. Keep the README's
security and production-use limitations when distributing the release.

## Release acceptance

Validate the final lockstep sources with strict native/wasm checks, full test
suites, Core/Component corpora, native sanitizers and the complete platform CI.
Install actual module archives in an isolated workspace, exercise CLI/WASI,
run the portable embedding on native and wasm, and run the native exception
and source-position regressions from the extracted package. A successful
workspace build alone does not establish that the packaged modules work.
