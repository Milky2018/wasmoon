# ISS-078: Move VMContext and Wasmoon register roles out of MachV ISA core

## Description
MachV should describe generic machine IR, ABI data structures, and ISA register properties. It still contains embedding-specific concepts such as VMContext register roles, extra-results pointer roles, and comments tying particular registers to Wasmoon.

This keeps Wasmoon ABI policy inside reusable machine-IR infrastructure and makes other embedders inherit Wasmoon-specific register assumptions.

## Design
Introduce a generic embedding ABI role description that is passed from Wasmoon JIT or another embedding layer into lowering, regalloc, and emission. MachV may keep generic register-role types, but it must not hardcode Wasmoon VMContext or Wasmoon-specific pinned-register policy.

Non-goals: do not remove support for pinned VMContext or extra-results pointer in Wasmoon; move ownership and configuration only.

## Acceptance Criteria
- [x] MachV ISA core no longer documents or hardcodes Wasmoon-owned register roles.
- [x] VMContext/extra-results pointer assignment is supplied by Wasmoon JIT or an explicit embedding ABI adapter.
- [x] Regalloc and emission still receive enough role information to preserve current generated-code behavior.
- [x] Targeted checks for `machv`, `machv_regalloc`, `isa_target`, `machv_emit`, and `wasmoon_jit` pass.
- [x] WAST correctness gates pass.
