## Description

Mechanically relocate the current union-style MachV backend to an unpublished `machv_legacy` module and reserve the official `machv` package locations for the final target-neutral architecture. This milestone changes ownership and dependency names, not backend behavior.

## Design

- Preserve the known-good lowering, allocation, emission, and JIT logic mechanically.
- Permit `machv_legacy` imports only from the old migration pipeline and the internal comparison seam.
- Do not publish, document, or expose `machv_legacy` as a supported API.
- Keep the repository buildable and make the entire relocation one coherent revert unit.

## Acceptance Criteria

- [ ] The current union representation and backend are moved mechanically to unpublished `machv_legacy` packages without semantic rewrites.
- [ ] Existing lowering, regalloc, emission, and JIT consumers compile against the relocated packages with unchanged production behavior.
- [ ] Final target-neutral `machv` package locations exist and do not import legacy, target, ABI, emitter, or Wasmoon-owned packages.
- [ ] A dependency audit or explicit allowlist proves that no new package can adopt `machv_legacy`.
- [ ] Key printer and machine-code snapshots, native tests, and WAST tests show no new failures.
- [ ] The common ISS-192 quality gates pass and generated-interface changes contain only the intended mechanical break.
