## Description

`machv_regalloc.allocate_vcode` currently projects Target VCode into the root `Program` model and consequently invokes the example-grade linear-scan strategy. Once the reusable regalloc core is corrected, MachV needs an explicit production integration and migration plan.

## Design

Do not commit to an adapter shape until ISS-216 through ISS-220 establish the core representation and checker contract. Then decide jointly whether MachV implements a narrow read-only allocator input interface directly or retains a compact projection, how reusable allocator contexts are owned, which strategy maps to each optimization level, and where independent verification runs.

## Acceptance Criteria
- [x] The integration design is agreed before implementation begins.
- [x] AArch64 and x64 production paths select the production strategy explicitly.
- [x] The final integration avoids redundant whole-function projection or documents measured reasons to retain it.
- [ ] Correctness, compile-time, runtime, and code-size gates pass on both targets.
- [x] The old implicit linear-scan production path is removed.
