# ISS-021: Migrate real machine-code emission into machv_emit

## Metadata
- Type: task
- Status: in_progress
- Priority: 0
- Labels: machv_emit, emitter, relocation, migration, agent
- Assignee: unassigned
- Created: 2026-07-04
- Updated: 2026-07-05
- External ref: none

## Description
Replace the pseudo-byte `machv_emit` skeleton with the real machine-code emission pipeline now under `modules/wasmoon/vcode/emit`, while keeping Wasmoon runtime fixups out of the generic emitter.

## Design
Port real encoding, stack frame emission, relocations, fixups, disassembly-support tests, machine-code metadata, and ISA-specific encoding internals into `machv_emit`. Runtime helper references must stay as generic external-symbol relocations or metadata records. Wasmoon-specific helper resolution, executable memory, traps, and hostcall trampoline binding belong in `wasmoon_jit`.

## Acceptance Criteria
- [ ] `machv_emit` emits real machine-code bytes for supported MachV instructions, not pseudo tags.
- [ ] Runtime helper references are generic relocations/metadata; `machv_emit` does not import `wasmoon`, `wasmoon_jit`, `jit_ffi`, or `wasm_core`.
- [ ] Existing `vcode/emit` byte encoding, stackframe, runtime-fixup, and disassembly tests are ported or explicitly split into generic emitter vs Wasmoon JIT tests.
- [ ] `x64_emit` or `aarch64_emit` packages are not introduced unless a later issue proves that split is necessary.
- [ ] WAST JIT correctness gates pass after Wasmoon consumes `machv_emit`.
