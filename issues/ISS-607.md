## Description
GC type records, canonical identities and function type indices are encoded in MoonBit and then copied into independent C allocations. Replace this duplication with a single typed-array binding. Repeated setup with an empty canonical mapping currently preserves stale identities; binding must replace empty mappings too.

## Design
Keep encoding and input snapshots in MoonBit. Native contexts retain the three FixedArrays using RC and read their payloads directly. Bind all arrays together through the package owning JITContext. Preserve legacy raw-pointer C setters by copying their inputs into managed arrays. Safepoint descriptors, function address snapshots and module-shaped layout are separate migration work.

## Acceptance Criteria
- [x] MoonBit setup binds typed arrays without a second native copy.
- [x] Empty canonical mappings replace previous mappings.
- [x] Aliased rebinding, owner release, replacement, clear and context isolation are tested.
- [x] Legacy C setters retain copy semantics and use the same destruction contract.
- [x] Strict checks, native tests, sanitizers and external regressions pass; record CI status.
- [x] Document storage/ABI changes and remaining migration boundaries.

## Close Notes

Local implementation and validation are complete. The pinned baseline fails the stale-canonical regression; the new implementation passes 2,615 native tests, 69 sanitizer tests, both-engine core WAST and async component WAST. Native pointer-identity tests verify that typed bindings retain the original arrays, and mixed legacy bindings verify copy semantics and teardown. Context layout remains unchanged; three distinct nonempty retained arrays add 24 bytes of array headers. See `docs/perf/gc-metadata-2026-09-29.md` for measurements and limitations. Cross-platform CI for the new commit remains pending, so this issue stays in progress.
