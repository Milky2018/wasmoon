## Description

The CLI run cache, WAST/test helpers, and public compile APIs still exchange and serialize v8 `PrecompiledModule` values.

## Design

Replace those seams with v9 artifact bytes plus explicit compatibility validation. Cache lookup must decode with limits, check source/policy/target identity, and delete incompatible or malformed entries without falling back to a compatibility decoder.

## Acceptance Criteria
- [x] CLI, WAST, WASI, testsuite, and public compile APIs exchange v9 artifacts only.
- [x] Run-cache reads use bounded decode and exact compatibility validation before installation.
- [x] Cache keys and manifests distinguish all codegen-affecting policy and module identity.
- [x] Corrupt, old, incompatible, and oversized cache entries are rejected and removed.
- [x] Native, run-cache, WAST, component, and WASIp1 regression paths pass.

## Close Notes

- Public compile APIs now return v9 `Artifact` values. Product callers verify them as `LoadedArtifact` values and use the transactional artifact installer; the CLI commands package no longer imports the v8 `cwasm` package.
- Run-cache entries use bounded v9 decoding and exact target, JIT ABI, codegen revision, module identity, semantic-feature, and compilation-policy validation. Invalid entries are removed without a compatibility decoder.
- Cache keys include the full source and semantic-feature SHA-256 digests plus explicit target, operating-system ABI, optimization, code model, call binding, cancellation, and debug policy tags.
- Regression tests cover compatible cache hits and removal of corrupt, v8, incompatible, and oversized entries.
- Validation: `moon check --target native --warn-list +73 --deny-warn`; `moon check --warn-list +73 --deny-warn`; `moon test --target native` (2323/2323); JIT WAST (258/258 files, 62563 assertions); component values/names (3/3 files); WASI Preview1 (90/90); all three compiler-boundary audits; and a real two-process CLI cache hit on `examples/stream2.wasm`.
