## Description
`EGraph::rebuild` (`modules/milkir/egraph/egraph.mbt:803`) restores
invariants by reconstructing the hashcons, opcode index, use-def edges,
type map, and remat set **from scratch for the whole graph**, looping the
full pass until congruence produces no new unions. Three compounding costs:

1. Every rebuild is O(total nodes) times its fixpoint rounds; egg-style
   incremental repair (a worklist of classes dirtied by unions) exists
   precisely to avoid this.
2. Node deduplication in both `merge` and `rebuild` is a linear scan
   (`for existing in nodes { if existing == canonical_node ... }`), i.e.
   O(|class|²) per class, even though `ENode` derives `Hash`. Today this is
   masked by `eclass_enode_limit = 5` — a throttle covering for a data
   structure choice.
3. `EGraph::rewrite_to_fixpoint` (`egraph.mbt:648`) is a `pub` API whose
   budget is `2 × (classes + nodes)` iterations with a full rebuild after
   every changed iteration — quadratic and worse. Nothing calls it; its own
   doc comment says to prefer `saturate_indexed(ruleset, 1)`. It exists
   only to invite misuse.

The production path (`EGraphBuilder::optimize`, single saturation pass) is
currently acceptable because it triggers at most one rebuild per function;
this issue is about removing the trap and the masked quadratic before
anything raises the iteration count.

## Design
- Replace full-graph rebuild with worklist repair keyed by the classes
  touched since the last rebuild (egg's algorithm), or at minimum bound the
  rebuild to dirtied classes plus their parents via the use-def index.
- Use a hash-based set for intra-class node deduplication.
- Delete `rewrite_to_fixpoint` (no callers) or demote it to a test-only
  helper with an explicit small budget.
- While in the area, fix the stale doc comment on `EGraph::add`
  (`egraph.mbt:492`): it still says new nodes are "queued for rule
  application (processed by add_eager)", but no `add_eager` exists — the
  eager path was removed long ago.

## Acceptance Criteria
- [x] Rebuild work is proportional to touched classes, demonstrated by a
      counter or benchmark on a graph where one merge occurs in a large
      e-graph.
- [x] Node dedup no longer performs linear scans.
- [x] `rewrite_to_fixpoint` is gone from the public interface (`.mbti`
      diff) or clearly test-scoped.
- [x] Full e-graph and optimizer suites plus the JIT/interp comparison
      corpus stay green.

## Close Notes

Rebuild is now worklist repair. `merge`/`subsume` enqueue the surviving
class; `rebuild` drains that queue, and `repair_class` recanonicalizes the
class plus the classes named by its `parents` edges — exactly the nodes
holding a stale child id. Congruences found during repair go through
`merge`, which re-enqueues, so the loop still reaches a fixpoint. Parent
pointers were reintroduced here, with their consumer, as ISS-382's close
note required.

Two latent bugs fell out of the rewrite:

- The old rebuild applied congruence unions with a raw `uf.union`, bypassing
  the type-map, remat-set, and constant-cache merging that `merge` performs.
  Routing them through `merge` fixes that; `UnionFind::union` became dead
  and was deleted (ISS-383 will pick its own root-selection strategy).
- `merge`'s intra-class dedup was an O(|class|²) scan; it now uses a hashed
  membership set, as does the repair path.

`rewrite_to_fixpoint` is gone from the public interface, and `add`'s doc
comment no longer references the long-removed `add_eager`.

Verified: egraph 195/195 (including a new test showing one union in an
~800-class graph repairs fewer than 10 classes via `last_rebuild_repairs`),
milkir 175/175, wasmoon testsuite 562/562, and the full WAST corpus —
258/258 files, 62,563 assertions, green in both interpreter and JIT modes.
