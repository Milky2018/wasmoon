## Description
WASI component function and type contracts must not become a second handwritten
protocol beside the official WIT packages. The host implementation needs a
deterministic generated contract layer for the pinned Preview 2 and Preview 3
snapshots.

## Design
Vendor the exact official WIT inputs and record their upstream commit. Use
`wasm-tools component wit --json --generate-nominal-type-ids` as the normalized
development input, then generate committed MoonBit contract source through a
`dev_build` rule. Published packages consume only generated MoonBit source and
must not execute the generator or load development assets.

If the generator itself is packaged as a MoonBit tool, embed its templates with
the official `moon runwasm moonbit-community/embed` command; do not use internal
embed commands.

## Acceptance Criteria
- [x] Preview 2 `0.2.11` and the pinned Preview 3 RC WIT inputs are byte-exact
      and have recorded upstream revisions.
- [x] Interface names, functions, async flags, parameters, results, named types,
      and resource identities are generated rather than copied into handlers.
- [x] `dev_build` deterministically refreshes committed generated MoonBit.
- [x] A drift check fails when WIT or generated output changes independently.
- [x] Downstream package builds do not require `wasm-tools`, Python, or embedded
      development assets.
