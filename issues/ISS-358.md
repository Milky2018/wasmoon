# ISS-358: Poll host events fairly beside runnable component subtasks

## Metadata

## Description
When a root component invocation blocks, `drive_once` combines one bounded
subtask step and the nonblocking host reactor poll with short-circuit `||`.
A detached or background subtask that continually yields therefore reports
progress every round and prevents the reactor from ever being polled. A root
invocation waiting for a WASI timer or socket can spin forever.

## Design
Preserve the existing bounded scheduler turn: advance at most one side task and
perform exactly one nonblocking host poll on every blocked root round. Evaluate
both operations independently, then combine their progress results. Do not add
an unbounded drain loop or change task ordering.

## Acceptance Criteria
- [x] A continually yielding detached task cannot starve a ready host event.
- [x] Each blocked root round performs at most one side-task step and one
      nonblocking host poll.
- [x] `ComponentCall::poll`, `wait`, and `join` retain their existing result and
      cancellation behavior.
- [x] A regression covers a yielding background task together with a
      reactor-driven host future.

## Close Notes

`ComponentInvocation::drive_once` now executes one bounded side-task step and
one nonblocking host reactor poll independently before combining their progress
results. Runnable guest work can no longer short-circuit reactor progress.

A public `ComponentRuntime` regression creates a detached callback task that
yields forever and concurrently waits on the real WASI Preview 3
`monotonic-clock.wait-for` timer. With the old expression the two finite polls
produced `(Pending, Pending)`; with the fix they produce
`(Pending, Ready([]))`.

Validation completed with the component facade tests (19/19), runtime
implementation tests (32/32), the JIT Component 0.3 async snapshot (24/24
files, 153/153 commands), the full native test suite (2498/2498), `moon fmt`,
`moon info`, the warning-73 check, and `git diff --check`.
