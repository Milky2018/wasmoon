# ISS-039: Restore AMD64 JIT-vs-interpreter correctness gate

## Description
The current testsuite behavior matches `origin/main`: `compare_jit_interp` skips JIT-vs-interpreter comparisons on AMD64 while the AMD64 backend is still being brought up. During the module split, removing that old skip exposed `wide_arithmetic_test.mbt` failures for `i64.mul_wide_u` and `i64.mul_wide_s` on Ubuntu AMD64 CI.

This issue tracks the real AMD64 JIT correctness work. Restoring the old skip is only a gate-behavior restoration, not a proof that the AMD64 JIT implements wide arithmetic correctly.

## Design
Keep the production JIT path free of interpreter fallback. Fix AMD64 lowering, register allocation, or emission by comparing against the old implementation first and only then applying a minimal targeted patch. Once the real AMD64 behavior is fixed, remove the AMD64 skip from `compare_jit_interp`.

## Acceptance Criteria
- [x] `compare_jit_interp` runs the JIT path on AMD64 instead of returning the interpreter result.
- [x] `testsuite/wide_arithmetic_test.mbt` passes on AMD64 through real JIT execution.
- [x] No interpreter fallback or interpcall trampoline path is reintroduced.
- [x] Ubuntu AMD64 CI passes without the AMD64 compare skip.

## Notes
- 2026-07-05: `origin/main` already contained the AMD64 skip in `testsuite/compare.mbt`. The module-split branch briefly removed it, which exposed the AMD64 `i64.mul_wide_*` mismatch in CI.
- 2026-07-05: Separate AMD64 production WAST regressions in `conversions.wast` and `float_exprs.wast` were traced to `JITContext.call_multi_return` using the new hand-written `wasmoon_jit.build_entry_trampoline_for_target` path instead of the old entry-trampoline semantics. Copy-first moving that entry trampoline implementation into `machv_emit.emit_entry_trampoline` fixed full Docker AMD64 WAST (`python3 scripts/run_all_wast.py --dir spec --rec --dump-failures` passed 258/258 files in both interpreter and JIT modes). This did not close ISS-039 because the AMD64 `compare_jit_interp` skip and wide-arithmetic JIT coverage remained unresolved.
- 2026-07-05: Compared the AMD64 `Umulh`/`Smulh` path against `main`. The old implementation also fixed lhs to RAX and masked the issue with the AMD64 compare skip. The final fix keeps both inputs as ordinary uses, constrains only the high-half result to RDX, and lets the AMD64 emitter move lhs into RAX while preserving rhs if it is already in RAX.

## Close Notes
Closed after removing the AMD64 skip from `compare_jit_interp` and fixing AMD64 `Umulh`/`Smulh` lowering/emission so wide multiplication high halves execute through the real JIT path.
