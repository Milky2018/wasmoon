## Description
Canonical ABI layout, flattening, conversion and resource traversal duplicate type knowledge across validation, calls and asynchronous payload transport.

## Design
Build type-environment-aware canonical ABI plans that centralize flat representation and memory layout, then share lift, lower and resource traversal machinery across invocation directions and asynchronous payload adapters. Preserve module dependency boundaries.

## Acceptance Criteria
- [ ] Canonical layout and flat representation have a single source shared by validation and runtime.
- [ ] Parameter and result conversion reuse one lowering and lifting implementation.
- [ ] Type ownership, memory width and string encoding are explicit inputs to plans and transport.
- [ ] Stream and future payload adapters reuse the same type and conversion rules.
- [ ] Native, stable and async component suites pass and misc has no new failures.
