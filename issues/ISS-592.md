## Description
ISS-591's combined owner-scan and conditional jump-use-count candidate produces byte-identical JIT artifacts but makes the aead_aegis128l CLI workload slower in two fixed 21-pair cold rounds (+0.71% and +1.11%). A cache-hit diagnostic that performs no compilation retains a +0.51% wall / +0.56% invocation difference. The source changes do not run on this cache-hit path. Do not dismiss this as noise, attribute it to allocation during compilation, or infer a specific address-layout root cause without evidence.

## Design
Use the exact baseline/candidate patches, executable and input hashes, cold samples and warm-cache recipe in docs/perf/compiler-candidates-2026-09-28.json.gz. Separate native executable layout, JIT/linear-memory placement, benchmark work and host scheduling effects. Keep fixed A/A controls and all samples. Individual owner/use-count CLI probes are inconclusive about which change causes the combined effect; neither identifies an algorithmic guest-code change.

## Acceptance Criteria
- [ ] Reproduce or bound the execution difference with fixed controls and unchanged artifact bytes.
- [ ] Identify a falsifiable root cause using runtime placement/work counters or an appropriately controlled experiment.
- [ ] Re-evaluate conditional use counts only after understanding end-to-end behavior; do not tune unrelated code layout until a benchmark happens to improve.

## Notes
The final owner-only CLI group had a +1.12% `onetimeauth` result, but a fixed follow-up was +0.02% with an interval crossing zero. Keep both observations; neither establishes a stable per-workload CLI gain. The baseline A/A control is -0.19% [-0.95, +0.40], so it does not demonstrate a fixed measurement-label bias.

Conditional use counts save small amounts of compiler work, but the combined candidate is withheld. This is a performance investigation, not evidence of incorrect Wasm results.
