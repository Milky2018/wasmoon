## Design
- Implement typed continuation syntax, type checking and feature configuration first, then interpreter and native execution with explicit one-shot ownership. Complete the unmodified external corpus through both actual engines.
- The pinned oracle keeps continuation allocations owned by its Store until Store destruction (`crates/wasmtime/src/runtime/store.rs`, allocate_continuation). A Store-owned continuation arena is therefore a valid baseline; it must cancel/release parked stacks at Store close and reject stale consumed handles. Allocate native stacks lazily where possible and release completed stacks promptly.
- The pinned stack-switching-and-gc.wast rejects a GC struct containing a continuation reference. This is a specific unsupported GC-storage contract, not evidence that every module containing both GC and continuation types must be rejected. Do not invent a blanket feature incompatibility rule.
- Earlier discussion of GC-reachable-only continuation stack ownership was a design hypothesis, not a requirement established by the pinned implementation. Preserve existing parked native GC-root safety and establish further compatibility with concrete oracle controls.
