## Description
`modules/wasmoon_jit/ir` still looks like a legacy Wasm-to-IR frontend package:
it exposes translation APIs, VMContext constants, frontend environment types,
and many MilkIR re-exports from under the JIT namespace. That blurs ownership
between Wasm frontend lowering, reusable MilkIR, and Wasmoon JIT integration.

Evidence:
- `modules/wasmoon_jit/ir/pkg.generated.mbti` exposes `translate_function(@types.Module, Int) -> @milkir.Function`.
- The same package exposes VMContext offset constants and public frontend translator/environment types.
- `modules/wasmoon/cmd/wasmoon/commands/moon.pkg` still imports `Milky2018/wasmoon_jit/ir`.

## Design
Audit every remaining import of `wasmoon_jit/ir`. Move still-needed frontend
translation APIs into `wasmoon/wasm_frontend` or another Wasm-owned frontend
package, and keep JIT-only integration code under `wasmoon_jit`. Remove the
compatibility package once all callers are migrated; if a short-lived shim is
unavoidable, make it private or clearly deprecated with a follow-up removal
issue.

Non-goal: change MilkIR translation semantics.

## Acceptance Criteria
- [x] Production code no longer imports `Milky2018/wasmoon_jit/ir`.
- [x] Wasm-to-MilkIR translation APIs live in a Wasm frontend package, not under the JIT namespace.
- [x] VMContext constants are not re-exported from `wasmoon_jit/ir`.
- [x] Any retained compatibility shim is private, documented as temporary, and unused by production Wasmoon JIT.
- [x] `moon info --target native` is run and generated `.mbti` diffs are reviewed.

- [x] CLI explore and native JIT WAST smoke tests still pass.
