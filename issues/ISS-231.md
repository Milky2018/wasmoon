## Description

The repository currently has two backtracking representations: the root production segment allocator and a separate `Milky2018/regalloc/backtracking` package containing bundle merge, queue, eviction, and split machinery. Once production bundle allocation is live, retaining both would recreate the semantic drift that left ISS-220 incorrectly closed before.

## Design

Make the root production implementation authoritative. Mechanically remove or reduce the stranded subpackage so bundle merge, allocation-loop, eviction, and split policy each have one maintained implementation. Add quality evidence that specifically measures transfers removed by coalescing and guards compile time, emitted size, and AEGIS runtime. Update regalloc and MachV integration documentation, generated interfaces, and ISS-220/ISS-221 status from current-tree evidence.

Performance comparisons are diagnostic gates against the pre-coalescing parent commit, not compatibility gates against deleted legacy code.

## Acceptance Criteria
- [x] No duplicate bundle merge, queue, eviction, or split implementation remains outside the authoritative production path.
- [x] Edge-heavy SSA workloads report fewer materialized edge moves or demonstrate why no legal coalescing opportunity exists.
- [x] `large_cfg.wast` compile time and code size do not materially regress against the pre-coalescing parent commit.
- [x] AEGIS128L and AEGIS256 value/wall ratios remain within the documented current envelope, with same-host interleaved evidence.
- [x] `moon fmt`, `moon info`, warning-73 checks, full tests, reusable-module audits, and recursive JIT WAST tests pass.
- [x] ISS-220 and ISS-221 are closed only after their current acceptance criteria are re-audited against production call paths.

## Notes
- 2026-07-22: Historical ISS-057 correctly moved the former MachV bundle merge algorithm into reusable infrastructure, but the later Target VCode cutover replaced its production caller. - 2026-07-22: Started current-tree audit. The `Milky2018/regalloc/backtracking` package has no live caller; `Milky2018/regalloc/planning` remains in use by root whitebox tests and contains unrelated reusable planning utilities, so cleanup will be limited to duplicated allocation policy.
- 2026-07-22: Removed the unreferenced `Milky2018/regalloc/backtracking` package and the test-only duplicate queue and bundle-split APIs from `Milky2018/regalloc/planning`. The root package is now the only implementation of bundle merging, allocation ordering, eviction, and splitting; unrelated CFG, edit, spill-slot, and frame planners remain in `planning`.
- 2026-07-22: Full allocation-plan snapshots show the loop/entry edge fixture dropping from four edge transfers to two: both conflict-free entry transfers disappear and only the two cyclic loop transfers remain. The critical-edge fixture retains one transfer only on the conflicting incoming edge.
- 2026-07-22: On Darwin arm64, one warmup plus five runs of the historical 512-branch `large_cfg.wast` measured `00cf4590` at 79,314 us and 16,408 bytes versus the bundle allocator at 76,987 us and 14,388 bytes: 0.971x compile time and 0.877x code size.
- 2026-07-22: Same-host AEGIS runs used one warmup and five interleaved Wasmoon/Wasmtime pairs. AEGIS128L measured 1.607x value and 1.595x wall ratios; AEGIS256 measured 1.597x and 1.590x. All ten runs per engine exited successfully, and both workloads remain below the prior documented roughly 1.90x/1.88x envelope.
