## Description

The repository currently has two backtracking representations: the root production segment allocator and a separate `Milky2018/regalloc/backtracking` package containing bundle merge, queue, eviction, and split machinery. Once production bundle allocation is live, retaining both would recreate the semantic drift that left ISS-220 incorrectly closed before.

## Design

Make the root production implementation authoritative. Mechanically remove or reduce the stranded subpackage so bundle merge, allocation-loop, eviction, and split policy each have one maintained implementation. Add quality evidence that specifically measures transfers removed by coalescing and guards compile time, emitted size, and AEGIS runtime. Update regalloc and MachV integration documentation, generated interfaces, and ISS-220/ISS-221 status from current-tree evidence.

Performance comparisons are diagnostic gates against the pre-coalescing parent commit, not compatibility gates against deleted legacy code.

## Acceptance Criteria
- [ ] No duplicate bundle merge, queue, eviction, or split implementation remains outside the authoritative production path.
- [ ] Edge-heavy SSA workloads report fewer materialized edge moves or demonstrate why no legal coalescing opportunity exists.
- [ ] `large_cfg.wast` compile time and code size do not materially regress against the pre-coalescing parent commit.
- [ ] AEGIS128L and AEGIS256 value/wall ratios remain within the documented current envelope, with same-host interleaved evidence.
- [ ] `moon fmt`, `moon info`, warning-73 checks, full tests, reusable-module audits, and recursive JIT WAST tests pass.
- [ ] ISS-220 and ISS-221 are closed only after their current acceptance criteria are re-audited against production call paths.
