# ISS-508: Release WAST execution contexts deterministically

## Description
WastContext owns a Store, WASI context and compiled modules but run_wast_commands does not close them. Investigate ownership of replaced and unnamed JIT modules and pending calls before implementing ordered cleanup.

## Acceptance Criteria
- [x] Prove native ownership is released after repeated successful and failing scripts.
- [x] Retain compiled code until all imported calls and continuations have ended; cancel pending work before releasing native owners.

## Close Notes

The public run_wast_commands regression retains all three compiled contexts (reused module name plus unnamed module) and observes get_func_count() == 1 after the script returns, where zero is required. The test fails before cleanup (/tmp/iss508-red2.log). Synchronous call_core_func already defers clear_async_host_state, which cancels imported interpreter continuations before returning; the WAST runner itself does not retain parked entry calls.

Full native validation exposed Store.close clearing borrowed module_types/type_rec_groups arrays in place. Reusing the same parsed WAST then failed with InvalidTypeIndex(0). Close now detaches those references instead of mutating the AST; the existing opt-in named-module reuse test gains explicit failure diagnostics.

WastContext now owns every successful compilation independently of mutable module names, closes compiled contexts and its Store at the end of run_wast_commands, and releases tracked WASI descriptors. Close is idempotent and terminal. Existing synchronous invocation cleanup cancels imported continuations before returning; public close requires all caller-owned invocations to have ended. The Store fix detaches borrowed AST arrays rather than clearing them.

Validation: 2,399 native tests; two lifecycle tests under ASan (detect_leaks=0, with explicit native table-owner counts and compiled-code release checks); info/fmt/check. All official core, runtime, component lanes and P1 passed. Full high-memory misc remains 576 pass, 70 script-only, 112 thread/continuation failures, six unsupported host/config executions (tmp/iss508-all-misc/summary.json).
