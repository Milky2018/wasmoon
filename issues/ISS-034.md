## Description
While restoring production-style `compare_jit_interp`, unsupported native frontend bodies were routed through the production interpreter fallback trampoline. The `br_table_as_block_value` testsuite case hangs when executed through that path. Supported native frontend functions can execute through production-loaded JIT code, so the remaining failure is specific to unsupported-body interpcall fallback.

## Design
Debug the `build_interpreter_fallback_trampoline_for_target` path for structured branch bodies, especially zero-parameter/single-result functions that call another local function before branching. The fix should make testsuite and CLI/WAST use the same interpcall fallback behavior without a testsuite-only shim.

## Acceptance Criteria
- [x] `br_table_as_block_value` returns through production interpcall fallback instead of hanging.
- [x] `compare_jit_interp` can remove its unsupported-function compatibility shortcut.
- [x] Add a focused regression test for unsupported-body interpcall fallback.
- [x] `moon test modules/wasmoon/testsuite/br_table_test.mbt --target native --warn-list +73 --diagnostic-limit=200` passes without compatibility fallback.
- [x] `moon test --target native --warn-list +73 --diagnostic-limit=200` passes.

## Notes
- 2026-07-05: Repro before the compatibility guard: `moon test modules/wasmoon/testsuite/br_table_test.mbt --target native --warn-list +73 --diagnostic-limit=200 --index 5`.
- 2026-07-05: AArch64 non-leaf `x30` preservation and fixed-constraint parallel moves made many ordinary direct-call cases return, but removing the broad direct-call compatibility guard exposed `br_nested_block_value` as a real miscompile (`JIT: I32(12)`, interpreter `I32(9)`). The guard remains until structured branch bodies with direct calls are fixed.
- 2026-07-05: Compared with `main`: the old JIT load path installs fallback trampoline entries for unsupported functions instead of skipping JIT execution in tests. The reusable frontend therefore needs a conservative capability boundary so unsupported structured branches reach the production fallback trampoline.

## Close Notes
- Tightened the native linear frontend so a direct `br 0` inside a block is flattened only when it is terminal. Non-terminal block exits now fall back to the interpreter trampoline instead of exposing unreachable expression operands to the linear stack model.
- Removed the `compare_jit_interp` unsupported-function compatibility shortcut; `run_jit` now always loads the production JIT module and calls the compiled or fallback entry.
- Added a focused frontend regression for non-terminal block branches falling back, and verified the existing `br_nested_block_value` and `br_table_as_block_value` tests through the production path.
