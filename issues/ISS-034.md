# ISS-034: Remove native JIT interpreter fallback trampoline path

## Metadata
- Type: bug
- Status: closed

- Labels: jit, wasmoon_jit, tests

- Updated: 2026-07-05

## Description
While restoring production-style `compare_jit_interp`, an attempted unsupported-body interpreter fallback trampoline path was introduced. That path caused hangs and hid semantic gaps rather than preserving the old main-branch JIT behavior.

## Design
Remove the interpreter fallback trampoline path entirely and restore production compilation semantics through the real reusable MilkIR/MachV pipeline. Testsuite and CLI/WAST should execute the same real JIT path.

## Acceptance Criteria
- [x] `br_table_as_block_value` returns through production JIT instead of hanging.
- [x] `compare_jit_interp` can remove its unsupported-function compatibility shortcut.
- [x] Remove the unsupported-body interpcall fallback API and tests.
- [x] `moon test modules/wasmoon/testsuite/br_table_test.mbt --target native --warn-list +73 --diagnostic-limit=200` passes without compatibility fallback.
- [x] `moon test --target native --warn-list +73 --diagnostic-limit=200` passes.

The guard remains until structured branch bodies with direct calls are fixed.

- Removed the `compare_jit_interp` unsupported-function compatibility shortcut; `run_jit` now loads the production JIT module compiled by `compile_module_to_jit`.
- Verified the existing `br_nested_block_value` and `br_table_as_block_value` tests through the production JIT path as part of full native and WAST gates.
