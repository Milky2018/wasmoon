## Description

The current MachV pipeline still has actionable compile-time hotspots, especially large-CFG target lowering and fixed costs on small functions. The retired backend is useful historical evidence but is no longer a release or migration authority.

## Design

Use current-version phase metrics, profilers, and scaling tests to identify shared fixed costs and workload-specific complexity. Preserve the final semantic MachV, verifier, Target VCode, allocation, and code-object seams; do not reintroduce legacy code or a fixed-legacy release threshold.

## Acceptance Criteria

- [x] Current-version diagnostics separate frontend, lowering, verification, regalloc, and emission costs.
- [x] Large-CFG scaling has a deterministic regression test and no demonstrated superlinear target-pipeline hotspot.
- [x] Representative AArch64 and AMD64 compile workloads have retained current-version trend reports.
- [x] Correctness and code-quality gates remain green.

## Close Notes

Closed after native Linux AMD64 evidence was retained in
`docs/perf/amd64-jit-current-version-2026-07-30.md`. Together with
`docs/perf/aarch64-jit-current-version-2026-07-23.md`, both supported native
targets now have exact current-version commit, host, toolchain, workload, raw
sample, compile-time, wall-time, and code-size provenance.

The AMD64 report contains one warmup and three measured compilations for two
successful run workloads and three successful WAST workloads. Median compile
times range from 101 microseconds for `const.wast` to 2,961,756 microseconds for
AEGIS128L. This is a retained trend, not a restored legacy comparison or CI
threshold.

The collection also found post-compilation AMD64 out-of-bounds traps in
`core3.wasm` and `pwhash_scrypt_ll.wasm`. They are excluded from the successful
trend and tracked as P0 correctness issue ISS-365. The current collection job
passed all 2,508 native tests before producing the report.
