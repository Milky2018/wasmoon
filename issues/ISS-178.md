# ISS-178: Fan out readiness for duplicate poll subscriptions

## Metadata
- Type: bug
- Status: closed

- Assignee: codex

## Description
`poll_oneoff` currently creates one host `pollfd` entry per guest subscription. On macOS, duplicate entries for the same native descriptor do not independently receive readiness: a public Preview 1 probe with two `fd_write` subscriptions for stdout returns one event instead of two. Wasmtime 40's legacy Preview 1 implementation returns both events.

The bug also affects different guest descriptors that alias one native descriptor and can affect mixed read/write subscriptions for the same source.

## Design
Normalize native subscriptions by host descriptor before calling the platform poll backend. Merge requested host event masks for each descriptor, then fan the returned readiness mask back to every original guest subscription while preserving guest subscription order and per-subscription event types.

## Acceptance Criteria
- [x] Duplicate read or write subscriptions for one native descriptor each produce an event when that descriptor is ready.
- [x] Mixed read/write subscriptions share one host entry but retain independent readiness checks.
- [x] Different guest descriptors aliasing one native descriptor behave like duplicate subscriptions.
- [x] Interpreter and JIT public Preview 1 tests cover the behavior.
- [x] Existing poll clock, fd, and error tests remain green.
