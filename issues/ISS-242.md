# ISS-242: Preserve typed target failures through JIT orchestration

## Description

`JitPipelineError::PipelineFailure(String)` currently flattens semantic lowering, target lowering, allocation, frame, emission, and code-object verification failures. This violates the structured-error decision in ISS-188 and prevents callers from identifying the failed checkpoint without parsing text.

## Design

Replace string flattening at pipeline seams with a closed Wasmoon-owned error hierarchy that retains the concrete reusable error cause and target. Keep embedding-configuration failures explicit and render strings only at CLI boundaries.

## Acceptance Criteria
- [ ] Semantic, AArch64, and x64 stage failures retain typed causes through `JitPipelineError`.
- [ ] Allocation, frame, emission, and code-object failures remain distinguishable without string parsing.
- [ ] Cancellation and artifact/installation errors remain separate domains.
- [ ] Negative tests snapshot complete structured errors at representative seams.
- [ ] Strict checks and full native tests pass.
