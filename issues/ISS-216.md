# ISS-216: Index live ranges by virtual-register identity

## Description

`LiveRangeSet::get_by_vreg` linearly scans all existing ranges for every operand and every block live-in/live-out value. On the 512-branch `large_cfg` workload this adds an extra factor to live-range construction and produces near-cubic compile-time growth.

## Design

Index each register class directly by its dense virtual-register id and use array lookup for the current range or range list. Preserve the existing identity contract in which the same numeric id may occur in different register classes. Do not use a hash table on the dense production path and do not expose new diagnostics in the public API.

## Acceptance Criteria
- [x] Live-range construction performs no scan over all ranges to find a virtual register.
- [x] Dense virtual-register lookup is constant-time and same-id registers in different classes remain distinct.
- [x] A deterministic package test locks the lookup/work bound over a parameterized program.
- [x] Existing allocation and verification tests remain green.

## Notes
- 2026-07-20: A diagnostic direct index reduced `large_cfg` allocation from about 12.884 seconds to 331 milliseconds without changing emitted code, confirming this lookup as the dominant near-cubic factor.

## Close Notes

Implemented constant-time per-class live-range lookup. The focused native regalloc suite passes with the new direct-index and cross-class regression coverage.
