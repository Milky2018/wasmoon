## Description

The initial complete misc_testsuite scan reports 130 failing files per engine
on macOS ARM64. This includes missing syntax/host harness behavior and runtime
correctness differences; individual failures need minimization before assigning
root causes. The full runner keeps these failures red without a baseline mask.

## Reproduction

```sh
./install.sh
python3 scripts/run_wasmtime_misc.py --output tmp/misc-investigation
python3 scripts/run_wasmtime_misc.py --filter call_indirect.wast
```

The historical inventory in `wasm-tests/wasmtime/INITIAL_RESULTS.json` records
all 382 files in both modes, including source and binary provenance. Full logs
can be regenerated by file filter. The initial 30-second sweep had no timeouts.

## Findings

- `call_indirect.wast`: interpreter passes; JIT reports indirect-call type
  mismatches on assertions that should return successfully.
- `alias-region-imported-tables.wast`: both engines fail while parsing a table
  declaration containing an export before the element type.
- `custom-page-sizes/custom-page-sizes-invalid.wast`: incompatible memories
  link successfully where the script expects an unlinkable module.
- `embenchen_*`: missing `env.memory` despite an earlier named `$env` module;
  compare upstream automatic named-module registration with our WAST linker.
- `gc/array-alloc-too-large.wast` and `gc/big-array-overflow.wast` terminate
  the interpreter with `SIGABRT` (exit -6); the JIT passes both. These are
  observed process aborts, not merely differing assertion messages.
- Additional mode differences occur in GC const expressions, large arrays,
  memory64 bounds/offsets/table growth and copies involving imported tables.
- The component lane has 38 failing files per engine; separate translation and
  validation limitations from runtime defects before fixing them.
- The 36 explicit missing host contracts and eight high-memory deferrals are
  separate from the 130 executed failures; do not reclassify failures merely
  to improve the pass count.

## First repair batch (macOS ARM64)

The complete rerun in `tmp/misc-fix6-all/summary.json` records 102 interpreter
failures and 109 JIT failures, down from 130 each. No new exclusions or baseline
allowances were added. Interpreter: 203 pass, 33 script-only, 36 unsupported,
eight deferred. JIT: 196 pass, 33 script-only, 36 unsupported, eight deferred.
The original result inventory remains historical and unchanged.

Fixed boundaries:

- Reject oversized GC array lengths before host allocation and enforce the
  native heap's signed 32-bit object-offset limit.
- Evaluate element constant expressions once during instantiation, preserve
  their values as GC roots, and reuse them for interpreter and JIT segment ops.
- Drop active data segments after initialization in both instantiation paths.
- Check custom memory page sizes during validation and import compatibility.
- Detect unsigned memory64 effective-address overflow, preserve table64 grow
  deltas until checked, and use the smaller address type for memory.copy length.
- Parse explicit i32 memory types, legacy data memory indices, mixed folded
  operands, numeric heap references, grouped mutable fields and exnref elements.
- Preserve explicit bottom-reference nullability for ref.test/ref.cast.
- Resolve imported and local tables in one index space, accept multiple exports,
  and avoid manufacturing a local table for an inline import.
- Support anonymous WAST module definitions/instances, opt-in Wasmtime named
  module registration, indexed ref.func identity and proper JIT funcref decoding.
- Count traps from bare invoke commands as failures instead of swallowing them.
- Include discriminant bounds and string alignment in component diagnostics.

Validation: 2,273 native tests and 89 Python tests pass. The unchanged P1 corpus
with the explicit-rights profile reports 116 passing engine/scenario pairs and
two intentionally not-applicable hostcall-fuel cases. Snapshot hashes still
validate. Linux has not been rerun for this batch.

A minimized cross-module JIT defect remains: a function obtained from an imported
table reads the caller's global (22) instead of its owner's global (11). Merely
remapping type indices would not fix this execution-context error. The repair
must preserve function identity, select the owning module's runtime state, and
check types across module-local index spaces. Threads, stack switching and the
remaining component failures are still tracked as failures.

`wide-arithmetic.wast` now passes unchanged in both engines. Added text/binary

`i64.sub128`, including unsigned carry/borrow. The reusable native frontend now
preserves both results of `i64.mul_wide_s/u`; its former fixtures incorrectly
modeled these as single-result instructions. End-to-end conditional products
and binary roundtrips cover the correct two-result contract.

The targeted report is `tmp/misc-wide-fixed/summary.json`. All 2,278 native tests

## Shared memory and atomic instruction repair

failures (`tmp/misc-shared-all/summary.json`), down from 130 each initially.
Unsupported and deferred inventories remain unchanged. Shared memory flags
survive text/binary parsing, encoding, rendering, instantiation and import
compatibility checks. Standard atomic subopcodes and exact natural alignment

All 2,284 native tests pass. An isolated AddressSanitizer harness also verifies

## Bulk memory helper repair

`memory64/bounds.wast`, `memory64/multi-memory.wast`, and `memory_init.wast`
now pass in JIT as well as the interpreter. The full unchanged scan reports
93 interpreter failures and 97 JIT failures (`tmp/misc-bulk-all/summary.json`).
The helper ABI retains 64-bit operands, normalizes memory32 operands as unsigned,
and checks ranges by subtraction before any memory access. Dropped data segments
have length zero but still require valid source and destination offsets.
Different memory indices may alias, so copies use overlap-safe memmove.
Both compiler producers share argument widening and memory64 bulk lowering.

The new guest regressions reproduced both defects before the fix. All 2,286

The targeted upstream scan has 22 passes, no failures, and unchanged exclusions.

## Component context and core module type boundaries

Both `async/sync-call-context*.wast` files now pass. Synchronous component

`component-model/modules.wast` and

## Numeric future payload repair

Pending future writes preserve canonical scalar bytes instead of truncating
values into an Int. Both rendezvous orders now support all numeric scalar
widths, with alignment and bounds checks and canonical bool/char validation.
The intra-component restriction compares the actual endpoint owners and
rejects non-numeric payloads. Structured cross-component payload transfer
remains incomplete.

The public component regression failed with an unsupported future type before
the change and now preserves u32, u64 above 32 bits, and f64 in both orders.
All 2,293 native tests pass. The full unchanged corpus reports 87 interpreter
failures and 90 JIT failures (`tmp/misc-future-all/summary.json`), with no new
exclusions or timeouts. `future-drop-writable-after-notified-drop.wast` and
`intra-futures.wast` now pass; `future-read.wast` still fails in scheduling.

## Stream readiness and count repair

Zero-length rendezvous completes only the writer; the reader remains pending
until a nonempty write arrives. Pending writes track element count independently
of byte length, so payloadless streams no longer allocate placeholder bytes.
Read/write counts are bounded to the 28 bits available in completion codes.
Resuming a suspended core continuation releases the scheduler's waiter before
executing guest code, allowing the guest to drop a completed waitable set.

Both readiness orders and the count boundary failed before the fixes and now
pass as public component regressions. All 2,295 native tests and all 24 pinned
Component Model async files (153 commands) pass. The full unchanged scan
(`tmp/misc-stream-resume-all/summary.json`) reports 85 interpreter failures and
88 JIT failures, with no new exclusions or timeouts. Both
`stream-zero-ops.wast` and `stream-big-read-and-writes.wast` now pass.

## Terminal endpoints and resumed canonical errors

Stream cancellation now consumes the completion event and records an observed
peer closure; cancellation without a pending stream operation traps. Canonical
lowering validates stream/future arguments before transferring them and does
not lift the same core arguments again when a suspended lower resumes. Task
identity migration preserves synchronous waitable ownership, and resumed future
writes consume their completion instead of being treated as a second write.

Continuation execution preserves canonical host trap reasons in both engines
and clears stale reasons before resuming. A native guest regression actually
suspends before triggering an invalid future handle, and interleaves a separate
plain-unreachable invocation to check that trap reasons cannot leak.
The component harness accepts only explicit historical terminal-state wording
aliases between the two pinned suites; wrong direction, missing notification,
and unrelated traps remain failures.

All 2,298 native tests pass. The final unchanged report is
`tmp/misc-terminal-final-all/summary.json`: 83 interpreter failures and 86 JIT
failures, with unchanged unsupported/deferred inventories and no timeouts.
`stream-cancel-finished-op.wast` and all 79 commands in `trap-if-done.wast` pass
in both engines. The existing async suite remains at 24 files / 153 commands.
WASIp1 remains at 116 passes and two intentionally not-applicable cases
(`tmp/misc-terminal-p1/summary.json`).

Minimization also exposed a separate defect: both future drop intrinsics silently
accepted unknown handles and opposite endpoints. An independent public guest
regression now checks all four combinations, and the intrinsics reject them.
All 2,299 native tests and the 24-file async suite pass. The full report
`tmp/misc-future-drop-all/summary.json` retains 83 interpreter / 86 JIT failures
with no added exclusions or regressions.

## Async task return contracts and completion

Canonical async exports now require a result published by `task.return` or
`task.cancel`; an empty core return no longer fabricates success. `task.return`
checks the result type, owning component, encoding and any explicitly specified
memory against the active lift. Omitted return memory remains valid when the
return type does not need it, including lifts whose parameters use memory.
Async function types are distinguished from an explicit canonical async ABI.

Explicit children publish into their root task. Main-thread completion preserves
children until a result is produced, and task teardown cancels remaining child
continuations. Task identity migration retains child ownership and scheduling.
A local background timer fixture was corrected to call its declared task.return;
all pinned upstream sources remain unchanged. Text encoding also now uses the
correct opcodes for thread.resume-later and thread.switch-to.

The unchanged full scan in `tmp/misc-task-contract-final-all/summary.json` has
81 interpreter failures and 84 JIT failures (445 passes, 66 script-only engine
pairs). Both task-return-traps.wast and task-deletion.wast pass in both engines;
no new failures, exclusions or timeouts were introduced. All 2,303 native tests,
24 async-suite files / 153 commands per engine, and the 116 applicable WASIp1
engine/scenario pairs pass. Two hostcall-fuel cases remain intentionally not
applicable. Linux has not been rerun.

## Canonical realloc isolation

Canonical realloc calls now run in a fresh logical task with component exits
prohibited, and restore the caller's context and exit permission on all paths.
A dedicated allocator value retains its component and async runtime ownership
when passed through pending stream/future operations. The two allocation paths
share invocation and bounds validation rather than duplicating them.

The public guest regression was initially red because realloc's context value
leaked into the lifted function. It now checks context isolation across repeated
calls and rejection of thread.index during realloc. All 2,304 native tests and
the unchanged 24-file async suite pass in both engines. The full scan in
`tmp/misc-realloc-all/summary.json` reports 80 interpreter / 83 JIT failures,
447 passes and no new regressions, exclusions or timeouts. threading-builtins.wast
now passes in both engines. Linux has not been rerun.

## Task return descriptor signatures

The validator now uses the shared Canonical ABI flattening rules for task.return
instead of treating every memory-backed value as one indirect pointer. String
and list pointer/length descriptors remain flat up to the 16-value limit, with
I32 or I64 addresses selected from the canonical memory. Runtime instantiation
uses the same memory width and propagates invalid result types instead of
silently declaring an empty signature. Required memory and type references are
validated before core instantiation.

Public string/list return guests pass with both memory widths. All 2,306 native
tests and both 24-file async suite runs pass. The complete inventory remains
80 interpreter / 83 JIT failures (`tmp/misc-return-flat-all/summary.json`), with
no new failures or exclusions. Within context-in-compositions.wast, failed
commands decreased from five to two; remaining runtime errors are not masked.

## Ready async callees through synchronous lowerings

Synchronous lowerings now take the callee's first step before deciding whether
the call needs to block. Both ordinary async returns and callbacks that publish
a result before yielding can complete immediately. A pending host call is
cancelled once and its task state removed when the synchronous caller cannot
block. Core-start tasks are tracked explicitly so instantiation retains its
stricter prohibition on entering a sync-lowered async import.

New guest and host-boundary regressions cover ready stackful/callback calls,
ready and pending host futures, cancellation, and rejection before host entry
from core start. All 2,309 native tests and the unchanged 24-file / 153-command
async suite pass. The full scan `tmp/misc-sync-ready-final-all/summary.json`
reports 77 interpreter / 80 JIT failures (453 passes), with unchanged exclusions
and no timeouts or new failures. callback-yield-then-exit.wast, fused.wast and
stackful.wast now pass in both engines.

## First-wait checks for synchronous futures

Synchronous future.read and future.write now reject a disallowed first wait
before installing pending endpoint state. Previously only a retry checked the
blocking permission, so the first suspension could report an unrelated deadlock.
A ready opposite endpoint still completes immediately. Public regressions cover
both directions, ready peers, and absence of pending state after rejection.
The preceding sync-lower cleanup now reuses the existing callback cancellation
helper instead of duplicating host-future and continuation cancellation.

All 2,310 native tests and the unchanged 24-file / 153-command async suite pass.
`tmp/misc-future-blocking-final-all/summary.json` reports 76 interpreter / 79 JIT
failures (455 passes) with no new failures, exclusions or timeouts. All commands
in future-read.wast now pass in both engines. Linux has not been rerun.

Slow functions first return Pending and become ready after one event-loop turn;

The return-two-slowly result is the pinned host's signed 32-bit value.

## Explicit thread resume state

Explicit resume operations now reject runnable, running, completed or wait-set
blocked threads rather than scheduling them as if they were suspended. Internal
scheduler wakeups retain their separate queue behavior. A public guest regression

## Async entry during synchronous waits

New asynchronous guest calls now queue while another task in that instance is
inside a synchronous future or stream wait, including after completion is queued
but before the waiting guest resumes. Immediate admission and queued admission
share the same check. Synchronous calls can still enter, and host functions do
not acquire the guest instance restriction. A public sibling-component test
covers pending and ready waits, synchronous entry to a probe, and an immediate
async host call from that probe.

All 2,314 native tests pass; the strengthened host/probe regression also passes.
Both unchanged async suite runs pass all 24 files / 153 commands. The full scan

required stream-write BLOCKED assertion but exposes a later scheduler event:
STARTED is delivered before a queued callee takes its first step, where the
upstream test expects its immediate RETURNED completion. Linux has not been rerun.

## Queued subtask first steps and status events

A queued subtask now takes its first guest step in the admission turn. Its
waitable retains the latest unconsumed subtask status, preserving its position
in the waitable-set queue when STARTED becomes RETURNED or cancelled. Admission
still counts as progress if the new task blocks. The preceding public regression
now also completes both sibling calls and requires RETURNED events in both
future readiness orders, while retaining host and synchronous-entry checks.

All 2,314 native tests and both unchanged 24-file / 153-command async runs pass.
`tmp/misc-subtask-start-all/summary.json` reports 73 interpreter / 76 JIT failures

## Null indirect thread-start entries

Thread creation distinguishes a null element in the selected table from a
non-function value and reports the core uninitialized-element trap. A public

This change does not claim to complete thread-start signature validation.

All 2,315 native tests and both unchanged async suite runs pass. The full report

## Exception boundaries and aborted async invocation cleanup

Core execution now distinguishes an uncaught Wasm exception from an unreachable
trap in both engines. Synchronous component ABI boundaries convert escaping
exceptions to traps, while async host-driven calls retain their exception
classification. A cooperative thread yield can resume without an unrelated
external event. Failed invocations cancel and retire their owned descendants
before removing ancestry, while preserving unrelated pending host invocations.
Public regressions exercise locally caught exceptions, both boundary styles,
repeated failures, residual scheduler state, and independent cancellation.

All 2,317 native tests and both unchanged 24-file / 153-command async runs pass.
The full report `tmp/misc-exception-cleanup-all/summary.json` records 70 interpreter
/ 73 JIT failures (467 passes). Both synchronous and asynchronous exceptions.wast
now pass in both engines, with no new failures, exclusions or timeouts. The P1
explicit-rights run before the component cleanup change passed 116 cases plus
two not-applicable cases. Linux has not been rerun.

## Canonical arguments and post-return across async drivers

Canonical argument lifting now accepts only parameter values; the lowering ABI
separates its return pointer exactly once. This fixes async calls with multi-field
results such as strings. All drivers of synchronous core ABIs invoke the same
post-return helper after lifting and validating results. A public regression
covers both engines, sync and async lowerings, immediate and yielding callees,
repeated calls, exact post-return counts, and returned strings whose source bytes
are overwritten by post-return.

All 2,318 native tests and both unchanged async suite runs pass.
`tmp/misc-result-all/summary.json` reports 69 interpreter / 72 JIT failures
(469 passes); context-in-compositions.wast passes in both modes, with no new
failures, exclusions or timeouts. Linux has not been rerun.

## Intra-component stream and post-return thread guards

Streams retain their numeric payload classification and reject guest-to-guest
rendezvous within the same component for non-numeric payloads, using the same
rule as futures. Public regressions cover both rendezvous orders, both engines,
strings, booleans, numeric payloads and payloadless streams. Thread promotion
intrinsics now check the prohibition on leaving a component before reporting
that promotion is not implemented. The text parser recognizes both promotion
spellings; tests retain the explicit unsupported result outside post-return.

All 2,320 native tests and both unchanged async suite runs pass.
`tmp/misc-guard-all/summary.json` reports 67 interpreter / 70 JIT failures
(473 passes), with intra-streams.wast and threading-trap-in-post-return.wast now
passing in both engines. No new failures, exclusions or timeouts were introduced.
Linux has not been rerun.

## Component containment, initialization and active entry

Removed the blanket ban on calls between parent and child components and the
whole-component readiness gate on adapters whose core functions already exist.
Active execution and permanent trap poisoning remain guarded. Public regressions
cover both containment directions, real cyclic reentry, poisoning, and core start
calling an already defined adapter. Obsolete ancestry metadata is removed.

The user approved following Wasmtime semantics where the old component-spec
snapshot's temporary assertions conflict. Direct Wasmtime 40.0.0 probes confirmed
that both simple containment calls succeed while the recursive callback case
still traps. The two assertions are corrected in a separately hashed local copy;
the upstream bytes and original snapshot hashes remain intact. The suite runner
announces each correction, and integrity tests reject source drift, corrected
file edits and unlisted files. No misc assertion or exclusion was changed.

All 2,322 native tests, both corrected async suite runs (24 files / 153 commands),
and the stable suite JIT run (23 files / 845 commands) pass. The full report
`tmp/misc-entry-all/summary.json` records 65 interpreter / 68 JIT failures
(477 passes); adapter.wast and async/reentrance.wast pass in both modes, without
new failures or timeouts. Linux has not been rerun.

## Unified host async invocation driver and backpressure

Blocking async calls now use the same invocation driver as pollable calls,
removing the duplicated callback/host-future waiting loop. Both respect instance
backpressure before entering guest code, allow cancellation while queued, and
report deadlock when nothing can release backpressure. Yielded invocations give
other tasks a scheduling turn; a suspended synchronous wait is not reported as
runnable progress. Callback context is restored on both normal return and trap.
Public regressions cover both engines and core ABI styles, queued cancellation,
synchronous unblocking, event-loop unblocking, and callback exception cleanup.

All 2,324 native tests and both corrected async suite runs pass. P1 explicit
rights remains 116 passes plus two not-applicable cases. The full report
`tmp/misc-backpressure-all/summary.json` records 64 interpreter / 67 JIT failures
(479 passes); drop-deadlock.wast now passes in both modes, with no new failures,
exclusions or timeouts. Linux has not been rerun.

## Subtask cancellation and shared completion

Synchronous subtask cancellation now waits through nonterminal guest progress;
host futures are cancelled through their actual cancellation callback. Cancelling
a completed task consumes its terminal status and rejects subsequent attempts.
The scheduler and cancellation path share result lowering and completion event
publication, including correct floating-point result stores and propagated store
errors. Public tests cover delayed guest cancellation, callees that return a value
instead, repeated cancellation, and host cancellation through both canonical ABIs.

All 2,326 native tests and both corrected async suite runs pass.
`tmp/misc-subtask-cancel-all/summary.json` reports 61 interpreter / 64 JIT failures
(485 passes). cancel-host.wast, yield-when-cancelled.wast and
threading/drop-subtask-on-separate-thread.wast pass in both engines, without new
failures, exclusions or timeouts. stackful-cancellation.wast now exposes the next
issue: async cancellation eagerly resumes a non-cancellable suspension instead
of waiting for a cancellable point. Linux has not been rerun.

## Cancellable suspension points and thread wakeups

Async cancellation now resumes a suspended guest only at a cancellable canonical
instruction. Task state records yield, suspend and wait separately, preserving
pending cancellation through non-cancellable points. An implicit thread suspended
without a runnable peer yields to its supertask and waits for an actual resume;
explicit threads waiting synchronously on futures/streams wake when their event
arrives. Cancellation belongs to the logical task across its explicit threads.

A public regression checks immediate versus deferred cancellation in both engines.
All 2,327 native tests and both corrected async suite runs pass.
`tmp/misc-cancel-point-all/summary.json` reports 60 interpreter / 63 JIT failures
(487 passes), with stackful-cancellation.wast now passing in both engines and no
new failures, exclusions or timeouts. Linux has not been rerun.

## Fixed-length lists and typed canonical memory layout

Fixed lists now parse from component text and participate in canonical validation,
flat signatures, parameter/result conversion, memory layout and resource traversal.
Signature-only flattening accepts a bounded prefix, so a large fixed list does not
allocate billions of type entries while deciding whether its ABI is indirect.
Indirect argument/result memory now uses the existing typed canonical load/store
implementation, preserving nested element padding instead of concatenating flat
field layouts. Single-scalar compound results are lowered recursively.

Public tests cover nested lists, exact length validation, padded result elements,
indirect padded parameters and single-element results in both engines; a signature
regression covers a 2,147,483,647-element type without expanding it. All 2,332 native
tests pass. Stable component-spec passes 23 files / 845 commands; both corrected
async runs pass 24 files / 153 commands. The full report
`tmp/misc-fixed-list-all/summary.json` records 59 interpreter / 62 JIT failures
(489 passes), with fixed_length_lists.wast newly passing in both modes and no new
failures, exclusions or timeouts. Linux has not been rerun.
