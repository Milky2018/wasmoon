## Description
After the real MilkIR/MachV migration, several remaining `legacy` or `fallback` strings are comments, docs, or test wording rather than old implementation paths. They are still worth cleaning because they can make the new architecture look like it relies on historical compatibility shims.

Historical ISS notes should remain as history. The cleanup target is current source-facing wording that describes live code imprecisely.

## Design
Do a surgical wording pass only. Reword misleading comments and documentation without changing behavior. If a term such as `fallback_root_counts` is still accurate and low-risk to keep, document that decision in this issue instead of forcing a rename.

Known examples from the audit:
- `modules/wasmoon_jit/runtime_symbols.mbt`: replace "legacy negative runtime-helper fixup id" wording with `cwasm` or compatibility-runtime terminology.
- `modules/wasmoon/README.mbt.md`: avoid describing the interpreter as a JIT fallback; describe it as the full interpreter execution engine.
- `modules/wasmoon/runtime/store.mbt`: clarify the "Keep for fallback" heap comment as interpreter/runtime state ownership.
- `modules/wasmoon/testsuite/compare.mbt`: remove "legacy" from the JIT value-conversion comment.
- `modules/machv_regalloc/reload_coalescing.mbt`: replace "legacy apply allocation path" with wording about the in-place allocation-application path.
- `modules/isa_target/lower/lower.mbt`: clarify "emitter fallback path" as immediate materialization fallback, not interpreter fallback.
- `modules/machv_emit/runtime.mbt` and `modules/wasmoon_jit/cwasm_artifact.mbt`: decide whether `fallback_root_counts` should be renamed to `default_root_counts` or `conservative_root_counts`.

## Acceptance Criteria
- [ ] Current source comments and README text no longer imply that the migrated JIT depends on old legacy code or interpreter fallback.
- [ ] Historical ISS notes are preserved unless a short corrective note is needed.
- [ ] Any retained `fallback` terminology is explicitly justified by current behavior.
- [ ] No behavior changes are included.
- [ ] `git diff --check` passes.
- [ ] `moon check --target native --warn-list +73 --diagnostic-limit=200` passes.
