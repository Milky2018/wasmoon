## Description
Current pinned regex GC execution spends about46% of sampled main-thread work
in native graph discovery and marking. Per-collection lifetime counters identify
mostly dead young allocations alongside a growing, almost entirely surviving
mature graph. Small traversal guard changes do not solve the repeated work.

## Design
Evaluate a generational collection path using the existing stable identities,
compact layouts, precise root protocol and reference-write barriers. Keep policy
and root coordination in MoonBit. Preserve the complete major collector for
explicit collection, rollback, unsupported layouts, quotas and auxiliary roots.
A remembered set must cover every old-to-young write without allocating or
collecting in the write barrier. Young collection must preserve old offsets,
stable nonrecycled identities, callback ordering and all admission semantics.
Do not introduce a workload-specific switch or weaken verification.

## Acceptance Criteria
- [x] Attribute the hot path and measure young/mature survival independently.
- [x] Audit every reference write, including bulk copy/fill and compiled stores.
- [x] Prove complete old-to-young roots and safe major fallback/abort transitions.
- [x] Reproduce repeatable invocation/RSS gains and report all workload controls.
- [x] Pass explicit GC, mutation, cycles, roots, rollback, quotas and fault tests.
- [ ] Pass full native/wasm, integration, fresh sanitizers and exact-head CI.
