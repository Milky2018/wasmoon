## Description

Fresh-cache AEGIS measurements on macOS AArch64 show two independent deficits:
warm execution is about 1.26x Wasmtime, while current-version module compilation
takes about 1.705 seconds versus 15.8 milliseconds for parallel Cranelift and
29.9 milliseconds for serial Cranelift. The runtime gap is concentrated in one
generated function; the compile-time gap is concentrated in large-CFG register
allocation.

## Design

Fix measurement validity first, then remove the demonstrated allocator and
instruction-selection bottlenecks. Re-measure allocation pressure before
extending stable environment-field reuse. Do not add speculative mid-end passes,
pin a dedicated allocatable register, weaken correctness checks, or add parallel
compilation in this epic.

## Acceptance Criteria

- [x] Cached artifacts cannot hide code-generation changes during measurement.
- [x] Compile metrics separate semantic lowering, target lowering, allocation,
      frame planning, and emission.
- [x] Large-CFG clobber queries no longer linearly rescan every clobber point.
- [x] AArch64 selects the immediate and shifted-operand forms demonstrated by
      the AEGIS comparison.
- [x] Fresh-cache AEGIS allocation pressure and stable environment-field reuse
      improve without ABI, trap, GC, or metadata regressions.
- [x] Final paired current-version evidence and validation commands are recorded.

## Close Notes

Closed after ISS-253 through ISS-260 completed. Code-generation revisions now
participate in cache identity; benchmarks alternate engine order and use an
isolated cache; schema-v3 metrics separate all target stages; and register
clobber queries use a logarithmic index.

The AArch64 hot path now selects immediate shifts and rotates, shifted-left
adds, and pointer-offset immediates. Bounded stable environment-field reuse
reduces repeated loads without reserving a physical register or increasing
spill pressure. AEGIS `func_30` fell from 19 slots / 17 spills / 22 reloads /
1,568 bytes to 10 / 8 / 10 / 1,296 bytes.

The final seven-pair current-version report is
`docs/perf/aarch64-jit-current-version-2026-07-23.md`. Median Wasmoon/Wasmtime
ratios are `1.166985` for the guest-reported value and `1.161701` for wall time,
an 8.13% and 8.14% improvement from the initial paired measurement. All recorded
quality and correctness gates pass. Remaining native AMD64 compile-trend
collection stays explicitly scoped in ISS-212 and is not a dependency of this
AArch64 epic.
