## Description
Make the Core interpreter usable as a MoonBit library compiled with `--target wasm`, with a runnable embedding example and automated execution tests. Selecting `--no-jit` currently changes the execution engine but does not remove native runtime dependencies.

At `94333aa3` (0.17.0), both `wasmoon` and `wasmoon_jit` declare `supported_targets = "native"`. The interpreter imports `runtime`, whose types and constructors depend on `wasmoon_jit` and `jit_ffi`:

- [Memory](../modules/wasmoon_runtime/runtime/memory.mbt) uses a C descriptor as its authoritative storage even for interpreter loads, stores and growth.
- [Store](../modules/wasmoon_runtime/runtime/store.mbt) constructs `NativeExecutionState` for an ordinary interpreter Store and owns native heap, table, callable and exception integration.
- [Resource budgets](../modules/wasmoon_runtime/runtime/resource_budget.mbt) use C `Quota` and `Reservation` objects; automatic reservation release depends on their native lifetime.
- [Rooted values](../modules/wasmoon_runtime/runtime/rooted_value.mbt) use `CleanupOwner` and a C finalizer to retire guest GC roots when the last host reference disappears.
- [Execution limits](../modules/wasmoon_runtime/runtime/execution_limits.mbt) depend on `wasmoon_jit.InvocationControl`, although cancellation and safepoint accounting are shared runtime policy.
- GC tracing and exception/continuation bridges mix portable Store identities with native encoded references and native registries.

The nine reusable specification/compiler modules already declare all-target support. Local `wasm` and `wasm-gc` strict checks and 1065/1065 tests per target pass, but these exclude the native-only interpreter and product runtime. They are a baseline, not acceptance of this feature. Moving policy from C into MoonBit under ISS-635 did not remove these representation and lifetime dependencies.

## Design

### Delivery scope
Deliver the Core interpreter library on the linear-memory `wasm` target, initially executing under the installed stable `moonrun` host. Document every required host import and distinguish a synchronous embedding from an embedding that uses async. A Wasm artifact must actually parse, validate, instantiate and execute guest Core Wasm; successful type checking alone is insufficient.

Full `wasm-gc`, browser/JavaScript packaging, the complete CLI, Component execution, WASI host implementations, HTTP serving and JIT execution are separate capabilities, not implicit acceptance criteria for this issue. Keep existing native behavior intact and document any target-specific Core feature or capacity limits. Do not describe interpreter portability as portable WASI support.

### Agreed implementation

Use target-selected files and `#cfg` declarations for physical storage and native
integration. Keep one guest instruction dispatcher, validator, explicit interpreter
stack, root worklist and continuation driver. A new generic backend interface or
lifecycle framework is not a prerequisite.

The shared implementation lives in `Milky2018/wasmoon_runtime`, below the native
`wasmoon_jit` and `wasmoon` modules. Existing native public paths reexport the
canonical implementations. Its native primitive packages select real managed
quota/metadata code on wasm; no C stub, native execution state or native JIT
module enters that target's build. Conditional package imports are unavailable
in the current stable build system, so file selection alone in the old native
module would not suffice.

Native descriptors, finalizers and independently retained native ownership stay
intact. wasm uses managed memory/tables and the existing explicit `close`,
`release` and `cancel` operations, normally enclosed by `defer`. Dropping a wasm
root/reservation does not promise native-style finalization. Store close and
rollback explicitly release owned resources. No runtime ABI hook or new scope
framework is introduced to imitate a C finalizer.

See [the implementation guide](../docs/portable-interpreter.md) for the ownership
inventory, host requirements, capacity limits and capability matrix. Keep this
issue open until platform CI, including Linux leak detection, has accepted the
submitted implementation; local wasm execution is separate evidence.
