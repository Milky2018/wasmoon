## Close Notes
Retained only the physically identical operand-array ownership scan optimization. Two fixed 21-pair complete-compilation rounds on eight inputs show small improvements (about 0.4–1.3% point estimates); four inputs have intervals below zero in both rounds. No general CLI speedup or peak-memory reduction is claimed. Existing malformed-array validation and first-error order remain intact.

Rejected prefix scratch: allocation decreases about 0.2–0.6%, but compilation regresses about 0.7–2.1% in both rounds and peak allocation is unchanged. Conditional use counts and the combined patch are withheld: repeated real CLI and cache-hit execution regressions require the investigation in ISS-592. Individual CLI probes do not establish the root cause. Owner-only CLI results include a non-repeating short-workload regression; the report preserves both the original group and fixed follow-up.

The report and compressed evidence at docs/perf/compiler-candidates-2026-09-28.md retain all fixed-round samples, patches, normalized allocation counts, diagnostics, input and binary hashes, and local supplemental-input provenance. All 2,688 timed compilation artifacts match exactly for each input.

Validation: info/fmt, strict native check, 2,586 native tests, fresh installed core WAST (258 files and 62,563 assertions per engine), and pinned misc (676 passes, zero unexpected errors; existing 72 script-only / 16 deferred entries unchanged).
