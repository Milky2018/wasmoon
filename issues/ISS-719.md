## Description
Physical address invalidation currently becomes an unknown logical write at the
native memory seam. Collection therefore discards values already read from
unchanged objects. Carry independent versions through the shared optimizer so
logical reuse does not require extending a physical borrow's lifetime.

## Design
See [Logical memory and physical address epochs](../docs/gc-memory-epochs.md).
Keep runtime layouts, helper ABI, allocation accounting, traps, root publication,
barriers, cancellation, fuel, cooperation and the independent borrow proof.

## Notes
- Initial production-seam regression fails on d36b0d9d with two reads instead
  of one. The implementation carries separate address and logical versions;
  it does not relax GC borrow verification or permit unknown call reuse.
- Two independent five-pair rounds on the original ten-call input retain
  median paired changes of -0.539% and -0.046%; the confirmation is mixed.
  No material original-workload speedup is established. All 60 processes pass;
  startup samples and RSS remain separately scoped in the design document.
- Omitting the physical epoch from extension GVN independently fails three
  controls, including a stale projection rejected by the unchanged borrow
  verifier. Restoring the implementation passes all six selected regressions.
- A deterministic capacity-bound allocation regression observes actual
  collection at optimization levels 0, 2 and 3, preserves logical field values,
  observes an aliased mutation and verifies the resulting heap.
- Local gates pass native 3233 ordinarily and with all three verification
  flags, Wasm 1512, strict checks on both targets with warning 73 denied,
  info/fmt, C45, module boundaries, guest bridges and Python 180 (54 existing
  host skips). Both engines pass Core 258/62563 and Component 59/1385 with
  all three verification flags. Exact committed-source sanitizer/platform
  acceptance remains pending.
