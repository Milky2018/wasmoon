## Description
MilkIR has working data structures, verification, printing, optimization, and
lowering paths, but its semantic contract is not yet documented enough for
external users. Important behaviors such as value ownership, block parameters,
memory operation meaning, effectful calls, traps, `CallPtr`, extension
operations, and optimization safety are currently learned from code.

Without a written semantic contract, MilkIR is harder to use as reusable
compiler infrastructure and harder to stabilize without accidental breakage.

## Design
Write executable and prose documentation for MilkIR's core semantics. The docs
should be precise enough for frontend authors and lowering authors, but should
not become a full formal specification before the API is stable.

Prefer README examples and focused docs that can be checked with `moon test
README.mbt.md` where possible.

## Acceptance Criteria
- [ ] MilkIR docs explain SSA values, block parameters, terminators, function signatures, stack slots, external symbols, traps, and call effects.
- [ ] Docs explain what optimizations are allowed to assume about calls, memory, and extension operations.
- [ ] Docs state the intended contract for `CallPtr` and how embedding-specific details are supplied outside MilkIR core.
- [ ] At least one executable README example exercises nontrivial control flow or extension operations.
- [ ] README tests and native checks pass.
