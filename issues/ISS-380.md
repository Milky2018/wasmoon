# ISS-380: Remove unbounded native recursion from e-graph build and write-back

## Description
Two paths in the e-graph pass recurse on the native call stack with depth
bounded only by input shape:

- `rewrite_block` (`modules/milkir/egraph_builder.mbt:439`) recurses down
  the dominator tree, so a long chain of blocks — common in generated
  code — grows the stack linearly with CFG depth;
- `EGraphBuilder::add_value` (`modules/milkir/egraph_builder.mbt:~250`)
  recurses along operand chains, so a long dependency chain of
  instructions does the same.

This project has already measured deeply nested inputs in the wild (the
ISS-370 report's 47-level component nesting); a function with thousands of
blocks in a chain risks a stack overflow inside the optimizer, which
surfaces as a crash rather than a diagnosable error.

## Design
Convert both traversals to explicit worklists/stacks (the codebase already
does this for the regalloc verifier's DFS in
`modules/regalloc/verify_plan.mbt`). The dominator-tree walk needs
enter/exit events to preserve the scoped `class_to_value` bind/restore
semantics. Add a stress test with a deep block chain and a deep operand
chain sized well past default-stack comfort.

## Acceptance Criteria
- [x] `rewrite_block` and `add_value` no longer recurse on the native
      stack.
- [x] Scoped representative binding still restores correctly on scope exit
      (existing dominator-scoping tests stay green).
- [x] A deep-chain stress test (blocks and operands) passes under the
      native test target.

## Close Notes

Both traversals now use explicit heap stacks.

- `add_value` walks operand chains with a `(value, expanded)` stack: a value
  is pushed once to request its operands and revisited once they are
  converted. Leaf handling and the class lookup were factored into
  `add_leaf_value` / `lookup_value` / `value_has_children`.
- The dominator-tree walk became `rewrite_dominator_tree`, driven by a
  `DomWalkEvent` stack. `Exit` carries the block's scoped bindings and is
  pushed before its children, preserving the exact bind/restore order the
  recursive version had.

Red/green evidence: with the two stress tests at 100,000 levels, the
recursive version dies with SIGSEGV (stack overflow) and the worklist
version passes. Note the first attempt at 20,000 passed on both, and an
operand-chain fixture built from `copy` proved worthless — `copy` has no
e-graph encoding, so it becomes a leaf; the fixture now chains `iadd`.
Verified: milkir 175/175 (including both stress tests), egraph 194/194,
wasmoon testsuite 562/562, `moon check --warn-list @73` clean.
