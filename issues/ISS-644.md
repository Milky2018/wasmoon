# ISS-644: Instantiation hangs on modules with thousands of distinct types

## Description
Instantiating a 647 KB wasm-gc module produced by moonc (Vitro `vitro/engine@0.8.0`: 5,003 types, 18 rec groups, 749 globals) never returns in wasmoon 0.17.0. Decode and validation complete, all imports link, but no guest instruction executes and no host import is ever called, with or without the start section. Synthetic modules from the same compiler up to 869 KB with few distinct types work fine, so module size, function count, and function body size are not the trigger; the number of distinct types is.

Two superlinear paths compound during instantiation:

1. `StoreTypeRegistry::register_graph` mapped every type by scanning all registered representatives and built a fresh `TypeEquivalenceContext::cross_module` (two O(n) `RecGroupIndex` constructions plus fresh caches) per candidate, making one registration pass cubic in the type count.
2. Constant-expression allocation (`eval_const_expr` -> `Store::alloc_struct`/`alloc_array` without an instance) reaches `record_gc_type`'s unowned branch, which registered with `store_index = -1` and therefore never hit the mapping cache: every allocating global initializer repaid the full pass.
3. `compute_canonical_type_indices` compared every rec group against every earlier group (quadratic in group count), which already cost minutes at 5,000 types before the registry work even started.

Measured on the 0.17.0 debug CLI with synthetic modules of N distinct singleton types plus one `struct.new_default` global: N=500 took 27.6 s, N=1000 took 244 s (cubic), two allocating globals at N=500 took 64.5 s (per-allocation recompute), and the types-only control at N=5000 took 205 s (quadratic canonical). N=5003 extrapolates to hours per pass, times hundreds of allocating initializers.

## Design
Give isorecursive rec groups a structural fingerprint (group members hashed in order; internal references by position; external references by a caller-supplied identity; abstract heap-type references such as WAT `arrayref` (`RefNullArray(-1)` and friends) encoded as-is), and use it as a necessary-condition bucket key. Exact equivalence is still decided by `TypeEquivalenceContext`, so fingerprints only narrow candidates and hash collisions cannot change results.

- New `wasm_core/types/canonical.mbt` exposes `fold_type_groups`, which visits groups in definition order so callers can resolve external identities lazily from the mapping being built. Hashing uses rotations and xor only: native debug builds trap on signed integer overflow, so wrapping multiplication (FNV-style) is not usable.
- `compute_canonical_type_indices` buckets previously seen groups by fingerprint and structurally verifies only within buckets, preserving its exact output.
- `StoreTypeRegistry::register_graph` locates candidate groups through fingerprint buckets, reuses one verification context per contributing graph, and assigns group identities position-by-position as before. The unowned module-types graph now caches under a version bumped by `Store::set_module_types` (including its rollback restore), so constant-expression allocations stop repaying registration.
