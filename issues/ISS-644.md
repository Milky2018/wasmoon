# ISS-644: Reuse type graphs during GC initialization

## Metadata
- Type: bug
- Status: in_progress
- Priority: 1
- Labels: runtime, gc, performance, type-system
- Assignee: unassigned
- Created: 2026-10-20
- Updated: 2026-10-20
- External ref: https://github.com/Milky2018/wasmoon/issues/548

## Description
Before a ModuleInstance exists, every GC allocation registers the full module
type graph with a negative instance index. That path has no cached mapping.
Registration also rebuilds recursive-group indices for each representative
comparison. On main `7854228a`, 100 simple globals with 100 types take about
4.7 seconds to instantiate; prevalidated input has the same cost.

## Design
Retain a Store-owned registered graph for the current set_module_types scope,
including both the immutable types and recursive groups. Reset it when that
scope changes, restore the prior graph on rollback, and never restore it after
terminal Store close. Published instances may reuse the same graph when their
snapshots agree. Keep graph identities separate from canonical Wasm identities.

Within one registration, reuse the type-equivalence context for each candidate
graph. Full recursive-group equivalence still decides every match; no shallow
shape test substitutes for it. Comparison contexts are temporary, not a new
Store-lifetime cache of all type pairs.

## Notes
- 2026-10-20: Final local [evidence](../docs/evidence/gc-type-registration-2026-10-20/README.md)
  records 100-global raw instantiation at 4916/4829 ms before versus 2/2 ms
  after, and real cmp unstarted instantiation at 2135/2104/2074 ms versus
  7/7/7 ms. Native 2808, wasm 1333, full Core/Component/misc corpora and fresh
  macOS sanitizer 200 passed. This is dirty working-tree evidence, not CI or
  Linux LSan acceptance; platform CI remains outstanding.
- 2026-10-20: The mapping-reuse regression fails on both native and wasm before
  the fix. A separate close-during-rollback regression exposed restoration of
  cached metadata after terminal close; the rollback guard now preserves close.
- 2026-10-20: A new GC-global JIT comparison failed on both unchanged main and
  the candidate. The existing comparison helper initialized globals in one
  heap but executed JIT code with a fresh empty CHeap. It now uses the same
  Store-owned CHeap throughout; the original expected value and parity check
  pass. This test-helper correction is separate from the registration optimization.
