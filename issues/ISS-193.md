## Question

Which compile-time, verification, correctness, code-quality, code-size, runtime-performance, interface, dependency, and artifact gates must the completed migration satisfy before the old MachV representation can be removed?

## Acceptance Criteria

- [x] Required unit, snapshot, verifier-negative, WAST, component, and WASI gates are named.
- [x] AArch64 and AMD64 correctness and performance comparison baselines are restored as executable inputs.
- [x] Boundary audits and API/interface checks are included alongside runtime tests.
- [x] The versioned workload manifest mechanically enforces the required micro-codegen features, multiple real algorithms, and large compile-stress shapes.
- [x] Real AArch64 and AMD64 CI jobs reject unexpected target identities and run the complete correctness matrix, including fixed-seed Wasm-Smith JIT/interpreter differential coverage.
- [x] A blocking paired runner rebuilds the fixed legacy commit and enforces the approved runtime, compile-time, and code-size thresholds.
- [x] Every migration-issue closing commit emits a complete machine-readable gate manifest and retains all referenced evidence as CI artifacts.

## Gate Contract

| Gate | Blocking rule |
| --- | --- |
| Common quality | Boundary audit, `moon info`, `moon fmt`, native check, native tests with regalloc validation, `git diff --check`, and reviewed `.mbti` diff must pass. |
| Target identity | AArch64 and AMD64 jobs run on real matching hardware and reject an unexpected `uname -m`. |
| Correctness | Repository-owned unit, blackbox, verifier-negative, snapshot, WAST, component, WASI, sanitizer, and artifact tests have zero new failures. |
| Structural parity | Stable semantic-site comparison must prove semantic IR, calls, traps, roots, relocations, fixups, frames, and unwind contracts are preserved. |
| Runtime performance | Paired fixed-legacy comparison permits at most 3% corpus geometric-mean regression and 5% on any workload. |
| Compile performance | Paired fixed-legacy comparison permits at most 5% corpus geometric-mean regression and 10% on any workload. |
| Code size | Total emitted corpus bytes may not increase; no workload may increase by more than 5%. |
| Interfaces and dependencies | Planned `.mbti` changes only, required dependency direction, shrinking adapter allowlist, and milestone-specific zero-residue audits. |
| Native artifacts | Bounded verified decoding, exact compatibility manifests, atomic installation, fuzz/property coverage, and live-JIT behavioral parity. |
| Evidence | Machine-readable correctness reports must be complete, parseable, retained as CI artifacts, and successful before an issue can close. |

- 2026-07-16: Workload-manifest changes are standalone reviewed commits that rebuild both architecture-specific fixed-legacy baselines. A candidate cutover may not change the benchmark corpus or its expected outputs while using the resulting measurements for acceptance.
- 2026-07-16: Approved normalized structural comparison rather than byte, layout, or physical-register identity. At semantic-producer cutover, normalized function signatures, blocks and edges, block arguments, operations, effects, traps, calls, and safepoints must match exactly. At target cutover, instruction selection, layout, physical allocation, constant pools, and final offsets may differ, but every stage must pass its verifier.
- 2026-07-16: Relocations and fixups compare `(function, semantic site, kind, target, addend)` while ignoring final code offsets. Traps compare `(function, Wasm source offset, trap kind)` with no missing or additional sites. Safepoints and stack maps compare semantic site plus live-root identity and type; each candidate root must resolve to a valid register or stack slot. Calls compare callee kind, signature, ABI argument/result assignment, clobber contract, and tail-call kind. Frame and unwind comparison requires recoverability, callee-save correctness, stack alignment, and legal frame size but not identical frame size.
- 2026-07-16: Normalized disassembly is diagnostic and review evidence, not the sole hard oracle. If metadata cannot be aligned by a stable semantic-site identity, the implementation must introduce a stable ID before comparison; array order and machine-code offsets are not accepted substitutes.
- 2026-07-16: Decided that generated interfaces and dependency direction are hard gates equal to runtime correctness. Every milestone commits and reviews its `.mbti` diff; any unplanned public symbol, field, constructor, or package import fails acceptance. The semantic `machv` module may not depend on targets, regalloc, emitters, Wasmoon product packages, or `machv_legacy`. AArch64 and x64 may depend on semantic MachV, the shared regalloc seam, and their own ISA packages, but not on each other.
- 2026-07-16: `wasmoon_jit` is the product-owned composition module for target pipelines, runtime-symbol resolution, executable memory, and installation. - 2026-07-16: Source-line count is not an acceptance metric. Interface depth, dependency direction, verification locality, and the absence of migration residue are the structural criteria.
