## Notes
- 2026-07-15: CI availability is not itself the architecture; the resolution must distinguish required evidence from temporarily unavailable runners.
- 2026-07-16: Claimed to define executable correctness, interface, artifact, code-quality, compile-time, code-size, and runtime-performance gates before ISS-194 may begin. Repository facts will be measured first; only policy thresholds and tradeoffs require HITL decisions.
- 2026-07-16: Current correctness CI runs `moon check`, all MoonBit native tests with `MACHV_REGALLOC_VALIDATION=1`, formatting/interface drift checks, release builds, component WAST, and core WAST on both `macos-latest` and `ubuntu-latest`. Ubuntu additionally runs ASan/UBSan GC differential stress. The jobs do not assert the actual host architecture, so the final AArch64/AMD64 gates must record and reject an unexpected `uname -m`.
- 2026-07-16: The Preview 1 CLI integration suite at `examples/wasi_tests/wasi_test.py` exercises 43 cases through both JIT and interpreter, but it is not currently invoked by GitHub Actions. It must become an explicit target-cutover gate rather than being inferred from `moon test`.
- 2026-07-16: Current performance CI is scheduled Ubuntu-only and warning-only. It uses 15% elapsed, 15% compile-time, and 5% code-size thresholds plus Wasmtime ratios, but neither `docs/perf/baselines/linux-amd64/perf-summary.json` nor `docs/perf/baselines/darwin-arm64/perf-summary.json` exists in the current tree.
- 2026-07-16: The existing benchmark runner cannot currently establish a complete baseline: on local Apple Silicon, three of its four default run workloads (`core3`, `stream`, and `box_easy2`) fail JIT compilation before metrics are written. The surviving `benchmark.wasm` probe over seven measured runs showed wall-time CV about 2.08%, compile-time CV about 5.88%, and deterministic 680-byte code size. A migration gate therefore needs repaired workloads and paired same-runner comparison rather than a single absolute historical timing.
- 2026-07-16: Existing opt-in metrics already expose module and per-function compile time, optimize/lower/regalloc/emit phases, code size, spills, reloads, moves, and pass work. The missing infrastructure is a legacy/new paired runner, stable aggregation and variance handling, target identity, and hard-failure integration for cutover milestones.
