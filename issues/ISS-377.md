## Description
The e-graph pipeline has no elaboration step, so almost all rewrite results
are discarded. The only write-back channels are:

- `get_simplified_opcode` (`modules/milkir/egraph_builder.mbt:324`), which
  applies an extraction result only when the best node is `Const` — its own
  comment says complex rewrites like `x*3 -> (x<<1)+x` "would require operand
  reconstruction";
- `get_simplified_operand` (`modules/milkir/egraph_builder.mbt:347`), which
  replaces an operand only when the better representative already exists as
  an IR value bound in a dominating scope (GVN-style aliasing).

Any rewrite that produces a new expression shape — strength reduction,
`select`→`bmask`, extend/reduce narrowing chains — is computed inside the
e-graph and then thrown away. The rules corpus this starves is large:
roughly 8,000 lines across `rules_icmp` (1,758), `rules_extends` (1,290),
`rules_bitwise` (1,032), `rules_shift`, `rules_select`, `rules_algebraic`,
`rules_spaceship`, and more. The pipeline pays full saturation cost and
harvests only constant folding plus aliasing.

The starvation is actually double: the production driver never loads that
corpus in the first place. `run_egraph_pass`
(`modules/milkir/opt_driver.mbt:76`) unconditionally uses
`get_compact_ruleset()` (~20 trivial identities plus constant folding);
`get_global_ruleset()` (~250 rules) and `legality_sensitive_rules()` have
zero production callers — only tests exercise them. The rematerialization
machinery (`rule_remat_*`, `EGraph.remat_set`, `remat_cost_bonus`) is wired
only into the global ruleset and is therefore also dead in production.
Building elaboration without revisiting the driver's ruleset choice would
change nothing observable.

## Design
Follow Cranelift's aegraph direction: after saturation, extract the best
node per needed class and materialize missing nodes as new IR instructions
at the appropriate insertion points (dominating the uses, reusing the
existing scoped `class_to_value` bindings for sharing). Alternatively, if
elaboration is judged too costly, prune the ruleset to the subset whose
results the current channels can realize, and record the trade-off here.
Do not keep the current middle state.

Hard prerequisite: the extraction memoization poisoning in ISS-378 must be
fixed first — elaboration consumes extraction results for non-constant
nodes, exactly the ones the poisoned memo can corrupt.

Whichever direction is chosen, the decision must cover the driver's
ruleset selection: elaboration only pays off if `run_egraph_pass` actually
loads the rules whose results it materializes (with limits scaled per
function size as today), and pruning must delete or test-scope the
never-loaded corpus rather than leave it as production dead weight.

## Acceptance Criteria
- [x] A rewrite whose best form is a new expression shape (e.g. a
      strength-reduction result) reaches the emitted MilkIR, verified by a
      before/after test.
- [x] Elaborated nodes are shared via dominator-scoped bindings rather than
      duplicated per use.
- [x] The examples/algorithms corpus sweep and both JIT/interp comparison
      suites stay green.
- [~] Pruning was not chosen, so this criterion does not apply.
- [x] The driver's ruleset choice is revisited as part of the decision:
      either the elaboration-backed ruleset is loaded in production, or the
      never-loaded corpus (including the remat machinery) is deleted or
      test-scoped.

## Close Notes

Chose elaboration over pruning: the rules corpus encodes real work, and the
project's direction is Cranelift-aligned, where elaboration is the piece
that makes a rule library pay off.

`modules/milkir/egraph_elaborate.mbt` adds the missing write-back channel.
For an instruction whose class extraction assigned a different best node, it
plans the operands — reusing dominator-scoped bindings where they exist,
otherwise scheduling new instructions children-first — and commits only if
the whole plan succeeds within `ELABORATION_BUDGET` (4) new instructions.
A plan that cannot be realized leaves the function untouched. Newly emitted
values are bound into `class_to_value`, so a later use in the same or a
dominated block shares them instead of rebuilding.

Deliberate limits, all of which make the planner refuse rather than guess:
e-nodes with no MilkIR spelling (`Smin`, `Bmask`, `SpaceshipS`, floats,
vectors) — the IR admission set is narrower than the e-node language; `Var`
nodes with no dominating binding; operands of unknown width; cyclic shapes;
and plans exceeding the budget. The budget exists because the cost model
prices a child subtree even when that child already sits in a register, so
it can favour rebuilding over reuse.

`run_egraph_pass` now loads the full ruleset for functions under 300
instructions and keeps the compact set above that, so the rules whose
results elaboration can realize actually run. Measured on the WAST corpus,
wall time is unchanged within noise (compact 10.73s / 10.37s, full 11.07s /
9.60s).

One test needed rewriting rather than fixing the compiler. `require_o3_
duplicates_loop_effect` proved unrolling by counting a mnemonic, which only
works when the duplicated operation cannot be folded again. With the full
ruleset, unrolling a `count += 1` / `i += -3` loop duplicates both adds and
reassociation then fuses each pair into `count += 2` / `i += -6` — strictly
better code with an unchanged `iadd` count. Verified by hand and by
execution that the result is still 10 in both JIT and interpreter, so the
arithmetic case now uses `require_o3_transforms_loop`, which compares O3
against O2. The three side-effecting cases (stores, calls, trapping
division) keep the original counting proxy, which remains valid.

Verified: milkir 176/176 (including a new test asserting `x * 8` reaches
the IR as `ishl`), egraph 196/196, wasmoon testsuite 562/562, the full WAST
corpus 258/258 files and 62,563 assertions in both interpreter and JIT
modes, WASI 90/90, component stable-0.2 845/845, and
`moon check --warn-list @73` clean. The only public interface change is
`EGraph::best_nodes`.

Follow-up worth its own issue if it ever matters: the remat machinery is
now reachable again through the full ruleset, but its cost bonus has never
been tuned against elaboration's budget.
