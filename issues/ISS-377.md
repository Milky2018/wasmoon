## Description
The e-graph pipeline has no elaboration step, so almost all rewrite results
are discarded. The only write-back channels are:

- `get_simplified_opcode` (`modules/milkir/egraph_builder.mbt:324`), which
  applies an extraction result only when the best node is `Const` — its own
  comment says complex rewrites like `x*3 -> (x<<1)+x` "would require operand
  reconstruction";
- `get_simplified_operand` (`modules/milkir/egraph_builder.mbt:347`), which
  replaces an operand only when the better representative already exists as
  an IR value bound in a dominating scope (GVN-style aliasing).

Any rewrite that produces a new expression shape — strength reduction,
`select`→`bmask`, extend/reduce narrowing chains — is computed inside the
e-graph and then thrown away. The rules corpus this starves is large:
roughly 8,000 lines across `rules_icmp` (1,758), `rules_extends` (1,290),
`rules_bitwise` (1,032), `rules_shift`, `rules_select`, `rules_algebraic`,
`rules_spaceship`, and more. The pipeline pays full saturation cost and
harvests only constant folding plus aliasing.

## Design
Follow Cranelift's aegraph direction: after saturation, extract the best
node per needed class and materialize missing nodes as new IR instructions
at the appropriate insertion points (dominating the uses, reusing the
existing scoped `class_to_value` bindings for sharing). Alternatively, if
elaboration is judged too costly, prune the ruleset to the subset whose
results the current channels can realize, and record the trade-off here.
Do not keep the current middle state.

Hard prerequisite: the extraction memoization poisoning in ISS-378 must be
fixed first — elaboration consumes extraction results for non-constant
nodes, exactly the ones the poisoned memo can corrupt.

## Acceptance Criteria
- [ ] A rewrite whose best form is a new expression shape (e.g. a
      strength-reduction result) reaches the emitted MilkIR, verified by a
      before/after test.
- [ ] Elaborated nodes are shared via dominator-scoped bindings rather than
      duplicated per use.
- [ ] The examples/algorithms corpus sweep and both JIT/interp comparison
      suites stay green.
- [ ] If pruning is chosen instead, the removed rules are listed and the
      remaining ruleset is shown to be fully realizable by the existing
      channels.
