# ISS-456: Remove semantic MachV from native compilation

## Metadata
- Type: epic
- Status: closed
- Priority: 0
- Labels: compiler, architecture, lowering, milkir, vcode, regalloc, aarch64, x64, compile-time, agent
- Assignee: codex
- Created: 2026-09-01
- Updated: 2026-09-01
- External ref: none

## Description

Native compilation currently materializes a complete target-neutral semantic
MachV graph between optimized MilkIR and each target's VCode. Both native
targets then rebuild target analysis and target instructions from that graph.
The intermediate duplicates function ownership, CFG, value, instruction,
metadata, verification, and traversal infrastructure without serving as an
executable target or a required public boundary.

Remove semantic MachV and compile optimized MilkIR directly into AArch64 or x64
VCode. Keep reusable VCode, code-object, allocation, and register-allocation
infrastructure as product-neutral standalone packages. Do not introduce an
interpreter or Pulley-like bytecode target until a concrete consumer requires
one.

## Design

The resulting native pipeline is:

`Wasm -> MilkIR -> optimize -> target VCode -> regalloc -> native code`

Move generic packages out of the `machv` namespace before deleting the
semantic package. Target lowering may share stateless lowering recipes and
runtime-ABI descriptions, but it must not construct another whole-function
semantic graph or retain a compatibility lowering path. Wasm-specific
extension handling remains owned by Wasmoon or is legalized into MilkIR before
target selection; reusable compiler infrastructure must remain independent of
Wasmoon packages.

## Acceptance Criteria

- [x] AArch64 and x64 production compilation consumes optimized MilkIR directly and emits target VCode without a semantic MachV function or selection plan.
- [x] Generic VCode, code-object, allocation types, and VCode regalloc live in product-neutral packages outside the `machv` namespace.
- [x] `machv`, `milkir_machv`, and `wasm_machv` source packages and their obsolete diagnostics, adapters, tests, and manifest dependencies are deleted.
- [x] No supported source, manifest, generated interface, script, or current architecture document imports or describes semantic MachV as part of native compilation.
- [x] Calls, traps, GC roots and stack maps, stack objects, block parameters, environment fields, atomics, SIMD, and runtime relocations remain correct on both native targets.
- [x] Focused JIT and target tests, WAST suites, native tests, strict register-allocation validation, warning 73, formatting, generated interfaces, and compiler-boundary audit pass.
- [x] Cache-isolated AEGIS-128L measurements preserve output and allocation invariants and compare serial Wasmoon with serial Wasmtime.

## Notes

- 2026-09-01: Semantic MachV is no longer considered a stable compiler boundary. ISS-449 and ISS-455 remain valid historical records of improvements to the prior architecture, but their retained semantic representation is superseded by this issue.
- 2026-09-01: A Pulley-like target would be a concrete sibling target with its own executable instruction semantics. Renaming semantic MachV or preserving it speculatively would not provide that value and is explicitly out of scope.
- 2026-09-01: The production JIT now streams verified MilkIR through `milkir_native` and `wasm_native` into target-owned lowering sessions. The three retained semantic packages, their compatibility diagnostics, and their cutover-only scripts were deleted. `moon check --target native --warn-list +73`, the compiler-boundary audit, 62 script tests, and 162 focused `wasmoon_jit` native tests pass at this checkpoint.
- 2026-09-01: White-box `native_lowering` tests now lock explicit transient-to-target value mapping with non-dense target ids, caller GC-root scope elaboration, and monotonic hidden allocation stack-map ids. All 3 focused protocol tests pass.
- 2026-09-01: Strict full native testing exposed sparse stack-object ids when an eagerly reserved but unused caller-root buffer preceded a used Wasm stack object. Root buffers are now allocated lazily on the first call with live roots. The 4 protocol tests and all focused GC-v128 (13), GC JIT (18), exception (26), and cache-command (13) tests pass.
- 2026-09-01: The first full core WAST run exposed two AArch64 `return_call_ref` failures. Direct tail calls now derive safepoint semantics from `NativeCall.behavior`, and VCode records every safepoint root as a hidden late allocation operand so regalloc must preserve its actual stack-map location across call clobbers. The strict `return_call_ref.wast` suite passes 46/46, its focused JIT/interpreter regression passes, and the reusable VCode/regalloc tests pass 114/114.
- 2026-09-01: Full strict native testing then exposed a high-pressure safepoint root assigned to an ephemeral late register after the call clobber. Hidden roots now use the generic `PreservedHome` constraint: home selection excludes every register clobbered at that root's safepoints, while still allowing ABI-preserved registers instead of forcing every root to spill. Two allocator regressions lock the spill and preserved-register cases; the deep-GC and `return_call_ref` JIT regressions pass under strict validation.
- 2026-09-01: Restored the target instruction selections that matter to AEGIS without recreating a second IR: indexed memory, scalar immediates, compare branches, multiply-add, and shifted-add are represented by dense side tables over authoritative MilkIR and streamed directly into target sessions. A negative high-multiply test prevents selection of operations without a valid immediate form.
- 2026-09-01: Strict validation found three selector boundary defects hidden by compatible register classes or ordinary execution: reference comparisons were fused as integer branches, shared address trees were covered more than once, and indexed `v128` memory used scalar target operations. The selector now restricts integer branch fusion to `i32/i64`, folds only single-use non-constant address trees, and both targets preserve vector memory operations after indexed address formation. Focused regressions lock all three cases.
- 2026-09-01: Final strict validation passes 2,367/2,367 native tests. Core JIT WAST passes 258/258 files and 62,563 assertions; component suites pass stable 23/23 files and 845 commands, async 24/24 and 153, and future-gated 12/12 and 387. Warning 73, formatting, generated interfaces, 62 script tests, and the compiler-module boundary audit pass.
- 2026-09-01: Seven cold isolated AEGIS pairs, with Wasmtime parallel compilation disabled, measured median Wasmoon wall time 0.792140 s, median Wasmtime wall time 0.746112 s, median paired wall ratio 1.058903, and median paired workload-value ratio 0.986957. All runs compiled into empty isolated caches. Seven detailed Wasmoon captures produced one identical 63-function allocation/code vector (`aeb37d0c46c7e2242139f583e9b4343a11e3dcbd575deff90293845bf3b46237`): 77,756 code bytes, 328 spills, 1,093 reloads, 74 register moves, and one spill-to-spill move. Median module compilation was 80,134 us.

## Close Notes

Semantic MachV and its Wasm/MilkIR adapters have been removed. The production
pipeline now has one authoritative optimized IR and one target-owned machine
representation: MilkIR streams through a target-neutral construction protocol
directly into AArch64 or x64 VCode, which is then allocated and emitted. Generic
native types, lowering protocol, VCode, code objects, and VCode register
allocation remain reusable packages; no compatibility graph or speculative
Pulley target remains.

The cutover also made correctness obligations explicit at the surviving seam:
call behavior owns safepoint semantics, hidden GC roots participate in
allocation with preserved homes, stack objects remain sparse-safe, and target
selection folds only legal single-use expression trees. Strict native, core
WAST, component WAST, module-boundary, and cache-isolated AEGIS gates all pass.
