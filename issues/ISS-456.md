# ISS-456: Remove semantic MachV from native compilation

## Metadata
- Type: epic
- Status: in_progress
- Priority: 0
- Labels: compiler, architecture, lowering, milkir, vcode, regalloc, aarch64, x64, compile-time, agent
- Assignee: codex

## Description

Native compilation currently materializes a complete target-neutral semantic
MachV graph between optimized MilkIR and each target's VCode. Both native
targets then rebuild target analysis and target instructions from that graph.
The intermediate duplicates function ownership, CFG, value, instruction,
metadata, verification, and traversal infrastructure without serving as an
executable target or a required public boundary.

Remove semantic MachV and compile optimized MilkIR directly into AArch64 or x64
VCode. Keep reusable VCode, code-object, allocation, and register-allocation
infrastructure as product-neutral standalone packages. Do not introduce an
interpreter or Pulley-like bytecode target until a concrete consumer requires
one.

## Design

The resulting native pipeline is:

`Wasm -> MilkIR -> optimize -> target VCode -> regalloc -> native code`

Move generic packages out of the `machv` namespace before deleting the
semantic package. Target lowering may share stateless lowering recipes and
runtime-ABI descriptions, but it must not construct another whole-function
semantic graph or retain a compatibility lowering path. Wasm-specific
extension handling remains owned by Wasmoon or is legalized into MilkIR before
target selection; reusable compiler infrastructure must remain independent of
Wasmoon packages.

## Acceptance Criteria

- [ ] AArch64 and x64 production compilation consumes optimized MilkIR directly and emits target VCode without a semantic MachV function or selection plan.
- [ ] Generic VCode, code-object, allocation types, and VCode regalloc live in product-neutral packages outside the `machv` namespace.
- [ ] `machv`, `milkir_machv`, and `wasm_machv` source packages and their obsolete diagnostics, adapters, tests, and manifest dependencies are deleted.
- [ ] No supported source, manifest, generated interface, script, or current architecture document imports or describes semantic MachV as part of native compilation.
- [ ] Calls, traps, GC roots and stack maps, stack objects, block parameters, environment fields, atomics, SIMD, and runtime relocations remain correct on both native targets.
- [ ] Focused JIT and target tests, WAST suites, native tests, strict register-allocation validation, warning 73, formatting, generated interfaces, and compiler-boundary audit pass.
- [ ] Cache-isolated AEGIS-128L measurements preserve output and allocation invariants and compare serial Wasmoon with serial Wasmtime.

## Notes

- 2026-09-01: Semantic MachV is no longer considered a stable compiler boundary. ISS-449 and ISS-455 remain valid historical records of improvements to the prior architecture, but their retained semantic representation is superseded by this issue.
- 2026-09-01: A Pulley-like target would be a concrete sibling target with its own executable instruction semantics. Renaming semantic MachV or preserving it speculatively would not provide that value and is explicitly out of scope.
