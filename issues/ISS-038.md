# ISS-038: Match production JIT recursive call-depth semantics

## Description
The attempted reusable MilkIR/MachV production path did not model the WebAssembly call-depth and stack-exhaustion behavior for directly recursive function bodies. A clean rebuild exposed this through `spec/skip-stack-guard-page.wast`: compiling recursive bodies through that incomplete path could run until the harness timeout instead of trapping with `call stack exhausted`.

## Design
Do not use interpreter fallback to hide this. Restore the old `origin/main` semantics through the reusable MilkIR/MachV pipeline so recursive functions execute through the real Wasmoon JIT stack model.

## Acceptance Criteria
- [x] Directly recursive production JIT bodies no longer time out and trap as `call stack exhausted` when required.
- [x] `spec/skip-stack-guard-page.wast` passes in JIT mode without interpreter fallback.
- [x] Regression coverage distinguishes ordinary direct calls from recursive direct calls through the full spec gate.
- [x] `python3 scripts/run_all_wast.py --dir spec --rec --dump-failures` passes in JIT mode.
