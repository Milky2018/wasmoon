# ISS-038: Match reusable JIT recursive call-depth semantics

## Description
The reusable MilkIR/MachV native JIT path currently does not model the interpreter's WebAssembly call-depth limit and stack-exhaustion behavior for directly recursive function bodies. A clean rebuild exposed this through `spec/skip-stack-guard-page.wast`: compiling recursive bodies natively can run until the harness timeout instead of trapping with `call stack exhausted`.

## Design
Keep the correctness-preserving fallback in place until the reusable JIT path can enforce WebAssembly call-depth or native stack-overflow semantics equivalent to the interpreter. The eventual fix should live in the reusable native call/stack model or Wasmoon embedding layer, not as a WAST-only special case.

## Acceptance Criteria
- [ ] Directly recursive native bodies can execute through the reusable JIT path without timing out and trap as `call stack exhausted` when required.
- [ ] `spec/skip-stack-guard-page.wast` passes in JIT mode without forcing those functions through interpreter fallback.
- [ ] Regression coverage distinguishes ordinary direct calls from recursive direct calls.
- [ ] `python3 scripts/run_all_wast.py --dir spec --rec --only-jit --timeout-sec 20` passes.
