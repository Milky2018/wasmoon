# ISS-219: Verify allocations with independent symbolic dataflow

- Updated: 2026-07-20

## Description

`verify_allocation` rebuilds the allocator's live ranges and uses the same analysis to validate its result. This doubles the dominant analysis cost and provides weak independence against bugs in range construction.

## Design

Implement a symbolic forward dataflow checker over physical registers, spill slots, inserted moves, and original virtual-register uses/defs. The checker must establish that every use reads a location containing the expected value and that constraints and clobbers are respected, without calling allocator live-range construction.

## Acceptance Criteria
- [x] Allocation verification does not call `build_live_ranges` or depend on allocator range fragments.
- [x] The checker rejects wrong-register values, unavailable values, clobbered live values, illegal fixed/tied assignments, and overlapping register or spill allocations.
- [x] Valid allocator output and spills pass on acyclic and cyclic CFGs.
- [x] Verification cost is measured independently from allocation cost.

## Notes
- 2026-07-20: Native sampling showed allocation verification rebuilding live ranges and spending 1,976 of 2,031 samples in the same `build_live_ranges` hotspot as allocation.
- 2026-07-20: The root `Program`/`Allocation` model has no inserted edit or edge-move representation. This issue therefore verifies the complete semantics expressible by that model; target VCode edge edits remain covered by its allocation verifier and the richer shared plan contract belongs to ISS-220/221.
- 2026-07-20: Added an independent forward symbolic checker with intersection at CFG joins. Focused tests cover cyclic convergence, a clobber on only one incoming path, shared spill corruption, fixed/tied constraints, and overlapping register homes.
- 2026-07-20: After unique spill homes were removed from symbolic state, a 512-branch native sample attributed about 18 samples to symbolic verification versus roughly 275 in the initial map-copy implementation and 1,976 samples in the old duplicate live-range analysis.
- 2026-07-20: The independent checker caught 13 previously accepted call/call-indirect clobber violations during the full native suite. Fixing live-range block boundaries made the allocator choose safe homes; the checker was not weakened.

## Close Notes

Allocation verification no longer reuses allocator liveness. It now proves value preservation with independent symbolic CFG dataflow and structured failures.
