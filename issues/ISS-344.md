# ISS-344: Add the stable ComponentCall lifecycle

## Description
`ComponentFunction::call` drives every invocation to completion and returns no
handle for observing pending work, cancellation, or concurrent logical calls.

## Design
Add an opaque `ComponentCall` owned by the stable facade. `start` creates one
invocation; `poll` is nonblocking; `wait` drives it synchronously; `join` is a
MoonBit async operation; and `cancel` is idempotent. Keep the existing `call` as
the blocking convenience implemented in terms of `start().wait()`.

## Acceptance Criteria
- [ ] Public calls have explicit pending, completed, failed, and cancelled terminal states.
- [ ] `poll` never waits for host readiness.
- [ ] `cancel` is idempotent and side effects are never replayed.
- [ ] Existing synchronous callers retain the `call` convenience behavior.
- [ ] Black-box tests inspect complete call-state transitions and errors.
