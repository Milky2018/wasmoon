## Description
`ComponentFunction::call` drives every invocation to completion and returns no
handle for observing pending work, cancellation, or concurrent logical calls.

## Design
Add an opaque `ComponentCall` owned by the stable facade. `start` creates one
invocation; `poll` is nonblocking; `wait` drives it synchronously; `join` is a
MoonBit async operation; and `cancel` is idempotent. Keep the existing `call` as
the blocking convenience implemented in terms of `start().wait()`.

## Acceptance Criteria
- [x] Public calls have explicit pending, completed, failed, and cancelled terminal states.
- [x] `poll` never waits for host readiness.
- [x] `cancel` is idempotent and side effects are never replayed.
- [x] Existing synchronous callers retain the `call` convenience behavior.
- [x] Black-box tests inspect complete call-state transitions and errors.

## Close Notes

Added the opaque stable `ComponentCall` and one internal
`ComponentInvocation` state machine. `start`, nonblocking `poll`, blocking
`wait`, and idempotent `cancel` share cached terminal results and never replay
host effects. `ComponentFunction::call` is now exactly `start(args).wait()`.
Black-box tests cover pending, repeated completion, cancellation, trap, and
structured error behavior.
