# ISS-132: Remove duplicate Function signature state

## Description
`Function` stores both `signature.params/results` and independent `params/results`, while MilkIR consumers disagree about which representation is authoritative. MilkIR-to-MachV lowering additionally fabricates parameter values from the stored signature when `params` is empty. A single function can therefore print and verify with one contract but lower with another.

## Design
After all producers use explicit parameters, remove the stored `Function.signature` field and the lowering fallback. Derive `Signature` values from the canonical explicit arrays when a snapshot is needed. Keep printer, verifier, optimizers, and lowering aligned on `Function.params/results`, and update generated interfaces and documentation.

## Acceptance Criteria
- [x] `Function` has one canonical parameter/result representation.
- [x] MilkIR-to-MachV lowering consumes explicit parameters only.
- [x] Printer, verifier, optimizer, and lowering observe the same parameter and result contract.
- [x] Generated interfaces and MilkIR documentation describe the canonical protocol.
- [x] Targeted and full native/wasm-gc quality gates remain green.
