## Description

The MachV backend migration is complete, but several project-owned compatibility paths remain after their independent behavior or caller population disappeared. They enlarge public and native interfaces, preserve invalid internal representations, and include an AArch64 test that now compares the final compiler with the same final compiler under stale candidate/legacy names.

## Design

- Delete internal migration paths rather than retaining aliases or forwarding wrappers.
- Migrate tests to the canonical indexed e-graph interface before removing test-only public helpers.
- Remove unused product-owned C/MoonBit FFI and memory-zero helper ABI surfaces together with their resolver entries.
- Reject the obsolete `I32Const(funcidx)` element initializer representation; canonical parsers already produce `RefFunc`.
- Preserve external Component Model, WAT, Wasm, and WASIp1 compatibility behavior, operational platform fallbacks, and the intentionally useful no-`Caller` host-function interface.

## Acceptance Criteria

- [x] The stale AArch64 candidate/legacy differential test is removed or replaced by a test with genuinely distinct observable paths.
- [x] MilkIR e-graph tests use the canonical indexed interface and no test-only legacy public helper remains.
- [x] The unused DWARF forwarding wrapper and memory-zero JIT helper/fixup ABI are absent from MoonBit, C, generated interfaces, and runtime symbol tables.
- [x] Interpreter element initialization accepts canonical `RefFunc` values and no longer accepts `I32Const(funcidx)` as a function reference.
- [x] A checked-in static audit rejects reintroduction of these internal compatibility paths.
- [x] Warning 73, generated-interface, native test, module-boundary, semantic-MachV, and CI gates pass.
