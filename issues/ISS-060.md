# ISS-060: Move Wasmoon VMContext ABI out of MachV core

## Metadata
- Type: task

## Description
`modules/machv/abi` currently defines Wasmoon VMContext offsets and Wasm memory,
table, and global layout helpers. That makes the generic MachV core depend on
Wasmoon's runtime embedding.

Evidence:
- `modules/machv/abi/abi.mbt` documents a "Wasmoon JIT ABI".
- The same package exposes `VMCTX_*` constants.

## Design
Move VMContext layout and Wasmoon runtime offsets into Wasmoon JIT or a
Wasmoon-owned ABI policy package. MachV core should only expose generic ABI
concepts and machine-layout effects that any embedding can consume. Preserve
existing offsets and helper semantics by moving current definitions
mechanically before reshaping call sites.

Non-goal: redesign the runtime VMContext layout.

## Acceptance Criteria
- [x] `modules/machv/abi` no longer defines Wasmoon VMContext offsets or Wasm memory/table/global layout constants.
- [x] Wasmoon JIT owns the VMContext layout API consumed by runtime integration.
- [x] Generic MachV ABI APIs remain usable without importing Wasmoon runtime concepts.
- [x] Existing native JIT memory/table/global/helper behavior is preserved.
- [x] `moon info --target native` is run and generated `.mbti` diffs are reviewed.
