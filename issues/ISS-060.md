# ISS-060: Move Wasmoon VMContext ABI out of MachV core

## Description
`modules/machv/abi` currently defines Wasmoon VMContext offsets, Wasm memory and
table layout helpers, and Wasm overflow-stack layout policy. That makes the
generic MachV core depend on Wasmoon's runtime embedding.

Evidence:
- `modules/machv/abi/abi.mbt` documents a "Wasmoon JIT ABI".
- The same package exposes `VMCTX_*` constants and helpers such as `wasm_layout_overflow_stack`.

## Design
Move VMContext layout, Wasmoon runtime offsets, and Wasm-specific stack layout
policy into Wasmoon JIT or a Wasmoon-owned ABI policy package. MachV core should
only expose generic ABI concepts and machine-layout effects that any embedding
can consume. Preserve existing offsets and helper semantics by moving current
definitions mechanically before reshaping call sites.

Non-goal: redesign the runtime VMContext layout.

## Acceptance Criteria
- [ ] `modules/machv/abi` no longer defines Wasmoon VMContext offsets or Wasm memory/table/global layout constants.
- [ ] Wasmoon JIT owns the VMContext layout API consumed by runtime integration.
- [ ] Generic MachV ABI APIs remain usable without importing Wasmoon runtime concepts.
- [ ] Existing native JIT memory/table/global/helper behavior is preserved.
- [ ] `moon info --target native` is run and generated `.mbti` diffs are reviewed.
- [ ] `git diff --check` passes.
- [ ] `moon check --target native --warn-list +73 --diagnostic-limit=200` passes.
- [ ] `moon test --target native --warn-list +73 --diagnostic-limit=200` passes.
- [ ] `python3 scripts/run_all_wast.py --rec --dump-failures --timeout-sec 20` passes.
