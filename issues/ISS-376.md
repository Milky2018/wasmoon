# ISS-376: Route CLI diagnostics to stderr and fail with non-zero exits

## Metadata
- Type: bug
- Status: closed
- Priority: 2
- Labels: cli, diagnostics, exit-codes, agent
- Assignee: unassigned
- Created: 2026-08-03
- Updated: 2026-08-10
- External ref: none

## Description

No code path in either CLI ever writes to stderr: every error, diagnostic,
and banner goes to stdout. `grep -rn stderr modules/wasmoon/cmd/` finds only
the guest-facing WASI `inherit-stderr` plumbing in `run.mbt`; the CLIs' own
output is roughly 160 `println` call sites.

Consequences, all verified on the current tree:

- `wasmoon wat foo.wat > out.wat` writes "Error reading file: ..." or
  "Error parsing WAT: ..." into the artifact, and `run_wat` then plainly
  returns (`commands/wat.mbt:6-14`), so the process exits 0 and a following
  `&&` step consumes the corrupt artifact. Even on success the artifact is
  polluted: the data is prefixed with a "Parsed WAT module:" banner
  (`commands/wat.mbt:18`).
- `wasmoon-tools wasm2wat` in stdout mode emits WAT to stdout; a parse
  failure prints "error: ..." to the same stream (`exit_error` is
  `println` + `native_exit(1)`, `wasmoon-tools/main.mbt:223-226`). The exit
  code is right, the stream is wrong.
- The `wasmoon` entry point prints clap parse errors, the help text on
  misuse, "Error: missing file argument", and "Unknown command: ..." to
  stdout and returns exit 0 (`cmd/wasmoon/main.mbt:206-211,296,304,415,467`).
  Only `component`/`component-test` propagate a status via
  `@sys.exit(status)` and `run` via `fail_and_exit`.
- The shared logger sends all four levels through `println`
  (`modules/wasmoon/logger`), so even `@logger.error` and `@logger.warn`
  land in stdout.

Pipelines therefore cannot separate data from diagnostics, and most
failures are invisible to `set -e` scripts.

What already works and must be preserved:

- `run` banners sit behind `@logger.debug`, so guest stdout is clean by
  default (`commands/run.mbt:316` onward).
- Guest `proc_exit` codes pass through to the host exit status
  (`native_exit(code)`, `commands/run.mbt:1417`).
- `wasmoon-tools` already exits non-zero on failure.

## Design

Establish one invariant across both executables: stdout carries data only;
diagnostics, banners, and errors go to stderr; every failure path exits
non-zero.

- Add an `eprintln` seam once (a trivial C stub next to the existing native
  stubs, or a stdlib facility if one exists) and expose it through the
  logger package: `warn`/`error` always to stderr, `debug` to stderr under
  the existing `--debug` gate, `info` stays stdout for genuine program
  output.
- Convert every CLI error path to stderr plus a non-zero exit through the
  seams that already exist (`@sys.exit`, `native_exit`). Misuse of the
  command line prints usage to stderr and exits non-zero; an explicit
  `help` command keeps stdout and exit 0.
- Drop or redirect decorative banners on data-producing commands, starting
  with "Parsed WAT module:".
- Non-goals: guest stream plumbing and `proc_exit` semantics are correct
  and stay untouched.

## Acceptance Criteria

- [x] `wasmoon disasm <bad-file> > out` leaves `out` empty, prints the
      diagnostic to stderr, and exits non-zero.
- [x] `wasmoon disasm <good-file> > out.wat` produces only WAT text in
      `out.wat`, for both binary and text inputs.
- [x] `wasmoon-tools wasm2wat` in stdout mode emits nothing but WAT on
      stdout; failures report on stderr with a non-zero exit.
- [x] Argument-parse errors, missing-file errors, and unknown commands in
      both entry points report on stderr and exit non-zero.
- [x] `@logger.warn` and `@logger.error` write to stderr; `@logger.debug`
      stays gated behind `--debug`.
- [x] Guest stdout passthrough and `proc_exit` exit-code propagation are
      covered by existing or new regression tests and remain unchanged.
- [x] Invalid fixed-choice values print usage to stderr and exit 2.
- [x] Frontend or JIT failures during `explore` print diagnostics to stderr
      and make the command exit non-zero, including after processing other
      functions.

## Close Notes

The stderr seam is a small C stub in the logger package
(`wasmoon_logger_write_stderr`, `fwrite` to `stderr` plus a flush), wired
per target the same way `wasmoon_jit/perf` handles its clock: native and
llvm use the stub, js and wasm targets fall back to stdout, since those
backends have no stderr of their own and the CLI only ships native.

`@logger.warn`, `@logger.error`, and the `--debug`-gated `@logger.debug`
now write to stderr; `@logger.info` deliberately stays on stdout because
callers use it for program output. A `plain_error` level carries usage
text, where a per-line prefix would be noise.

Both entry points route diagnostics through the logger and exit non-zero:
argument-parse failures, missing files, and unknown commands exit 2 (the
conventional "wrong usage" status, distinct from 1 for a failure while
doing the work), while command failures exit 1 via the existing
`exit_failure` / `native_exit` seams. An explicit `help` keeps stdout and
exit 0.

Verified against a rebuilt binary:

| Case | Result |
| --- | --- |
| `disasm no/such.wat > out` | exit 1, `out` empty, diagnostic on stderr |
| `disasm examples/add.wat > out` | exit 0, first line `(module`, no banner |
| `disasm` with no argument | exit 2, stdout empty |
| `wasmoon bogus` | exit 2, stdout empty |
| `wasmoon help` | exit 0, 558 bytes on stdout, stderr empty |
| `wasmoon-tools wasm2wat <good>` | WAT on stdout, stderr empty |
| `wasmoon-tools wasm2wat no/such.wasm` | exit 1, stdout empty |
| `run --debug` | result on stdout, `[DEBUG]` lines on stderr |

The banner criterion resolved itself: the `wat` command that printed
"Parsed WAT module:" was removed when it folded into `disasm`, and
`disasm` never had one. Guest stream plumbing and `proc_exit` propagation
were not touched, and the WASI suite covers them.

Suites: commands 29/29, sanitizer_testsuite 28/28, testsuite 534/534,
`moon check --warn-list @73` clean.

The 2026-08-10 follow-up makes post-parse fixed-choice rejection print the
argparse-generated usage before exiting 2. `explore` now records any frontend,
host-target, or JIT diagnostic failure while it continues collecting other
function reports, writes the diagnostic to stderr, and returns 1 after the
text or HTML report is complete.

Verified with the rebuilt native CLI: `explore --stage bogus` exits 2, leaves
stdout empty, and prints both the invalid-value diagnostic and usage on stderr;
`python3 scripts/cli_behavior_test.py` passes all checks. Package tests pass
29/29, the full native suite passes 2639/2639, and
`moon check --target native --warn-list +73` is clean.
