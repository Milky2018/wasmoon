# ISS-419: Make parallel moves emergency-spill aware

## Description
The AArch64 JIT can silently corrupt a stack-slot cycle because the parallel
move resolver reuses a transfer scratch register that still holds the saved
cycle value. The Lane parser reproducer then creates a self-referential object,
recursively releases it, and eventually reports a misleading stack exhaustion
trap.

Replace the multi-purpose scratch convention with an explicit parallel-move
plan that uses one dedicated transfer scratch per register bank and an optional
emergency spill area.

## Design
Keep cycle linearization target-neutral in `machv/vcode`. A legalization pass
tracks the transfer scratch lifetime, parks a live cycle value in an abstract
emergency location when a stack-to-stack move needs the scratch, and returns an
explicit resolved plan. Target frame planners own the physical emergency area,
and target emitters consume only legalized steps.

## Acceptance Criteria
- [ ] Target-neutral move plans preserve parallel assignment semantics with one transfer scratch per register bank.
- [ ] AArch64 assigns disjoint roles to move-transfer, stack-address, and instruction/call scratch registers.
- [ ] AArch64 and x64 frames reserve emergency storage only when a move plan requires it.
- [ ] The Lane parser JIT reproducer exits successfully from a cold artifact cache.
- [ ] Persistent JIT artifacts are invalidated and scratch-role documentation is current.
- [ ] Native checks, tests, and module-boundary audit pass.
