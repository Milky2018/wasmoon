## Description
`wasm_milkir` repeats the Wasm extension opcode protocol across `WasmOpcode`, `descriptor`, `descriptor_by_name`, `encode`, and `decode`. Serialized names, immediate counts, and immediate constraints can therefore drift independently. MilkIR core only validates the generic `ExtOp` signature, while `wasm_isa_lower` relies on dialect decoding at the adapter boundary.

## Design
Persist serialized Wasm opcode metadata in one package-owned schema and embed it into a committed MoonBit source file with `dev_build` and the public `moon runwasm moonbit-community/embed@0.1.1` tool. Derive descriptor lookup and wire validation from the embedded schema. Keep typed constructor conversion and the lowering behavior match explicit and exhaustive; target lowering semantics are not schema metadata. Commit the generated source because dependency builds do not execute `dev_build`.

## Acceptance Criteria
- [x] Serialized opcode names, immediate counts, and immediate kinds have one persisted source of truth.
- [x] `descriptor`, `descriptor_by_name`, `encode`, `decode`, and `decode_error` consume the shared schema instead of repeating wire metadata.
- [x] Every typed `WasmOpcode` round-trips through `ExtOp`, and malformed integer and boolean immediate layouts are rejected.
- [x] `moon.pkg` uses `dev_build` with pinned `moon runwasm moonbit-community/embed@0.1.1`; the internal `:embed` shorthand is absent.
- [x] The generated `.mbt` asset is committed, included by `moon package --list`, and usable by a downstream module without running `dev_build`.
- [x] Generated interfaces, relevant tests, full native tests, warning checks, formatting, diff checks, and module-boundary audit pass.
