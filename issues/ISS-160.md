## Description
`wasm_milkir` repeats the Wasm extension opcode protocol across `WasmOpcode`, `descriptor`, `descriptor_by_name`, `encode`, and `decode`. Serialized names, immediate counts, and immediate constraints can therefore drift independently. MilkIR core only validates the generic `ExtOp` signature, while `wasm_isa_lower` relies on dialect decoding at the adapter boundary.

## Design
Make one package-owned schema the actual build-time source for the typed `WasmOpcode` enum, wire metadata, and both codec directions. A deterministic generator invoked by `dev_build` emits committed MoonBit source; dependency builds compile that source without loading or parsing the schema. Keep lowering behavior as a handwritten exhaustive match because target semantics are not wire metadata.

## Acceptance Criteria
- [x] `WasmOpcode`, wire metadata, and both codec directions are generated from one schema.
- [x] No stable numeric ID, constructor name, wire name, or immediate layout is independently maintained in handwritten MoonBit matches.
- [x] No schema text is parsed at package initialization, and schema errors are reported by the development generator rather than runtime `abort`.
- [x] Every generated opcode round-trips through `ExtOp`, and malformed integer and boolean immediate layouts are rejected.
- [x] The generated `.mbt` source is committed, included by `moon package --list`, and usable by a downstream module without executing `dev_build`.
- [x] Generated interfaces, relevant tests, full native tests, warning checks, formatting, diff checks, and module-boundary audit pass.
