# ISS-526: Validate trailing-slash symlink traversal at the WASI capability boundary

## Description
A trailing slash makes a directory symlink an intermediate path component. Preview 1 followed it in the host open while validating the path with no-follow-leaf rules. A link to the parent of a preopen could therefore open a directory outside that preopen. The regression reproduced on macOS: `path_open` returned success instead of PERM.

## Design
Treat a trailing slash as requiring final-link traversal in Preview 1 open/stat/time validation. Route component stat calls through the existing held-directory capability walker when the path ends in a slash. Preserve legal directory-link operations and native platform error distinctions.

## Acceptance Criteria
- [x] Reproduce an outside-directory open through a trailing-slash link.
- [x] Reject the escaped open and stat while preserving an in-root directory link.
- [x] Pass local native tests and both engines of the complete P1 profile.
- [ ] Confirm the fix through Linux, macOS and Windows CI.
