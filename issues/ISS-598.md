## Description
Current C, MoonBit and Rust workload captures put register allocation at roughly one quarter to one third of full compilation, with bundle allocation the largest allocation subphase. The occupied-range index already has successor links, but its scan interface still maintains an Array containing at most one cursor and returns Option[Int] on every advance.

## Design
Experiment with a scalar segment-id cursor, preserving traversal order, seek boundaries, contiguous-owner skipping, conflict costs and all allocation decisions. Remove the obsolete session scratch only if the experiment is retained. No register-allocation policy, memory-base policy or public interface change.

## Close Notes
Rejected after two fixed 21-pair rounds across four inputs (336 timed compilations). No workload shows stable benefit across rounds. All artifacts match; strict native checks and 71 regalloc tests pass. Dedicated allocation-counter equivalence was not established. The complete-compilation gate failed, so CLI performance and full external regressions were not run for the candidate. All five changed source files were restored byte-for-byte. No production optimization is shipped.

Acceptance criteria were clarified to distinguish the early rejection path from retention gates; this closure does not claim the unperformed checks passed. Raw samples, patch and validation logs: [compiler priorities](../docs/perf/compiler-priorities-2026-09-29.md).
