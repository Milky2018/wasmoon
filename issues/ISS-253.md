# ISS-253: Invalidate JIT cache entries after codegen changes

## Description

The default AEGIS cache entry was created before the current global-value
code-generation change but remained compatible because
`WASMOON_CODEGEN_REVISION` still had the old constant value. It produced a
misleading roughly 1.60x runtime ratio instead of the current fresh-artifact
ratio of about 1.26x.

## Design

Advance the codegen revision for the current target pipeline and make the cache
path explicitly discriminate that revision. Preserve manifest compatibility
checking as the authority; the filename discriminator prevents repeated decoding
of known-incompatible files. Document the required revision-bump boundary.

## Acceptance Criteria

- [x] Artifacts produced by the pre-change codegen revision are rejected or
      bypassed by the current run cache.
- [x] The cache filename identifies the codegen revision without unsafe path
      characters.
- [x] Tests lock both revision-sensitive cache naming and manifest rejection.
- [x] A current artifact still round-trips and loads from cache.

  The manifest remains the compatibility authority.

## Close Notes

Closed after the CLI cache tests demonstrated that `machv-vcode-1` artifacts
are rejected and removed, while a current artifact round-trips successfully.
`moon test modules/wasmoon_jit --target native --warn-list +73` passed 141
tests; `moon test modules/wasmoon/cmd/wasmoon/commands --target native
--warn-list +73` passed 21 tests. A real cold/warm CLI run created only a
revision-tagged `machv-vcode-2` cache file.
