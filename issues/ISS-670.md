## Description
Continue from release commit 7cf4fe98. The exact parse_double property retains a
3.24x invocation gap to V8. Prior sampling attributes substantial work to typed
allocation, root selection and checked GC views. The existing no-GC reservation
protocol admits only scalar structs; every struct containing references still
stages roots and invokes the general allocation policy.

## Design
First measure an isolated single-variable extension of the existing reservation
and initialization protocol to typed reference structs. Fresh initialization must
finish without helpers, safepoints, reentry or publication to guest code. Preserve
canonical layout admission, stable IDs, quotas, injected failures, precise roots,
rollback, legacy fallbacks and the common interpreter/JIT storage model. Retain
the change only with measured benefit and meaningful regression protection.

## Close Notes
Implemented the minimal extension of existing typed reservation to reference
structs, retaining the canonical shape check and collecting fallback. Five
serial pairs improve invocation 7.5% (2.534273s to 2.344985s), cold wall 4.9%,
with a 4.9% compilation cost. Word-struct slow allocations decrease from
14944141 to 1097548 without changing the counted allocation total. The same-run
V8 ratio improves from 3.22x to 2.98x; ISS-661 remains in_progress.

The target-selection regression failed before implementation. Both target
selections and O0/O2/O3 public reference-graph, pressure, byte-quota, failure and
reuse checks pass. Full native 3046/3046 ordinarily and with all three verifier
flags; wasm 1445/1445; strict both/info/fmt/boundaries/MSVC generation; Python
178 tests/54 existing platform skips; fresh macOS ASan/UBSan 286/286 plus both
controls; Core native interpreter/JIT/actual wasm each 258/62563; Component each
59/1385 all pass. No x64 execution, Linux LSan or CI acceptance is claimed.

See the [checkpoint summary](../docs/perf/parse-double-gc.md). All owned
