## Description
Replace the skeletal `modules/milkir` model with a real generic IR core suitable for non-Wasmoon compiler users. The current production IR lives under `modules/wasmoon/ir` and is WebAssembly-shaped in several places; this issue extracts the reusable parts while preserving correctness.

## Design
Start from the real `modules/wasmoon/ir` data model, builder, CFG, validator, printer, and tests. Keep source-language-specific WebAssembly translation out of MilkIR. Any WebAssembly-only concepts must move into `modules/wasmoon/wasm_frontend` or remain in Wasm-owned adapters. MilkIR should expose stable generic constructs for blocks, values, instructions, signatures, calls, memory operations, traps, metadata, and verification.

## Acceptance Criteria
- [x] `modules/milkir` has a real builder, verifier, CFG utilities, printer, and test suite derived from the old IR behavior where appropriate.
- [x] MilkIR public APIs do not import `wasm_core`, `wasmoon`, `wasmoon/ir`, `wasmoon/runtime`, or `wasmoon/jit`.
- [x] WebAssembly-specific opcodes, heap/reference semantics, and runtime state are represented through frontend lowering or metadata, not MilkIR core ownership.
- [x] Existing IR unit tests are ported to MilkIR or have explicit migration follow-up issues.
- [x] `moon check --target native --warn-list +73 --diagnostic-limit=200` and targeted MilkIR tests pass.
