# ISS-263: Coalesce loop-carried values across backedges

## Description

The allocated `func_42` loop backedge contains:

```text
edge(block3, 0): move v99 stack14:i32(size=4, align=4) ->
  stack0:i32(size=4, align=4)
```

Emission expands this allocation mismatch to a load, a store, and an extra
branch on each continuing Salsa iteration:

```text
ldr w17, [sp, #56]
str w17, [sp]
b   loop
```

The source value and destination block parameter represent one loop-carried SSA
value, but bundle formation/allocation leaves them in different spill slots.
The edge resolver preserves correctness while introducing recurring
stack-to-stack traffic in a hot loop.

## Design

Make compatible loop-carried definitions and block parameters share an
allocation bundle or a canonical spill location. If hard constraints require a
split, place the transfer outside the repeated edge where possible. Keep the
general parallel-copy and symbolic allocation verifier contracts intact; do not
special-case a particular block or function.

## Acceptance Criteria

- [ ] A focused regression test reproduces compatible loop-carried values being
      assigned different spill slots.
- [ ] Compatible backedge values coalesce to one register or one canonical
      spill slot.
- [ ] `func_42` no longer emits a stack-to-stack edge move on its loop backedge.
- [ ] Cyclic and fixed-register parallel-copy cases remain correct.
- [ ] Regalloc symbolic verification and native target tests pass.
