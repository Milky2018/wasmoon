# ISS-263: Coalesce loop-carried values across backedges

## Description

The allocated `func_42` loop backedge contains:

```text
edge(block3, 0): move v99 stack14:i32(size=4, align=4) ->
  stack0:i32(size=4, align=4)
```

Emission expands this allocation mismatch to a load, a store, and an extra
branch on each continuing Salsa iteration:

```text
ldr w17, [sp, #56]
str w17, [sp]
b   loop
```

The source value and destination block parameter represent one loop-carried SSA
value, but bundle formation/allocation leaves them in different spill slots.
The edge resolver preserves correctness while introducing recurring
stack-to-stack traffic in a hot loop.

## Design

Make compatible loop-carried definitions and block parameters share an
allocation bundle or a canonical spill location. If hard constraints require a
split, place the transfer outside the repeated edge where possible. Keep the
general parallel-copy and symbolic allocation verifier contracts intact; do not
special-case a particular block or function.

## Acceptance Criteria

- [x] A focused forced-spill regression reproduces compatible loop-carried
      values being assigned different spill slots.
- [x] Compatible backedge values coalesce to one register or one canonical
      spill slot.
- [x] `func_42` no longer emits a stack-to-stack edge move on its loop backedge.
- [x] Cyclic and fixed-register parallel-copy cases remain correct.
- [x] Regalloc symbolic verification and native target tests pass.

## Notes
- 2026-07-24: This is independent from the larger spill-placement decision: a
  spilled value still should not migrate between two stack slots on every
  backedge.
- 2026-07-24: ISS-262 incidentally removed the original `func_42` backedge
  move by retaining the hot state in registers. ISS-263 remains necessary for
  the forced-spill case, where home assignment currently discards the
  compatible SSA bundle relation.
- 2026-07-24: Home assignment now retains the original bundle plan and gives
  compatible spilled values one canonical slot. Sharing requires the
  embedding's symmetric compatibility result plus identical size and
  alignment. Stable range IDs are resolved explicitly because live ranges are
  stored in layout order.

## Close Notes

Closed after a zero-allocatable-register loop regression proved that three
transitively related SSA values share one spill home and need no entry or
backedge stack copy. The existing same-block lifetime compaction remains the
fallback for unrelated values; parallel-copy resolution and fixed-register
constraints were not weakened.

Validation passed all 68 regalloc tests, 967 wasm-gc tests, 1,344 native tests,
and all 258 interpreter plus 258 JIT WAST files. The rebuilt
`pwhash_scrypt_ll` pipeline passes both allocation verifiers, `func_42` has no
stack-to-stack continuation move, and a diagnostic run completed in 9.70
seconds. Final paired performance evidence remains assigned to ISS-266.
