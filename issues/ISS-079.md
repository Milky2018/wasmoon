## Description
`machv_emit` should emit machine code and symbolic metadata from allocated MachV. It still owns JIT/VMContext-specific stack-frame logic such as `JITStackFrame`, `runtime_layout`, VMContext requirements, and trap/runtime comments.

This leaks Wasmoon embedding-frame details into a generic emitter module.

## Design
Make `machv_emit` accept generic frame-layout and relocation metadata as inputs. Move Wasmoon-specific VMContext layout, trap policy, and runtime helper expectations into `wasmoon_jit`, while preserving generated code behavior.

Non-goals: do not remove symbolic fixup support from the generic emitter; do not change executable-memory ownership.

## Acceptance Criteria
- [x] Generic `machv_emit` public API no longer requires Wasmoon-specific runtime layout concepts.
- [x] Stack-frame construction separates generic frame layout from Wasmoon embedding details.
- [x] Wasmoon JIT owns VMContext/trap/runtime policy and passes concrete emission inputs to `machv_emit`.
- [x] Existing emission tests, JIT tests, and WAST gates pass.
