## Description
`CoreExecutionMode` mixes semantic call shape (`Synchronous`,
`Suspendable`) with backend selection (`Interpreted`). This makes the JIT
adapter route every non-synchronous call to the interpreter, including
callback-driven async steps that return normally and do not need a native
continuation.

## Design
Replace the mixed mode with an execution contract that distinguishes
run-to-completion, callback-step, and stackful calls. Backend fallback remains
an adapter policy rather than a component runtime instruction. Add typed
execution observations for tests; do not convert the new type back into
strings.

## Acceptance Criteria
- [x] The core execution seam distinguishes callback steps from stackful calls.
- [x] Backend choice is not encoded as a semantic call style.
- [x] Existing interpreter and synchronous JIT behavior remains unchanged.
- [x] Tests snapshot typed call styles and adapter routing.
- [x] `moon check`, targeted tests, formatting, and generated interfaces pass.
