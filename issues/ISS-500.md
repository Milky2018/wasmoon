## Close Notes

Independent controls in `/tmp/iss500-allocation-controls.wast` pass pinned Wasmtime and fail three assertions in each pre-fix Wasmoon engine. In addition to allocation/growth overflow, a declared maximum of 4294967296 was narrowed to zero and incorrectly rejected growth by one. The fix preserves table limits through allocation, import matching, and native context setup, checks allocation overflow after declared limits, and distinguishes failed allocation from ordinary growth failure. Native regressions cover both compiler paths and unsigned count-addition overflow. Final external gates pending.

Final validation: 2384 native tests pass; core WAST, local runtime scripts, all component suites in both engines, and macOS P1 pass (`/tmp/iss500-gate-results.json`). Both executions of unmodified `memory64/table-too-big.wast` pass (`tmp/iss500-misc`). Focused allocation and growth tests pass ASan. The native shared-table allocator and slot initialization also widen counts before multiplication, and failed native owner allocation is rejected before Store state is mutated. Interpreter table64 indexing remains separately tracked under ISS-505.
