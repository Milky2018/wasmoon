## Description
Hundreds of vector constants, lane operations, arithmetic operations, comparisons, conversions, and relaxed operations are flattened into the top-level MilkIR opcode enum. This forces every consumer to match the entire source-shaped opcode set and obscures which operations have language-neutral semantics.

## Design
Introduce `VectorOp` and supporting semantic types for lane shape, signedness, comparison, unary/binary operations, and exceptional operations. Parameterize repeated operation families where doing so preserves exact semantics; retain named vector sub-operations only where a parameterized representation would be less clear. Migrate printer, verifier, identity, optimization, and lowering together.

## Acceptance Criteria
- [x] Repository producers canonicalize language-neutral vector operations under VectorOp.
- [x] Repeated lane-width/signedness variants are parameterized where practical.
- [x] Verifier and lowering exhaustively accept the vector family during the expand phase.
- [x] Existing SIMD behavior and target-specific tests remain green.
