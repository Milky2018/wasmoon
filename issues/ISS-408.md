## Description

The production allocator has the outer shape of a bundle-based backtracking
allocator, but its core still relies on sorted arrays, per-segment register
probes, shallow splitting, global edge scans, and post-hoc heuristics. Large
functions consequently spend most compilation time in register allocation.

Replace those mechanisms in dependency order. Each child issue is an
independently verified and committed step.

## Design

First remove heuristics that compensate for missing allocator semantics. Then
introduce a range index and merged bundle probe, derive edge transfers from
live edge facts, preserve split lineage with spillsets and real range splits,
and finally evaluate an independent linear-time allocator. Remove that
experiment if it cannot preserve end-to-end performance and generated-code
quality.

Do not preserve compatibility for internal implementation details. Preserve
the public allocation contract and correctness on both production targets.

## Close Notes

- ISS-409 through ISS-413 replaced the patch heuristics, per-segment probes,
  global edge scans, shallow split lineage, and misleading fast-allocation
  strategy with the intended allocator structure.
- Follow-up measurements removed repeated spill-bundle normalization, merged
  clobber scans, cached segment metadata, bounded spillset splitting, and cut
  off dominated conflict probes.
- `moon test --target native --warn-list +73` and the same command with
  `MACHV_REGALLOC_VALIDATION=1` both completed successfully. Linux AMD64 and
  macOS ARM64 also produced successful validation for the same change SHA.
- AEGIS128L median bundle allocation fell from 210.176 ms to 41.825 ms and
  median full register allocation fell from 306.872 ms to 146.994 ms without
  hiding allocation-quality regressions behind a strategy change.
- ISS-415 subsequently removed the independent allocator after representative
  workloads showed that worse generated code outweighed its allocation-time
  reduction. The final architecture has one verified allocator.
