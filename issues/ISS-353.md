## Description
The validate-before-instantiate audit compares two raw `str.find` results.
Comments and strings can supply fake validation evidence, and an instantiate
before validation is ignored when another instantiate follows validation.

## Design
Analyze the effective code of `ComponentRuntime::instantiate_component`.
Remove comments and string contents, extract the target function body with
balanced braces, require validation and instantiation, and reject every
instantiation whose source position precedes validation.

## Acceptance Criteria
- [x] Validation text in a comment or string cannot satisfy the gate.
- [x] Any instantiation before validation fails even if another follows it.
- [x] The target function must contain both validation and instantiation.
- [x] The current facade and full audit test suite pass.

## Close Notes

Replaced raw `str.find` ordering with a small MoonBit source scanner that
removes line comments, nested block comments, ordinary literals, and multiline
string lines while preserving source positions. The audit extracts the target
function with balanced braces and requires a preceding real validation for
every linker instantiation.

The focused red tests now pass, as do the live security audit and all 60 Python
gate tests.
