# ISS-398: The register allocator's self-checks abort, next to code that raises for the same thing

## Description
Eleven `abort()` calls in `modules/regalloc` assert that the allocator's own
output is self-consistent:

| File | Sites | Claim |
| --- | --- | --- |
| `bundle_allocate.mbt` | 637, 644, 647, 650, 661, 667 | allocation left a bundle pending, lost a metric, or is not atomic |
| `bundle_plan.mbt` | 34, 43, 52, 62, 71 | the bundle plan's range/segment mapping is malformed |

The claims are correct: reaching one means the allocator is broken, not that
the input was bad. The mechanism is the problem, and the evidence is in the
same package.

`VerifyError` already exists, is already `pub`, and already has the exact
variant these want:

```moonbit
pub suberror VerifyError {
  ...
  ScratchRegisterUnavailable(message~ : String)
  InvalidPlan(message~ : String)
}
```

`verify_plan.mbt` raises `InvalidPlan` five times for this same class of
claim, and `parallel_edits.mbt:120` raises it for
`"parallel-transfer cycle has no source owner"`.

No signature needs to change. The enclosing function already declares it:

```moonbit
fn[F : FunctionView] allocate_bundle_plan(   // backtracking_allocate.mbt:1053
  ...
) -> AllocationPlan raise VerifyError {
```

`validate_bundle_allocations` and `ProductionBundlePlan::validate` are both
inside that call, and `allocate_function` already surfaces `VerifyError` to
the caller. So the same package expresses one claim two ways, and the eleven
that abort are the ones that produce SIGABRT and a message on stdout instead
of a diagnostic a caller can act on.

An allocator bug is a plausible thing to hit while developing a target. It
should report which invariant broke, not kill the process.

## Design
Convert the eleven to `raise InvalidPlan(message=...)`, keeping the existing
message text. `pick_scratch`'s exhaustion case (see ISS-399) is what
`ScratchRegisterUnavailable` was named for.

The point is not that abort is wrong for defect claims — `validated_*` in
`wasm_core` aborts deliberately and correctly (ISS-396). It is that this
package already decided to use a typed channel for exactly this class, and
these eleven predate or ignore that decision.

## Acceptance Criteria
- [ ] No `abort()` remains in `modules/regalloc` for plan-consistency claims.
- [ ] Each converted site raises with its existing message preserved.
- [ ] A test drives at least one of them and asserts the raised error rather
      than the process dying.
