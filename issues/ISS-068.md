# ISS-068: Replace Wasm function indices in MachV call and address opcodes

## Description
MachV currently represents direct Wasm targets with raw integer payloads in
instructions such as `LoadFuncAddr(Int)` and `CallDirect(Int, ...)`. The integer
is a Wasm function index, so MachV instruction core still knows a frontend-owned
identifier.

## Design
Introduce a generic code-symbol or code-address reference for MachV direct
function targets. Wasmoon-owned lowering maps Wasm function indices to those
generic references, and Wasmoon JIT/native glue maps the emitted relocation or
fixup metadata back to the current runtime patching representation.

Preserve existing generated behavior by keeping the current patching format
where necessary at the Wasmoon artifact boundary. The MachV opcode payload
itself must stop being a raw Wasm function index.

## Acceptance Criteria
- [ ] `LoadFuncAddr(Int)` is replaced by a generic code-address or code-symbol opcode.
- [ ] `CallDirect(Int, ...)` no longer carries a raw Wasm function index.
- [ ] Wasm function-index to code-symbol/fixup mapping is owned by Wasmoon JIT or Wasm lowering code.
- [ ] Existing direct-call and tail-call fixup behavior is preserved.
- [ ] Relevant direct call, return_call, and function-reference WAST tests pass.
- [ ] Public `.mbti` diffs are reviewed with `moon info --target native`.
- [ ] `git diff --check` passes.
- [ ] `moon check --target native --warn-list +73 --diagnostic-limit=200` passes.
- [ ] `moon test --target native --warn-list +73 --diagnostic-limit=200` passes.
