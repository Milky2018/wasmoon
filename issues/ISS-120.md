## Description
MilkIR verification currently checks value existence and selected type and control-flow contracts, but it can accept duplicate value definitions, duplicate instruction IDs, use-before-definition, non-dominating uses, and divergence between an instruction's `args` and `operands`. These gaps allowed the removed loop-unroll implementation to produce malformed SSA without a deterministic verifier failure.

## Design
Collect definition sites before validating uses, compute dominance from the CFG, and verify every instruction and terminator use against its definition site. Add explicit uniqueness and instruction-shape checks without changing valid MilkIR public construction patterns.

## Acceptance Criteria
- [x] Duplicate value definitions and duplicate instruction IDs are rejected.
- [x] Same-block use-before-definition and cross-block non-dominating uses are rejected.
- [x] Function parameters and block parameters have correct dominance semantics.
- [x] Divergent `args` and `operands` are rejected.
- [x] Focused verifier tests, full MilkIR tests, and warning-as-error checks pass.
