## Notes
- 2026-09-09: Wasmtime 40 passes sync-streams after wasm-tools 1.254 binary normalization. Minimal positive/negative controls show the two sync-lowered async trap assertions and the invalid subtask.cancel assertion have obsolete precedence expectations: Wasmtime reports unreachable and an invalid handle, respectively. The original full trap script uses newer threading opcodes unsupported by Wasmtime 40, so oracle checks use independent minimal components.
- A ready synchronous future waiter permits the next async call to complete eagerly in Wasmtime; the current runtime leaves that call queued. A non-ready waiter must still keep it queued. Existing local ready-wait tests encode the wrong expected queue status and need correction alongside the runtime.
