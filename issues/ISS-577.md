# ISS-577: Make native host dependencies independent of repository layout

## Description
Registry installation of wasmoon 0.16.0 fails because WASI C sources include headers through a sibling module path. Workspace builds mask the dependency on repository layout. Windows descriptor, filesystem, and reactor sources have the same dependency pattern.

## Design
Move native WASI C implementations and raw FFI declarations into `wasmoon_jit/host_io/wasi`, and move the reactor and opaque ownership into `host_io/reactor`. Retain WASI policy and guest-memory adaptation in `wasmoon` and reexport the reactor's existing interface. Compile shared path portability functions once in `host_io`; both engines explicitly link this backend. Includes may reference directories within the same published module, never a sibling module's source tree.

## Acceptance Criteria
- [x] Standalone placement reproduces the original missing-header failure before the change.
- [x] Native implementation ownership and imports do not depend on sibling module directories.
- [x] Real module archives install from isolated directories and execute a WASI guest on both engines.
- [x] Strict checks, native tests, native C probes and both-engine HTTP regressions pass.
- [ ] CI runs isolated archive installation on macOS, Linux, Windows Clang and Windows MSVC.

## Notes
The original source preprocesses successfully in the repository but fails with the exact reported missing header when the module is placed independently. This is a packaging defect, not a libtool empty-object warning or a user cache failure. Registry 0.16.0 remains unchanged; publishing a corrected version is separate from this source refactor.

Local validation: strict native checking passes with zero MoonBit warnings; all 2554 native tests pass. Script tests pass (165 tests, 53 platform-dependent skips). Fresh CLI HTTP regressions pass on both engines, CLI behavior checks pass, and existing module-boundary, JIT-lifetime and component-security gates pass. The CI matrix now includes real archive installation and a WASI guest run on each native platform.

Real archive verification on macOS passed twice, including a clean direct `moon install` without a preparatory build. Module archives were unpacked into unrelated slot directories; the installed CLI executed the WASI output fixture successfully with JIT and interpreter. Cross-platform CI results remain pending.
