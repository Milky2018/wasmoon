# ISS-505: Preserve table64 indices and lengths through bounds checks

## Description
While fixing table allocation limits, an independent WAST probe exposed premature Int64-to-Int narrowing in interpreter table.get, table.set, table.fill, and table.copy. Offset or length 4294967296 aliases zero. Seven trap assertions fail in the interpreter; JIT and pinned Wasmtime pass all eight assertions. Evidence: /tmp/iss505-table64-offsets.wast, /tmp/iss505-before-interp.log, /tmp/iss505-before-jit.log, /tmp/iss505-oracle.log. Audit native table slot-address arithmetic for the same widening-after-multiplication mistake.

## Acceptance Criteria
- [x] Reproduce using independent expected results and a low-index control.
- [x] Keep table indices and counts wide until checked, including zero-length operations.
- [x] Regressions and external runtime suites pass in both engines.

## Close Notes

The same truncation also affected ordinary and tail indirect calls. The fix routes all table accesses through Int64 bounds-checked entry points, including mixed table32/table64 copies and zero-length operations, and preserves checked 32-bit compatibility wrappers. Native table and ABI-slot pointer arithmetic now widens before multiplication. Final native baseline: 2388 passed. Focused table bounds, indirect calls, and native slots above 2 GiB passed ASan. Core WAST, runtime WAST, all four component suites in both engines, and explicit-rights P1 passed (/tmp/iss505-gate-results.json). The independent extended WAST probe also passed pinned Wasmtime. Full misc accounting remains tracked by ISS-478.
