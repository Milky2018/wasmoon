# ISS-161: Normalize MilkIR vector operation semantics

## Description
`VectorOp` exposes 222 mostly copied constructors that encode lane width, signedness, half selection, and relaxed behavior in constructor names. Verifier, printer, opcode semantics, frontend producers, and MilkIR-to-MachV lowering must repeat that matrix, increasing drift and mis-lowering risk.

## Design
Replace the copied constructor matrix with a semantic algebra built from explicit operation families and orthogonal lane, signedness, half, and relaxedness parameters. Keep genuinely distinct operations explicit, reject unsupported parameter combinations in the verifier, and lower the normalized representation directly to the already parameterized MachV SIMD instruction families. Do not replace the enum with strings or a generated copy of the same 222 operations.

## Acceptance Criteria
- [x] Vector operations use semantic families instead of lane widths embedded in constructor names.
- [x] Verifier, printer, opcode semantics, and lowering consume the same normalized representation.
- [x] Existing Wasm SIMD and relaxed-SIMD behavior remains unchanged across supported backends.
- [x] The legacy copied constructor matrix and temporary compatibility code are removed.

## Close Notes
Closed on 2026-07-13. Replaced 222 lane-encoded `VectorOp` constructors with 18 semantic families and orthogonal lane, signedness, half, conversion, memory, and relaxed-operation parameters. Verifier, printer, effects, frontend production, GVN memory handling, and MachV lowering now consume the normalized representation. The implementation removes compatibility adapters and is net smaller than the copied matrix. Verified with all-target warning-denied checks, all-target MilkIR regressions, 43 SIMD JIT/interpreter cases, V128 stack-parameter tests, 1829 native tests with register-allocation validation, interface regeneration, formatting, boundary audit, legacy-constructor search, and diff checks.
