## Description
Create `modules/milkir` as the reusable Cranelift-like generic SSA IR. MilkIR must not be semantically owned by WebAssembly and must not contain Wasm-specific opcodes for memory, table, global, GC, exception, or runtime operations.

## Design
Start with MilkIR Core: SSA values, block parameters, generic scalar/vector/reference carrier types, arithmetic, comparisons, select, load/store/address operations, direct and indirect calls, branches, returns, traps, function signatures, external symbols, stack slots, and metadata for stack maps, source mapping, or runtime lowering. Keep known limitations explicit with scoped `TODO(milkir)` comments, but do not make TODOs a correctness gate. Keep basic optimization, builder, verifier, pretty printer, and CFG/SSA utilities inside `milkir` for the first stage; do not create a separate `milkir_opt` module until optimization dependencies become heavy enough to justify it.

## Acceptance Criteria
- [x] `milkir` defines function, block, value, type, instruction, signature, external symbol, stack slot, and metadata models.
- [x] MilkIR has no dependency on `wasm_core`, `wasmoon_jit`, or `wasmoon`.
- [x] Wasm-specific concepts are absent from core MilkIR opcodes.
- [x] No first-stage `milkir_opt` module is introduced.
- [x] Known incomplete areas include scoped `TODO(milkir)` comments.
- [x] MilkIR has basic construction, formatting, and verification tests.
