# ISS-504: Reject accidental double failures in engine parity checks

## Description
The native `compare_jit_interp` helper currently reports `matched` whenever both engines return errors, even for parsing failures and unrelated error messages. This was directly observed while adding ISS-497: an invalid numeric-memarg parse satisfied the `matched` assertion; an explicit expected-value assertion caught it. Successful-result parity must not accept accidental errors, and intended trap tests must assert their trap contract explicitly.

## Acceptance Criteria
- [x] Parse/validation failures and unexpected engine traps cannot satisfy success parity checks.
- [x] Intended trap comparisons use explicit expected errors without weakening existing tests.
- [x] Re-run and repair any additional failures exposed by the stricter helper.

- [ ] Apply the same success-only contract to both WASI comparison helpers and repair exposed tests.

## Close Notes

Success parity now requires successful results from both engines, and validates WAT before execution. Explicit trap checks remain separate. The stricter helper exposed 17 previously passing tests: intentional traps now assert their error text; invalid bitwise-complement, factorial, and generated GC fixtures now execute valid Wasm. Added contract regressions for parse, validation, missing exports, unexpected traps, and successful values. All 2376 native tests pass. Corrected static bitwise and factorial fixtures also pass the pinned Wasmtime 668016 oracle with explicit expected results (`/tmp/iss504-fixtures.wast`, `/tmp/iss504-oracle.log`).

Follow-up discovered during ISS-503: the separate WASI comparison helpers in `testsuite/wasi_jit_wbtest.mbt` still accept double errors and require the same success-only contract. Reopened to audit those helpers and migrate any intended trap tests explicitly; the core helper fix and its earlier validation remain complete.
