## Description

Implement the complete x64 vertical pipeline through the same semantic, Target VCode, allocation, frame, emitter, and code-object seams proven by AArch64, while production x64 still uses the legacy backend.

## Design

- Model x64 conditions, flags, addressing, fixed registers, instruction constraints, ABI facts, and encodings directly in x64 packages.
- Do not introduce AArch64-shaped compatibility concepts into shared MachV interfaces.
- Use tests and diagnostics for comparison; production stays single-path.

## Acceptance Criteria

- [ ] x64 lowers every production semantic MachV operation into verified x64 VCode or a structured unsupported-operation error.
- [ ] Selection, legalization, regalloc constraints, frame planning, emission, relocations, fixups, traps, GC metadata, stack maps, and unwind data use the final seams.
- [ ] Static tests prove x64 VCode cannot contain AArch64 instructions, register roles, conditions, or ABI facts.
- [ ] Tests compare normalized VCode, metadata, disassembly, and executed JIT behavior with the legacy x64 path.
- [ ] JIT/interpreter differential coverage includes arithmetic, calls, memory, SIMD, GC, exceptions, tail calls, and stack arguments.
- [ ] Ubuntu AMD64 native, WAST, component, relevant WASI, and sanitizer gates from ISS-193 pass in shadow mode.
- [ ] Production x64 remains on the legacy path until ISS-201.
- [ ] The common ISS-192 quality gates pass.
