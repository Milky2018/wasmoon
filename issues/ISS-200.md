## Description

Implement the complete x64 vertical pipeline through the same semantic, Target VCode, allocation, frame, emitter, and code-object seams proven by AArch64. The approved direct-break route now lands the production cutover and legacy deletion in the same PR rather than retaining a shadow backend after implementation.

## Design

- Model x64 conditions, flags, addressing, fixed registers, instruction constraints, ABI facts, and encodings directly in x64 packages.
- Do not introduce AArch64-shaped compatibility concepts into shared MachV interfaces.
- Keep production single-path with no fallback. Historical comparison remains available from Git rather than from a second backend in the final tree.

## Acceptance Criteria

- [x] x64 lowers every production semantic MachV operation into verified x64 VCode or a structured unsupported-operation error.
- [x] Selection, legalization, regalloc constraints, frame planning, emission, relocations, fixups, traps, GC metadata, and stack maps use the final seams.
- [x] Static tests prove x64 VCode cannot contain AArch64 instructions, register roles, conditions, or ABI facts.
- [x] Whole-object snapshots cover normalized VCode, allocation constraints, frames, code bytes, relocations, fixups, and safepoints.
- [x] Repository differential coverage includes arithmetic, calls, memory, SIMD, GC, exceptions, tail calls, and stack arguments.
- [x] Ubuntu AMD64 native, WAST, component, relevant WASI, and sanitizer gates from ISS-193 pass on the final single production path.
- [x] Production x64 uses the new target pipeline with no runtime fallback; ISS-201 removes the old implementation in the same PR.
- [x] The local common ISS-192 quality gates pass.
