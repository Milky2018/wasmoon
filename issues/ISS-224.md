## Description

AArch64 and AMD64 emitters independently derive the ordering of stack argument stores and register moves. Replace those shallow copies with one pure planner operating on allocated source locations and normalized ABI destinations.

## Design

The planner first snapshots outgoing stack arguments while original register sources are intact, then resolves register destinations as parallel moves using reserved scratch registers. It returns a structured plan and error rather than emitting bytes or aborting. Target adapters retain ABI layout and instruction encoding.

## Acceptance Criteria
- [x] A pure planner accepts allocated sources, normalized register/outgoing-stack destinations, and legal scratch registers.
- [x] Its result is symbolically verifiable for cycles, spills, duplicate sources, mixed banks, and indirect callees.
- [x] Invalid destination overlap, type/class, alignment, range, and scratch contracts return structured errors.
- [x] The planner contains no AArch64, AMD64, Wasm, or Wasmoon product knowledge.

## Notes
- 2026-07-21: The shared planner is justified by two production target adapters and a pure symbolic test adapter.
- 2026-07-21: Reopened after review showed that the planner cannot validate a stack source's allocation ownership/type or an outgoing offset against the actual outgoing-area bound. Those contracts need explicit data rather than a checked acceptance box.
- 2026-07-21: The planner now receives the source allocation and exact outgoing stack interval. It rejects foreign or malformed source slots, source/destination class mismatches, duplicate or overlapping destinations, invalid alignment/ranges, protected-root overwrites, and missing or wrong-class scratch registers with structured errors.
