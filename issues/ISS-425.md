## Description
Strict register-allocation validation rejects the x64 signed division,
remainder, and multiply-high JIT tests after the emergency-move refactor. The
lowered instructions require their second input in R11, but R11 is intentionally
neither allocatable nor an allocator edit/spill scratch after ISS-423.

The default pipeline emits working code because plan verification is optional.
With `MACHV_REGALLOC_VALIDATION=1`, the verifier reports R11-backed values as
illegal allocation locations.

After that contract is repaired, strict core WAST also exposes live floating
and vector values left in caller-clobbered AArch64 registers across calls.

## Design
Represent registers reserved for fixed instruction operands separately from
allocatable registers and allocator edit/spill scratches. The allocator may
honor an explicit fixed constraint in such a register, while it must not choose
that register for a value home, an unconstrained operand, or a general-purpose
edit scratch. Matching fixed-operand materialization may still move a value into
the named register at the instruction boundary.
Pass the x64 instruction-reserved registers through the MachV adapter without
granting them transfer-scratch authority.

Model clobbers at their real boundary between Early and Late operands, and make
clobber intersection include a live segment start but exclude its end.

## Acceptance Criteria
- [x] The allocation environment distinguishes fixed-operand-only registers from allocator edit/spill scratches.
- [x] The plan verifier accepts an explicit matching fixed constraint in a reserved operand register and rejects unconstrained use there.
- [x] X64 keeps R11 outside allocatable, spill-scratch, and transfer-scratch roles.
- [x] The three strict-validation JIT regressions pass.
- [x] The full native suite passes with `MACHV_REGALLOC_VALIDATION=1`.
- [x] Core, project-specific, and component JIT WAST pass with strict regalloc validation.
- [x] Formatting, interfaces, native checks, and module-boundary audit pass.
