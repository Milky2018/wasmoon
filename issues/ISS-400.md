# ISS-400: A v128 exception payload makes the JIT refuse the whole module

## Metadata
- Type: bug
- Status: closed
- Priority: 2
- Labels: jit, simd, exceptions, agent
- Assignee: unassigned
- Created: 2026-08-05
- Updated: 2026-08-05

## Description
Throwing a vector and catching it works in the interpreter and stops the JIT
from compiling the module at all:

```wat
(module
  (tag $t (param v128))
  (func (export "roundtrip") (result v128)
    (block $b (result v128)
      (try_table (result v128) (catch $t $b)
        (throw $t (v128.const i32x4 1 2 3 4))
        (v128.const i32x4 0 0 0 0)))))
```

| | result |
| --- | --- |
| `wasmoon run --no-jit` | `v128:01000000020000000300000004000000` — correct |
| `wasmoon run` | `Error: JIT compilation failed`, nothing runs |
| `wasmoon test` | fails, strict mode reports the compile failure |

Failure is not the intended bail-out:

```
SemanticLoweringFailed(cause=InvalidMilkIR(
  message="TypeMismatch(message=\"bitcast cannot convert i64 to v128\")"))
```

`lower.mbt` guards the spill and throw sides with reason strings, but the
value-retrieval side has no such guard and simply bitcasts the runtime word
to the payload type. It reaches the MilkIR verifier, which rejects it. A
guard that another path bypasses is worse than no guard, because the error
surfaces far from the assumption it broke.

A v128 that merely stays *live across* a try is fine — only a payload
crossing the tag breaks:

```wat
(local $v v128)   ;; set, throw, catch, read back -- works in both modes
```

## Design
Same root as ISS-397: the runtime ABI carries every value in one `int64_t`
and a v128 does not fit.

But **not** the same fix. ISS-397's by-address 16-byte slot was the wrong
shape to copy here, because this codebase already had an answer for v128 in
the exception machinery and it was working: spilled locals go through
`local_to_spill_words`, which gives a v128 two consecutive i64 words, and
`spill_words_to_v128` puts it back. There is even a
`V128 => abort("internal error: use v128 spill restore path")` guard to keep
the two paths apart. That is why a v128 *local* across a try already worked.

The payload path simply never got the same treatment. So it gets it now,
rather than a second, competing convention:

- `emit_payload_word_buffer` packs the payload, spending two words on a v128
  and one on everything else.
- `Translator::read_exception_payload` walks the tag's declared types and
  advances the word index by two only where the tag says v128.

Both sides derive the layout from the same tag signature, which is what keeps
them in step, and it is the same reasoning that makes the existing spilled
-locals walk safe.

The unguarded retrieval is fixed by construction: the catch-all now routes
through `i64_bits_to_local`, which is exhaustive over the IR types and cannot
be asked to bitcast a word into something it has not considered.

No C change, no new dialect opcode, no new runtime capability.

## Close Notes

Three files: the payload packer in `wasm_machv/lower.mbt`, the reader in
`wasm_frontend/ir/translator_core.mbt`, and the tests. No public interface
changed.

The first attempt was larger and wrong. It widened the C payload buffers to
two words per entry, added `GetExceptionValueHigh`/`GetSpilledLocalHigh`
opcodes, and threaded two new capabilities through six layers -- carrying
ISS-397's convention over wholesale. It would also have **broken spilled
locals**, which already pack a v128 as two entries and count words, not
values; doubling them in C would have desynchronised an index that was
already correct. Reverted, then rewritten to follow the convention already
there.

`lower_spill_locals` keeps its guard, but its message was wrong once vectors
worked: it said the ABI "cannot spill v128", when in fact vectors reach it
already split and a vector arriving whole means the split was skipped. It now
says that instead.

Verified: 2591/2591 native tests, spec corpus 258/258 files and 62563 tests in
both modes, `find_gc_bugs.py` clean, CLI behaviour tests pass. The 7 new tests
cover a lone vector, a vector between two scalars, the scalar on each side of
one, two adjacent vectors, and a vector local across a try -- the last of
which already worked and is pinned so that changing one path cannot quietly
break the other.
