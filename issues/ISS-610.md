## Description
The invocation-control migration's paired end-to-end run reports median slowdowns of 2.32% for indirect calls, 1.20% for GC and 1.04% for exceptions. AEGIS is +0.24% with an interval crossing zero. These measurements do not isolate a cause; the independent before/after medians differ from paired ratios. Do not label the change performance-neutral or attribute the result to added RC without further evidence.

## Design
Use the pinned baseline and archived fixtures/samples in `docs/perf/invocation-controls-2026-09-29.json.gz`. Separate invocation entry and cooperative polling from guest execution, compilation and process startup. Inspect generated code and control-helper machine code before changing ownership design. Keep paired serial measurement and distinguish repeatable regressions from placement or host variation.

## Close Notes

Local diagnosis and fix are complete. WAST forces cancellation instrumentation at guest entries/loop heads. ARM64 disassembly identifies duplicate activation lookup (each lookup performs two macOS TLV resolutions), with extra control-view branches after migration. A/A and phase-separated controls bound interpretation of small timing changes. A poll-only build removes the duplicate lookup without changing ownership; independent paired runs show a substantial indirect-workload improvement. This does not assign every original percentage point to one cause. See `docs/perf/control-diagnosis-2026-09-29.md` and its archived samples/disassembly. Native, sanitizer and external regressions pass; cross-platform CI for the fix is pending.
