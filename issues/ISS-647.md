# ISS-647: Clean up WASI03 fixture workspaces after each case

## Description
The WASI03 runner copied each guest and mutable fixture into a permanent
`<output>-work` tree for both engines. One complete run retained about 301 MiB;
repeated local verification accumulated multiple identical guest copies.

## Design
Use a system TemporaryDirectory for each case, separate from durable reports.
Clean it on success, failure, malformed/missing results and timeout. Stop and
reap interrupted child processes before removing their fixtures. Keep pinned
inputs, deadlines, assertion outcomes and report contents unchanged.

## Acceptance Criteria
- [x] Regression reproduces leaked workspaces before the fix.
- [x] Both engine workspaces disappear for success, failure, missing/malformed results and timeout.
- [x] Logs and result files survive cleanup; inaccessible fixture directories are removed without following external symlinks.
- [x] Actual pinned HTTP contract profile passes all 110 executions without leftover workspaces.
- [x] Python script suite passes locally.
- [ ] Supported-platform CI passes after submission.
