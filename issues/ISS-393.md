## Description
`modules/milkir/egraph/egraph.mbt` had grown to 2125 lines holding the
union-find, the congruence rebuild, the per-class type and constant caches,
extraction, and saturation scheduling.

Divergent change, and recently demonstrated: ISS-378 changed extraction's
memo, ISS-379 the type-conflict handling, ISS-381 the rebuild and its
fixpoint, ISS-383 rule-application progress, ISS-384 the harvest cost. Five
issues, five different responsibilities, one file — each edit touching a
file whose other 1900 lines had nothing to do with it.

## Design
Split within the package. Nothing crosses a package boundary, so no
visibility changes and no API growth — the point is only that a reader
opening a file finds one subject in it.

The file already carried `// ====` section banners marking these seams, so
the split follows the boundaries the author had already drawn rather than
inventing new ones.

| File | Lines | Holds |
| --- | ---: | --- |
| `enode.mbt` | 307 | `EClassId`, `EOpcode`, `EOpcodeTag`, `ENode` |
| `union_find.mbt` | 88 | `EClass`, `UnionFind` |
| `egraph.mbt` | 634 | the structure: add, find, canonicalize, index, merge, repair |
| `egraph_class_facts.mbt` | 142 | width and bounds cache, type conflicts, remat marks |
| `egraph_build.mbt` | 472 | the `add_*` constructors |
| `egraph_extract.mbt` | 279 | cost model and extraction |
| `egraph_saturate.mbt` | 235 | limits, rule index, saturation scheduling |

## Close Notes

A refactor this mechanical is worth proving mechanically rather than reading
over, so two checks stand in for review:

- `moon info` regenerates every `.mbti` and none changed. The package
  exports exactly what it did.
- Concatenating the seven files and dropping comments gives 1470 code lines,
  an identical multiset to the original file's 1470. Not a line was edited,
  added, or dropped; only its address changed.

The 32-line growth is the six new file headers, each saying what its file is
for and why it is separate.
