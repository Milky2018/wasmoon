# ISS-580: Bound resolver work and prevent notification inheritance

## Description
DNS lookups currently create unbounded detached threads, and POSIX notification pipes are inheritable. Cancellation must not let callers bypass the work limit.

## Design
Use a shared bounded resolver queue with at most four active workers and 32 queued/executing requests. Cancel queued requests immediately, but account for executing cancelled requests until getaddrinfo returns. Workers exit when the queue empties. Preserve system resolver semantics and all returned addresses; the async dependency exposes neither a suitable public all-address resolver nor a generic blocking executor.

Use atomic close-on-exec Linux pipes and Darwin kqueue user events (created close-on-exec/close-on-fork), retaining the existing Windows non-inheritable notification transport. No process-global fork lock or private Darwin syscall is needed.

## Notes
Darwin kqueue creation marks descriptors FP_CLOEXEC and FP_CLOFORK before publishing them: https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_event.c (kqueue_internal). This avoids the pipe-plus-fcntl race even in an embedding host with unrelated spawn operations.

Local validation: all 2559 native tests pass, 35 C translation units pass strict warning checks, and 168 script tests pass (54 platform skips). ASan/UBSan passes 42 tests plus the deterministic allocation/queue/cancellation/exec probe and both positive controls. Ordinary poll and native reactor registrations both observe resolver completion on Darwin. The module boundary audit passes. Windows child inheritance is covered by a new native CI test; cross-platform validation is pending.
