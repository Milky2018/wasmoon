# ISS-415: Remove the uncompetitive Fast allocator

## Metadata
- Type: task
- Status: closed

- External ref: none

## Description

The independent `Fast` experiment created excessive stack homes, transfers,
and emitted code on representative multi-block workloads. It lost end-to-end
time despite spending slightly less time inside register allocation. Keeping a
second public strategy would preserve code and API complexity without a useful
deployment case.

## Design

Delete the implementation and its public selection surface. Keep one verified,
bundle-aware allocator and improve its data structures directly. Do not retain
a compatibility enum, a one-case strategy field, or strategy-specific metrics
and tests.

## Acceptance Criteria
- [x] `AllocatorStrategy`, `FastAllocation`, and the strategy option are absent
      from the public API.
- [x] The independent allocator implementation and strategy-only tests are
      deleted.
- [x] Production and reusable callers use the sole bundle-aware allocator.
- [x] Current architecture and package documentation describe one allocator;
      historical issue evidence identifies the experiment as removed.
- [x] Native warning check, the complete regalloc suite, and the full native
      workspace suite pass.

## Notes
- 2026-08-11: Measurement showed that local changes could not meet
  the quality gate. Five interleaved AEGIS128L runs measured Backtracking at
  213,757 us module compile, 79,384 us regalloc, 59,500 bytes, 347 spill slots,
  407 spills, and 1,222 reloads. Current Fast measured 227,490 us module
  compile, 75,810 us regalloc, 80,384 bytes, 1,648 spill slots, 1,365 spills,
  and 3,799 reloads; wall time was about 1.33 s versus 0.98 s.
- 2026-08-11: A temporary stable-register preference reduced Fast to 78,060
  bytes, 1,445 slots, and 3,585 reloads. Adding conflict-point prefix splitting
  reached 77,992 bytes and 3,568 reloads. Both remained far outside the quality
  gate and were discarded rather than committed as heuristics.
- 2026-08-11: The user chose deletion instead of a second rewrite. No
  compatibility surface is retained.
