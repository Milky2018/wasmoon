## Description
At main commit `7dec3153`, production compilation derives its context shape from the input module (`modules/wasmoon/cmd/wasmoon/commands/run.mbt`). In contrast, `commands/explore.mbt` constructs the default embedding environment, and `modules/wasmoon_jit/native_wasm_lower.mbt::compile_wasm_body_diagnostics_for_target` uses `vmcontext_layout()` and a function index of `-1`. Diagnostic and production paths separately assemble lowering and allocation stages.

Consequently, explore output does not necessarily describe the configuration or artifact used by production execution. This is a diagnostic fidelity and maintenance problem; the inspection did not demonstrate incorrect guest execution or invalidate every previous performance conclusion.

## Design
Use a shared production compilation configuration and pipeline with optional diagnostic observations. Carry the module-derived context layout, function identity, ABI settings and applicable validation options through diagnostics. Preserve inspection of both native targets without introducing a second runtime compilation or a parallel compiler implementation.

## Acceptance Criteria
- [x] Production and diagnostics use the same explicit compilation configuration for the same module, function and target.
- [x] Add a regression exercising a module-specific context shape and actual function identity; compare meaningful code-object output and metadata between production and diagnostics.
- [x] Verify x64 and AArch64 diagnostic paths and existing CLI diagnostic failure handling; distinguish cross-compilation from native execution.
- [x] Run relevant compiler/CLI tests and repository validation; document any intentional diagnostic differences.

## Close Notes
The CLI now derives its frontend and native context layout from the module,
uses production function naming and optimization-level normalization, and
passes absolute function indices including imports. A NativeCompiler owns the
same layout and target session for artifact compilation and diagnostics.
Both paths call one Wasm lowering/compilation implementation. Target sessions
render optional diagnostic strings from the actual allocation and emission;
the standalone target diagnostic APIs also delegate to that pipeline.
Ordinary compilation does not render diagnostic text. Internal verification
uses the same VCODE_REGALLOC_VALIDATION policy.

Validation on 2026-10-12:
- `moon info`, `moon fmt`, and `moon check --target native --warn-list +73 --deny-warn` passed.
- `moon test --target native`: 2,636 passed, zero failures.
- With `VCODE_REGALLOC_VALIDATION=1`, CLI commands passed 17/17 and wasmoon_jit passed 197/197.
- The new CLI regression compares machine bytes and relocations, source sites, traps, safepoints and unwind metadata at O0/O2 for x64 and AArch64. The host lane compares against the complete production module compiler; the other lane uses the production artifact compiler through cross-compilation. The fixture includes an imported function, compact context, memory/global accesses and GC allocation, with nonempty relocation and safepoint metadata.
- Temporarily restoring the old Legacy context, then separately restoring owner index -1, caused the parity regression to fail in both experiments. The corrected source was restored before the successful full suite.
- Existing earlier-failure/later-success CLI handling and spilled multi-result exploration remain covered. Invalid Wasm dialect diagnostics are compared against production errors under both verification settings.
- `python3 scripts/audit_module_boundaries.py` and `git diff --check` passed.

`docs/development.md` records the comparison boundary: explore currently uses
default cancellation and NaN policy and has no imported-memory maximum override.
The standalone compatibility API retains Legacy/-1 defaults for existing callers;
module diagnostics use the shaped compiler and real function identity. This work
was verified locally on macOS ARM64; x64 was cross-compiled, not executed. No new
remote CI or full external corpus run is claimed. No follow-up issue is required
for the recorded scope.
