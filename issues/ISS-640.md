## Description
The JIT's builtin `spectest.print_char` does not receive the requested character: a minimal invocation with 65 prints NUL, while the interpreter prints `A`. Both commands exit successfully. This reproduces in the saved pre-investigation binary as well as the later candidate, so the exception-construction optimization does not introduce it.

The wider concern is native import argument/return routing. Most spectest builtins are no-ops, and existing registry tests assert that their pointers exist rather than checking observable argument routing. They cannot detect a stale calling-convention assumption. The exact register mismatch is not established yet; audit the emitted direct-import call and the C declarations together instead of patching one printed character.

## Design
Use the existing shared hostcall mechanism where appropriate. Where a direct builtin remains justified, establish its actual guest calling convention and verify integer, floating-point and mixed signatures through observable behavior. Keep ABI adaptation in a small native primitive; avoid duplicate host implementations or silently skipping behavior checks.

## Acceptance Criteria
- [ ] Reproduce the `print_char(65)` interpreter/JIT mismatch and establish the emitted argument-register mismatch.
- [ ] Review the complete builtin import family and its hidden arguments, parameter classes and returns.
- [ ] Repair routing and add behavior tests that detect incorrect values, rather than pointer-presence assertions alone.
- [ ] Verify both engines and supported native calling conventions, including Windows Clang/MSVC.
