# ISS-082: Minimize reusable module metadata dependencies

## Description
Several module manifests declare broader dependencies than their current package imports require. Over-broad `moon.mod` imports make the reusable module graph look more coupled than the implementation really is, and can accidentally preserve stale dependencies.

This already happened with `machv` declaring `milkir` after the code stopped importing it.

## Design
Compare `moon.mod` imports with actual `moon.pkg` imports for each reusable module. Remove stale manifest dependencies where MoonBit checks prove they are unnecessary. Keep dependencies that are required by generated docs/tests or public package imports.

Non-goals: do not change source behavior, package imports, or public APIs.

## Acceptance Criteria
- [x] Reusable module manifests no longer declare stale internal dependencies that are unused by package imports.
- [x] Removed dependencies are validated by targeted `moon -C <module> check`.
- [x] Workspace-level native check and tests pass.
- [x] Module dependency documentation reflects the minimized graph if it changes.
