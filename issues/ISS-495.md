# ISS-495: Retain shared linear memory across independent Stores

## Metadata

## Description
WAST threads require independent Stores importing shared memory. Reusing a Memory handle currently lets either Store invalidate the other. Give each importing Store its own handle and retain the native descriptor until the last owner releases it.

## Acceptance Criteria
- [x] Closing either Store invalidates its own handle while other owners retain data and growth visibility.
- [x] Reject non-shared memory and closed source/destination Stores without acquiring a leaked reference.
- [x] Final close frees the descriptor once; lifetime and sanitizer regressions pass.

## Close Notes
- Native descriptors now carry independent reference-counted ownership; each Store import gets its own invalidation handle through `Store::alloc_shared_mem`. Final release frees the backing while ordinary aliases retain their existing shared-invalidation behavior.
- Public lifetime tests cover both close orders, memory32/memory64, growth visibility, transitive ownership after the original Store closes, non-shared rejection and closed source/destination rejection.
- Native tests: 2,369 passed. Lifetime tests: six passed normally and under AddressSanitizer. Core WAST: 258 files / 62,563 assertions per engine passed; local runtime scripts and module-boundary audit passed.
- Full misc verdicts remain unchanged: 558 pass, 68 script-only, 112 fail, 10 unsupported, 16 deferred (`tmp/iss495-full-misc/summary.json`).
- Shared growth synchronization and stable memory64 backing remain prerequisites of ISS-476; ownership alone does not claim concurrent growth safety.
