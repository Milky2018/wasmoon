# ISS-379: Stop silently swallowing e-class type conflicts

## Description
`EGraph::set_type` (`modules/milkir/egraph/egraph.mbt:550`) handles a
conflicting bit-width assignment with
`Some(existing) => if existing == bits { () } else { () }` — both branches
are no-ops, so a conflict is dropped on the floor. `EGraph::merge` behaves
the same way structurally: the root's type wins and the other class's type
entry is removed without comparison; the rebuild finalization re-roots the
type map first-wins as well.

A 32-bit class merged with a 64-bit class is a soundness violation, and the
bit-width-driven rules (`rules_extends` alone is 1,290 lines keyed on
`get_bits`) would keep rewriting with the wrong width — silently.

The constant caches have the same hole with a sharper consequence.
`EGraph::merge` (`egraph.mbt:784`) merges `const_value`/`fconst_value` by
"prefer non-None": when **both** classes carry a constant and the values
differ — the loudest possible evidence that some rule performed an unsound
union, since it equates two distinct constants — the root's value silently
wins. `get_simplified_opcode` then rewrites every value of that class to
the surviving, possibly wrong, constant. This case must be part of the
same loud-failure mechanism, not just the width conflict.

## Design
Type conflicts must be loud. On conflicting `set_type` or a merge of two
classes with differing widths, at minimum record and surface a diagnostic
(debug assertion in test builds); ideally refuse the merge or mark the
class poisoned so width-dependent rules skip it. Decide and document which.
Add a whitebox regression asserting the chosen behavior.

## Acceptance Criteria
- [ ] A conflicting `set_type` no longer silently returns; the chosen
      mechanism (assert, diagnostic, or poison) is observable in a test.
- [ ] A merge of classes with differing known widths triggers the same
      mechanism.
- [ ] A merge of two classes carrying differing `const_value` (or
      `fconst_value`) triggers the same mechanism, verified by a whitebox
      regression.
- [ ] Existing e-graph and optimizer suites stay green.
