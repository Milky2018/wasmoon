# ISS-199: Cut over AArch64 and remove its legacy backend

## Metadata
- Type: task
- Status: in_progress

- Updated: 2026-07-20

## Description

Switch production AArch64 compilation to the final Target VCode pipeline and delete the AArch64 branch of the legacy adapter and backend in the same coherent milestone.

## Design

- Production has one AArch64 path and no automatic fallback.
- A new-backend failure is returned as a structured compilation error.
- AMD64 has completed its separate implementation cutover under ISS-200/ISS-201; this issue retains the target-specific AArch64 acceptance boundary.

## Acceptance Criteria

- [x] All production AArch64 JIT entry points use the final semantic MachV, AArch64 VCode, allocation, frame, emitter, and code-object seams.
- [x] The AArch64 branch of the semantic-to-legacy adapter and all legacy AArch64 target instructions, selection, allocation glue, and emitter logic are deleted.
- [x] No runtime flag, fallback, public compatibility API, or hidden retry can select the legacy AArch64 path.
- [x] macOS AArch64 native, WAST, component, WASI, artifact, and JIT/interpreter differential gates from ISS-193 pass.
- [ ] The macOS AArch64 paired fixed-legacy runtime, compile-time, and code-size gates from ISS-193 pass.
- [x] Relocation, fixup, trap, GC, stack-map, unwind, and normalized-disassembly comparisons meet their acceptance thresholds.
- [x] AMD64 correctness CI remains green after its separate target pipeline cutover.
- [x] The common ISS-192 quality gates pass.
