# ISS-199: Cut over AArch64 and remove its legacy backend

## Description

Switch production AArch64 compilation to the final Target VCode pipeline and delete the AArch64 branch of the legacy adapter and backend in the same coherent milestone.

## Design

- Production has one AArch64 path and no automatic fallback.
- A new-backend failure is returned as a structured compilation error.
- AMD64 remains on the temporary legacy path until its own cutover.

## Acceptance Criteria

- [ ] All production AArch64 JIT entry points use the final semantic MachV, AArch64 VCode, allocation, frame, emitter, and code-object seams.
- [ ] The AArch64 branch of the semantic-to-legacy adapter and all legacy AArch64 target instructions, selection, allocation glue, and emitter logic are deleted.
- [ ] No runtime flag, fallback, public compatibility API, or hidden retry can select the legacy AArch64 path.
- [ ] macOS AArch64 native, WAST, component, WASI, artifact, and JIT/interpreter differential gates from ISS-193 pass.
- [ ] Relocation, fixup, trap, GC, stack-map, unwind, and normalized-disassembly comparisons meet their acceptance thresholds.
- [ ] AMD64 CI remains green on its unchanged path.
- [ ] The common ISS-192 quality gates pass.
