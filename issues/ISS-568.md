## Description
The network client currently maps unstructured async TLS failures to TLS-protocol-error. Certificate verification still rejects bad certificates, but distinct error categories are not preserved. This is an error-fidelity limitation, not evidence that certificate validation is disabled.

## Acceptance Criteria
- [x] Determine which WIT error categories can be faithfully exposed by the TLS backend.
- [ ] Preserve available structured categories and document unavoidable limitations.
- [ ] Cover certificate validation, handshake failure and connection failures with independent peers.

## Notes
See docs/wasi03-acceptance.md and docs/evidence/wasi03-2026-09-18/.

The async maintainer agent verified that async 0.21.2 and upstream main expose only `TlsError(String)` across OpenSSL, Schannel and wasm. No reliable certificate/protocol/alert discriminator is available. Upstream issue #620 requests structured categories and alert codes. Unblock when that API is available; do not classify errors by localized diagnostic substrings. Certificate verification remains enabled.
