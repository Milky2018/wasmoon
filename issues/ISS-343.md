## Description
Native component JIT construction currently lives in the CLI command package,
so ordinary embedders cannot select it and the CLI bypasses the stable component
facade.

## Design
Move the native adapter into a Wasmoon-owned native component package. It returns
the stable opaque engine configuration while privately coordinating JIT
contexts, Store registration, traps, continuations, GC, and executable mappings.
Cut the CLI and conformance runner over to the stable facade.

## Acceptance Criteria
- [x] Native engine construction is available outside the CLI through a stable opaque handle.
- [x] Native selection is strict and returns structured unsupported-target or compilation errors.
- [x] Ordinary CLI invoke and WASI command paths no longer construct or call `runtime_impl.ComponentLinker` directly.
- [x] Interpreter and native CLI modes use the same facade invocation path.
- [x] Existing JIT evidence tests prove no silent interpreter fallback.

## Close Notes

Moved strict native component construction into `component_native`, exposed it
as an opaque stable `ComponentEngine`, and routed ordinary CLI invoke and WASI
command execution through `ComponentRuntime`. Native execution evidence is
typed and strict: unsupported targets and compilation failures are structured
errors, with no interpreter fallback. Verified by the stable facade black-box
suite, CLI error suite, and focused JIT evidence tests.
