## Description

The optimizer has become a cohesive subsystem, but its driver, GVN, rewrite
families, optimization analyses and tests still share the root IR package.
Move it into `Milky2018/milkir/optimize` within the existing module.

## Design

Keep IR ownership, construction, verification and reusable CFG analysis in
`Milky2018/milkir`. Move the optimization pipeline and its private state together;
callers import `optimize` explicitly, without a circular root forwarding layer.
Preserve the existing algorithms and snapshots. Expose only the read-only views
and invariant-maintaining IR mutations needed across the package boundary, not
private owner records or mutable arena/layout arrays. Move optimizer-only tests
and update live documentation and generated interfaces.

## Acceptance Criteria
- [x] Optimizer implementation and tests live in the optimize package; no new module.
- [x] Production dependencies remain acyclic and pass the module-boundary audit.
- [x] IR mutation APIs preserve ownership and DFG/layout invariants with regressions.
- [x] Documentation and all callers use the new package entry points.
- [x] Strict native tests, warning-73 checking, formatting and generated interfaces pass.
- [x] Representative cold compilation and generated-code comparison show no material regression.

## Close Notes

Completed on 2026-09-04. The optimizer package owns the driver, metrics,
dominator-scoped session, GVN, all handwritten rule families, optimization-only
analyses, CFG cleanup, loop transformations and their tests. The root keeps IR,
builders, verification and reusable CFG/dominance utilities. Root-level MoonBit
files fell from 52 to 20. Module identities and versions did not change.

All runtime/CLI/component/preflight/metrics consumers now import
`Milky2018/milkir/optimize`. The module README uses a black-box-test-only import;
there is no root production dependency or forwarding layer. Private owner
records, mutable instruction arenas and layouts remain private. Reads reuse
`instruction_by_id` and borrowed block-ID views; rewrites use ownership-checked
opcode and layout operations. `FunctionAnalysis` and `OptimizerSession` remain
private to the optimizer.

The old private layout replacement helper inferred deletion only when its new
array was shorter. Its three optimizer callers preserve all original
instructions and only insert helpers. The public `set_instructions` contract
now consistently changes placement without implicit deletion: omitted
instructions must be relocated or explicitly discarded. This removes the
unused length-dependent deletion path and the root package's hash-set import.
Six public-API test groups cover relocation/definition identity, candidate
discard, foreign instruction/global rejection, atomic layout rejection and
shorter/equal/longer replacements. The mixed IR/GVN test was split without
dropping either assertion.
