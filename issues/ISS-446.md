## Description

After ISS-442, AEGIS-128L target VCode construction has a 6,155 us median, but
the completed VCode is then scanned by a separate target verifier for another
4,925 us. The target owns every construction call and immediately seals the
builder, yet that construction evidence is discarded before
`SelectedFunction` is created.

## Design

Introduce a target-owned checked builder or sealing protocol that validates
local instruction constraints, ownership, arity, and block state at mutation
time. Sealing must return an opaque verified VCode state consumed by
`SelectedFunction`. Any global property that cannot be established during
construction may use one bounded final check, but must not rescan local facts
already established by the builder.

Keep standalone `lower`, `compile`, and public VCode verification strict for
externally supplied functions. Do not add an unchecked flag or expose a public
constructor for the verified state.

## Acceptance Criteria
- [ ] Trusted AArch64 and x64 target construction returns an opaque verified VCode state without a second full local-invariant scan.
- [ ] Externally supplied or mutated VCode still receives complete target verification and preserves current typed failures.
- [ ] Focused malformed-builder tests prove that construction cannot mint the verified state when any required invariant is absent.
- [ ] AEGIS-128L VCode, artifact bytes, relocations, metadata, and code sizes remain unchanged.
- [ ] Across seven cache-isolated captures, `target_vcode_validation` falls by at least 75 percent from 4,925 us without moving equivalent work into construction.
- [ ] Strict native allocation validation, target tests, formatting, warning-73, generated interfaces, and module boundaries pass.

## Notes

- Added nested `target_common_validation` and `target_isa_validation` metrics so
  the construction protocol can preserve genuinely global checks without
  guessing which full-function scan owns the measured cost.
- Seven cache-isolated AEGIS-128L captures at `c6235b17` measured a 4,905 us
  median total validation cost: 2,650 us in common VCode validation and 2,184
  us in ISA validation. Neither scan can remain on the trusted selection path
  if the 75 percent reduction gate is to hold.
- Target selection now returns a private `ConstructedFunction` capability that
  can only be created by the exhaustive lowering routine from verified
  semantic MachV. `SelectedFunction` owns that capability and exposes no raw
  VCode mutation seam. Standalone `lower`, `verify_vcode`, and `compile` still
  run both complete verifiers; the selected path records a distinct sealing
  phase and does not accept generic builder output.
