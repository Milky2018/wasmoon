# ISS-471: Centralize stable task identity and lifecycle

## Description
Task state is spread across parallel maps and changes identity when a guest subtask handle is allocated. Lifecycle cleanup and migration require synchronized edits across many paths.

## Design
Give tasks stable internal identities and owned task records. Guest handles reference those records. Centralize creation, completion, cancellation and retirement, and establish shared runtime ownership before instantiation.

## Acceptance Criteria
- [ ] Guest handle allocation never migrates task identity or task state.
- [ ] Task lifecycle state and cleanup are owned by a single module rather than parallel per-property maps.
- [ ] Cancellation, waiting, borrowing and child-thread cleanup retain existing observable semantics.
- [ ] Host runtime acquisition order cannot split one linker into independent execution states.
- [ ] Native and component async regression suites pass with no new misc failures.
