# ISS-605: Make MoonBit own callable registry data and update policy

## Description
Replace the C-managed callable container with MoonBit-owned typed arrays and update policy. C should retain RC references for the native view and expose only the operations required by native execution. Preserve native lookup without a callback into MoonBit.

## Acceptance Criteria
- [x] Sorting, duplicate handling and publication decisions live in MoonBit.
- [x] Native views retain MoonBit arrays rather than copying them into malloc buffers.
- [x] Callable context binding uses a package-owned managed type and FFI declaration.
- [x] Mutation, rebinding, clearing and owner release preserve lookup and subtype semantics.
- [x] Measure full public publication cost, native query cost and persistent storage against 2c0b2997.
- [ ] Strict native checks, sanitizers, external regressions and Linux/MSVC CI validate the change.

## Close Notes

Local implementation and validation are complete. See `docs/perf/moonbit-callable-registry-2026-09-29.md` for the pinned baseline, full publication/query/guest measurements and allocator accounting. Persistent registry storage increases by 88 bytes; unchanged-address publication avoids temporary allocations, while address changes are about 14% slower. All 2,611 native tests, 66 sanitizer tests, both-engine core WAST and async component regressions pass. Linux/MSVC CI remains pending. Full context/activation migration remains separate (ISS-602).
