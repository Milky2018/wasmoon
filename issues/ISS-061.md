# ISS-061: Move Wasm calling-convention policy out of MachV ISA traits

## Description
The generic MachV ISA trait exposes Wasm-specific calling-convention methods,
such as VMContext argument registers and Wasm argument/return register sets.
That makes a reusable ISA abstraction encode Wasmoon internal ABI policy.

Evidence:
- `modules/machv/isa/isa.mbt` exposes `wasm_vmctx_arg_preg`, `wasm_user_arg_gprs`, `wasm_arg_fprs`, `wasm_ret_gprs`, and `wasm_ret_fprs`.
- AArch64 and AMD64 ISA packages define internal Wasm ABI registers under the MachV ISA namespace.
- `modules/machv/abi/abi.mbt` still exposes `wasm_layout_overflow_stack`, which is Wasm calling-convention stack policy rather than generic ABI machinery.

## Design
Move Wasm internal calling-convention selection into machine target or Wasmoon JIT
ABI policy code. The MachV ISA trait should expose target facts and generic
calling-convention hooks, while Wasmoon chooses how VMContext and Wasm values
map onto those facts.

Non-goal: change the actual AArch64 or AMD64 register assignment.

## Acceptance Criteria
- [x] Generic `machv/isa` APIs no longer expose Wasm-named methods.
- [x] Wasmoon internal calling convention is owned by Wasmoon JIT or machine-target ABI policy.
- [x] `wasm_layout_overflow_stack` and related Wasm stack-slot helpers move out of generic MachV ABI ownership.
- [x] Existing AArch64 and AMD64 Wasm ABI register assignments are preserved.
- [x] Target packages remain reusable without importing Wasmoon runtime concepts.
- [x] `moon info --target native` is run and generated `.mbti` diffs are reviewed.
- [x] `git diff --check` passes.
- [x] `moon check modules/machv modules/milkir_machv modules/wasmoon_jit --target native --warn-list +73 --diagnostic-limit=200` passes.
- [x] `moon test modules/machv modules/milkir_machv modules/wasmoon_jit --target native --warn-list +73 --diagnostic-limit=200` passes.
- [x] Native WAST tests that exercise direct, indirect, import, and return calls pass.
