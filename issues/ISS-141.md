## Description
The expand phase temporarily permits old flat opcode forms beside the semantic families. Once all repository producers and consumers migrate, retaining compatibility variants would recreate duplicate protocols and allow new code to bypass the intended seam.

## Design
Delete all migrated flat variants and compatibility helpers, regenerate public interfaces, update MilkIR/wasm_milkir/milkir_machv documentation, and close the epic only after static searches and full gates demonstrate that no old representation or unconsumed Wasm immediate remains.

## Acceptance Criteria
- [ ] No legacy flat variant or compatibility constructor remains.
- [ ] `Opcode` exposes only the approved semantic families and explicit dialect form.
- [ ] Generated interfaces and documentation describe the core/dialect phase contract.
- [ ] Module-boundary audit passes.
- [ ] Native, wasm-gc, register-allocation validation, and relevant WAST/JIT differential gates pass.
