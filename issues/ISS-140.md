# ISS-140: Separate dialect-bearing IR from core lowering

## Description
`Ext` is structurally part of `Opcode`, so the same `Function` type can mean either generic core IR or dialect-bearing IR. Generic lowering accepts an optional extension callback, making it impossible for callers and tests to know from the interface whether a function is legal core MilkIR or requires a dialect adapter.

## Design
Add an explicit verified-core interface and a clearly named dialect-lowering interface. Core verification rejects unresolved extensions, while `wasm_milkir` validation and `wasm_isa_lower` own Wasm extension decoding and adaptation. The implementation may share internal lowering machinery, but generic callers must not receive a silent extension hook. Do not require a big-bang rewrite of GC/exception operations into core CFG in this slice.

## Acceptance Criteria
- [x] Generic lowering accepts only functions verified to contain core operations.
- [x] Dialect-bearing lowering is explicit in its name and required adapter input.
- [x] Unknown or malformed Wasm extensions fail at the Wasm adapter seam.
- [x] Generic MilkIR/MachV code contains no Wasm decoding or runtime names.
- [x] Wasmoon JIT continues to route Wasm functions through wasm_isa_lower.
