# ISS-065: Separate MilkIR generic core from Wasm semantic extensions

## Description
MilkIR is intended to be a reusable compiler IR, but the core IR file still
describes itself as WebAssembly IR and includes Wasm-specific memory, table,
call, GC, reference, and exception operations as core opcodes.

Evidence:
- `modules/milkir/ir.mbt` begins with "Intermediate Representation (IR) for WebAssembly".
- The core `Instruction` model includes operations such as `MemoryGrow`, `TableGrow`, `WasmCall`, `WasmCallIndirect`, GC allocation/reference operations, and exception operations.

## Design
Separate the reusable MilkIR core from Wasm semantic extensions. For each
Wasm-specific opcode, either lower it through generic MilkIR constructs and
runtime/helper calls, move it into a Wasm extension/lowering package, or leave a
clear TODO comment when the migration is intentionally incomplete. Match the
Cranelift-style direction recorded in `CONTEXT.md`: runtime operations should
not become custom core opcodes unless they are genuinely generic IR concepts.

Non-goal: remove Wasm support from the compiler pipeline.
