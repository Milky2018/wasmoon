# ISS-624: Reclaim unreachable runtime roots throughout long-lived Stores

## Metadata
- Type: bug
- Status: open

- Updated: 2026-10-14

## Description
Runtime-owned registries can keep guest objects reachable after the guest has
discarded every reference. Terminal Store cleanup does not establish correct
reclamation during a long-lived Store's operation. Review the entire class of
retained roots and ownership edges, using the confirmed externref case as the
first regression rather than the complete scope.

At `25381fc764c47e805f318012c272fdd51f62c57f`, an interpreter function creates a
struct, applies `extern.convert_any`, and drops the result. After 1000 calls,
forced GC collects zero objects and leaves 1000 live objects. The control that
drops the struct directly collects all 1000. `runtime/store.mbt::wrap_as_extern`
appends every wrapper to `wrapped_externs`, and `collect_roots` roots every
stored value until close.

## Scope and Evidence
- Inspect wrapped externrefs, exception payload registries, element/data
  segments, registered instances, parked continuations, root leases, callbacks,
  and retained native metadata. Other families are investigation targets, not
  additional proven leaks.
- Distinguish required Store-lifetime ownership, live host references, temporary
  roots, unreachable objects, and reference cycles. Record the release event for
  each owned edge and the mechanism that makes an unreachable entry collectible.
- Preserve [the paired reproduction and raw outcomes](../docs/evidence/runtime-quality-2026-10-14/README.md).

## Design
Make reachability and ownership explicit across interpreter, native GC, and
host-visible references. Reclamation must preserve reference identity and keep
live host references and parked frames safe. Removing all wrapper roots or
recycling numeric handles without lifetime protection is insufficient.

## Acceptance Criteria
- [ ] Record an ownership/root inventory for the listed families, including required retention and release events; reproduce or explicitly bound each suspected defect.
- [ ] The wrapped-struct regression returns live objects and temporary registry storage to the expected baseline after references are dropped and GC runs.
- [ ] Live externrefs in globals, tables, host-held references, exception payloads, and parked calls remain usable across collection; identity and conversions remain correct.
- [ ] Repeated success, trap, cancellation, failed instantiation, and terminal close cover the investigated root families without accumulating unreachable objects or stale handles.
- [ ] Verify both heap representations and both engines where the path exists; keep logical-state checks distinct from native leak-sanitizer evidence.
- [ ] Relevant native, external GC/component, and sanitizer gates pass; closure explains every inventory disposition and any separately tracked follow-up.
