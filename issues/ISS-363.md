# ISS-363: Reject non-dominating validation control flow in the security audit

## Description
The component security audit checks only brace depth and lexical ordering when
proving that validation precedes instantiation. It therefore accepts validation
that is deferred until function exit or whose failure is caught and ignored.

The current runtime facade propagates validation failures correctly, so this is
a false-pass in the regression gate rather than a live runtime bypass.

## Design
Strengthen the audit's lightweight MoonBit control-flow analysis at the
validation statement boundary. Reject deferred validation and require every
validation catch arm to terminate the path before instantiation. Keep accepting
the facade's structured `ValidationFailed` propagation.

## Acceptance Criteria
- [x] A swallowed validation error fails the audit.
- [x] Deferred validation fails the audit.
- [x] Structured validation-error propagation remains accepted.
- [x] The current repository security audit and Python test suite pass.
