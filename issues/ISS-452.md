## Description

VCode and regalloc independently represent register classes, physical
registers, operand roles, operand constraints, and allocation locations.
`machv_regalloc` must therefore translate every operand read and every
allocation result even though both sides describe the same target-neutral
machine-allocation facts.

ISS-450 prototypes proved that this is not a cosmetic adapter cost. Direct
indexed input repeated the conversion in each allocation phase and regressed
AEGIS-128L regalloc from 32,016 us to 34,267 us after local caching. An event
sink reduced final plan translation but double-wrote decisions through dynamic
callbacks and regressed regalloc from the retained 30,701 us result to 34,772
us. Removing the adapter safely requires one canonical value vocabulary below
both packages.

## Design

Define target-neutral allocation value types in a dependency layer shared by
VCode and regalloc. Keep VCode owner-tagged `Value`, `Block`, and `Instruction`
handles at the IR boundary, but store already-normalized allocation operands
and result locations in canonical dense value types. Model register classes as
target-defined identities rather than baking the current duplicate enum names
into the shared contract.

Migrate one concept at a time with exact allocation/code-vector tests. Delete
the corresponding conversion only after both producers and consumers use the
canonical type. Do not introduce a VCode-to-regalloc dependency, dynamic event
callbacks in allocator hot loops, or a second cached production representation.

## Acceptance Criteria
- [ ] VCode and regalloc use one target-neutral register-class and physical-register representation.
- [ ] Selected VCode stores allocation-ready operand role, timing, constraint, preference, and tie facts without per-phase conversion.
- [ ] Regalloc result locations and VCode allocation locations share one dense value representation; owner-tagged public handles remain validated at API boundaries.
- [ ] `machv_regalloc` no longer maps equivalent allocation enums or records in hot loops.
- [ ] Input and output ownership changes preserve exact allocation decisions, spills, reloads, moves, scratch roles, safepoint roots, frame layout, and generated code.
- [ ] Seven cache-isolated AEGIS-128L runs improve complete regalloc and module compilation without moving cost into target construction or emission.
- [ ] Normal and `MACHV_REGALLOC_VALIDATION=1` native tests, both targets, formatting, warning-73, generated interfaces, and module boundaries pass.
