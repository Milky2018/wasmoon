# ISS-204: Support x64 internal-call extra-results areas

## Description

The production AMD64 JIT rejects a valid internal call when its results exceed the register-return capacity. A function returning nine `i32` values fails with `UnsupportedOperation(message="internal call requires an extra-results area")`, while the interpreter returns all nine values.

This was exposed by the AArch64 result-area regression test added while fixing reversed address/value operands. It is an existing x64 backend gap, not a regression in the AArch64 emitter.

## Design

Implement the extra-results area in the target-owned x64 call ABI rather than deepening the legacy backend. Model result-area allocation, pointer passing, callee stores, caller loads, forwarding, and tail-call constraints through the x64 Target VCode pipeline and its verifier.

## Acceptance Criteria
- [ ] Direct and indirect internal calls support results beyond the x64 register-return capacity.
- [ ] Callees store overflow results through a valid extra-results pointer and callers load them with the correct types and offsets.
- [ ] Tail calls either forward a compatible result area or return a structured validation/lowering error.
- [ ] A JIT/interpreter differential test returns nine `i32` values on AMD64.
- [ ] Mixed integer, floating-point, reference, and vector overflow results have target-owned ABI tests.
- [ ] Ubuntu AMD64 native, WAST, component, and sanitizer gates pass.
