## Description
After `legacy_ir` and `legacy_vcode` were deleted, the remaining incomplete reusable JIT areas are tracked here instead of on the closed cleanup issue. These include full entry/hostcall/interpcall trampoline signature coverage, VMContext ABI layout centralization, remaining native frontend lowering gaps, and restoring unit-level JIT execution coverage without reintroducing private legacy setup.

## Design
Replace each `TODO(ISS-026)` with reusable infrastructure, not Wasmoon-local duplicates. The test harness should be rebuilt around the production Wasmoon JIT path instead of reconstructing JIT state locally: instantiate the same Store/Instance state used by the CLI/WAST path, install hostcall and interpcall dispatchers, and execute exported functions through reusable runtime APIs.

The work must not reintroduce legacy IR/VCode lowering, emit, register allocation, or private runtime setup copies.

## Acceptance Criteria
- [ ] Entry, hostcall, and interpcall trampolines cover V128 values, stack-passed arguments, overflow result areas, and nontrivial immediate/offset encodings.
- [ ] VMContext memory/table/function layout constants are sourced from a reusable embedding ABI instead of duplicated in Wasmoon lowering.
- [ ] Native frontend lowering either supports or explicitly rejects the remaining structured-control-flow and operator cases without falling back to legacy IR/VCode.
- [ ] `compare_jit_interp` can execute production-loaded JIT code without locally duplicating Store/Instance setup.
- [ ] WASI JIT tests can execute production-loaded JIT code with captured stdio and preopens.
- [ ] Unsupported signatures or function bodies use the production interpcall fallback path, not test-only interpreter shortcuts.
- [ ] `moon test --target native --warn-list +73 --diagnostic-limit=200` passes.
