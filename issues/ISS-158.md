## Description
E-graph admission independently asks whether an instruction is pure, while verifier, printer, and lowering each maintain large opcode matches. Shared purity facts should come from one source, but adapter-specific contracts and representations must remain explicit and exhaustive.

## Design
Derive e-graph purity from ISS-155 while retaining the e-graph encoding match in the e-graph adapter. Audit verifier, printer, and MilkIR-MachV lowering for exhaustive built-in opcode dispatch, document the ownership split, and add regression or compilation gates where current wildcard handling could hide a new built-in opcode.

## Acceptance Criteria
- [x] E-graph purity uses the centralized semantic summary.
- [x] E-graph encodability remains local to the e-graph adapter.
- [x] Built-in verifier, printer, and lowering dispatch are exhaustive at opcode-family seams.
- [x] The semantic ownership split and new-opcode checklist are documented.
- [x] Generated interfaces, full native tests, warning checks, and module-boundary audit pass.
