## Description
Full-width and narrow raw-pointer loads and stores are separate top-level opcode variants with host-oriented names. Their verifier, alias, effect, printer, optimizer, builder, and lowering logic is distributed across independent flat matches.

## Design
Introduce a generic `MemoryOp` family beside the existing forms, with explicit access width and extension semantics and no Wasmoon vocabulary. Migrate builders, producers, verification, effect/trap facts, printing, optimization, and lowering end to end before deleting the old variants in the final contract issue. Preserve current effective-address behavior and generated code.

## Acceptance Criteria
- [x] Generic loads and stores use `Opcode::Memory(MemoryOp)` through all core consumers.
- [x] Full-width and narrow access semantics are represented structurally rather than by unrelated top-level variants.
- [x] Alias/effect/trap facts and lowering behavior remain conservative and equivalent.
- [x] Focused memory verifier, optimization, and target-lowering tests pass.
