# ISS-318: Remove the redundant wasmoon_async scheduling layer

## Description
`Milky2018/wasmoon_async` is described as an async runtime, but it contains no
MoonBit async functions or continuation machinery. In production it only
forwards native reactor readiness through task IDs, operation IDs, a ready
queue, and a second readiness map before a Preview 3 host future can observe
the event.

## Design
Delete the standalone module. Make each opaque native registration own a
`Pending`, `Ready`, or `Cancelled` state and let Preview 3 host futures observe
that state directly. Keep Component Async semantics in `component/runtime_impl`,
kernel readiness in `async_native`, and native guest suspension in
`wasmoon_jit`. Retain monotonic reactor tokens so cancelled registrations
cannot receive stale kernel events.

## Acceptance Criteria
- [x] `Milky2018/wasmoon_async` and all workspace/package dependencies on it are removed.
- [x] Native registrations expose direct readiness and idempotent cancellation.
- [x] Preview 3 timers and descriptor operations no longer maintain task IDs or a parallel readiness map.
- [x] Reactor, WASI component, and complete native test suites pass.
- [x] Architecture and module documentation describe the simplified ownership seam.
