## Description
The regression matrix is strong for fixed corpora, but generation, independent
semantic comparison, and long-lived lifecycle stress are not continuous gates.
Existing `component_fuzz.py`, `component_differential.py`, and component stress
tools are manual diagnostics. Mutation fuzzing checks process/error-envelope
health without independently checking validation acceptance. Generated component
arithmetic currently uses only i32 add/sub/mul/xor with a small number of shapes.

The newly reproduced unreachable-root retention in ISS-624 illustrates why
correct outputs and terminal leak checks alone miss operational memory growth.
Expand defect discovery across the runtime rather than adding only that fixture.

## Scope and Evidence
- Cover Core/Component decoding and validation, optimizer/codegen equivalence,
  interpreter/JIT semantics, host resource state transitions, and repeated
  success/trap/cancel/rollback/release sequences.
- Preserve existing conformance suites, allocation-failure injection, capability
  race tests, and sanitizer detection controls. A selected sanitizer closure
  cannot establish coverage for excluded paths or emitted JIT instructions.
- See [the current hardening evidence boundary](../docs/component-security.md)
  and the reproducible cases in ISS-624/ISS-625.

## Design
Use established generators/oracles where suitable and add bounded deterministic
smoke campaigns plus explicit broader scheduled campaigns. Independently check
input validity and successful behavior. Retain exact seeds, minimized inputs,
tool/source versions, process outcomes, and the first diagnostic failure.
Logical resource baselines need direct checks in addition to native sanitizers.

## Acceptance Criteria
- [ ] Record a discovery/coverage matrix and the supported independent oracle for each family; identify untested families explicitly.
- [ ] Generation exercises meaningful control flow, references/GC, memory/tables, canonical ABI, and lifecycle sequences beyond the current scalar arithmetic shapes.
- [ ] Validation disagreement, wrong results, trap differences, signals, timeout, resource growth, and harness failure remain distinct failures; matching failures do not count as semantic agreement.
- [ ] A bounded PR smoke lane and a documented scheduled broader lane run reproducibly, preserve failures, and have explicit time/resource limits.
- [ ] Known defects or deliberately injected controls demonstrate detection; repeated live-Store operations verify reclamation without relying only on shutdown.
- [ ] Keep public-behavior regressions for minimized discoveries, document instrumented/excluded paths, and avoid textual audits or test-count assertions as behavioral proof.
