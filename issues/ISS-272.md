# ISS-272: Establish typed component host-instance registration

## Description
The Component Model linker can accept a fully constructed
`ComponentInstance`, but callers must currently populate all runtime-internal
arrays and maps themselves. There is no supported way for a product host to
define typed functions and resource types while sharing one resource table,
stream table, and async state across imported interface instances.

## Design
Add a narrow `HostInstanceBuilder` to the generic component runtime. It owns no
WASI policy. It creates function and type exports, allocates stable host
resource identities through the linker, and finishes an instance that shares
an explicitly supplied host runtime state.

Add a Wasmoon-owned `WasiComponentCtx` and linker-registration object that owns
the shared state and capability configuration consumed by all Preview 2/3
interfaces.

## Acceptance Criteria
- [x] Hosts can define exact component function signatures without constructing
      `ComponentInstance` internals directly.
- [x] Multiple host interface instances can share one resource and async state.
- [x] Host resource type identities are stable and usable by equality-bounded
      imports.
- [x] Invalid duplicate exports and invalid type references fail structurally.
- [x] Black-box linker tests cover functions, resources, and shared tables.
