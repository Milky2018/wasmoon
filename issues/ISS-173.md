# ISS-173: Preserve table index width in indirect-call address lowering

## Metadata

## Description
The Wasm indirect-call lowering paths accept a MilkIR table index value but always calculate the table-entry address with MachV `AddExtend(Uxtw, 4)`. `Uxtw` explicitly reads and zero-extends the low 32 bits, so the emitted address calculation does not preserve an i64 table64 index. The current `call_indirect64.wast` fixture uses index zero and therefore cannot expose this separate lowering-width debt.

## Design
Select address arithmetic from the MilkIR index type: preserve the existing zero-extended 32-bit form for table32, and use a full-width i64 shift/add form for table64. Apply the same rule to `call_indirect` and `return_call_indirect`. Keep this separate from ISS-172, which only repairs the schema regression preventing legal table64 IR from reaching lowering.

## Acceptance Criteria
- [x] Table32 indirect calls zero-extend i32 indices before scaling.
- [x] Table64 indirect calls preserve all 64 index bits before scaling.
- [x] `call_indirect` and `return_call_indirect` share the same width-aware address calculation.
- [x] Lowering tests inspect the generated MachV shape for both index widths without requiring an impractically large table allocation.
- [x] Relevant all-target tests and native JIT regressions pass.

## Notes
- 2026-07-14: Discovered while verifying that loosening the schema was sufficient for the reported index-zero regression. The original WAST passes after ISS-172, but both lowering sites still contain `AddExtend(Uxtw, 4)`.
- 2026-07-14: Implementation started on PR #430. The regression seam lowers public Wasm dialect builders through `lower_function` and snapshots complete MachV output for both index widths and both indirect-call forms.

## Close Notes
- Added one private table-entry address helper shared by `call_indirect` and `return_call_indirect`. It emits `AddExtend(Uxtw, 4)` for an I32 index and `AddShifted(Lsl, 4)` for an I64 index, preserving the full table64 carrier while retaining table32 zero-extension.
- Added complete MachV printer snapshots for table32 and table64 variants of both indirect-call forms. The table64 `call_indirect` test first failed with the exact `add.uxtw #4` versus `add.lsl #4` mismatch before the implementation changed.
