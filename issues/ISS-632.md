# ISS-632: Measure and reduce transient allocation in streaming HTTP processing

## Description
Streaming protocol processing can create transient allocations and repeated
async/trait calls for very small fragments. `wasi_http/wire.mbt::HttpInput::line`
reads one byte at a time; `HttpInput::read` copies each returned buffer slice
into owned Bytes. The parser therefore creates a small Bytes value for each
syntax byte even when the underlying read already buffered up to 64 KiB.

This is a concrete implementation pattern and a performance hypothesis, not a
measured throughput defect. Investigate the wider fragment/copy/representation
class before choosing a rewrite.

## Scope and Evidence
- Review line/header/chunk parsing, buffer compaction, HTTP fields, byte/value
  stream conversion, body handoff, trailers, and output assembly.
- Distinguish necessary ownership copies from per-fragment overhead. Existing
  bounded buffering, backpressure, original byte spelling, and cancellation are
  correctness requirements.

## Design
Measure allocation count/bytes, CPU work, and end-to-end behavior on small,
large-header, fragmented, streaming, and concurrent workloads. Retain changes
only when reproducible measurements justify them. Prefer scanning existing
buffer windows and batching justified conversions, while continuing the current
protocol implementation and async I/O ecosystem.

## Acceptance Criteria
- [ ] Record allocation/CPU profiles across the listed processing families and classify the suspected overheads with representative independent workload shapes.
- [ ] Compare paired baseline/candidate measurements with pinned inputs and binaries; report cold compilation separately from steady transport costs.
- [ ] Any retained optimization reduces meaningful measured cost without a material end-to-end regression; negative experiments are reverted and documented.
- [ ] Fragmented CRLF/headers/chunks, limit boundaries, malformed framing, timeouts, cancellation, trailers, and backpressure retain observable behavior.
- [ ] Buffer occupancy remains bounded and borrowed slices do not outlive their owner or change after compaction.
- [ ] Both-engine HTTP integration and supported platform gates pass. A justified no-change conclusion may close the issue only with the reviewed scope and measurements recorded.
