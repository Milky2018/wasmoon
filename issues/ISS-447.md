## Description

ISS-441 measured 5,402 us constructing semantic MachV, followed by 3,154 us
verifying cleanup input and 2,999 us verifying cleanup output on AEGIS-128L.
The production lowerer owns the builder and has already validated MilkIR, but
`FunctionBuilder::finish` discards construction evidence and treats the result
like arbitrary mutable MachV.

## Design

Split semantic construction into explicit unsealed and sealed states. The
builder should enforce owner, definition, block, terminator, and type contracts
as mutations occur. Mandatory alias canonicalization and dead-instruction
removal should consume the unsealed state once and return an opaque verified
function, validating only global properties that cannot be maintained
incrementally.

Keep `Function::verify` and validating cleanup entry points for externally
constructed or transformed MachV. Do not remove semantic MachV, merge Wasmoon
policy into target modules, or replace validation with an unchecked boolean.

## Acceptance Criteria
- [x] Production MilkIR-to-MachV composition performs no redundant full input verification before mandatory cleanup.
- [x] Sealing validates each local invariant once and returns an opaque verified semantic function.
- [x] External transformations retain a complete verifying cleanup path and typed diagnostics.
- [x] Alias rewrite, dead-instruction behavior, GC roots, stack maps, and target artifacts remain unchanged.
- [x] Seven cache-isolated AEGIS-128L captures materially reduce the combined 6,153 us cleanup-verifier baseline without shifting work into construction.
- [x] Semantic lowering, both targets, strict native validation, formatting, warning-73, generated interfaces, and module boundaries pass.

## Notes

- A direct attempt to skip input verification for every `FunctionBuilder`
  correctly failed existing white-box regressions: cleanup can canonicalize a
  cross-branch non-dominating alias and deduplicate illegal GC roots before the
  output verifier sees them. The optimized path therefore needs a capability
  specific to lowering from already verified MilkIR; the general builder must
  retain defensive input verification.
- The final design instead makes the general builder genuinely checked: local
  contracts, duplicate roots, and stack-map density are established during
  mutation; sealing checks only completion, CFG reachability, dominance, and
  exact GC roots. Cleanup transformations preserve that proof and publish a
  `SealOutput` event instead of running or claiming a second verifier.
- Seven final AEGIS captures measured 976 us median input sealing and 7 us
  output sealing, down 84.02 percent from the 6,153 us combined verifier
  baseline. Construction rose only 57 us to 5,459 us, and semantic lowering
  fell to 12,603 us. The artifact remained byte-identical with SHA-256
  `0c31ca17b8f04e9ecd0022eb185d367d7027d197ba83f87cd762a8e2f4639840`.

## Close Notes

Closed with mutation-time local checks, one bounded global construction seal,
