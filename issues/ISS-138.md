# ISS-138: Consume Wasm SIMD memory arguments before MilkIR core

## Description
Wasm SIMD memory instructions retain `(memidx, align, offset)` inside MilkIR even after the frontend has selected the memory, performed bounds handling, and computed an effective address. Generic lowering ignores the memory index and alignment and treats the offset as already folded into the address. These redundant fields affect printing and instruction identity without affecting machine semantics.

## Design
Consume `memidx`, alignment hints, and Wasm offsets at the frontend/dialect seam. Emit vector memory operations whose operands and generic immediates fully determine core semantics. Alignment may be discarded deliberately or mapped to a documented generic memory flag; source memory indices must never enter core MilkIR.

## Acceptance Criteria
- [x] Core vector memory operations contain no Wasm memory index.
- [x] Wasm offsets are represented exactly once in the checked effective address.
- [x] Alignment handling is explicit: frontend hints do not survive into core operations that cannot consume them.
- [x] Printed frontend MilkIR contains no Wasm mem metadata for vector memory operations.
- [x] SIMD JIT/interpreter differential tests remain green.
