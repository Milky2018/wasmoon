## Description
Component instantiation binds runtime state and recompiles core code together.
The HTTP CLI creates a fresh native session per connection, so repeated requests
to the same service repeatedly translate, optimize, compile, and install its
core modules. Fresh instance state is required by the current service contract;
its lifetime should be distinct from reusable immutable compiled code.

At `25381fc7`, `commands/component/serve.mbt` creates the session inside the
connection handler. `component_native/engine.mbt` registers each instance through
`load_component_jit_context`, which calls `compile_component_artifact`. No
cross-connection compiled-artifact reuse is present in this path.

## Scope and Evidence
- Review repeated HTTP connections, middleware layers, repeated component
  instantiation, and multiple instances/Stores that use equivalent core modules.
- Separate immutable code and metadata from instance memory/globals/tables,
  import binding, mutable VMContext, task state, and installation ownership.
- Alias rewrites and imported-memory limits can affect emitted code; equivalence
  must be established rather than assumed from input file names.

## Design
Prepare compatible compiled artifacts independently of fresh instance state and
bind them through explicit retained owners. Define identity from the actual
lowered module, compilation policy, target/ABI/features, and context shape.
Bound retained storage and preserve transactional installation and teardown.
Investigate code-object reuse separately from address-bound executable reuse.

## Acceptance Criteria
- [x] Record which artifact/code/metadata portions can be shared and the exact conditions preventing reuse, including instance-dependent alias mappings.
- [x] Equivalent repeated instantiations reuse preparation/compilation with observable compile-count or phase evidence; changed policy or incompatible bindings invalidate reuse.
- [x] Instances keep independent mutable state, resource identities, cancellation, traps, and GC roots; closing one instance cannot invalidate another's code.
- [x] Retained compiled storage has an explicit owner and bounded release/eviction behavior, tested across failed installation, cancellation, and terminal close.
- [ ] Measure cold preparation and repeated-request/instantiation costs on representative services; report throughput and allocation results separately from guest execution.
- [ ] Both-engine functional behavior, native lifetime/sanitizer cases, external component/HTTP suites, and cross-platform CI pass.

  middleware before binding. No guest start, executable allocation, Store or
