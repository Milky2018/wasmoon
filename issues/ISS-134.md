## Description
MilkIR verification currently accepts legacy `Load` and `Store`, duplicate `IcmpEq`, instruction-form `Trap`, and core `CallIndirect`, while generic lowering rejects them. `StackAddr` is publicly constructible and tested only to confirm that lowering rejects it. `Custom(String, Signature)` is an untyped escape hatch duplicated by the stronger dialect extension mechanism and is used mainly as a test fixture. These operations make successful core verification weaker than the actual lowering contract.

## Design
Use existing verifier/lowering contract regressions and compile-time interface checks to establish that every remaining core opcode has a supported semantic path. Replace test-only `Custom`, instruction-trap, and indirect-call uses with real supported operations where the behavior remains meaningful; remove tests whose input ceases to be valid core IR. Remove legacy `Load`/`Store`, duplicate `IcmpEq`, and the unused stack-slot surface. Do not add fallback lowering.

## Acceptance Criteria
- [x] `Custom`, legacy `Load`/`Store`, duplicate `IcmpEq`, instruction `Trap`, core `CallIndirect`, and unsupported `StackAddr` are absent from the public MilkIR interface.
- [x] Test fixtures use operations with real verifier and effect contracts.
- [x] Apart from explicitly dialect-owned `Ext`, no verifier branch accepts an operation that generic lowering unconditionally rejects.
- [x] Generated interfaces and focused MilkIR/MachV tests pass.
