## Description
Strict WAST assertions expose collapsed and inconsistent trap codes. Both emitters encode table bounds as memory bounds and null/alignment/stack failures as backend traps. Native GC helpers additionally use stack-exhaustion codes for null references and memory-bounds codes for array bounds. Interpreter ref.cast and call_ref use unrelated generic errors. Preserve precise trap reasons end to end and correct numeric-conversion failure classification.

## Acceptance Criteria
- [x] Distinct native trap encodings, C signal decoding, helper codes, and user-visible diagnostics agree.
- [x] Interpreter errors identify cast failure, null references, and indirect-call bounds correctly.
- [x] All previously passing core spec and misc cases pass with strict trap/exception assertions, without changing upstream expectations.
- [x] Focused category regressions, native checks, and both engine corpus runs pass.

- Introduced target-independent native trap payloads, one C decoder shared by all signal-handler platforms, and explicit runtime codes for table/array bounds, null references, cast failures, and alignment.
- Numeric conversion checks now distinguish NaN from integer overflow in emitted instructions and metadata. Native artifact ABI advances from 4 to 5 so cached artifacts with collapsed trap encodings are rejected.
- Fixed array segment empty-source handling, allocation-size errors, and overflow-safe bounds checks. Fixed atomic address overflow classification and explicit notify bounds checks, plus non-shared wait traps. Imported memory metadata now preserves index order and sharing.
- The first complete strict core spec run passed all 258 files / 62,563 assertions per engine. The following misc sweep exposed 15 additional cases requiring canonical table-bound diagnostics, allocation-size errors, atomic address checks, and acceptance of stack exhaustion in assert_trap (as in the pinned Wasmtime adapter). The final complete sweep restores all 498 passing cases; its per-case statuses exactly match the pre-strict baseline (112 thread/stack-switching failures, 66 script-only, 72 unsupported, 16 deferred, zero timeout/harness errors).
- An isolated AddressSanitizer CLI build, using a private SDK copy with the system allocator, passed four local runtime fixtures on both engines (eight runs). Apple Clang ASan was enabled; leak detection was disabled because it is unavailable with that runtime. The final private SDK build uses ASan with the system allocator and -O0. All five local runtime fixtures and three oversized-array misc fixtures pass on both engines (16 runs), with no ASan diagnostics. Leak detection remains disabled.
