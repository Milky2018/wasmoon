## Description
The previously corrected trap-on-reenter script still assumes a yielded parent callback prevents a child from calling the parent. The pinned Wasmtime 50 oracle instead executes the callee and traps at its unreachable instruction. Separate host-call admission from nested execution, continuation resumption, and synchronous wait ownership.

## Acceptance Criteria
- [x] Yielded and synchronous reentry controls, plus trap-poisoning controls, agree with the pinned oracle.
- [x] Nested activity gates async scheduling; shared trap state rejects new host calls while admitted continuations and their guest calls may resume.
- [x] The reviewed fixture correction and component suites pass on both engines.

## Close Notes

- Independent controls pass Wasmtime 50: a yielded parent callback observes the child call completing; active synchronous recursion traps before executing its unreachable callee. Before the fix, Wasmoon fails only the positive control (`/tmp/iss490-red.log`). Removed ancestry-based gates while retaining ComponentInstanceEntryState and sync-wait ownership.

- Correction to the preliminary control report: the initial combined oracle command was not fully read before interpreting it. Its synchronous reentry negative assertion actually fails on Wasmtime 50, independently of stackful/threading flags. The corrected fixture expects synchronous reentry to execute, and uses trap poisoning as the negative control. The pre-fix runtime fails both positive entry cases; the poison case passes.
- A further independent case traps one child component then calls its sibling. Wasmtime rejects the sibling; Wasmoon incorrectly succeeds (`/tmp/iss490-poison-red.log`). Entry poison must therefore be shared by every instance owned by a linker/store.
- Replaced the active boolean with nested depth, retained async admission checks, and removed cancellation's extra release of an already suspended activation. White-box coverage verifies that cancelling a parked call cannot decrement another call's active depth.

- A negative control for over-poisoning returns malformed UTF-16 then invokes another export. Both the pinned WAST oracle and Wasmoon allow the later call: result decoding failure is not a core trap in this lane. Keep poison propagation at the core execution trap boundary rather than marking every component API error as a trap.

- The final runtime uses nested execution depth for async admission, permits synchronous reentry, and shares core-trap poison across a linker's instances. The original correction and all local controls pass the matching oracle. Component verification passes after ISS-491's store isolation and nominal resource reflection; native validation remains pending.

- The full native regression exposed an overly broad poison check on resuming an already admitted task. A matching-revision Rust embedding probe starts two calls in one Store, traps the second at invalid handle 42, then drives the first again. Wasmtime executes its nested child and reports unreachable, while a new host call is rejected (`/tmp/iss490-poison-rust-nested-result.log`, exit 0). Moving poison admission to both public host-call entry points preserves this distinction; shared AsyncState owns the trap bit, and per-instance depth only tracks execution. The expanded public API regression covers both engines and both new-call entry points; all 21 component_native tests pass.

- Final verification after splitting host admission from continuation execution: 2,358 native tests pass (`/tmp/iss490-admission-full-native.log`); local 119, stable 845, async 153 and future-gated 387 commands pass per engine; component misc has 184 passes, zero failures/timeouts/harness errors, eight unchanged unsupported and four deferred cases (`tmp/iss490-admission-misc/summary.json`).
