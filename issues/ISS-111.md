## Description
Production JIT compilation imports `wasm_frontend/ir` directly, while the top-level `wasm_frontend` API exposes a separate limited linear lowering path. The split makes the public package look canonical even though production bypasses it.

## Design
Extract embedding configuration types into a dependency-neutral frontend subpackage so the complete translator no longer imports the top-level facade. Expose the production translation context and function-body lowering through the top-level `wasm_frontend` package, then remove direct `wasm_frontend/ir` imports from product call sites. Reuse the existing production translator instead of rewriting structured-control lowering.

## Acceptance Criteria
- [x] Product code imports the top-level `wasm_frontend` package rather than `wasm_frontend/ir`.
- [x] The top-level frontend can lower structured control flow through the production translator.
- [x] Existing embedding-environment callers remain source compatible.
- [x] Frontend, preflight, explore, and JIT compilation tests pass.
- [x] Reusable module dependency direction remains clean.
