## Description

The AEGIS hot function materializes shift constants, uses register shifts, and
emits a separate negate for every constant rotate-left. It also retains separate
left shifts before additions that AArch64 can encode as shifted operands.

## Design

Add closed Target VCode forms for immediate LSL/LSR/ASR/ROR and the required
shifted integer operands. Select them from single-use semantic definitions while
preserving value width, modulo shift semantics, source metadata, and regalloc
constraints. Do not add an untyped catch-all target instruction.

## Acceptance Criteria

- [x] Constant LSL, LSR, ASR, ROR, and rotate-left lower without a materialized
      shift register.
- [x] Eligible add/index expressions fold a left shift into the consuming
      AArch64 instruction.
- [x] Exact encoding tests cover W32/W64 boundaries and malformed target forms.
- [x] AEGIS `func_30` removes the demonstrated redundant shift sequences without
      increasing spills or reloads.
- [x] Recursive JIT WAST tests remain green.

## Close Notes

AEGIS `func_30` now has 40 immediate shift/rotate instructions and 16
shifted-left adds, with none of the previous 56 register shift/rotate
sequences. Spill/reload counts fell from `17/22` to `10/14`, stack slots fell
from `19` to `12`, and code size fell from `1568` to `1372` bytes.

A three-pair cache-isolated benchmark improved the median Wasmoon/Wasmtime value
ratio from `1.270317` to `1.215873` and wall ratio from `1.264638` to
`1.211529`. `moon test --target native --warn-list +73` passed `2305/2305`;
recursive interpreter and JIT WAST both passed `258/258` files and `62563`
assertions.
