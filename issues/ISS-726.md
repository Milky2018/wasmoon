## Description
The accepted ee89e73c product still takes 206.405 seconds for the original
8,384-test serial suite versus 18.600 seconds for official SDK28 V8. The last
guarded-access and sparse-frame change improves the paired complete suite only
2.04%. Local fast paths have not resolved the combined object representation,
effect-proof, precise-root and cold-compilation costs.

## Design
Establish a source-matched phase baseline, then integrate explicit call effects,
checked logical accesses and explicit collecting-edge root requirements through the existing
reusable compiler interfaces. Preserve stable public references and every root,
barrier, address epoch, trap, quota, fault, rollback, cancellation, fuel, quantum,
reentry, exception and parked-stack lifetime contract. Replace obsolete paths
when their replacement is verified; do not accumulate speculative fast paths.
Measure compiler and execution effects independently and confirm with the
unchanged complete-suite driver. Keep platform and independent verifier gates.

## Acceptance Criteria
- [x] Capture mutually exclusive compiler, installation and execution phases on the exact parent and retain original inputs and assertions.
- [x] Derive and independently validate transitive call effects; unknown or mutable targets retain conservative behavior.
- [x] Carry checked logical accesses separately from physical address lifetimes across supported calls and control flow.
- [x] Separate observability from collecting-edge root requirements, preserving complete active and parked roots; reject final-machine-home protocols without independent measured gains.
- [x] Reject forged call effects and stale addresses, and demonstrate that intentionally omitting a live root fails reclamation assertions.
- [ ] Pass strict native/Wasm checks, full ordinary and verified native tests, integrations, clean sanitizers and all exact-head platform checks.
- [x] Retain independent cold measurements, including regressions, and establish a material complete-suite gain.
- [ ] Push focused functional commits to PR582, record final source identities and limitations, and clean owned temporary files.

## Notes
- The fresh parent diagnostic splits 101.759 seconds in compilation and 102.297
  seconds in start/tests across the original 157 invocations. This single
  capture is phase attribution, not a paired gain estimate.
- All three machine-location prototypes fail their declared hot-performance
  criterion, including the version retaining small scoped frames and publishing
  one map pointer at calls. Their uncommitted protocol was removed; the retained
  architecture gives the native adapter an explicit validated root-site contract.
- A mapped execution sample identifies closure-field reads and a read of field
  eight in a 27-field decoder. Logical callable/opaque carriers and the complete
  physical-prefix proof are now handled explicitly. A private matched run
  changes only projection selection, admitting small acyclic getters called
  by outer loops. All 32 original flate processes preserve their outputs;
  median paired wall reductions are 5.63% blackbox and 4.55% whitebox.
- The immediate-parent fast path must bound both canonical identities. A
  warmed view admitted an invalid rebound type before this fix; the same
  regression traps on both missing and out-of-range identities after it.
- All 3,277 native tests pass with and without the three independent runtime
  and allocator checks. All 1,535 Wasm tests pass. Both engines pass 62,563 Core
  assertions and 1,385 Component commands under those checks.
- The initial frozen refactor fails the complete-suite performance criterion.
  Three rotating SDK28 V8/parent/refactor rounds each pass all 8,384 original
  synchronous tests. The paired wall changes are -3.15%, +0.85% and -0.08%; the
  median refactor/V8 wall ratio is 10.99×.
- Twelve phase pairs preserve the original 4,055 selected tests. Compilation
  rises by 4.60% across eight compile-heavy children; execution falls by 7.97%
  across four execution-heavy children. See
  [the phase comparison](../docs/perf/checked-call-access-contracts.md#complete-serial-core-comparison).
- The final candidate separates ordinary view admission from the mutable
  allocation fault control. Twelve isolated child pairs pass with identical
  output. The final complete comparison preserves all 157 input hashes and
  selections and all 8,384 tests in each arm. Its paired wall changes are
  -3.23%, -5.11% and -0.05%, with a median candidate/V8 ratio of 10.67×.
  The final source also passes 3,278 native tests in both validation modes,
  1,535 Wasm tests and the complete Core and Component integrations.
- In the original flate whitebox fill loop, the field-eight projection passed
  the inlining filter after the eight struct slots had been spent. Native
  lowering now reserves one of those slots for a reference-field read in the
  smallest eligible loop. Every access uses the existing checked view or the
  complete helper. Full polls and address-epoch checks still apply.
- Four alternating cold Wasmoon pairs per flate fixture preserved the original
  Wasm inputs and all 80 whitebox and 13 blackbox tests. Whitebox compilation
  and execution medians were 1.068/21.139 seconds before and 1.031/20.198 after.
  Paired median execution fell 4.58% for whitebox and 0.25% for blackbox. Two
  cold reference runs per fixture used serial Wasmtime 48.0.1 and eager V8.
  Their whitebox compile/execute medians were 0.707/17.684 and 0.379/3.281
  seconds respectively. These measurements cover the flate fixtures.
- The final AArch64 artifact branches around `gc_struct_data_impl` on the
  fill loop's checked view hit. Misses reach the original call, and the loop
  still reaches the cancellation poll. The function shrank from 8,880 to
  8,832 bytes with the same 400-byte frame. The final worktree passes strict
  native and Wasm checks, 3,282 native tests in each validation mode, and
  1,537 Wasm tests.
