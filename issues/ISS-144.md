# ISS-144: Remove residual opcode compatibility APIs

## Metadata
- Type: task
- Status: closed
- Priority: 1
- Labels: milkir, memory, call, api, cleanup, agent
- Assignee: codex
- Created: 2026-07-12
- Updated: 2026-07-12

## Description
After scalar and vector contraction, raw-pointer memory variants and compatibility call helpers can still bypass MemoryOp and CallOp.

## Design
Migrate any remaining producers and consumers, remove legacy raw-pointer Opcode forms, remove the old call_ptr wrapper and temporary instruction-rewrite helpers, and leave Opcode with only approved semantic families plus Ext.

## Acceptance Criteria
- [x] Opcode exposes only Scalar, Memory, Call, Vector, and Ext.
- [x] No legacy raw-pointer memory Opcode variant remains.
- [x] No legacy call_ptr compatibility builder remains.
- [x] No temporary canonicalize, with_opcode, or legacy-consumer helper remains.
- [x] Native checks and targeted trampoline tests pass.
