# ISS-514: Preserve native guest stacks across atomic waits and scheduling yields

## Description
Lower JIT atomic wait/notify to the checked native queue instead of synthetic results. Suspend only native guest activations after any MoonBit callback has returned. Preserve typed suspension reasons through the native execution layers, and reclaim pending wait registrations before destroying parked stacks. Enable scheduling only for artifacts containing safepoints.

## Acceptance Criteria
- [x] JIT waits are notified by independent native and interpreter participants.
- [x] Long native guest loops yield and resume without replaying completed work.
- [x] Cancelling parked native waits releases registrations and shared-memory leases.
- [x] Parked GC references remain live across collection.
- [x] Native, ASan and external regressions pass; stale synthetic-wait artifacts are rejected.

## Close Notes

- Native wait/notify helpers use the shared checked-address queue. Parked fibers own wait registrations and destroy them before releasing their stack. Guest scheduling yields run only after cancellation callbacks return, preserving the native-only parked stack boundary.
- Native suspension reasons (hostcall, cooperative yield, atomic wait) now propagate through all core adapters. Scheduling requires an instrumented artifact; codegen revision direct-vcode-4 rejects prior synthetic-wait artifacts without changing the artifact format or fixed JIT ABI.
- Validation: 2422 native tests, 41 JIT-focused ASan tests and module-boundary audit pass. Regressions cover parked GC references, interpreter/native notification, exact memory-owner counts, parked cancellation and controlled cancellation of an indefinitely blocked wait.
- Fresh-CLI external gates all preserve their baseline: all core/runtime/component/P1 lanes pass; misc is 582 pass, 70 script-only, 112 known thread/typed-continuation failures, zero unsupported/timeout/deferred/harness errors (`tmp/iss514-all-misc/summary.json`).
