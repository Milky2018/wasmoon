# ISS-635: Make MoonBit own native runtime policy and lifecycle

## Description
Resolve the mechanisms that force native runtime policy into C: JIT helper ABI, synchronous callback return before control transfer, raw storage ownership, tracing across heaps and private C layout exposure.

## Design
Start from complete executable paths and explicit ownership. Reuse the existing hostcall and root-visitor conventions; preserve machine layout and direct access where required. Move decisions with their state and delete old implementations. Do not equate wrapping C in more FFI functions with migration, or claim the complete architecture is repaired after one slice.

## Acceptance Criteria
- [x] Publish the concrete call/state/ownership inventory and justify each retained native mechanism.
- [x] Complete GC slow-path policy migration with one implementation and no duplicated native retry decisions (ISS-636).
- [x] Complete native exception logical-state ownership migration while preserving guest identity and root retention (ISS-637).
- [x] Complete continuation logical-state and cancellation ownership migration while retaining stack primitives (ISS-638).
- [x] Keep private native layouts with their implementation owner and remove cross-package test allocations of those layouts (ISS-639).
- [ ] Validate failures, reentry, cancellation, GC roots, both engines, sanitizers, platform behavior and measured performance; retain explicit limitations.
