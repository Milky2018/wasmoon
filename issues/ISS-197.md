## Description

Create the typed target VCode, allocation, operand-side-table, register-allocation adapter, and verifier boundaries that both AArch64 and x64 will use, without switching either production target.

## Design

- Target VCode is selected, target-specific code before allocation; Allocation remains separate data.
- Stable instruction handles and program points survive layout and allocation.
- Operand constraints, clobbers, fixed and tied operands, edge moves, stack slots, and safepoints are explicit side data rather than encoded by mutable opcode conventions.
- Target packages share interfaces and invariants, not a union of target opcodes.

## Acceptance Criteria

- [ ] AArch64 and x64 VCode instruction types are statically distinct and cannot be mixed.
- [ ] Stable instruction handles and program points remain valid across layout, allocation, spill insertion, and metadata production.
- [ ] Allocation is represented separately from target VCode and can be verified against operand constraints.
- [ ] The regalloc adapter and checker cover fixed, tied, clobbered, spill, reload, edge-move, stack-slot, and safepoint cases.
- [ ] Verifier checkpoints exist for selected VCode, allocated VCode, frame planning, and final emission input.
- [ ] Neither production target is switched by this issue.
- [ ] The common ISS-192 quality gates pass.
