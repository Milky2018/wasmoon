# ISS-032: Model stack arguments and multi-value return areas in MachV ABI

## Description
Trampoline ABI completion is blocked by missing target-independent machine ABI concepts. `x64_target` and `aarch64_target` currently leave stack-passed entry parameters, outgoing stack arguments, and overflow multi-value return areas as target-local TODOs because MachV has no IR-level way to represent those locations and effects.

## Design
Add explicit MachV ABI modeling for incoming stack argument slots, outgoing stack argument materialization, and multi-value return areas. ISA targets should lower MilkIR calls and function entries through that model instead of silently dropping overflow operands. `wasmoon_jit` trampolines can then consume the shared ABI model rather than reimplementing per-target calling conventions.

## Acceptance Criteria
- [x] MachV can represent incoming function stack argument slots.
- [x] MachV can represent outgoing stack arguments for direct and indirect calls.
- [x] MachV can represent overflow result areas for Wasm multi-value returns.
- [ ] `x64_target` and `aarch64_target` lower overflow arguments/results without TODO-only paths.
- [ ] Trampoline generation in `wasmoon_jit` uses the shared model for stack-passed arguments and overflow result areas.
- [ ] Focused target, emitter, and trampoline tests cover signatures that exceed register-only ABI limits.
- [x] `moon check --target native --warn-list +73 --diagnostic-limit=200` passes.
