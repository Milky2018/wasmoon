## Description
A diagnostic 8 MiB allocation allowance makes the current asserted parse-double
fixture stop with `gc precise roots unavailable`. Both full-only and young
collection reject the graph at collection 90. The production 64 MiB allowance
passes, but changing collection frequency must not expose an invalid root path.
Do not suppress incomplete-root rejection or select a larger allowance to hide it.

## Notes
- 2026-10-25: The same temporary diagnostic binary, unchanged guest and cold
  caches reject full-only at cycle90/minors0 and young at cycle90/minors84.
  Barrier assertions alone do not change the failure. A separate full-GC
  verification run exceeded the diagnostic 180-second watchdog; it establishes
  neither success nor a new correctness failure. Sources are restored after
  instrumentation, and raw logs stay in auto-cleaned temporary storage.

- 2026-10-25: The first staged root is numeric f64 payload0x12869794a160cb58,
  which aliases the exception tag. Allocation operand descriptors cover payload
  words, including numbers. Collection now uses the immutable canonical layout
  to replace only known numeric operands with null during root materialization;
  genuine reference fields and unknown embedding layouts retain their contracts.
  No allocation-path copying, extra native allocation, guest ABI/cache change or
  relaxed exception decoder is introduced.
- 2026-10-25: Two public fault-induced regressions first fail with the same trap:
  scalar struct/repeated/fixed array numeric tag aliases, and a mixed numeric/
  actual-child struct. Both now pass ordinarily and with all three verifiers,
  across O0/O2/O3; interpreter controls preserve payload bits. The complete
  diagnostic8MiB parse-double fixture now returns1 under both full-only and young
  collection. Full current-head acceptance remains pending.
