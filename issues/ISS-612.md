## Description
Native contexts still calloc/free their function-address table. Move typed table construction to MoonBit while preserving the generated-code pointer-array ABI and raw C context allocation compatibility.

## Design
Use a private external FunctionAddress type: entries are borrowed executable addresses, not RC-managed objects. MoonBit builds the FixedArray and transfers ownership to native context allocation. Context finalization decrefs the array, never its addresses. Raw C allocation uses the same MoonBit external-pointer array representation. Preserve zero/negative count behavior and retain existing executable-code owners.

## Acceptance Criteria
- [x] Typed MoonBit setup and raw C allocation use one array ownership contract.
- [x] Pointer width/stride and generated offsets remain unchanged.
- [x] Zero counts, negative counts, initialized entries and non-owning executable addresses are covered.
- [x] Strict checks, native tests, sanitizers and external regressions pass.

## Close Notes

Local migration and validation are complete: MoonBit constructs external-pointer arrays, both allocation paths share RC destruction, and function addresses remain non-owning. Context and generated prefix remain 352/128 bytes; nonempty tables add one 8-byte array header on this target. Negative and zero counts plus non-RC address teardown are covered. 2,619 native tests, 73 sanitizer tests and both external suites passed. See `docs/perf/control-diagnosis-2026-09-29.md` for separate poll-fix and table-migration measurements. Cross-platform CI remains pending.

The initial +0.61% GC timing difference was followed by a randomized interleaved 63-pair A/B and A/A check: A/B +0.26% [-0.02%, +0.75%], A/A +0.10% [-0.48%, +0.98%]. The follow-up did not clearly separate the small difference from control variation; both datasets remain in the report.
