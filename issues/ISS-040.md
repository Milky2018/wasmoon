# ISS-040: Move Wasmoon native runtime coupling out of machv_emit

## Description
`machv_emit` is intended to be reusable compiler infrastructure, but it still owns a Wasmoon-specific native runtime seam: `modules/machv_emit/moon.pkg` imports `Milky2018/machv_emit/jit_ffi`, and reusable emitter code resolves Wasmoon runtime helper addresses through `@jit_ffi`/`c_jit_*` functions and helper-index APIs.

This is a real module-boundary leak, not just a naming cleanup. A generic emitter should emit machine code plus relocation/fixup metadata; the Wasmoon JIT integration should decide how those fixups become runtime helper addresses.

## Design
Keep `machv_emit` generic. Move native-stub ownership and Wasmoon runtime-helper address resolution into `wasmoon_jit` or an explicit Wasmoon-owned native runtime package. `machv_emit` may expose symbolic relocations, abstract runtime-call fixups, or a resolver callback, but it must not import or call Wasmoon-specific C FFI directly.

Strengthen the module-boundary audit so future migrations cannot place product-specific native glue back into reusable packages.

## Acceptance Criteria
- [x] `modules/machv_emit/moon.pkg` no longer imports `Milky2018/machv_emit/jit_ffi`.
- [x] Reusable `machv_emit` MoonBit sources contain no `@jit_ffi` references and no `c_jit_` runtime-helper calls.
- [x] Wasmoon-specific native stubs live under `wasmoon_jit` or another explicitly Wasmoon-owned module, not under reusable `machv_emit`.
- [x] `machv_emit` no longer exports Wasmoon runtime address lookup APIs such as `resolve_runtime_func_fixup_idx`; it only emits generic relocation/fixup data or calls a generic resolver supplied by its caller.
- [x] `wasmoon_jit` resolves runtime helper addresses and links generated code through the reusable emitter path.
- [x] `scripts/audit_module_boundaries.py` rejects Wasmoon-specific FFI imports or symbols inside reusable compiler-infrastructure modules.
- [x] Full correctness gates still pass without interpreter fallback or workaround paths.
