# ISS-330: Remove GC frame test counters from release artifacts

## Metadata
- Type: bug
- Status: closed

- Labels: jit, gc, ffi, release, tests, agent
- Assignee: codex
- Created: 2026-07-30
- Updated: 2026-07-30
- External ref: none

## Description
The native JIT updates a process-global `live_gc_frame_count` on every GC frame
push and pop and exports `wasmoon_jit_gc_live_frame_count`. Only a white-box
test consumes this instrumentation, but both symbols are present in the release
`libwasmoon_jit.a`.

## Design
Delete the counter, its internal declaration, and its exported FFI symbol.
Replace the implementation-coupled white-box assertion with public-boundary
continuation lifecycle coverage where observable behavior is available. Do not
retain a test-only hook in production code.

## Acceptance Criteria
- [x] GC frame hot paths do not update a process-global test counter.
- [x] Release `libwasmoon_jit.a` contains no live-frame counter symbol.
- [x] No MoonBit or C API exposes the deleted counter.
- [x] Continuation terminal-path behavior remains covered without the counter.
- [x] Native and isolated sanitizer validation passes.

## Close Notes
- Deleted the process-global counter, its hot-path updates, its internal
  declaration, and the exported C symbol.
- Removed the counter-coupled high-level white-box test. The existing native
  continuation lifecycle suite uses only public APIs, so it is now a black-box
  test file without changing API visibility.
- Added a release archive gate that rejects any reintroduced
  `live_gc_frame_count` symbol.
- Validation: native continuation black-box tests 12/12, release CLI build and
  archive symbol inspection, and an isolated ASan/UBSan build with verified
  instrumentation all passed.
