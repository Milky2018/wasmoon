## Description
Complete native Windows readiness and verify it through the actual interpreter and JIT. The original Windows backend returned `ENOSYS`; the implementation now supports the descriptor kinds documented in [Windows native runtime](../docs/windows.md), and full native runtime acceptance is complete.

The original Windows JIT path only slept for timers and could return success with zero events. An interim explicit host error prevented that silent contract violation; the implemented backend now reports actual descriptor readiness.

## Design
Add a Windows-specific readiness adapter appropriate to each descriptor kind. Do not emulate all descriptors with a single busy loop: console input, regular files, pipes, and Winsock sockets have different readiness primitives. Keep subscription validation, clock handling, event ordering, and ABI encoding in the shared MoonBit implementation.

## Acceptance Criteria
- [x] Windows native stdin, regular-file, pipe, and socket subscriptions have documented readiness behavior.
- [x] Mixed clock/fd subscriptions return when the first event becomes ready and never return success with zero events.
- [x] Interrupt, invalid-descriptor, hangup, and host-error cases map to structured WASIp1 results.
- [x] Windows interpreter and JIT run the same poll conformance tests.
