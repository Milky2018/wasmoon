## Description

The ISS-261 optimization sequence needs reproducible closing evidence. The
initial diagnostic used one isolated sample and observed a guest-value ratio of
1.4589 and wall ratio of 1.5786 against Wasmtime 40.0.0. That sample included a
fresh Wasmoon compilation in the wall measurement and is not statistically
sufficient for acceptance.

Final evidence must connect assembly changes to cached runtime behavior and
must retain enough provenance to reproduce the comparison. Per the explicit
2026-07-24 review decision, this issue records one final measured pair per
workload rather than using repeated samples or statistical acceptance.

## Design

After ISS-262 through ISS-265 close, run all 70 algorithm workloads with an
isolated Wasmoon cache, one warmup, and one measured Wasmoon/Wasmtime pair.
Record tool versions, host identity, commits, cache state, the guest values,
wall times, relevant function code sizes, memory-base loads, and loop stack
traffic. Report each direct pair ratio; do not describe a single observation as
a median or average.

This report is diagnostic acceptance evidence, not a restored CI performance
gate.

## Acceptance Criteria

- [x] One valid pair for each of the 70 workloads completes with no timeout,
      runtime failure, or measured fresh Wasmoon compilation.
- [x] Every direct guest-value and wall ratio is recorded; values above 1.15
      and wall ratios above 1.20 remain explicit residual blockers.
- [x] Final `func_37`, `func_41`, `func_42`, and `func_43` assembly metrics are
      recorded alongside the baseline.
- [x] `moon check --target all --warn-list +73`, native tests, module-boundary
      audit, and recursive interpreter/JIT WAST tests pass.
- [x] Any unmet assembly or performance criterion is filed as a follow-up issue
      before this issue closes.
