## Description

The ISS-261 optimization sequence needs reproducible closing evidence. The
initial diagnostic used one isolated sample and observed a guest-value ratio of
1.4589 and wall ratio of 1.5786 against Wasmtime 40.0.0. That sample included a
fresh Wasmoon compilation in the wall measurement and is not statistically
sufficient for acceptance.

Final evidence must connect assembly changes to cached runtime behavior and
must retain enough provenance to reproduce the comparison.

## Design

After ISS-262 through ISS-265 close, run the paired algorithms benchmark with an
isolated Wasmoon cache, one warmup, at least seven measured pairs, and
alternating engine order. Record tool versions, host identity, commits, cache
state, per-pair guest values, wall times, medians, geometric means, relevant
function code sizes, memory-base loads, and loop stack traffic.

This report is diagnostic acceptance evidence, not a restored CI performance
gate.

## Acceptance Criteria

- [ ] At least seven valid alternating-order pairs complete with no timeout,
      semantic mismatch, or measured fresh Wasmoon compilation.
- [ ] Median guest-value ratio is at most 1.15 and median wall ratio is at most
      1.20, or the issue remains open with explicit residual blockers.
- [ ] Final `func_37`, `func_41`, `func_42`, and `func_43` assembly metrics are
      recorded alongside the baseline.
- [ ] `moon check --target all --warn-list +73`, native tests, module-boundary
      audit, and recursive interpreter/JIT WAST tests pass.
- [ ] Any unmet assembly or performance criterion is filed as a follow-up issue
      before this issue closes.
