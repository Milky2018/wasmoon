# ISS-338: Preserve Store errors when allocating component host core functions

## Metadata
- Type: bug
- Status: closed
- Priority: 2
- Labels: component-model, runtime, errors, lifecycle, tests, agent
- Assignee: Codex
- Created: 2026-07-30
- Updated: 2026-07-30
- External ref: none

## Description
`alloc_host_core_func` accepts an embedding-provided `Store` but uses `try!`
around `Store::alloc_host_func`. A closed Store therefore aborts instead of
returning the structured `RuntimeError::StoreClosed` failure.

## Design
Make the low-level public allocation seam propagate `RuntimeError` directly.
Adapt that error once at component instantiation boundaries where the API
requires `ComponentRuntimeError`; do not use `try!` or convert the public
low-level failure into an untyped abort.

## Acceptance Criteria
- [x] Calling `alloc_host_core_func` with a closed Store returns `StoreClosed`.
- [x] Component instantiation maps allocation failures without aborting.
- [x] No `try!` remains on this allocation path.
- [x] Focused error regressions, warning checks, and the native suite pass.
