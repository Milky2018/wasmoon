# ISS-346: Make ComponentRuntime own outstanding invocation teardown

## Description
The low-level linker currently requires callers to finish or cancel every
continuation before closing it. That ordering constraint leaks implementation
knowledge and leaves stable callers unable to guarantee cleanup.

## Design
Track every active `ComponentCall` in its owning runtime. Runtime close becomes
terminal, rejects new work, cancels outstanding calls, removes reactor
registrations, releases continuations and GC roots, closes the execution
session, and finally closes Store-owned resources. Calls retain a shared
invalidatable runtime state so aliases cannot continue after close.

## Acceptance Criteria
- [x] Runtime close cancels every active call and is idempotent.
- [x] Closed runtimes reject instantiate, bind/start, and host registration operations.
- [x] Old call aliases return structured closed/cancelled states without touching freed Store state.
- [x] Native sanitizer regressions cover return, trap, cancel, and close teardown.
- [x] Public docs describe execution selection, call lifetime, and thread confinement.

## Close Notes

Added a shared invalidatable runtime state that owns every outstanding call and
installed host context. Terminal, idempotent close first prevents new work,
cancels calls, closes host reactors, and only then closes the execution session
and Store. Retained runtime, instance, function, and call aliases return
`RuntimeClosed` or `Cancelled` without re-entering freed state. The focused
black-box lifecycle suite covers normal return, trap, explicit cancellation,
async cancellation, and runtime close and is included in native sanitizer CI.
