## Description
Use AArch64 W-register zero extension when an i64 constant fits in 32 bits, and reuse comparison matching between boolean values and branches without introducing ISLE.

## Design
Keep memory-base and register allocation policy unchanged. Preserve branch immediate fallback and target eligibility for boolean results. Measure code size separately from end-to-end execution; preserve all timing samples.

## Acceptance Criteria
- [x] Narrow constants use correct shortest supported encodings, with upper-bit and signed controls.
- [x] Shared comparison matching preserves target eligibility, operand order, branch and value semantics.
- [x] Strict native gates and fresh core WAST pass.
- [x] Before/after binaries, code objects and fixed-pair workload timing are recorded.

## Close Notes
Narrowed zero-extended constant emission without changing register allocation or memory-base policy. Value and branch comparison selection now share operand matching and condition reversal; their target-eligibility and fallback policies remain unchanged. No ISLE or public API change.

Exact returning-i64 probes for 0xffff1234 and 0x00ff00ff shrink from 12 to 8 bytes including RET. Other encodings may merely change width without saving instructions. Complete real-module code shrinks by 8 bytes each for onetimeauth, AEGIS and scrypt; allocated VCode is identical. Seven fixed cold pairs per workload establish no speedup or regression (all paired confidence intervals cross zero); separate compile-phase measurements are also inconclusive. All samples, including warmups, are retained.

Validation: info/fmt, strict native check, 2,605 native tests and fresh core WAST 258/258 files / 62,563 assertions per engine pass. See docs/perf/aarch64-constant-width-2026-09-29.md and its compressed evidence archive for exact comparisons, methods and limitations.
