# ISS-442: Remove snapshot allocation from target lowering

## Description

Semantic MachV accessors such as `Function::blocks`, `block_instructions`,
`instruction_operands`, and `instruction_results` return copied arrays or newly
constructed handles. Target analysis repeatedly calls these accessors while
making several whole-function passes. AArch64 then walks the function again to
create target blocks and again in CFG order to lower instructions.

Current AEGIS-128L target lowering takes 23,100 us in aggregate and 5,707 us in
function 56. The cost scales almost perfectly with surviving IR instruction
count, which points to repeated traversal and allocation rather than fixed ISA
setup.

## Design

Add a narrow internal indexed traversal surface to semantic MachV: counts plus
checked `*_at` queries, or an equivalent non-owning cursor that does not copy
collections. Preserve the snapshot semantics of existing public APIs for
external callers.

Refactor both target selectors to collect raw definitions, uses, constants,
and instruction slots in one canonical scan. Later selection steps should
iterate dense analysis tables when their data dependencies require ordering,
instead of rescanning the full IR through snapshot APIs. Keep instruction
selection policy and target-neutral ownership unchanged.

Do not remove semantic MachV or fuse product-owned Wasmoon policy into a target
module as part of this issue.

## Acceptance Criteria
- [ ] Production AArch64 and x64 target lowering does not allocate copied block, instruction, operand, or result arrays merely to traverse semantic MachV.
- [ ] The public snapshot APIs retain their current ownership and validation behavior.
- [ ] Target analysis performs one canonical IR fact-collection scan; dependent selection passes use indexed facts rather than repeated snapshot traversal.
- [ ] Target VCode, relocation records, metadata, and generated code are unchanged for AEGIS-128L and focused target-lowering fixtures.
- [ ] Across at least seven cache-isolated AEGIS-128L captures, median target-lowering time falls by at least 20 percent from the 23,100 us baseline without shifting equivalent work into another stage.
- [ ] AArch64, x64, MachV, strict allocation-validation, formatting, warning-73, generated-interface, and module-boundary gates pass.
