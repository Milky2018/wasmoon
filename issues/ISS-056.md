# ISS-056: Clarify regalloc public API after production cutover

## Metadata

## Description
After the production backtracking allocator moves into `regalloc`, the public API should not mislead users into thinking the small linear-scan `allocate(program)` helper is the production allocator. The package should expose clear names for the production backtracking engine, simple examples, and any intentionally retained simple allocator.

## Design
Audit `modules/regalloc/pkg.generated.mbti`, package docs, tests, and `machv_regalloc` adapter names after ISS-055. Rename or document APIs so users can tell production backtracking allocation from simple/educational allocation helpers. Keep compatibility only when needed and use deprecation aliases if public API churn would be disruptive.

## Acceptance Criteria

- [x] `machv_regalloc` adapter APIs clearly describe projection and materialization responsibilities.
