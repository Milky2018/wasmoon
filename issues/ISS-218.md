# ISS-218: Preserve disjoint virtual-register live ranges

## Description

Although `LiveRange` stores an array of ranges, current construction creates one range per virtual register and expands it from the earliest touched point to the latest. Dead holes become false interference, increasing spills, moves, and generated-code size.

## Design

Build ranges by scanning each block backward from precise live-out state. Track the current range for every virtual register by dense id, extend only contiguous ranges, and preserve separate fragments across dead holes. Maintain a deterministic range order suitable for allocation and later bundle construction.

## Acceptance Criteria
- [x] A virtual register with two separated live regions retains two disjoint ranges.
- [x] Values whose only apparent overlap lies in dead holes may share a physical register.
- [x] CFG joins, block parameters, clobbers, fixed constraints, and tied operands retain correct ranges.
- [x] Allocation verification accepts the new representation and rejects genuine interference.

## Notes
- 2026-07-20: The present `touch_with_order` implementation only expands the first start and last end, making the nominal range array effectively a single conservative interval.
- 2026-07-20: Range construction now scans each block backward from live-out and records one fragment per contiguous block-local region. The red regression proves that a value spanning around an unrelated layout block keeps two fragments and shares a register with the dead-hole value.
- 2026-07-20: Full-suite validation found that instruction indices alone cannot represent a live-through single-instruction block. Fragments now use `-1` and `instruction_count` as block boundary points, preserving early-use/late-def clobber semantics. A focused three-block call-clobber regression passes.

## Close Notes

Live ranges now preserve disjoint CFG/layout fragments, and interference checks operate on those fragments instead of the enclosing first-to-last interval.
