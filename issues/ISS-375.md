# ISS-375: Keep managed JIT contexts alive while raw pointers are in use

## Metadata
- Type: bug
- Status: closed
- Priority: 1
- Labels: native-jit, ffi, memory-safety, sanitizer, tests
- Assignee: unassigned
- Created: 2026-08-02
- Updated: 2026-08-10
- External ref: none

## Description
The verified ASan run of `modules/wasmoon_jit/gc_wbtest.mbt` reports a
heap-use-after-free in the test "gc_setup: fail fast on inconsistent function
table context". The managed `JITContext` returned by
`c_jit_alloc_context_managed` is finalized after its raw pointer is extracted,
before `gc_setup` calls `wasmoon_jit_gc_set_heap` through that pointer.

ASan reports the write in `ctx_set_gc_heap_internal` at
`jit_ffi/jit_context.c:572`; the same context was freed by
`finalize_jit_context` from `jit.c:493`. This demonstrates that the current API
does not express or enforce the lifetime relationship between a managed JIT
context and raw-pointer consumers.

## Design
Keep the managed owner live for the complete duration of every raw context
pointer use. Prefer an API that takes the managed context or scopes raw-pointer
access through a callback so callers cannot accidentally outlive the owner.
Do not fix only the failing test with an incidental read: audit all
`c_jit_context_ptr` callers for the same lifetime hole.

The lifetime boundary must also prevent the raw context address from escaping
the callback. Merely observing one callback use after registering keep-alive is
not sufficient: the callback result, the accessor return value, aliases, and
captured mutable state can all carry the address past the managed-owner scope.
If the MoonBit API and type system cannot make that property structural, remove
the raw `Int64` capability from MoonBit callers instead of treating a lexical
audit as proof.

## Acceptance Criteria
- [x] The failing GC setup test passes under verified ASan instrumentation.
- [x] Managed-context operations keep the external owner as an FFI argument;
      MoonBit cannot obtain the native context address.
- [x] `c_jit_context_ptr` callers are audited and unsafe lifetime patterns are
      removed or covered by regression tests.
- [x] Native JIT and component rollback sanitizer tests pass; the known macOS
      UBSan failure remains tracked separately by ISS-367.
- [x] The audit rejects any MoonBit declaration of the raw context extractor,
      including declarations that rename its C symbol.
- [x] The audit rejects same-package raw access without relying on an extractor
      call count, owner filename, callback spelling, or lexical lifetime proof.
- [x] Negative fixtures cover the reported return escape and the former scoped
      callback seam; both fail at capability creation, before aliasing or
      storage is possible.

## Notes
- 2026-08-02: Reproduced in a fresh sanitizer target with
  `ASAN_OPTIONS=detect_leaks=0` and `UBSAN_OPTIONS=halt_on_error=1`.
- 2026-08-02: Reopened after `f8ffa6e3` reduced the audit to checking that raw
  extraction occurs in at most one implementation file. A minimal fixture
  containing only `c_jit_context_ptr(context)` and no keep-alive returns no
  audit failures; the positive test fixture likewise requires three unsafe
  extractions to pass. The production `NativeJITContext::with_ptr` remains
  safe, but the gate no longer protects its owner-lifetime invariant.
- 2026-08-03: Maintainer decision: the static audit gate is not worth
  strengthening. The owner-lifetime invariant is enforced at runtime by the
  `NativeJITContext::with_ptr` seam (extraction followed by
  `defer c_jit_context_keep_alive`) and verified by ASan regression tests;
  the audit duplicates that protection. The two audit acceptance criteria are
  waived and remain unchecked deliberately.
- 2026-08-10: Reversed the audit waiver after review found that the closed issue
  still had two unchecked acceptance criteria. The restored audit scans every
  MoonBit source in the package and validates the scoped callback, matching
  owner keep-alive, and ordering of the first raw-pointer use. Its fixtures
  cover owner-file lifetime omissions, use-before-keep-alive, and direct
  same-package bypasses while allowing renamed files and multiple valid scoped
  accessors.
- 2026-08-10: **Reopened after a property-level negative fixture passed the
  audit.** A same-package function can extract `raw`, register the matching
  keep-alive, call `body(raw)`, and then return `raw`. `moon check` accepts the
  function and `audit_repo` returns `[]` because the audit only proves that one
  callback consumption occurs after keep-alive registration; it never checks
  later uses or escape through the return value. The generic
  `with_ptr(fn(raw) { raw })` shape exposes the same unproven lifetime hole
  without containing `c_jit_context_ptr` in the caller, so closure requires a
  non-escapable capability boundary rather than another spelling-specific
  callback check.
- 2026-08-10: Replaced the callback seam with managed C entry points. Every
  MoonBit operation now passes the opaque `JITContext` owner directly into C,
  where the native address is unwrapped only for that call. The raw extractor
  and `with_ptr` no longer exist in MoonBit, so callback results, aliases, and
  captured state cannot carry the context address. The audit now enforces this
  structural boundary and rejects renamed declarations of the extractor's C
  symbol.
