# ISS-730: Reuse guarded stacks for completed nested native calls

## Metadata

- Assignee: Codex

## Description

Each synchronous native Component call mapped, protected, and unmapped
a stack for the nested Core invocation. In the matched scalar workload,
635 of 1,016 parent samples ended in munmap.

## Design

Reuse only the guarded POSIX mapping from a successful first JIT entry.
The running parent owns at most one equally sized mapping, capped at
16 MiB. Drop the spare when the parent parks or its stack is released.
The next child still has fresh execution state and goes through the same
allocation failure, trap, and parked root paths. Windows retains its
existing OS fiber lifecycle.

## Notes

- On the 200,000-call scalar fixture, the first invocation median drops
  from 2.489 to 0.567 seconds, with a 75.8% median paired reduction.
  Serial Wasmtime takes 0.324 ms on this boundary-dense fixture.
  Its generated Core adapter calls the provider directly and checks
  the entry flag on the native path. The remaining gap includes the
  Wasmoon host boundary and canonical ABI execution.
- The 1 MiB trial missed the actual 16 MiB Component stack and showed
  no improvement. The final cap includes that configuration without
  shrinking the stack or removing the guard page.
