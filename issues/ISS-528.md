## Description
Replace periodic readiness checks for exclusive CLI stdin with bounded input buffering and completion notifications. Preserve the native Unix readiness path and the non-consuming contract for shared host descriptors.

## Design
Explicitly claim exclusive input at the CLI boundary. Windows synchronous pipe and console reads use a dedicated worker, one bounded buffer shared by descriptor aliases, and a socket notification that can participate in the same WSAPoll wait as network sockets. Polling and reading observe the same buffer, EOF and error state. Close joins the worker before releasing resources. The async reactor uses the same interruptible descriptor wait. Shared input and synchronous pipe output retain their compatibility observation path. Unix input remains directly kernel-backed.

## Acceptance Criteria
- [ ] Explicit exclusive input policy is shared across platforms; embedding defaults remain shared.
- [ ] Windows exclusive input waits on completion without periodic readiness scanning, including mixed socket and reactor waits.
- [ ] Partial reads, duplicates, EOF, nonblocking reads and close/cancellation preserve the input contract.
- [ ] Native Windows tests cover managed pipes and consoles, idle waits, aliases and cancellation.
- [ ] Windows MSVC/Clang, Linux and macOS CI and both-engine readiness regressions pass.
- [ ] Documentation states the ownership and compatibility contracts.
