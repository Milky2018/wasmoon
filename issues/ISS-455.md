## Description

ISS-449 removed the owned semantic `Function` from ordinary JIT compilation,
but both targets still consume a shallow, open `SelectionInput` trait with
about thirty storage-navigation and verification methods. Verified production
input repeatedly reconstructs owner-aware handles, checks indices, unwraps
`Option` values, and copies aggregate operations while lowering. More
importantly, an external implementation can claim that arbitrary input is
verified, so the trait is not an authoritative proof seam.

## Design

Make one opaque, sealed `SelectionPlan` the only trusted production input to
target selection. Construction and target-neutral ABI elaboration happen
before sealing. A sealed plan exposes dense read-only block, instruction,
value, metadata, terminator, and stack-layout views without copied traversal
collections or owner recovery. AArch64 and x64 accept the concrete plan and
keep their target-specific analysis in private lowering contexts.

Retain owned semantic `Function` for diagnostics, transformations, and
standalone clients, with an explicit verified conversion when it must enter
target selection. Do not merge semantic MachV with target VCode or move
target-specific selection policy into MachV.

## Acceptance Criteria

- [x] Only MachV can create a sealed verified `SelectionPlan`; external traits cannot assert verification.
- [x] Target traversal uses dense zero-copy views and does not recover owner-aware indices on verified input.
- [x] AArch64 and x64 accept one concrete sealed plan and keep target analysis local.
- [x] Owned `Function` remains available for diagnostics and explicit transformations but is absent from the production JIT path.
- [x] Runtime ABI elaboration, calls, traps, GC roots, stack maps, block parameters, and environment fields remain behaviorally identical.
- [x] AEGIS-128L retains identical code and allocation vectors without a material target-lowering or end-to-end regression.
- [x] Focused target tests, strict native validation, formatting, warning 73, generated interfaces, and module-boundary gates pass.

## Close Notes

Implemented an authoritative semantic-to-target seam: checked construction
produces `PreparedSelection`, the sole permitted target-neutral ABI elaboration
runs before sealing, and only the opaque verified `SelectionPlan` can enter a
target. Both targets traverse borrowed grouped `SelectionView` records. The
open verification trait, owner-recovering adapters, duplicate trusted entry
points, duplicate target builders, and the production owned-`Function` ABI path
were removed. Owned `Function` remains a separate diagnostics and explicit
transformation representation.
