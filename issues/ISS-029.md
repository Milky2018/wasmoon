# ISS-029: Centralize the reusable VMContext embedding ABI

## Description
Some native lowering paths still rely on Wasmoon-local knowledge of VMContext memory, table, global, and function-table layout. That leaks runtime embedding details into lowering code and makes the extracted infrastructure harder to reuse outside Wasmoon.

## Design
Introduce a reusable embedding ABI description owned by `wasmoon_jit` or a smaller shared package. Native lowering should query this description instead of hard-coding offsets or layout assumptions. Keep the existing runtime layout stable while moving the constants and accessors behind a named API.

## Acceptance Criteria
- [x] VMContext memory, table, global, function-table, and helper layout constants are exposed through a reusable ABI API.
- [x] `wasm_frontend` lowering no longer hard-codes Wasmoon runtime layout details.
- [x] Existing runtime/JIT behavior is unchanged.
- [x] Layout-sensitive tests or WAST coverage exercise memory, table, global, and indirect-call paths.
- [x] `python3 scripts/run_all_wast.py --rec --only-jit --dump-failures --timeout-sec 20` passes.
