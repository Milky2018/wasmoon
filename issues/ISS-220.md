## Description

The root `regalloc.allocate` API exposes only the simple linear-scan allocator even though its implementation states that it is intended for examples and model-level tests. The repository contains reusable backtracking components, but no complete production allocator assembles them behind the root strategy API.

## Design

Assemble a production backtracking allocator inside the reusable `regalloc` module using fragmented ranges, bundles, eviction, splitting, spill weights, register hints, and spill-slot reuse. Keep the current linear/single-pass allocator as an explicitly selected low-compile-latency strategy rather than the implicit production default. This issue stops at the reusable regalloc API and does not cut over MachV.

## Acceptance Criteria
- [x] `RegallocConfig` offers explicit production and fast strategies with documented tradeoffs.
- [ ] The production strategy uses the backtracking engine rather than a fragment allocator with only an `enable_eviction` flag.
- [x] Range splitting, eviction, fixed constraints, calls/clobbers, and spill-slot reuse have focused tests.
- [x] The fast strategy remains correct and is never described as the production-quality default.
- [x] Public API changes are reflected by `moon info` and documented as a deliberate breaking change if required.

## Notes
- 2026-07-20: This issue follows the `regalloc2` separation between a quality-oriented backtracking allocator and a compile-latency-oriented single-pass allocator, without copying its Rust API.
- 2026-07-20: The current root `Allocation` stores one global home per virtual register and cannot represent split ranges, inserted reloads, or edge moves. Implementing only global eviction behind a `Backtracking` name would not meet this issue. The production plan/result seam and its MachV adapter must therefore be designed together with ISS-221 after the completed ISS-216 through ISS-219 foundation.
- 2026-07-20: Approved direction: introduce a narrow read-only allocator function view, return per-operand locations plus before/after/edge edits and spill slots, use production backtracking by default with an explicit single-pass option, adapt Target VCode directly, and delete the projection/global-home compatibility path after cutover.
- 2026-07-20: Implemented the approved breaking API. `FunctionView` now feeds fragmented liveness directly into an `AllocationPlan`; production backtracking performs weighted eviction, fixed/clobber-aware placement, per-operand edits, and compatible spill-slot reuse. `SinglePass` uses the same verified plan contract without eviction. Focused full-plan snapshots cover early/late reuse, eviction strategy differences, a split range across a clobbered CFG fragment, fixed operands, and spill-slot reuse.
- 2026-07-20: Deleted the old `Program`, `Instruction`, `Block`, global-home `Allocation`, `allocate_linear_scan`, and duplicate legacy verifier from the production package. `moon info`, warning-73 checks, and all 2,255 native tests pass. The independent plan checker also has regressions proving that a self-looping entry block and an unreachable cyclic component cannot bypass verification.
- 2026-07-20: The full JIT WAST gate exposed register pressure beyond the focused models: an instruction could require more spilled operands than the target's dedicated scratch set. The allocator now borrows an otherwise occupied allocatable register by saving its live value before the instruction and restoring it afterward; the complete allocation plan is independently verified. `skip-stack-guard-page.wast` with 1,056 live locals and all 62,563 JIT WAST assertions pass.
- 2026-07-20: Full-suite validation now passes all 2,260 native tests. A separate codegen regression found during this gate also locks same-register unsigned `i32`-to-`i64` extension on both AArch64 and x64, and the run-cache version was bumped so stale machine code cannot mask semantic fixes.
- 2026-07-20: Reopened after production inspection and paired probes contradicted the close claim. `allocate_function` currently maps `Backtracking` only to `enable_eviction=true` in the shared fragment allocator; it does not use the reusable backtracking queue, bundle merge, split, or conflict-index components. On `large_cfg.wast`, Backtracking with plan verification disabled measured about 1.219 seconds and 30,756 bytes, while SinglePass measured about 0.908 seconds and 28,680 bytes. The production strategy therefore remains incomplete and pathologically worse on this workload.
- 2026-07-20: The root production path now uses a stable weighted priority queue, whole-range spill weights, indexed disjoint-fragment conflicts, fixed/clobber constraints, weighted eviction, spill reuse, and edge affinities. Backtracking remains the default and both production targets select it explicitly. Final 21-pair AArch64 evidence measures the whole compile corpus at 0.922647x legacy and `large_cfg.wast` at 0.973788x, while retaining the independent materialized-VCode verifier. This resolves the pathological performance behavior, but the issue remains open because the deeper bundle/coalescing acceptance item has not been implemented.
- 2026-07-21: Algorithms probes exposed that fragment non-overlap is insufficient to share one stable spill home across CFG blocks: `box_easy2` trapped and `box_seal` returned corrupted output, while unique homes passed. Spill compaction is now restricted to single-range, same-block lifetimes, with focused same-block reuse and cross-block separation tests. Path-sensitive cross-block spill-home contents remain part of the open production allocator work.
