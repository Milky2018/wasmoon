# ISS-683: Remove redundant callable adapter crossings at the indirect call boundary

## Description
After compact bindings, the checked single-target indirect loop still spends
about nine tenths of main-thread samples in table/type/native-entry adapters.
The release ARM64 resolver makes separate calls to table_entry,
callable_type_for_value, callable_subtype and callable_entry. The shared-view
lookup functions live in a different C translation unit.

## Design
First test mechanical colocation of read-only lookup implementations in a
private header, preserving the public C adapters and every checked branch.
Let ordinary release compilation optimize one complete boundary; no forced
inlining, new registry format, target cache, ABI or compiler expansion.
Retain only after frozen-binary serial paired controls. If insufficient,
use new attribution before considering direct compiler loads/callee contexts.

## Acceptance Criteria

- [x] Repeat asserted indirect/corpus controls with a frozen parent.
- [x] Preserve table/null/type/backend traps, sparse/legacy views and mutation.
- [ ] Pass full target, integration, sanitizer and platform gates.
