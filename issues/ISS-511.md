## Description
Implement the wasmtime.set-max-table-capacity host contract against actual concurrent runtime resources. Task, thread, waitable-set, future/stream state and endpoint, and error-context owners must share a finite slot pool. Removing owners returns slots; failed multi-resource allocations must unwind earlier reservations. Follow pinned Wasmtime's capacity semantics: lowering capacity does not evict existing entries, and freed slots remain reusable even below the old high-water mark.

## Acceptance Criteria
- [x] All concurrent resource owners use the shared capacity with deterministic release and rollback.
- [x] A capacity-exceeding negative control fails, while cancellation/drop recycles capacity over repeated calls.
- [x] The unmodified upstream cancel-starting-subtask-does-not-leak script passes in both engines.
- [x] Native and ASan tests pass; the complete external sweep introduces no regressions or hidden exclusions.
