## Description

`JITModule::load_with_imports` still allocates imports and functions, mutates the function table, installs GC metadata, and patches code incrementally through the v8 loader.

## Design

Resolve direct imports and build owned hostcall trampolines without publication, then install the verified v9 artifact through `JitCodeInstaller`. Stage the JIT context and every GC/debug/address-range registration, and expose the new module plus function table only after the complete transaction commits. Preserve the previous module on every failure.

## Acceptance Criteria
- [ ] `JITModule` consumes verified v9 artifacts and does not allocate or patch function bodies itself.
- [ ] Direct imports and generated hostcall trampolines participate in the same rollback lifetime.
- [ ] Function-table, GC stack-map, trap/debug, unwind, and address-range state publishes once after all registrations succeed.
- [ ] Registration failures are structured and leave no partial module or executable mapping.
- [ ] JIT/interpreter regression tests cover direct imports, host imports, calls, GC safepoints, traps, and replacement rollback.
