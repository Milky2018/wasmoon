## Description

The production root allocator constructs and queues independent `AllocationSegment` values. It records block-argument affinities only as soft register-order hints, so an argument and its target block parameter are not one allocation unit and can still require an avoidable edge transfer. The repository's older `plan_bundle_merges` implementation is tested but stranded in `Milky2018/regalloc/backtracking`; the production `allocate_function` path cannot call it and currently has no bundle model.

## Design

Adapt the existing union-find merge policy into the root production package instead of designing a second coalescer. Build candidate edges from SSA edge arguments to target block parameters. Merge only same-class live ranges whose ordered fragments do not overlap and whose fixed-register requirements are compatible, including the before-definition boundary rule. Return a production-owned bundle table mapping every live range and segment to exactly one bundle. This issue establishes bundle identity and facts only; it does not change register assignment yet.

Keep the implementation private unless a caller outside `regalloc` genuinely needs the representation. Do not add target-opcode knowledge or infer copies from opaque Target VCode instructions.

## Acceptance Criteria
- [ ] Every production live range and allocation segment maps to exactly one stable bundle ID.
- [ ] Compatible, non-overlapping SSA argument/parameter chains coalesce transitively.
- [ ] Overlapping ranges, register-class mismatches, conflicting fixed registers, and before-definition interference do not coalesce.
- [ ] Focused tests snapshot the complete bundle plan rather than boolean comparisons.
- [ ] Bundle construction is deterministic under stable function/block/instruction order.
- [ ] `moon check modules/regalloc --target native --warn-list +73` and `moon test modules/regalloc --target native --warn-list +73` pass.
