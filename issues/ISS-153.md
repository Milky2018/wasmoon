# ISS-153: Remove unlowerable Wasm dialect opcodes

## Description
The public Wasm MilkIR dialect accepts eleven memory and table runtime operations that `wasm_isa_lower` always routes to an aborting unsupported-opcode path. Production frontend builders already expand these operations into generic runtime calls, so the dialect variants expose states that can be encoded but never lowered.

## Design
Remove the eleven variants and their descriptor, encoding, and decoding support. Keep the existing builder functions that expand the operations into generic calls. Remove the unsupported lowering arm so the exhaustive `WasmOpcode` match guarantees that every remaining public dialect opcode has a real lowering implementation.

## Acceptance Criteria
- [x] MemoryGrow, MemorySize, MemoryFill, MemoryCopy, MemoryInit, and DataDrop are not public Wasm dialect opcodes.
- [x] TableGrow, TableFill, TableCopy, TableInit, and ElemDrop are not public Wasm dialect opcodes.
- [x] Legacy encoded names are rejected by the Wasm dialect decoder.
- [x] `wasm_isa_lower` has no unsupported arm for a valid `WasmOpcode`.
- [x] Production memory and table frontend paths continue to emit generic runtime calls.
- [x] Generated interfaces, relevant tests, full native tests, warning checks, and module-boundary audit pass.

## Close Notes
Closed on 2026-07-13. Removed the eleven runtime-lowered variants and their descriptor, encode, and decode arms; the exhaustive Wasm adapter match now contains no valid-opcode unsupported branch. Runtime helper builders remain the only producer path for these operations. Legacy encoded names have a regression matrix that requires decoder rejection. Verified with `moon check --target native --deny-warn`, wasm_milkir tests (10/10), frontend tests (55/55), `MACHV_REGALLOC_VALIDATION=1 moon test --target native` (1820/1820), and the module-boundary audit.
