# ISS-339: Tear down resumable JIT setup when execution admission fails

## Description
`JITModuleContext::call_core_func_resumable` prepares the JIT GC environment
before calling `NativeExecutionState::begin`. If the execution state is already
sealed, `begin` returns `ExecutionStateSealed` but the installed heap pointer
and GC type cache remain attached to the JIT context. Closing the Store then
leaves a dangling native heap pointer.

## Design
Treat `NativeExecutionState::begin` as the admission boundary and run it before
installing Store-owned GC state in the JIT context. If subsequent environment
preparation fails, release the admitted invocation. Keep the existing cleanup
for failures after environment setup.

Use a black-box resumable-call regression. Inspect native GC state only through
the separate test-support package so no probe enters release artifacts.

## Acceptance Criteria
- [x] A sealed execution state is rejected before GC state is installed.
- [x] Environment-setup failure releases the admitted invocation.
- [x] The failure remains the structured `ExecutionStateFailure`.
- [x] Focused lifecycle tests, warning checks, and the native suite pass.

## Close Notes

  A rejected `begin` can no longer install Store-owned pointers in the native
  context, and a later setup failure releases the admitted invocation.

  for both a sealed state and a GC setup failure. The pre-fix sealed-state
  regression observed a non-clear native GC environment; both cases now leave
  zero active/live invocations and a clear environment.
