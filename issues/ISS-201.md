# ISS-201: Cut over x64 and delete the legacy backend

## Description

Switch production x64 compilation to the final Target VCode pipeline and remove the complete legacy MachV generation in the same milestone.

## Design

- Production has one x64 path and no automatic fallback.
- Legacy removal is part of the cutover definition, not follow-up cleanup.
- Preserve regression coverage while deleting comparison-only legacy fixtures.

## Acceptance Criteria

- [ ] All production x64 JIT entry points use the final semantic MachV, x64 VCode, allocation, frame, emitter, and code-object seams.
- [ ] `machv_legacy`, the semantic-to-legacy adapter, the shared target-opcode union, old allocation representation, `machv_emit`, `wasm_isa_lower`, legacy comparison fixtures, and boundary-audit exceptions are deleted.
- [ ] Source packages, manifests, generated interfaces, scripts, and supported documentation contain no imports or references to retired legacy surfaces.
- [ ] No runtime flag, fallback, public compatibility API, or hidden retry can select a legacy backend.
- [ ] Ubuntu AMD64 native, WAST, component, WASI, sanitizer, artifact, and JIT/interpreter differential gates from ISS-193 pass.
- [ ] macOS AArch64 gates remain green after the shared legacy deletion.
- [ ] Relocation, fixup, trap, GC, stack-map, unwind, and normalized-disassembly comparisons meet their acceptance thresholds.
- [ ] Verifiers are not weakened and regression tests are not removed to satisfy the cutover.
- [ ] The common ISS-192 quality gates pass.
