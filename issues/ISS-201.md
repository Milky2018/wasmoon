# ISS-201: Cut over x64 and delete the legacy backend

## Description

Switch production x64 compilation to the final Target VCode pipeline and remove the complete legacy MachV generation in the same milestone.

## Design

- Production has one x64 path and no automatic fallback.
- Legacy removal is part of the cutover definition, not follow-up cleanup.
- Preserve regression coverage while deleting comparison-only legacy fixtures.

## Acceptance Criteria

- [x] All production x64 JIT entry points use the final semantic MachV, x64 VCode, allocation, frame, emitter, and code-object seams.
- [x] `machv_legacy`, the semantic-to-legacy adapter, the shared target-opcode union, old allocation representation, `machv_emit`, `wasm_isa_lower`, legacy comparison fixtures, and boundary-audit exceptions are deleted.
- [x] Source packages, manifests, generated interfaces, scripts, and supported documentation contain no imports or references to retired legacy surfaces.
- [x] No runtime flag, fallback, public compatibility API, or hidden retry can select a legacy backend.
- [ ] Ubuntu AMD64 native, WAST, component, WASI, sanitizer, artifact, and JIT/interpreter differential gates from ISS-193 pass.
- [x] macOS AArch64 local gates remain green after the shared legacy deletion.
- [x] Relocation, fixup, trap, GC, stack-map, frame, and code-byte contracts have target-owned whole-object regression coverage.
- [x] Verifiers are not weakened and regression tests are not removed to satisfy the cutover.
- [x] The local common ISS-192 quality gates pass.
