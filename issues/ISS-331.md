# ISS-331: Match sanitizer evidence without substring false positives

## Description
`missing_sanitizers` treats any dependency text containing `asan` or `ubsan` as
instrumentation evidence. Adversarial names such as `libnotasan.so` and
`libnotubsan.so` therefore pass even when the binary has no sanitizer runtime
or handler symbols.

## Design
Recognize only known ASan/UBSan runtime basenames or strict sanitizer handler
symbols. Add adversarial tests alongside Linux and macOS positive cases so
future matching changes cannot reintroduce substring false positives.

## Acceptance Criteria
- [x] Adversarial dependency names do not count as sanitizer evidence.
- [x] Linux sanitizer runtime basenames remain accepted.
- [x] macOS compiler-rt sanitizer runtime basenames remain accepted.
- [x] Strict ASan and UBSan handler symbols remain accepted independently.
- [x] Script tests and isolated sanitizer verification pass.

## Close Notes
- Replaced unrestricted substring checks with full-match runtime basename
  patterns for GNU and compiler-rt ASan/UBSan libraries.
- Added boundary-aware sanitizer symbol patterns that accept Linux and Darwin
  `nm` spellings without accepting prefixed lookalikes.
- Added adversarial dependency and symbol cases plus Linux, macOS, and
  symbol-only positive cases.
- Validation: focused verifier tests 4/4, all script tests 50/50, and strict
  inspection of the isolated sanitizer CLI and three test executables passed.
