# ISS-448: Keep large MilkIR functions on authoritative IR

## Description

The production O2 pipeline copied admitted MilkIR expressions into a standalone
`EGraph` even for large functions, where it then used a deliberately restricted
compact ruleset. AEGIS-128L spent a 27,788 us median in MilkIR optimization even
after ISS-445 removed several hot temporary records. Phase probes showed that
the representation round trip and rewrite/elaboration walk were the dominant
aegraph costs.

## Design

Use a tiered strategy at the existing 300-instruction boundary. Small functions
retain the full aegraph ruleset, where algebraic exploration can justify the
second representation. Large functions stay in authoritative MilkIR and use
the existing in-place constant folding, alias cleanup, and global GVN passes;
do not build a compact e-graph that duplicates the function for only a handful
of identity rules. Preserve the standalone aegraph implementation and its deep
graph tests independently of the production tier selection.

## Acceptance Criteria
- [x] Functions with 300 or more post-cleanup instructions do not construct a second complete expression graph.
- [x] Small functions retain the full aegraph ruleset and standalone aegraph stress coverage.
- [x] Memory-analysis, alias, and GVN budget behavior remains covered by focused controls.
- [x] Seven cache-isolated AEGIS-128L runs materially reduce optimizer and module compile medians.
- [x] AEGIS code size, spill count, and reload count do not regress.
- [x] MilkIR tests, native validation, warning-73 checking, formatting, generated interfaces, and module-boundary validation pass.

## Notes
- 2026-08-29: Work started after compile-only measurement showed Wasmoon at 112.429 ms versus serial Wasmtime at 34.659 ms.
- 2026-08-29: Phase attribution across 62 optimized functions measured 4,555 us building, 3,739 us saturating, 1,398 us extracting, and 6,691 us rewriting/elaborating. The repeated rewrite was the largest subphase.
- 2026-08-29: A fused aegraph-rewrite plus separate pure-GVN hash table preserved the exact AEGIS code vector but regressed optimizer time to 28,068 us, so it was rejected as layering rather than integration.
- 2026-08-29: Direct e-class representative reuse reduced code and register pressure but changed optimization decisions without improving compile time, so it was also rejected.
- 2026-08-29: Removing only the large-function compact e-graph produced stable, superior code: 57,396 total bytes, 15,256 bytes for function 56, 350 spills, and 1,023 reloads.

## Close Notes

- 2026-08-29: Seven cache-isolated detailed AEGIS runs recorded medians of 85,058 us module compilation and 15,127 us optimization, down from 99,114 us and 27,788 us. The retained captures are in `target/aegis-iss448-skip-large.IXIxbpSF`.
- 2026-08-29: `moon test modules/milkir --target native` passed 191/191; both ordinary and `MACHV_REGALLOC_VALIDATION=1` native suites passed 2,685/2,685. `moon info`, formatting, warning-73 checking, and module-boundary validation passed.
