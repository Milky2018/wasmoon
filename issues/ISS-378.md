# ISS-378: Fix cycle-context poisoning in e-graph extraction memoization

## Description
`EGraph::extract_impl` (`modules/milkir/egraph/egraph.mbt:1734`) detects
cycles with an `in_progress` set and returns an infinite cost for a class
that is re-entered. That part is correct. The bug is at the function tail:
the computed `(best_cost, best_node)` is memoized **unconditionally**, even
when the cost is infinite only because the class was evaluated inside
another class's cycle context.

Sequence: extracting class A visits child B; B's only path goes back
through A, so B evaluates to infinity *in A's context* and that infinity is
stored in `memo`. A later query for B from a different root then returns
the poisoned entry although B has a finite extraction along another route.

The bug is currently latent because extraction results are only consumed
for `Const` nodes (constants have no children and cannot be poisoned), but
any consumer of non-constant extractions — in particular ISS-377's
elaboration — would silently receive wrong costs and nodes.

## Design
Do not memoize results whose cost is infinite due to an active
`in_progress` ancestor; only context-free results may enter the memo.
Alternatively replace the DFS with the fixpoint cost iteration used by egg
(repeatedly relax per-class best costs until stable), which has no context
sensitivity by construction. Add a regression with a cyclic class pair
where the DFS visit order previously poisoned the second query.

## Acceptance Criteria
- [ ] A class reachable both through a cycle and through a finite route
      extracts its finite cost regardless of query order (regression test).
- [ ] Extraction still terminates on cyclic e-graphs and existing extract
      tests pass.
