## Description
`modules/wasmoon_jit/runtime_symbols.mbt` still describes negative runtime-helper function-index values as `legacy` and says `resolve_runtime_func_fixup_idx` is for the old VCode emitter. That wording is misleading after the MilkIR/MachV migration: the live purpose is cwasm/runtime-loader compatibility for negative function-index fixups, not an old implementation path.

## Design
Reword comments only. Prefer terminology such as `cwasm runtime-helper fixups`, `runtime-helper function-index fixups`, or `negative runtime-helper function indices`. Do not rename public functions or change fixup values in this issue.

## Acceptance Criteria
- [ ] `modules/wasmoon_jit/runtime_symbols.mbt` no longer describes live runtime-helper fixups as `legacy`.
- [ ] The `resolve_runtime_func_fixup_idx` comment no longer says the path belongs to the old VCode emitter.
- [ ] Comments accurately state that the negative IDs are the cwasm/runtime-loader encoding currently consumed by Wasmoon JIT integration.
- [ ] No behavior changes are included.
- [ ] `git diff --check` passes.
