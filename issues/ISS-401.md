# ISS-401: Graph walks over input-sized structures still recurse on the native stack

## Description

`milkir`'s `egraph survives a deep dominator spine` test fails on the
`wasm-gc` target:

```text
[Milky2018/milkir] test opt_driver_wbtest.mbt:302
  ("egraph survives a deep dominator spine") failed:
  RangeError: Maximum call stack size exceeded
    at @Milky2018/milkir.CFG::is_valid cfg.mbt:133
    at @Milky2018/milkir.postorder_visit cfg.mbt:126
    at @Milky2018/milkir.postorder_visit cfg.mbt:131
    ... (repeated)
```

The same test passes on `native`, which is why it went unnoticed: ISS-380
introduced it and verified it "under the native test target". A native
thread gets an 8 MB stack, the wasm-gc backend gets the host JS engine's
much smaller one, so the two targets disagree about how deep a function
may be before the optimizer dies.

## Root cause

ISS-380 fixed two *named functions* — `rewrite_block` and `add_value` in
`egraph_builder.mbt` — rather than the class of defect. Every remaining
traversal in the optimizer was still hand-rolled recursion whose depth is
bounded only by the shape of the input function:

| Site | Walk | Bound on depth |
| --- | --- | --- |
| `milkir/cfg.mbt:120` `postorder_visit` | CFG DFS | CFG path length |
| `milkir/opt_passes_basic.mbt:543` `dfs` | dominator tree, alias scopes | tree depth, no budget |
| `milkir/opt_passes_cse_gvn.mbt:667` `dfs` | dominator tree, GVN scopes | tree depth until the work budget runs out |
| `machv/verify.mbt:105` `postorder_visit` | CFG DFS | CFG path length |
| `milkir/opt_loop_unroll.mbt:70` `find_integer_constant_outside_loop_inner` | copy chain | chain length |

The CFG walk is the one the failing test hits, because
`compute_dominators` calls `reverse_postorder`, so *any* pass that asks
for dominators pays for it.

The two dominator-tree walks are not on that test's path, so the test
would not have caught them either. Both are reachable:

- `canonicalize_aliases` runs inside `run_optimized_mandatory_pre_cleanup`
  and again in `run_mandatory_final_cleanup`, on every level above O0,
  with no budget to cut the descent short.
- `run_global_value_numbering_with_budget` stops descending when its work
  budget runs out, but only *instructions* spend that budget. A spine of
  blocks holding nothing but their terminator — what a chain of jumps
  looks like before `merge_blocks` runs — descends the full depth however
  large the function is.

So the underlying defect is not any one of these five functions. It is
that stack safety was a property each traversal had to establish for
itself, at five sites, and only one of them did.

## Design

Traversal became one thing instead of five.

- `CFG::postorder` walks its own explicit `(block, next successor)` stack.
  `postorder_visit` is gone.
- New `visit_dominator_tree(domtree, root, enter, exit)` in `cfg.mbt`
  drives the descent from an event stack. `enter` returns the scope state
  a node introduced together with whether to descend; `exit` receives that
  state once the subtree below it is finished, so a scoped pass binds on
  the way down and restores on the way up exactly as recursion nested it.
  `Exit` is pushed before the children and the children are pushed in
  reverse, so the emitted order matches the recursion it replaced.
- `canonicalize_aliases`, `run_global_value_numbering_with_budget` and the
  e-graph `rewrite_block` all call it. `egraph_builder.mbt`'s private
  `DomWalkEvent` is deleted; it was ISS-380's one-off copy of this.
- `machv`'s `reverse_postorder` gets the same explicit stack as
  `milkir`'s.
- `find_integer_constant_outside_loop` follows copies with a loop. Its
  block search moved to `definition_outside_loop`.

## Acceptance Criteria

- [x] No traversal in `milkir` or `machv` recurses on the native stack
      with depth bounded only by input shape.
- [x] The e-graph deep-spine test passes on wasm-gc, not only native.
- [x] The dominator-tree walks are covered by tests that fail without the
      fix, since the existing test does not reach them.
- [x] Compiled output is unchanged.

## Notes

- 2026-08-06: The e-graph walk's sibling order changes with this edit.
  ISS-380's copy pushed children in forward order onto a LIFO stack, so it
  visited siblings backwards relative to the recursion it replaced; the
  shared walker restores the recursive order. This is safe because the
  only channel between sibling subtrees there is `class_to_value`, which
  is scope-restored — and it was confirmed rather than assumed, see below.

## Close Notes

Red/green evidence, per walk, on wasm-gc:

- `egraph survives a deep dominator spine` (pre-existing, 100k blocks):
  red before, green after. This is the reported failure.
- `the optimizer pipeline survives a deep dominator spine` (new, drives
  `optimize_with_level(func, O3)`): reverting only `canonicalize_aliases`
  to recursion reproduces `Maximum call stack size exceeded` at
  `opt_passes_basic.mbt:571`.
- `global value numbering survives a deep spine of empty blocks` (new):
  reverting only the GVN walk reproduces the overflow at
  `opt_passes_cse_gvn.mbt:800`. The fixture needed a correction — a
  function of nothing but empty blocks has an instruction count of zero,
  so GVN refuses the work before walking anything, and the first version
  of this test passed against the recursive code. The entry block now
  carries the only two instructions, which buys a budget that nothing
  below it can spend.

Verified: workspace 2634/2634 on native, 1028/1028 on wasm-gc, `moon
check` clean from a cold `moon clean`, and the WAST corpus at 258/258
files and 62563 assertions in both interpreter and JIT mode — identical
to the pre-change baseline, which is what establishes that the e-graph
sibling-order change moved no compiled output.

`machv`'s `reverse_postorder` is converted but has no deep-spine test of
its own; it is reached through `blocks_in_cfg_order` on the JIT lowering
path, which is native-only, so the same input has an 8 MB stack rather
than a JS one to exhaust.
