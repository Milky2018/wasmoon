# ISS-057: Move production bundle merging into regalloc

## Description
The production backtracking allocator now delegates allocation-loop, probe,
eviction, split, spill, and result policies to `regalloc`, but bundle
coalescing still keeps its production union-find merge algorithm inside
`modules/machv_regalloc/backtracking_adapter.mbt`. This leaves one important
allocator-core decision path owned by the MachV adapter instead of reusable
compiler infrastructure.

## Design
Move the current production bundle-merge/coalescing decision logic into
`modules/regalloc` without changing behavior. The generic planner must preserve
MachV's current semantics by accepting pre-ordered spans and callback/payload
inputs for class and fixed-register compatibility instead of encoding
`ProgPoint` positions through ad-hoc integer tricks. `machv_regalloc` should
project `LiveRangeSet` and move/block-param edges into the generic planner,
then materialize the returned plan into MachV `BundleSet` and range `bundle_id`
updates.

## Acceptance Criteria
- [x] `regalloc` owns the production bundle merge/coalescing union-find,
  overlap-scan, fixed-constraint compatibility, and root-span merge policy.
- [x] `machv_regalloc` no longer contains a duplicate production merge
  algorithm; it only projects MachV ranges/edges and materializes `BundleSet`.
- [x] MachV `ProgPoint` ordering, `Before`/`After` positions, and fixed-bank
  compatibility are preserved through typed projection/callbacks, not encoding
  hacks.
- [x] Existing `regalloc.plan_bundle_merges` tests are updated or supplemented

## Close Notes

`regalloc` as a generic `BundleMergeRange[C, P, R]` /
`BundleMergePlan[C, R]` API. `machv_regalloc` now projects MachV live ranges
into typed merge spans and block-parameter merge edges, calls
`@regalloc.plan_bundle_merges`, and materializes the returned plan into
`BundleSet`.
