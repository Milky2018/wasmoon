# ISS-256: Index register clobber queries for large CFGs

## Description

For every bundle segment and candidate physical register,
`first_clobber_point` linearly scans every clobber point recorded for that
register. AEGIS `func_56` has 882 optimized blocks and spends most target
compilation time in this repeated scan.

## Design

Build one block-order-sorted clobber index per physical register and answer
range queries by binary search. Preserve the exact earliest-conflict semantics,
including non-physical block numbering and fixed-register operand points. Avoid
public API changes.

## Acceptance Criteria

- [x] First-clobber lookup uses a bounded logarithmic search over sorted points.
- [x] Tests cover no match, boundary exclusion, multiple blocks, custom block
      order, and fixed-register clobbers.
- [x] A deterministic scaling test locks the query-work bound.
- [x] Regalloc snapshots and full allocation verification remain unchanged.
- [x] Fresh AEGIS compile metrics demonstrate the large-function improvement.

## Notes

- 2026-07-23: Sampling attributed 329 of 437 `allocate_bundles` samples directly
  to `first_clobber_point`.
- 2026-07-23: Claimed after ISS-255 established phase-complete production
  metrics. The implementation starts with boundary and custom-order red tests
  before replacing the scan.
- 2026-07-23: Clobber points are now sorted once per physical register in the
  live-range block order. Each strict-interior query uses an upper-bound binary
  search; 4096 points require 14 comparisons in the regression test.

## Close Notes

Closed after a detached `3ab01b80` before/after comparison on macOS AArch64.
Three-run medians improved from 1,781,545 to 1,233,427 microseconds for the
module (`-30.77%`), from 1,630,101 to 1,091,796 for aggregate regalloc
(`-33.02%`), and from 1,232,817 to 783,556 for `func_56` regalloc (`-36.44%`).
The emitted code and allocation edit counts were unchanged.

All 65 regalloc tests and warning-73 checking passed.
