# ISS-585: Check all public descriptor memory accesses

## Description
Managed descriptors retain allocations but public read/write/copy/fill operations could bypass high-level Memory bounds checks. Invalid offsets, lengths or undersized MoonBit buffers could cause host memory access outside the allocation.

## Design
Validate committed descriptor ranges at the C access boundary using subtraction rather than overflow-prone addition. Validate actual MoonBit buffer lengths in public wrappers before calling private FFI functions. Check both copy ranges before modification; preserve memmove overlap behavior. Permit zero-length operations through the end of live allocations without pointer arithmetic, and reject empty handles. Remove unused raw-address memory_read/memory_init APIs.

## Acceptance Criteria
- [x] Public descriptor accesses reject invalid ranges and undersized buffers without partial modification.
- [x] Empty allocations, empty handles, zero-length operations, overlap and integer extremes have public-interface regressions.
- [x] Guarded/shared memory validation uses committed length and follows growth.
- [x] Preserve managed ownership and existing success/failure result convention.
- [x] Strict MoonBit/C checks, complete native tests and ASan/UBSan pass.
- [ ] Cross-platform CI validates the change.

The first new regression failed on the old zero-length access contract before executing dangerous invalid ranges; it passes with the centralized checks. Remaining alloc_memory/free_memory functions are explicitly documented unmanaged ABI allocation primitives, not checked descriptor access.
