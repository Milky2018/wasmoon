## Description
The pinned Core regex workload amplifies per-function executable mappings,
per-call root-scope allocation, wide physical heap slots, historical identity
scans and runtime safepoint calls. Reduce these costs without changing guest
results, root protection, continuation/exception lifetimes or resource admission.

## Design
- Stage one compact executable image per artifact, retaining transactional
  publication, permission transitions, cleanup and logical code-byte charging.
- Reuse root scopes within their execution owner; retain copies and trap markers.
- Keep stable identity high-water semantics with reclaimable sparse descriptor
  pages and a separate ordered live-object traversal.
- Share immutable Store-canonical field layouts between allocation, access and
  graph tracing. Keep wide untyped APIs and the existing reference encoding.
- Expand typed object graphs iteratively in a temporary native owner; visit
  logical exceptions, continuations and untyped edges through the Store. Graph
  queries never change collector marks. Mark only inside the collection protocol.
- Use allocation pressure plus post-collection live bytes, rather than physical
  allocation failure alone. Preserve quota denial and incomplete-root outcomes.
- Inline the no-callback safepoint countdown only for the current activation;
  retain the runtime path for callbacks and foreign contexts. Configure native
  quantum for future invocations; active and parked controls remain snapshots.
- Bump artifact codegen revision to `direct-vcode-11` for the polling protocol.
