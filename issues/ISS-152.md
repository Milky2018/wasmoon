# ISS-152: Encapsulate mutable MilkIR entity collections

## Description
MilkIR exposes mutable `Array` fields on `Function`, `Block`, and `Inst`. Callers can therefore bypass checked methods and directly push foreign blocks, parameters, instructions, arguments, operands, or results into an entity. The verifier detects these cases eventually, but the public representation prevents ISS-147's ownership invariant from being enforced at every mutation boundary.

## Design
Make mutable entity storage private and expose read-only inspection APIs plus checked mutation methods. Migrate reusable compiler modules and product-owned consumers without weakening verifier checks. Preserve printer output and avoid copying large instruction arrays on hot paths.

## Acceptance Criteria
- [ ] External callers cannot mutate `Function.params`, `Function.blocks`, or other function-owned collections directly.
- [ ] External callers cannot mutate `Block.params` or `Block.instructions` directly.
- [ ] External callers cannot mutate `Inst.args`, `Inst.operands`, or `Inst.results` directly.
- [ ] Read-only traversal remains ergonomic and does not require full-array copies on compiler hot paths.
- [ ] All replacement mutators enforce function ownership before changing IR state.
- [ ] Public API migrations, MilkIR tests, full native tests, warning checks, and module-boundary audit pass.
