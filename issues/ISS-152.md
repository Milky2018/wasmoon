## Description
MilkIR exposes `Array` fields on `Function`, `Block`, and `Inst` for efficient traversal. MoonBit arrays are mutable, so the interface must state which mutations are supported instead of implying that every exposed collection is an editing surface.

## Design
Keep the existing zero-copy representation and document the caller contract on the public IR types. Collection fields are for inspection; construction and structural changes use `FunctionBuilder` and the checked `Function`/`Block` methods. `finalize()` remains a validation checkpoint rather than a freeze operation, and consumers verify after the final supported mutation.

## Acceptance Criteria
- [x] `Function` API documentation marks its collection fields as inspection-only and names the supported mutation path.
- [x] `Block` API documentation marks its structural fields as inspection-only and names the checked mutators.
- [x] `Inst` API documentation marks its structural fields as inspection-only and names the supported construction and metadata paths.
- [x] The contract retains zero-copy traversal and does not introduce freezing, copying, or a persistent verified state.
- [x] MilkIR checks, tests, generated interface review, and formatting pass.
