# ISS-171: Validate contextual Wasm dialect contracts against module types

## Metadata
- Type: bug

- Assignee: codex

- Updated: 2026-07-20
- External ref: none

## Description
Wasm dialect validation can derive fixed operand and result contracts directly from an extension instruction, but calls, aggregate operations, reference operations, exception operations, and indexed segment operations depend on module function, type, field, element, table, tag, or segment metadata. The current `wasm_machv.lower_function` interface does not receive that metadata, so it cannot independently prove that producer-supplied contextual types and indices match the referenced module entities.

## Design
Define a minimal Wasm validation context owned by the Wasm adapter and pass it at the production lowering seam. Resolve linked function signatures, indexed function types, tables, struct fields, array elements, tags, reference types, and indexed segments through that context. Keep MilkIR and MachV independent of `wasm_core`; the generic extension validator should continue to expose only a read-only instruction view. Standalone lowering without module metadata must reject contextual operations instead of silently trusting instruction-local declarations.

## Acceptance Criteria
- [x] Direct, indirect, and reference calls are checked against resolved function signatures.
- [x] Struct and array operations are checked against resolved aggregate types.
- [x] Throw operations are checked against resolved tag signatures.
- [x] Indexed reference, table, element, and data operations validate index existence and contextual contracts.
- [x] Invalid indices and contextual type mismatches return structured validation errors before instruction selection.
- [x] MilkIR core does not import Wasm-owned packages or hard-code Wasm opcodes.
- [x] Production JIT paths pass trusted module validation context and targeted forged-IR regressions pass.

## Notes
- 2026-07-14: Created while adding schema-derived local contracts. The schema deliberately marks module-dependent positions as `any` or `...` rather than claiming they are statically verified.
- 2026-07-20: Claimed for implementation. Current CLI byte paths validate source modules, but public MilkIR/MachV lowering seams still accept forged contextual contracts and can silently build incorrect ABI, GC, or exception layouts.

## Close Notes
- 2026-07-20: Added an explicit `WasmValidationContext` at the Wasm adapter seam. It resolves linked function signatures and module-local function types, tables, aggregate fields/elements, tags, memories, data segments, element segments, and reference heap types without storing validator closures in MilkIR.
- 2026-07-20: `wasm_machv.lower_function` and all production JIT/code-object paths now require the context and return structured MilkIR validation failures before instruction selection. Public decoded-module JIT compilation now validates the module before entering the trusted compilation path.
- 2026-07-20: Added forged-IR regressions for calls, table64, aggregates, packed fields, segments, exceptions, references, and adapter integration. Also corrected invalid legacy WAT fixtures and fixed standalone recursive aggregate parsing exposed by the new production validation boundary.
- 2026-07-20: Verified with warning 73 checks, 2249/2249 native tests, the reusable-module boundary audit, and paired JIT/interpreter WAST runs for table64 indirect calls, GC structs/data segments, and exception references.
