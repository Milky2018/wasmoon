# ISS-041: Remove legacy trap-immediate public API

## Description
`wasmoon_jit` still exposes `legacy_trap_immediate_from_message` in its generated public interface. Current references appear to be tests, so the name leaks migration history into a package that is supposed to be the new Wasmoon JIT integration layer.

No public API in the new modules should retain `legacy` naming unless it is a deliberate compatibility contract. This helper does not look like one.

## Design
Prefer deleting the helper from the public surface. If the behavior is still useful for tests or internal trap encoding, make it private or rename it to a non-historical name such as `trap_immediate_from_message` or `trap_immediate_for_message`. Do not keep a deprecated public alias unless an actual external compatibility requirement is documented.

## Acceptance Criteria
- [ ] `rg "legacy_trap_immediate_from_message" modules` finds no live public API use.
- [ ] `modules/wasmoon_jit/pkg.generated.mbti` contains no `legacy` symbol names.
- [ ] Trap-immediate tests are updated to use behavior-level assertions or a non-legacy helper name.
- [ ] No new fallback, compatibility shim, or duplicate trap encoding logic is introduced.
- [ ] `moon info --target native` updates generated interfaces.
- [ ] `moon check --target native --warn-list +73 --diagnostic-limit=200` passes.
- [ ] Targeted `wasmoon_jit` tests pass on native.
