# ISS-293: Verify and repair component resource lifecycle cleanup

## Metadata
- Type: bug
- Status: closed
- Priority: 1
- Labels: component-model, resources, leaks, async, runtime
- Assignee: codex
- Created: 2026-07-28
- Updated: 2026-07-28
- External ref: none

## Description
Stream and future endpoint drop paths remove local handles but retain their
backing `streams` and `futures` entries. Native leak sanitizers do not report
these MoonBit-managed logical leaks, and host futures lack a symmetric explicit
drop operation.

## Design
Centralize last-endpoint cleanup for streams and futures. Remove backing state,
host source values, waitable membership, and recyclable handles only after no
live endpoint remains. Add lifecycle snapshots that repeatedly create, use,
cancel, and drop host resources and assert all live-state counts return to the
baseline.

## Acceptance Criteria
- [x] Dropping the last stream endpoint removes backing stream and host-source
      state.
- [x] Dropping the last future endpoint removes backing future and host-source
      state.
- [x] Host-created future handles have an explicit drop path.
- [x] Resource destructors run exactly once and resource handles are recycled.
- [x] Repeated lifecycle tests leave no task, waitable, stream, future, event,
      borrow, or resource entry above baseline.
