# ISS-342: Separate component engine configuration from execution sessions

## Description
The existing `CoreExecutionEngine` combines execution policy with mutable
Store-scoped instance contexts. The stable runtime cannot accept it without
exposing an implementation type or accidentally allowing mutable sessions to be
shared across runtimes.

## Design
Introduce an opaque stable engine configuration/factory owned by the component
facade and a private execution session created for each runtime. Preserve the
existing typed core execution request/outcome seam internally. The interpreter
and native implementations must create independent sessions.

## Acceptance Criteria
- [x] Stable public types distinguish reusable engine configuration from private runtime session state.
- [x] Each `ComponentRuntime` receives a fresh execution session.
- [x] Interpreter construction remains portable.
- [x] Public generated interfaces contain no `runtime_impl` types.
- [x] Focused black-box tests prove two runtimes do not share mutable execution state.

## Close Notes

Added the opaque `ComponentEngine` configuration and Store-scoped session
factory, made the interpreter an explicit adapter, and taught the stable runtime
to open a fresh session for every construction. The component facade re-exports
only the opaque engine type and interpreter factory; its generated interface
contains no low-level runtime type. Verified with `moon info`,
`moon check --target native`, and the 10/10 black-box
`component_runtime_facade_test.mbt` tests.
