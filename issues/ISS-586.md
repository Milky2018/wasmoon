## Description
Emission currently copies code and metadata into an immutable UnlinkedCodeObject, then copies them again into a mutable FunctionCode before installation revalidates them. Register-allocation sessions reuse scratch arrays but lack an explicit release operation. Measure the effect before changing additional optimizer scratch storage.

## Design
Retain existing immutable code-object APIs and defensive copies. Add a plain code-data path for compiler output, validate it without materializing an immutable snapshot, and transfer the fresh emitter arrays directly to artifact packaging. Keep installation validation. Add explicit scratch release at the reusable session boundary without shrinking on every function.

## Acceptance Criteria
- [x] Record reproducible before/after compilation time and peak memory with identical inputs and cold artifact caches.
- [x] Remove intermediate code-object snapshots from artifact production without weakening public snapshot or installation safety.
- [x] Verify previously returned results survive session reuse, failed compilation, and explicit scratch release.
- [x] Run warning-denied checks, relevant regression tests, full native tests, and module-boundary audit.
- [x] Publish measured results and limitations, including optimizations not justified by evidence.

## Close Notes
Implemented a verified mutable code-data path on both targets while preserving immutable snapshot APIs and artifact installation checks. Added explicit scratch release through all reusable compiler layers. Native tests (2,584), core WAST (258 files / 62,563 commands per engine), warning-denied check, module-boundary audit, benchmark unit tests, and sanitizer harness (61 tests plus lifecycle/positive controls) passed.

Measured eleven cold-process samples per binary for four workloads with and without detailed metrics. Ordinary CLI time changed by less than 1%; peak RSS was essentially unchanged. Packaging fell 37-39% for many-small-function workloads. The allocator probe released 409,760 bytes of retained scalar payload to zero. No broad speedup or optimizer-pool justification is claimed. Full measurements and limitations: [report](../docs/perf/compiler-temporary-memory-2026-09-28.md).
