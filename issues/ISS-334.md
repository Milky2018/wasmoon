# ISS-334: Enforce terminal Store and Linker close semantics

## Metadata
- Type: bug
- Status: closed

- Assignee: Codex
- Created: 2026-07-30
- Updated: 2026-07-30
- External ref: none

## Description
`Store::close` and `Linker::close` are documented as terminal, but Store
mutation and allocation APIs can still retain or create resources after close.
A second close returns immediately, so those resources are never released by
the owner. Linker registration and host-resource APIs have the same problem.

## Design
Add one Store-owned open-state guard and apply it before every operation that
can retain, allocate, or mutate Store-owned state. Report a structured
`RuntimeError::StoreClosed` instead of silently accepting or ignoring the
operation. Linker mutation APIs reuse the underlying Store guard so closing the
Store through an alias also closes the Linker mutation boundary. Read-only
inspection remains available after close.

## Acceptance Criteria
- [x] Store allocation and state-retention APIs reject calls after close before
  mutating state or creating native resources.
- [x] Linker registration and host-resource APIs reject calls after either the
  Linker or its aliased Store is closed.
- [x] `close` remains idempotent.
- [x] Black-box lifecycle regressions and the native test suite pass.
