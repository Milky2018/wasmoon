# ISS-296: Validate canonical lift signatures through core instance exports

## Metadata
- Type: bug
- Status: closed

- Assignee: codex
- Created: 2026-07-28
- Updated: 2026-07-28
- External ref: none

## Description
The component validator skips a canonical lift signature check for values that
need canonical memory. Its scalar-only mapping returns `None` for a string
result, so an invalid core function returning `(i32, i32)` instead of one
indirect result pointer is accepted. Wasmtime 45.0.0 rejects the same
component.

## Design
Put complete Canonical ABI value flattening in the component model and make
both the validator and runtime consume it. Model `canon lift` and `canon lower`
core signatures separately because their indirect-result conventions differ.
Reject a known lift core function whose signature differs from this mapping.

## Acceptance Criteria
- [x] A core module instance export alias retains its core function type.
- [x] An indirect string result encoded as two direct core results is rejected
      with `CanonCoreFuncTypeMismatch`.
- [x] The valid one-pointer indirect result form remains accepted.
- [x] The pinned Wasmtime differential includes the valid string case and the
      validator regression test includes the malformed case.
