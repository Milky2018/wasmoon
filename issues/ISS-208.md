# ISS-208: Enforce contextual rights for WASIp1 path and socket operations

## Description
Path and socket calls bypass stored rights, while `path_open` only checks requested child rights against the parent's inheriting rights. It does not require `PATH_OPEN`, conditional create/truncate rights, or the separate source and target rights of two-directory operations.

## Design
Apply explicit contextual checks in both backends: one-directory path rights, source/target rights for link and rename, `PATH_OPEN` plus conditional create/truncate requirements, and socket receive/send/shutdown/accept rights. Perform checks after ABI and descriptor-kind validation but before resolving or mutating host resources.

## Acceptance Criteria
- [ ] Every path operation enforces its corresponding base right.
- [ ] Link and rename enforce distinct source and target descriptor rights.
- [ ] `path_open` enforces `PATH_OPEN`, inheriting-right subsets, and conditional create/truncate rights.
- [ ] Socket receive/send/shutdown/accept enforce the Preview1 rights contract.
- [ ] Focused interpreter and JIT tests prove denied operations have no host side effects.
