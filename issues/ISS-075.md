# ISS-075: Pass host ISA explicitly instead of detecting it in MachV

## Metadata
- Type: task
- Status: open
- Priority: 1
- Labels: machv, isa_target, machv_emit, machv_regalloc, wasmoon_jit, boundary, reusable-infra, agent
- Assignee: unassigned
- Created: 2026-07-07

## Description
`machv` is intended to be reusable compiler infrastructure, but `modules/machv/isa` currently owns host-architecture detection through `host_arch.c`, `c_host_arch()`, `ISA::host()`, `ISA::current()`, and a global ISA override. This makes `machv` native-only and leaks embedding/runtime concerns into the generic machine-IR layer.

Host architecture detection belongs to the embedding layer that decides which backend to instantiate. For Wasmoon, that means `wasmoon_jit` or the CLI/runtime integration may query the host and then pass the selected ISA into lowering, register allocation, and emission. `machv`, `isa_target`, `machv_regalloc`, and `machv_emit` should receive the target ISA/configuration explicitly instead of reading global process state.

## Design
Remove host-architecture detection and implicit current-ISA state from `machv`. Introduce or reuse an explicit target configuration value, such as an `ISA` plus ABI settings, and thread it through public compiler-infrastructure entry points.

Callers that currently depend on `ISA::current()` should accept an explicit `isa` or target config parameter. Wasmoon-specific host detection can stay in `wasmoon_jit` because that module already owns native JIT runtime glue. Tests should pass a concrete target explicitly rather than using global override helpers.

Non-goals: this issue should not redesign instruction selection semantics or change generated code behavior beyond replacing implicit host-state lookup with explicit configuration.

## Acceptance Criteria
- [ ] `modules/machv/isa` no longer contains `host_arch.c`, `c_host_arch()`, or a `native-stub` entry for host detection.
- [ ] `machv` no longer exposes `ISA::host()`, `ISA::current()`, `push_isa_override`, `restore_isa_override`, or equivalent global current-target state.
- [ ] `isa_target`, `machv_regalloc`, and `machv_emit` entry points receive target ISA/configuration explicitly where they need ISA-specific policy.
- [ ] Wasmoon JIT host detection remains in a Wasmoon-owned module, and the selected target is passed into the reusable compiler-infrastructure pipeline.
- [ ] Tests that need a target pass `AArch64` or `AMD64` explicitly instead of mutating global ISA state.
- [ ] `modules/machv/moon.mod` can be changed away from `supported_targets = "native"` once no other native-only dependency remains in the module.
- [ ] `moon check --target native --warn-list +73 --diagnostic-limit=200` passes.
- [ ] Targeted checks for affected reusable modules pass, including `moon -C modules/machv check --target all --warn-list +73 --diagnostic-limit=200` if `machv` is made portable by this fix.
