# ISS-228: Eliminate quadratic allocation-edit processing

## Description

The JIT compilation of `spec/skip-stack-guard-page.wast` exceeds the Ubuntu
runner's 20-second per-file timeout after the production regalloc cutover. The
1,056-local stress function lowers to roughly 16,897 instructions. Local native
profiling initially exposed repeated complete-list scans in allocation-edit
resolution and verification. A follow-up profile after removing those scans
identified the dominant cost: both target emitters scanned every allocation
edit before and after every instruction. This made emission quadratic in the
number of instructions and allocation edits.

## Design

Group non-edge allocation edits by instruction position in one pass, preserving
their first-seen position order and the existing per-position parallel-move
semantics. Maintain instruction-point and CFG-edge edit indexes at the
`Allocation::add_edit` mutation boundary. Let verification and target emission
query those indexes rather than rescanning the complete edit list. Do not relax
the WAST timeout or weaken allocation verification.

## Acceptance Criteria
- [x] Focused tests preserve edit order, duplicate elimination, cycles, stack-to-stack expansion, and edge edits.
- [x] Allocation verification still rejects missing reloads, spills, and edge moves.
- [x] `spec/skip-stack-guard-page.wast` passes in JIT mode with substantial compile-time headroom below 20 seconds.
- [x] Warning-73 checks, native tests, formatting, generated interfaces, and repository quality gates pass.

## Notes
- 2026-07-21: CI run 29802977391 reproduced the exact JIT timeout independently in the ordinary Ubuntu job and the Linux AMD64 cutover job; interpreter mode passed 258/258 files.
- 2026-07-21: Removing the resolver and verifier scans alone did not materially change the approximately 11-second local reproduction. A second profile showed that the AArch64 emitter spent most samples in `emit_edits_at`, which scanned all edits twice per instruction; the AMD64 emitter had the same implementation.

## Close Notes

Implemented incremental before/after/edge indexes in `Allocation`, switched the
allocation verifier and both target emitters to precise indexed queries, and
grouped instruction edits in one pass before parallel-move resolution. Existing
cycle and stack-to-stack tests remain green; new snapshots cover ordering,
duplicate elimination, edge preservation, and the indexed reload/spill data.

On the original stress file, a forced uncached JIT compilation now completes in
1.42 seconds with `module_compile_us=1403028`, down from approximately 11
seconds locally and well below the unchanged 20-second CI timeout. The complete
spec runner passed 258/258 files and 62,563 assertions in both interpreter and
JIT modes. Warning-73 checks, 2,299 native tests, formatting, generated
interfaces, diff checks, and all three architecture audits passed.
