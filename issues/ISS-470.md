## Description
Native function references expose code addresses separately from instance context, type identity and ownership. Cross-instance calls can consequently execute against the caller environment.

## Design
Introduce one callable contract binding executable entry, owning execution context, canonical type identity and lifetime. Route indirect and imported calls through that contract while preserving native tail calls, GC roots and exception unwinding.

## Acceptance Criteria
- [x] Cross-instance calls read and mutate the callee globals, memories and tables in both engines.
- [x] Indirect and imported calls validate canonical types and preserve GC context and references.
- [x] Tail calls preserve bounded stack usage and exceptions or suspension restore the appropriate context.
- [x] Callable registrations cannot outlive their owning execution state or resolve to released code.
- [x] Native tests, affected misc WAST cases and module boundary audit pass.

## Close Notes
Bound native entries preserve the defining VMContext while remaining leaf tail-call targets. Store-owned global cells replace copied global arrays and synchronization. Store-wide recursive type identities, persistent callable metadata, and object type ownership cover JIT and interpreter transfers. Precise allocation sites carry their function owner; exception handlers and caller roots belong to the active invocation while tag identities belong to the defining instance. Store leases defer executable release until Store retirement, and failed installation unwinds staged resources. Partially initialized modules acquire ownership before publishing element-segment side effects.
