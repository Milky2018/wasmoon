## Description
Several invalid Component Async operations are detected only by later guest
assertions, producing a generic core `unreachable` trap. The official suite
requires the canonical operation itself to reject deadlock, operations on
completed future/stream endpoints, and transfers still owned by a waitable
set.

## Design
Validate these state transitions at the canonical intrinsic boundary and
raise typed `ComponentRuntimeError` values with stable spec-facing messages.
Do not normalize unrelated core traps into the expected text.

## Acceptance Criteria
- [ ] `async/deadlock.wast` passes.
- [ ] `async/trap-if-done.wast` passes.
- [ ] `async/trap-if-transfer-in-waitable-set.wast` passes.
- [ ] Trap classification is identical in interpreter and native JIT modes.
