# ISS-149: Remove MilkIR optimization size cliffs

## Metadata
- Type: bug
- Status: closed
- Priority: 1
- Labels: milkir, optimizer, dce, egraph, performance, correctness, agent
- Assignee: codex
- Created: 2026-07-13
- Updated: 2026-07-13
- External ref: PR #421

## Description
MilkIR O1/O2 skip the e-graph at 300 instructions and wrap the complete local optimization pipeline in an `instruction_count < 300` condition. A function with 299 dead constants is reduced to zero instructions, while adding one dead constant causes all 300 instructions to survive; O1 can therefore produce worse IR than O0. The size-tier branches in `egraph_limits_for_function` for 300 and 600 instructions are unreachable because `run_egraph_pass` returns before consulting them.

## Design
Separate scale-independent mandatory cleanup from expensive optimization. Run DCE, alias canonicalization, block-parameter cleanup, and other cheap canonicalization without size gates. Remove the whole-pipeline 300-instruction switch. Run expensive passes with explicit work budgets and safe early termination; e-graph size tiers may reduce saturation effort but must not disable the pass. Compute expensive-pass budgets after mandatory cleanup and run final cleanup after partial or complete optimization.

## Acceptance Criteria
- [x] O1/O2 remove pure dead instructions on both sides of the 300 and 600 instruction boundaries.
- [x] Mandatory DCE and alias canonicalization are not controlled by function size.
- [x] Expensive optimization uses explicit work budgets and safe early termination rather than a whole-pipeline size switch.
- [x] The 300-599 and 600-plus e-graph budget branches are reachable and covered by tests.
- [x] Side-effecting and trapping instructions remain intact when cleanup or an expensive pass terminates early.
- [x] MilkIR, native, warning, boundary, and relevant performance gates pass.

## Notes
- 2026-07-13: Claimed after a probe showed O1 reducing 299 dead constants to zero but retaining all 300, while O0 still removed all 300.
- 2026-07-13: The existing `SaturationLimits(1, 1)` large-function tier was also an effective off switch because every e-class starts with one node and the limiter stops at `nodes.length() >= limit`. The live tiers are now `2/3` for 300-599 and `1/2` for 600-plus.
- 2026-07-13: The documented metrics runner produced no JSON on both the baseline and modified binaries. That separate collector regression is tracked as ISS-150; same-host wall-clock sampling showed an unchanged `benchmark.wasm` median of approximately 0.25 seconds.

## Close Notes
Closed on 2026-07-13. O0 and optimized levels now share scale-independent backend cleanup, while O1-plus runs constant folding and alias/DCE cleanup before selecting expensive-pass budgets. E-graph no longer returns at 300 instructions and retains nonzero bounded rewrite work in both large-function tiers. Global GVN uses a 300-instruction work-unit budget, reports work and exhaustion to pass metrics, preserves partial safe rewrites, and is followed by unconditional alias, DCE, and CFG cleanup. Regression tests cover 299/300/301 and 599/600/601 boundaries, live fold and alias chains, nonzero e-graph work, GVN early termination, and effect preservation. Verified with `moon check --target native --deny-warn`, `moon test modules/milkir --target native` (116/116), `MACHV_REGALLOC_VALIDATION=1 moon test --target native` (1809/1809), `python3 scripts/audit_module_boundaries.py`, `./install.sh`, and the full interpreter and JIT WAST matrices (258/258 files and 62563 assertions each).
