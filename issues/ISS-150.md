# ISS-150: Emit compile metrics when a run cache entry exists

## Metadata
- Type: bug
- Status: closed
- Priority: 2
- Labels: performance, metrics, cli, tooling, agent
- Assignee: codex
- Created: 2026-07-13
- Updated: 2026-07-13
- External ref: PR #421

## Description
The documented performance workflow sets `WASMOON_PERF_METRICS=1` and expects the CLI to write `WASMOON_PERF_METRICS_FILE`. A cold `wasmoon run` writes that file, but a repeated run that loads a precompiled module from the run JIT cache bypasses `compile_module_to_jit` and therefore never exports metrics. Consequently `scripts/run_perf_benchmarks.py` can exit with `metrics=False` even when workloads complete successfully.

## Design
Treat compile metrics as a request to observe compilation, so disable run-cache reads and writes while metrics are enabled. This avoids both the missing artifact and a misleading zero-duration cache-hit report. Preserve the existing cache behavior when metrics are disabled.

## Acceptance Criteria
- [x] A metrics-enabled JIT run writes the requested JSON even when an entry for the same module already exists in the run cache.
- [x] Metrics-enabled runs do not read or write the run JIT cache.
- [x] Metrics-disabled runs retain the existing cache behavior.
- [x] The cache policy is covered by a unit regression test and a real cold/second-run CLI probe.

## Notes
- 2026-07-13: Discovered while comparing ISS-149 against commit `0ebfc01d`; both baseline and modified binaries exited successfully but emitted no metrics file.
- 2026-07-13: A controlled probe showed that the first run with a fresh cache wrote a 1830-byte JSON report, while the second run using the same cache wrote no report. The output path and filesystem are therefore not the cause.

## Close Notes
Closed on 2026-07-13. The run JIT cache policy now excludes metrics-enabled runs, so compile reports always describe real compilation and cache artifacts remain untouched. A policy-matrix unit test covers metrics and dump combinations. A real probe first populated one cache artifact, then ran the same module twice with metrics enabled; both runs wrote JSON while the cache artifact count remained one. The benchmark runner completed one warmup and one measured run with `metrics_present=true`.
