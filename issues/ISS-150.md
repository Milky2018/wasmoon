## Description
The documented performance workflow sets `WASMOON_PERF_METRICS=1` and expects the CLI to write `WASMOON_PERF_METRICS_FILE`, but successful `wasmoon run` commands currently produce no metrics JSON. Consequently `scripts/run_perf_benchmarks.py` exits with `metrics=False` even when workloads complete successfully. MilkIR currently links a no-op `perf_stub.mbt`, so pass-level work and budget exhaustion cannot reach the documented artifact.

## Design
Restore an embedding-neutral metrics sink between reusable compiler packages and the Wasmoon-owned CLI collector. Keep MilkIR free of product imports, allow the embedding layer to install an optional recorder, and make the benchmark script's documented JSON path observable again. Cover disabled and enabled modes without adding default runtime overhead.

## Acceptance Criteria
- [ ] `WASMOON_PERF_METRICS=1` writes the requested metrics JSON for a successful JIT run.
- [ ] `scripts/run_perf_benchmarks.py` completes without `metrics=False` on its supported workloads.
- [ ] Per-pass work counts and budget-exhaustion state can be represented in the metrics schema.
- [ ] Metrics remain disabled with negligible overhead unless explicitly requested.
- [ ] Reusable MilkIR does not import Wasmoon-owned packages.
