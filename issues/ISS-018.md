## Description
Replace the skeletal `modules/machv` model with the real reusable virtual-register machine IR now spread across `modules/wasmoon/vcode/abi`, `block`, `instr`, `layout`, `runtime.mbt`, and `target.mbt`.

## Design
Extract the target-independent machine representation: virtual/physical registers, register classes, operands, instruction constraints, block layout, CFG, stack effects, and debug metadata. Keep ISA instruction selection and ABI policy out of MachV; those belong to `x64_target` and `aarch64_target`. Keep Wasmoon runtime-specific operations out of MachV; those belong to `wasmoon_jit` or Wasmoon adapters.

## Acceptance Criteria
- [x] `modules/machv` can represent the real VCode functions currently emitted by Wasmoon lowering.
- [x] MachV does not import `wasmoon`, `wasmoon/vcode`, `wasm_core`, `milkir`, `wasmoon_jit`, or `jit_ffi`.
- [x] VCode block/instruction/layout tests are ported to MachV or tracked by explicit follow-up issues.
- [x] Legacy `modules/wasmoon/vcode` data-model packages are removed, reduced to shims, or clearly marked as temporary.
- [x] Targeted MachV tests and `moon check --target native --warn-list +73 --diagnostic-limit=200` pass.

## Notes
- 2026-07-04: This issue owns the reusable machine IR shape, not instruction selection or code emission.
- 2026-07-04: In progress. The register model (`RegClass`, `VReg`, `PReg`, `Reg`, `Writable`, `OperandConstraint`) now has MachV as its source of truth, with `wasmoon/vcode/abi` reduced to aliases plus Wasmoon ABI constants. MachV block/function metadata was expanded to carry VCode-like params, terminators, and spill/ABI metadata. `VCodeFunction::to_machv` bridges real Wasmoon VCode functions into MachV; remaining work is to migrate or shim the instruction/block/function model itself.
- 2026-07-04: Moved target-independent VCode CFG/dominator/loop analysis into `modules/machv/cfg.mbt`. `modules/wasmoon/vcode/layout/cfg.mbt` is now a wrapper over MachV CFG using `VCodeFunction::to_machv()`, so Wasmoon no longer owns a duplicate machine CFG implementation. Remaining layout code still returns legacy `VCodeFunction` and will need a later adapter or function-model migration.

## Close Notes
Closed after moving the reusable machine register model and CFG/dominator/loop analysis into `modules/machv`. `wasmoon/vcode/abi` is now an alias shim for MachV register types plus Wasmoon ABI constants. MachV function/block metadata now covers real VCode-like params, results, terminators, spill counts, param physical-register metadata, and outgoing-arg size. Added `VCodeFunction::to_machv()` so real Wasmoon VCode functions can be projected into MachV, with a regression test for the bridge. `wasmoon/vcode/layout/cfg.mbt` now delegates to `@machv.CFG`, removing the duplicated CFG implementation. The legacy VCode instruction/block/function containers are explicitly marked `TODO(wasmoon_vcode)` because they still mix Wasmoon runtime helpers, GC/exception details, and ISA pseudos that must not be moved into MachV core; their retirement is tracked by ISS-019, ISS-020, ISS-021, and ISS-023.
