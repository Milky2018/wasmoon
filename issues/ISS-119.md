## Description
Restore O3 loop unrolling after the previous implementation was removed for duplicating instructions without trip-count analysis, CFG updates, SSA remapping, or effect preservation. The replacement must apply only to loops whose iteration count and canonical control-flow shape are proven.

## Design
Build the feature behind one private planning-and-application seam. Strengthen SSA verification first, add conservative counted-loop analysis and fresh-ID cloning, then grow from bounded full unrolling to factor-two unrolling with remainder handling and checked I64 arithmetic. Keep O3 unrolling disabled until the final integration issue closes.

## Acceptance Criteria
- [ ] MilkIR rejects duplicate IDs, non-dominating uses, and malformed instruction operands.
- [ ] Canonical constant-trip loops can be fully or partially unrolled without changing observable behavior.
- [ ] Loop-carried values, calls, stores, traps, and multi-result instructions preserve their semantics.
- [ ] Unsupported or arithmetically unsafe loops remain unchanged.
- [ ] O3 JIT and interpreter differential tests pass.
- [ ] Native and wasm-gc quality gates pass.
