# ISS-493: Isolate resource destructor contexts and honor the execution engine

## Metadata
- Type: bug
- Status: closed

## Description
Enabling the real GC host exposes context-in-resource-drop.wast: resource destructors inherit and overwrite the caller's context slots. Resource drop also calls the interpreter directly instead of the destructor CoreFuncRef's engine, bypassing native dispatch.

## Acceptance Criteria
- [x] Destructors start with zero context slots, preserve their slots across host calls, and restore caller slots after nesting or failure.
- [x] Resource destruction dispatches through the owning execution engine.
- [x] The unchanged external resource-drop script and both component engine gates pass.

## Close Notes

- The matching CLI requires `--wasmtime-builtins` to register this host. With that flag, the entire unmodified resource-drop script passes (`/tmp/iss493-context-oracle-builtins.log`, exit 0).

- Resource destruction now enters a fresh synchronous task for the defining component, dispatches through CoreFuncRef.engine, and retires its task on every exit. Destructors with no callback avoid task allocation. The unmodified 13-command upstream script passes both engines (`tmp/iss493-misc-context`); a focused engine spy verifies dispatch, component identity, zero context, nonblocking semantics, caller restoration and task retirement after both normal return and trap.

- Final verification: 2,361 native and 90 Python tests pass; warning 73 and module-boundary checks pass. Both engines pass all 258 core spec files, five local runtime files, 119 local component commands, 845 stable, 153 async and 387 future-gated commands. P1 remains 116 pass and two intentionally not-applicable fuel cases.
- Full misc: 558 pass, 68 script_only, 112 unchanged thread/stack-switching failures, 10 unsupported and 16 deferred, with no timeout or harness error (`tmp/iss492-full-misc`). Exactly 62 trials changed from unsupported to success (60 assertions-bearing pass, two script_only); no other verdict changed.

The two targeted host-GC tests, including cross-Store, shared-Store and same-context native reentry, pass under ASan. This does not close remaining external acceptance work in ISS-476/477/478.
