# ISS-439: Avoid whole-function runtime ABI rebuilding

## Description

Runtime ABI elaboration first scans a semantic function and, when any call or
runtime operation needs adaptation, rebuilds the complete function through a
new builder. Builder finalization then runs mandatory cleanup and verification
again. Large functions pay copies and validation proportional to total IR even
when only a small set of instructions needs ABI adaptation.

## Design

Represent runtime-ABI requirements during semantic construction or apply a
targeted, invariant-preserving transformation that reuses unaffected blocks and
metadata. Retain the identity fast path for functions needing no elaboration.
Do not expose unsafe general mutation or move Wasmoon runtime policy into the
reusable compiler modules.

## Acceptance Criteria
- [x] Runtime ABI elaboration does not rebuild unaffected instructions in a large function.
- [x] The no-elaboration path remains allocation-free after its requirement scan.
- [x] Calls, multi-value returns, safepoints, roots, and helper symbols preserve their current ABI behavior.
- [x] Reusable compiler modules remain free of Wasmoon-owned imports.
- [x] A large serial GC fixture materially improves across at least seven cold captures while AEGIS's identity path does not regress.
- [x] Strict native, WAST, Component Model, and module-boundary gates pass.

## Notes

- 2026-08-28: `semantic_runtime_abi.mbt` performs a full requirement scan and
  reconstructs every block and instruction when elaboration is needed. The
  builder's mandatory cleanup then verifies the rebuilt function again.

- 2026-08-28: Added a constrained, target-neutral MachV call-site elaborator.
  It keeps every existing block, value, instruction, result, and metadata
  handle, inserts root-scope operations only around affected calls, and
  rewrites only explicitly configured hidden safepoints. Wasmoon supplies the
  helper symbols and allocation ABI policy; reusable modules import no Wasmoon
  package. White-box tests lock handle preservation and the no-op identity path.

- 2026-08-28: On a serial 25,490-instruction GC module with one hidden
  allocation safepoint, seven cold runs reduce median target lowering from
  55,924 us to 29,194 us and module compilation from 160,797 us to 129,501 us,
  with identical 30,004-byte code. AEGIS contains no affected GC call site;
  seven final cold runs keep its target stage at 21,933 us and total compilation
  at 160,795 us. Native, WAST, Component Model, and module-boundary gates pass.

## Close Notes

Closed after replacing whole-function reconstruction with verified, in-place
call-site elaboration and measuring both the affected large-function win and
