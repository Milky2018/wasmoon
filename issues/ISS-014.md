## Description
Turn the first-stage module shells into real reusable compiler infrastructure. The current split created package boundaries and skeletal models, but the production compiler still lives mostly under `modules/wasmoon/ir`, `modules/wasmoon/vcode`, `modules/wasmoon/cwasm`, and `modules/wasmoon/jit`. This epic tracks the real migration needed before these modules are useful to non-Wasmoon compiler users.

## Design
Migrate behavior, tests, and ownership boundaries in vertical slices. Do not close this epic merely because packages compile. Completion requires the reusable modules to own the real implementation paths and for Wasmoon to consume them through explicit adapters. Keep MilkIR generic, keep regalloc independent of MachV, keep target ABI policy in `x64_target`/`aarch64_target`, keep runtime fixups in `wasmoon_jit`, and avoid introducing `wasmoon_runtime`.

## Acceptance Criteria
- [x] `modules/milkir` owns a real generic IR model, builder, verifier, printer, and optimization surface extracted from or replacing `modules/wasmoon/ir`.
- [x] `modules/machv`, `modules/x64_target`, `modules/aarch64_target`, `modules/regalloc`, `modules/machv_regalloc`, and `modules/machv_emit` own the real VCode lowering, allocation, and emission pipeline now under `modules/wasmoon/vcode`.
- [x] `modules/wasmoon_jit` owns real `.cwasm`, `jit_ffi`, runtime symbol resolution, executable memory, and native glue integration.
- [x] Legacy `modules/wasmoon/ir` and `modules/wasmoon/vcode` paths are removed, reduced to compatibility shims, or tracked by explicit follow-up issues.
- [x] Correctness gates pass after Wasmoon consumes the migrated modules.
