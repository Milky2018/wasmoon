# ISS-172: Accept table64 indices in Wasm indirect-call contracts

## Description
The schema-derived contracts for `call_indirect` and `return_call_indirect` require an `i32` first operand. WebAssembly table64 uses an `i64` table index, and the Wasm Frontend correctly preserves that type, so valid table64 modules are rejected before JIT lowering. `spec/memory64/call_indirect64.wast` passes in the interpreter but reports one JIT compilation failure.

## Design
Add an explicit schema type pattern that matches only MilkIR `I32` or `I64`, and use it for the table index operand of both indirect-call operations. Do not use the unrestricted contextual pattern because floating-point and reference carriers are invalid table indices. Keep the fix inside the Wasm dialect adapter; MilkIR core remains source-language independent.

## Acceptance Criteria
- [x] `call_indirect` accepts both i32 and i64 table-index operands.
- [x] `return_call_indirect` accepts both i32 and i64 table-index operands.
- [x] Non-integer table-index carriers remain rejected with a structured verification error.
- [x] `spec/memory64/call_indirect64.wast` passes in JIT and interpreter modes.
- [x] Generated schema artifacts, all-target checks, and relevant tests pass.
