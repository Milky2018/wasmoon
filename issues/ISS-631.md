# ISS-631: Give large implementations cohesive responsibilities and private state

## Description
Package extraction has improved dependency direction, but several large files
still combine responsibilities or force callers to know implementation details.
At `25381fc7`, `wasm_component/text/component_wat.mbt` has 7474 lines containing
text parsing, name/index resolution, and binary encoding; CLI `commands/run.mbt`
has 2268 lines combining execution setup, cache/artifact handling, and compilation
orchestration. `wasmoon_jit/jit_ffi/jit.c` has 2082 lines spanning native runtime
operations and FFI adapters.

Size identifies review targets, not automatic defects. ISA instruction tables or
methods requiring the same private owner may legitimately remain together. The
goal is local reasoning and smaller interfaces, rather than a line-count target.

## Scope and Evidence
- Manually review the component text parser, Core CLI assembly, native FFI/runtime
  adapters, and other comparable files for multiple owners/responsibilities.
- Record the actual dependency/state graph and the information a caller must
  know. Prioritize duplicate policy and public private-state exposure identified
  by ISS-626 and ISS-628.
- Preserve the concrete retained-package rationales from ISS-576; re-evaluate
  them only when source changes or a specific defect warrants it.

## Design
Organize code around semantic responsibility and owned state. Extract packages
only when a small acyclic interface can hide complexity; use cohesive files
inside one package when private state should stay shared. Keep MoonBit runtime
policy with its owner and C operations at justified native/FFI seams. Preserve
public import compatibility through established reexports where appropriate.

## Acceptance Criteria
- [ ] Record a manual responsibility/ownership review for the named targets and comparable hotspots, including concrete keep/extract decisions.
- [ ] Resolve confirmed responsibility mixing and duplicated decisions with focused changes; caller complexity and public implementation exposure do not increase.
- [ ] Parsing, resolution, encoding, compilation, runtime ownership, and CLI presentation have identifiable owners and appropriately narrow interfaces.
- [ ] Behavior-preserving moves retain implementation equivalence and meaningful existing regressions; intentional behavioral fixes receive separate evidence.
- [ ] Generated interfaces, package dependency audit, strict MoonBit/C checks, native tests, and relevant external suites pass.
- [ ] No ad hoc filename/line-count style audit or speculative abstraction is introduced; closure reports the review dispositions rather than declaring quality from file sizes.
