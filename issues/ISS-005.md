## Description
Move Wasm-to-IR translation behind a Wasm Frontend that lowers `wasm_core` modules into MilkIR through an Embedding Environment. WebAssembly-specific operations must lower into ordinary MilkIR constructs rather than MilkIR-specific Wasm opcodes.

## Design
Model the boundary after `cranelift-wasm`: the frontend owns Wasm stack/control translation, while the embedding environment resolves memories, tables, globals, references, runtime calls, hidden parameters, external symbols, traps, and metadata. Wasm heap types and canonical type information remain frontend/runtime concerns and lower to generic carriers plus metadata.

## Acceptance Criteria
- [ ] Wasm functions can be translated into MilkIR functions through an embedding environment interface.
- [ ] `memory.*`, `table.*`, `global.*`, ref/GC, exception, and runtime helper operations are not introduced as core MilkIR opcodes.
- [ ] Existing Wasm correctness tests still pass through the updated lowering path or have follow-up issues.
- [ ] Known incomplete lowering cases include scoped `TODO(milkir)` or `TODO(wasm_frontend)` comments.
