## Description
Bulk-memory/table segment setup copies MoonBit payloads into C allocations and keeps separate length and dropped arrays. Migrate segment snapshots and ownership to MoonBit, while native helpers continue implementing guest memory/table operations.

## Design
MoonBit builds private outer reference arrays for each instance, sharing immutable data Bytes and copying mutable element inputs. Native state owns the transferred arrays through RC. Array lengths replace parallel size/count metadata; empty payloads represent dropped segments. Drop releases that instance's payload reference. Preserve copy semantics for legacy raw C setters and zero-length/dropped segment bounds behavior, including GC array data/element operations.

## Acceptance Criteria
- [x] Immutable data payloads are shared, mutable inputs are snapshotted, and instance drop states are independent.
- [x] Legacy setters preserve copying and interoperate with typed setup and cleanup.
- [x] Repeated drop, zero-length bounds and GC segment operations retain behavior.
- [x] Strict checks, native tests, sanitizers and external regressions pass.
