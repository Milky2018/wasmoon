## Description
Wasmoon owns two independent WAT printers inside CLI packages while its public
WAT library exposes parsing only. External consumers with an in-memory
`@types.Module` therefore have to invoke an executable, import a heavyweight
command package, or copy the renderer. The duplicate instruction spelling,
escaping, and float formatting logic has already drifted in Lane.

## Design
Add a deep `Milky2018/wasm_core/wat` package whose public interface renders a
complete module or one function selected from a module. Extract the existing
full-module printer mechanically, then make module and function rendering share
the same private instruction implementation. Preserve IEEE float bits with
deterministic WAT literals, return structured errors for malformed in-memory
module references, migrate both CLI consumers, and delete the duplicate
printers. Do not expose instruction-level rendering helpers.

## Acceptance Criteria
- [x] `Milky2018/wasm_core/wat` publicly renders a complete `@types.Module`.
- [x] The same package renders one selected function for Explore without duplicating instruction rendering.
- [x] `wasmoon-tools wasm2wat` and Wasmoon Explore consume the public renderer.
- [x] The two CLI-owned WAT printer implementations are deleted.
- [x] Black-box parse-render-parse tests cover every instruction constructor and every module section.
- [x] Float tests preserve finite values, signed zero, infinities, and NaN sign and payload.
- [x] Formatting, generated interfaces, native tests, CLI smoke, WAST, and module-boundary gates pass.
