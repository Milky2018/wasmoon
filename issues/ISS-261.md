## Description

`examples/algorithms/pwhash_scrypt_ll.wasm` exposes a current-version AArch64
performance gap that is not explained by arithmetic instruction selection.
Wasmoon and Wasmtime both select the expected `add`/`ror`/`eor` Salsa20/8
sequence, but Wasmoon keeps cold address values live through the hot loop,
spills loop-carried Salsa state, reloads the linear-memory base repeatedly, and
emits avoidable SMix control-flow branches.

The concrete `func_42` Salsa20/8 loop contains 126 Wasmoon instructions versus
99 Wasmtime instructions. Both contain 33 additions, 32 rotates, and 32 XORs;
the difference is 27 Wasmoon stack accesses in the arithmetic loop plus a
stack-to-stack loop-edge move. Wasmoon also loads the stable memory base 24
times in `func_42`, while Wasmtime loads it once.

The workload runs 200 iterations and calls the Scrypt path with `N=1`, `1024`,
and `16384`. This amplifies the lower-level defects to approximately 6,963,600
BlockMix calls and 111,417,600 Salsa20/8 calls. A single isolated diagnostic
sample reported a guest-value ratio of 1.4589 and a wall ratio of 1.5786
(Wasmoon divided by Wasmtime); this one-sample result is provenance, not final
acceptance evidence.

## Design

Treat the gap as four independent compiler problems: loop-aware spill
placement, loop-edge coalescing, profitable stable environment-field reuse, and
SMix CFG cleanup. Preserve the target-neutral MachV/regalloc boundary, do not
reserve an AArch64 physical register for the embedding memory base, and do not
add workload-specific opcode patterns.

Close the epic only after the child fixes pass correctness gates and a
cache-isolated paired benchmark records final assembly and performance evidence.

## Close Notes

Closed after ISS-262 through ISS-266 completed the target-neutral allocator,
edge-coalescing, environment-field reuse, CFG layout, and final evidence
slices. No workload-name check, Scrypt-specific opcode, or permanently
reserved physical register was introduced.

The retained closing report is
`docs/perf/pwhash-scrypt-ll-closing-evidence-2026-07-30.md`. A current
cache-hit pair measures 1.084032 for the guest-produced value and 1.083654 for
wall time against Wasmtime 40.0.0; the measured pair performs no fresh Wasmoon
compilation. A separate schema-v3 trace records 1,269,527 microseconds for
fresh compilation, preserving the distinction between compilation and cached
execution.

Assembly evidence connects the result to the intended fixes: the `func_42`
arithmetic loop has 98 instructions and zero allocator stack edits versus the
126/27 baseline, uses one memory-base load instead of 24, and has no
stack-to-stack continuation-edge move. `func_43` remains below the accepted
branch and code-size limits.
