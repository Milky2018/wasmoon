# ISS-467: Expose read-only WASIp1 preopens and complete applicable P1 coverage

## Description

Three pinned P1 programs require a separate read-only preopen. Existing CLI and
embedding configuration only grant writable preopens. The fourth excluded
program checks Wasmtime-specific hostcall fuel policy, which is outside
Wasmoon's intended WASIp1 contract.

## Design

Add a read-only builder method, optional JIT preopens and `--dir-ro` CLI mappings.
Use explicit base/inheriting capability masks in both engines, relying on the
existing operation checks and irreversible rights attenuation. Exclude link
source and rename source rights as well as destination mutation rights.

Create the upstream read-only fixture outside the writable scratch tree. Adapt
only the three permission errno assertions to exact legacy `NOTCAPABLE`, retain
the guest content assertions and independently verify host filesystem state.
Classify hostcall fuel as `not_applicable`, never as a pass or missing capability.
The Wasmtime CLI reference still cannot express the three per-preopen permission
fixtures and reports those as unsupported.

## Acceptance Criteria
- [x] Read-only configuration reaches interpreter and JIT through public APIs and CLI.
- [x] Three read-only P1 guests pass with exact capability-denial errors and unchanged fixtures.
- [x] Independent guest covers reads/listing, inherited rights and denied mutations in both engines.
- [x] Fuel is excluded explicitly, without an implementation or a passing-test count.
- [x] Source snapshot remains byte-for-byte unchanged; patches apply inside the repository build directory.

## Close Notes

On macOS ARM64, the full explicit-rights profile executes 58 passing scenarios
per engine with no failures, timeouts or unsupported cases. Each engine also
reports one not-applicable hostcall fuel case. This is adapted legacy-rights
coverage, not unchanged upstream conformance or evidence of Linux execution.
All 2,265 native tests and 81 Python tests pass locally. Module boundary and
pinned snapshot audits pass. The regular platform workflow runs the same full
profile on Linux and macOS.
