# ISS-076: Split Wasm dialect operations out of MilkIR core

## Description
MilkIR is intended to be a reusable Cranelift-like SSA IR, but its core package still owns Wasm-shaped operations and builder helpers. Examples include `Wasm(WasmOpcode)`, Wasm memory/table/GC/reference/call opcodes, `IRBuilder` methods such as `memory_grow`, `table_fill`, `struct_new`, and Wasm-specific validation/optimization behavior.

This leaks Wasmoon frontend and runtime semantics into a generic IR module. Downstream compiler authors should be able to use MilkIR without inheriting WebAssembly-specific concepts.

## Design
Move Wasm semantic extensions out of the MilkIR core surface. Preserve behavior by first copying the current Wasm extension logic into a Wasmoon-owned or explicitly Wasm-dialect package, then mechanically retargeting the Wasmoon frontend/lowering path to use that package.

Non-goals: do not rewrite Wasm lowering logic from scratch, do not remove functionality, and do not weaken existing WAST/JIT correctness gates.

## Acceptance Criteria
- [x] `Milky2018/milkir` no longer exposes a generic `Wasm(WasmOpcode)` opcode variant in its core IR.
- [x] Wasm-specific builder helpers are no longer public API of the generic MilkIR core package.
- [x] Wasm frontend translation still has a behavior-preserving way to represent Wasm-only operations before final lowering.
- [x] MilkIR validation and optimization passes either become generic or delegate Wasm-specific logic to an explicit Wasm dialect/adapter.
- [x] Existing Wasmoon JIT and interpreter correctness gates still pass.
- [x] README and module metadata describe the new ownership boundary.

## Close Notes

- 2026-07-07: Replaced MilkIR's Wasm-owned opcode variant with generic
  `Ext(ExtOp)`, moved the Wasm opcode set and builder helpers into
  `Milky2018/wasm_milkir`, and retargeted the Wasmoon frontend to emit through
  that dialect adapter.
- 2026-07-07: MilkIR validation, printing, and optimization now treat
  extension operations generically and conservatively. The old Wasm mem-base
  optimization path is intentionally left as a TODO for a dialect-owned pass,
  since this issue only covers correctness gates rather than performance gates.
- 2026-07-07: `isa_target` temporarily decodes `wasm_milkir` extension
  operations before dispatching to the existing copied lowering logic. The
  remaining ownership leak is tracked separately by ISS-077.
