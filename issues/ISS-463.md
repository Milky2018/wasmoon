## Description

Add independent upstream P1 programs beyond the existing curated CLI smoke
tests. Preserve guest assertions and reproduce host fixtures, with explicit
coverage gaps and failure reports for interpreter and JIT execution.

## Design

Pin Wasmtime commit `668016926adfd1b8a79dbce894f1e203d8892599`, vendor all 58
`p1_*` guest sources and their shared support module unchanged, retain upstream
host reference files and license, and build a small standalone Cargo package.
Run each guest with a fresh scratch preopen and platform-specific errno mode.
Exercise terminal/nonterminal stdio and EOF/pending stdin for polling.

## Acceptance Criteria
- [x] Source inventory and hashes cover every upstream P1 guest in the snapshot.
- [x] Guest programs build reproducibly with a locked dependency graph.
- [x] Runner preserves nonzero exits, exact output checks, timeouts and harness errors.
- [x] Both Wasmoon execution modes are exercised on the available host.
- [x] CI entry point, usage documentation and concrete coverage limitations exist.
- [x] Observed runtime failures are retained and tracked without weakened expectations.

## Close Notes

Completed integration on 2026-09-07. `scripts/run_wasmtime_p1.py` validates 63
upstream files, builds all 58 guest binaries with locked dependencies, and
reports 59 scenarios per engine (the polling program has EOF and pending-stdin
variants). The Python runner has 10 subprocess/snapshot tests; all 72 repository
Python tests passed. `moon info`, `moon fmt`, warning-73 native checking, and
all 2,257 native tests passed. A fresh release CLI was built with `./install.sh`.

macOS ARM64 baseline: interpreter and JIT each had 11 passes, 44 failures,
4 unsupported scenarios, and no timeouts or harness errors. Of the failures,
42 involve zero-rights directory expectations (ISS-464), and two involve
polling valid inherited stdio (ISS-465). No guest assertion was changed and no
expected-failure suppression was added. Wasmtime 40.0.0 passed 54 scenarios;
its one failure is a host panic in the extreme timestamp test. Both runners
returned exit status 1 for their failing suites.

Regular CI checks snapshot integrity and runner tests. The manual Linux AMD64 /
macOS ARM64 workflow builds and runs the complete selected suite and uploads
diagnostics even on failure. Linux execution was not performed locally.

Local machine-readable evidence: `tmp/p1-wasmoon/summary.json` and
`tmp/p1-oracle-verified/summary.json`. These directories are ignored; the
checked-in README and follow-up issues preserve the baseline interpretation.
