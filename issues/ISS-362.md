# ISS-362: Restrict WASI context close authority after runtime ownership transfer

## Metadata
- Type: bug
- Status: closed
- Priority: 1
- Labels: component-model, wasi, ownership, lifecycle, capability, tests, agent
- Assignee: codex
- Created: 2026-07-30
- Updated: 2026-07-30
- External ref: none

## Description
`WasiComponentCtx::try_claim_runtime_owner` records exclusive runtime ownership,
but every pre-existing alias can still call the public `WasiComponentCtx::close`
method. That call closes the reactor, inherited descriptors, resources, and
preopens while the owning component runtime is still active.

The owner claim therefore prevents a second runtime from installing the
context, but does not transfer teardown authority away from ordinary aliases.

## Design
Represent runtime teardown authority as an explicit capability returned by a
successful owner claim. The component host installer retains that capability
and consumes it during runtime teardown. Ordinary `WasiComponentCtx::close`
remains useful for unclaimed contexts, but refuses to close a context after
ownership has transferred.

Do not expose a general owner-bypass close method on the context itself.

## Acceptance Criteria
- [x] Closing an alias after successful runtime installation does not close
      runtime-owned WASI resources.
- [x] Runtime teardown still closes the claimed context exactly once.
- [x] A context closed before ownership transfer cannot later be installed.
- [x] Public black-box tests exercise alias close through a real Preview 3
      stdin operation.
- [x] Native and Component Model regression suites pass.

## Notes
- 2026-07-30: Initial issue.
- 2026-07-30: Reproduced through the public facade: after runtime installation,
  `ctx.close()` changed a real Preview 3 stdin command from `result::ok` to
  `result::err(error-code::io)`.
- 2026-07-30: `try_claim_runtime_owner` now returns an explicit close
  capability. The host installer retains and consumes it during teardown,
  while ordinary aliases can close only unclaimed contexts.
- 2026-07-30: The stdin fixture now requires the expected `hello` bytes instead
  of also accepting an I/O error, so it detects premature resource teardown.
