# ISS-453: Keep target operand descriptors inline

## Description

Target lowering creates short-lived VCode `Input` and `Output` descriptors for
every selected instruction. The builder immediately normalizes them into the
long-lived allocation operand table, so heap-allocating each immutable
descriptor adds object and reference-count traffic proportional to selected
instruction and operand counts.

## Design

Represent `Input` and `Output` as inline value records. Keep their target-facing
constructors, constraints, preferences, and timing behavior unchanged; do not
make the larger long-lived allocation operand record a value type or retain a
second normalized representation.

## Acceptance Criteria
- [x] Target operand descriptors do not allocate one heap object per input or output.
- [x] Tied, fixed, preferred, any-register, and any-location operands retain their existing behavior.
- [x] AEGIS-128L allocation decisions and generated code remain unchanged.
- [x] Seven alternating cache-isolated AEGIS-128L pairs improve VCode construction without moving cost into regalloc.
- [x] VCode, both targets, normal and strict native tests, formatting, warning-73 checking, generated interfaces, and module boundaries pass.

## Notes

- 2026-08-30: Three screening pairs reduced target VCode construction by 5.7
  percent and complete module compilation by 3.2 percent, so the representation
  change proceeded to a full paired comparison.
- 2026-08-30: Seven alternating cold-cache AEGIS-128L pairs against `1317eabb`
  reduced median target VCode construction from 6,896 to 6,720 us, target
  lowering from 12,857 to 12,685 us, and module compilation from 85,309 to
  84,565 us. Regalloc was effectively flat at 29,656 versus 29,675 us. All 14
  runs preserved 57,396 total code bytes, function 56 at 15,256 bytes, 350
  spills, 1,023 reloads, and 83 register moves. Capture:
  `_build/aegis-vcode-io-valtype-screen.zOtqhrwK`.
