# ISS-321: Close all WASI component context resources

## Metadata
- Type: bug
- Status: closed
- Priority: 1

- Assignee: codex
- Created: 2026-07-29
- Updated: 2026-07-29
- External ref: none

## Description
`WasiComponentCtxBuilder::build` duplicates inherited stdin, stdout, and
stderr and marks the resulting stream states as owning those descriptors.
`WasiComponentCtx::close`, however, closes only preopen roots. Repeated CLI
execution or long-lived embedding therefore leaks up to three inherited stdio
descriptors per context.

The same close path does not cancel unfinished native async registrations or
explicitly close the context's kqueue/epoll reactor handle. Dynamic
context-owned descriptors, sockets, and resolvers also rely on every guest
resource being dropped before context closure.

## Design
Make context closure terminal and idempotent. Cancel all native registrations
before closing their source descriptors, release every context-owned host
resource through the existing resource drop boundary, close preopen roots,
and explicitly close the native reactor. Keep shared resource states
double-close safe and prevent post-close async registration.

## Acceptance Criteria
- [x] Closing a context closes all inherited stdio duplicates exactly once.
- [x] Closing a context releases dynamic descriptors, sockets, resolvers, and preopen roots.
- [x] All unfinished native registrations are cancelled before their source descriptors close.
- [x] The context's native reactor handle is explicitly closed.
- [x] Repeated `close()` calls are harmless and post-close async registration is rejected.
- [x] Targeted lifecycle tests, sanitizers, complete native tests, and Component Async suites pass.

## Notes
- 2026-07-29: Reported after per-registration kqueue descriptor ownership was
  corrected; context-level ownership still lacked a complete terminal close.
- 2026-07-29: Wider package testing exposed that cloned resource handles
  shared one stream state without reference counting. Marking every stream
  closed on drop therefore broke the existing independent-handle contract.
  The fix now counts shared context resource entries and finalizes only the
  last handle.

## Close Notes
- 2026-07-29: Made `WasiComponentCtx::close` terminal and idempotent. It first
  closes the native reactor, which cancels every pending registration, then
  sweeps all context resource handles and closes preopen roots.
- 2026-07-29: Added explicit idempotent native reactor close support so
  kqueue/epoll, wake handles, timers, and duplicated registration descriptors
  are not left to eventual GC. Post-close async registration is rejected and
  the event loop reports no pending work.
- 2026-07-29: Introduced reference-counted context resource entries so cloned
  standard-stream and other shared handles preserve the underlying resource
  until the last handle is dropped. Context closure drops all remaining
  references and finalizes each underlying fd, socket, resolver, or stream
  exactly once.
- 2026-07-29: Added direct fd-closure, shared inherited-stream, dynamic
  descriptor, preopen, pending-timer, reactor-handle, idempotence, and terminal
  registration regressions. Verified 42/42 WASI component tests, 8/8 reactor
  tests, 50/50 ASan/UBSan lifecycle tests, 2470/2470 complete native tests, and
  the official async 0.3 matrix in JIT and interpreter modes at 24/24 files and
  153/153 commands each.
