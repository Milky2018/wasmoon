# ISS-336: Seal Store-owned native execution state on close

## Metadata

- Status: closed

- Updated: 2026-07-30
- External ref: none

## Description
`Store::close` is terminal, but an alias obtained earlier from
`Store::native_execution_state` can still call `begin`. The registry then
allocates invocation and resource IDs and retains the supplied release closure
after its owning Store has closed.

## Design
Give `NativeExecutionState` an irreversible sealed state. `begin` must reject a
sealed registry with a structured error before allocating an ID or retaining
the release closure. `Store::close` seals its registry so all aliases observe
the terminal state. Existing invocation handles retain their normal completion
and cleanup operations.

## Acceptance Criteria
- [x] `Store::close` seals its `NativeExecutionState`.
- [x] An alias captured before close cannot begin an invocation afterward.
- [x] Rejected begin does not allocate IDs, retain a release closure, or add a
  live resource.
- [x] Sealing is idempotent and does not prevent existing handles from cleanup.
- [x] Focused lifecycle tests, warning checks, and the native suite pass.
