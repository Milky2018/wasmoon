## Description

Implement the complete AArch64 vertical pipeline from verified semantic MachV through selection, legalization, allocation, frame planning, emission, and metadata production while production still uses the legacy AArch64 path.

## Design

- Mechanically reuse known-good AArch64 behavior where possible, but express it in the final target seams.
- Keep target sequences, temporary registers, addressing modes, conditions, ABI details, and encodings inside AArch64 packages.
- Use shadow comparison only in tests and diagnostics.

## Acceptance Criteria

- [ ] AArch64 lowers every production semantic MachV operation into verified AArch64 VCode or a structured unsupported-operation error.
- [ ] Selection, legalization, regalloc constraints, frame planning, emission, relocations, fixups, traps, GC metadata, stack maps, and unwind data use the final seams.
- [ ] Tests compare normalized VCode, metadata, disassembly, and executed JIT behavior with the legacy path.
- [ ] JIT/interpreter differential coverage includes arithmetic, calls, memory, SIMD, GC, exceptions, tail calls, and stack arguments.
- [ ] The complete macOS AArch64 native, WAST, component, and relevant WASI gates from ISS-193 pass in shadow mode.
- [ ] Production AArch64 remains on the legacy path until ISS-199.
- [ ] The common ISS-192 quality gates pass.

## Notes

- This issue expands the new implementation; ISS-199 performs the cutover and contraction.
- 2026-07-17: Claimed on `milky/improve-machv`. Implementation starts with a shadow-only vertical slice that copies proven AArch64 selection and encoding behavior into the final typed VCode, Allocation, FrameLayout, and emission seams. Unsupported semantic operations must be returned as structured errors rather than falling through to legacy code.
- 2026-07-17: Replaced the placeholder VCode metadata ids and string symbol with semantic `SourceLocation`, `TrapReason`, and a closed code/external/data symbol reference. Whole-function snapshots now expose these facts together with safepoints and live roots, so target lowering and later code-object comparison cannot silently erase or reinterpret metadata.
- 2026-07-17: Added the first real semantic MachV-to-AArch64 selector. It reconstructs independent typed blocks, values, edge arguments, and signatures; selects integer constants, copies, nontrapping integer unary/binary operations, comparisons, pointer offsets, jumps, branches, and ABI-constrained returns; preserves source metadata; and verifies the complete target VCode before success. Valid but unsupported operations return a typed error with the MachV block and instruction site. Division remains deliberately unsupported until its zero/overflow trap legalization is emitted rather than incorrectly relying on AArch64 hardware behavior.
- 2026-07-17: Established the first complete executable vertical slice. AArch64 now owns ABI parameter/result materialization, a target register environment, allocation verification, aligned spill/callee-save frame planning, scalar instruction encoding, stack edits, prologue/epilogue emission, and checked local-branch fixups. The final output is a verified unlinked code object with typed relocation/trap/safepoint seams. Floating-point and SIMD allocation now share one `FpVector` bank to model the architectural register alias instead of permitting impossible simultaneous assignments. Whole-object snapshots cover allocated integer arithmetic and conditional control flow. Production coverage, metadata emission, edge-move resolution, calls, memory, SIMD, GC, exceptions, tail calls, shadow comparison, and gate closure remain open under this issue.
- 2026-07-17: Completed the final-seam CFG copy and metadata slice. Generic VCode now resolves typed parallel copies, stack-to-stack transfers, register cycles, and mixed scalar-float/SIMD cycles without aborting; AArch64 supplies reserved scratch registers, full-width FP/SIMD moves, stack encodings, and isolated conditional-edge stubs. Emission now records general source sites, typed safepoints, and allocated register/stack GC roots in the verified code object. Whole-object tests cover jump-edge copies, conditional copies, explicit register cycles, source maps, and precise GC roots. Trap-site production awaits the corresponding trapping instruction families rather than attaching false traps to nontrapping scalar instructions.
- 2026-07-17: Added the first complete direct-call slice for the platform ABI. Semantic external calls now select to verified target VCode with allocatable arguments, explicit caller-saved clobbers, ABI-ordered result materialization, and structured rejection of unsupported internal, returns-twice, multi-result, and stack-argument forms. AArch64 emission resolves call arguments as parallel moves, preserves and restores `x30` for non-leaf functions, emits `BL` with a typed `AArch64Call26` relocation, and records source plus GC/cancellation safepoints at the actual call instruction. Explicit keepalive uses make precise GC roots cross the clobber point; allocation and whole-code-object snapshots verify a live root in `x19`, typed relocation offsets, LR frame state, and result/clobber contracts. Stack arguments and internal/tail calls remain open in this issue.
- 2026-07-17: Extended platform calls through AAPCS64 stack arguments. One derived call layout assigns the independent integer and FP/SIMD register banks, preserves source-order stack overflow with 8/16-byte alignment, and computes the maximum 16-byte-aligned outgoing area per function. Frame planning reserves that area below spills and saved registers; incoming stack parameters remain addressed above the complete frame. Emission stores overflow arguments before resolving register arguments as a parallel copy, so source registers cannot be overwritten before their stack values are captured. Mixed-layout, frame, and whole-code-object snapshots cover the ninth integer argument, outgoing-area placement, stack load/store encodings, call relocation offset, and LR restoration. Internal and tail-call ABIs remain open.
- 2026-07-17: Replaced the implicit internal convention with an explicit, validated AArch64 `InternalAbi` and required `LoweringContext`. The contract contains only execution-environment, user integer/FP argument, and integer/FP result registers; it rejects illegal, duplicate, and context-reused registers before lowering. Target lowering derives immutable entry and per-call plans, including grouped overflow stack arguments and structured extra-result-area rejection, then materializes verified `InternalCall` VCode. The emitter shares the parallel argument mover and outgoing-area frame machinery with platform calls, preserves LR, and emits typed `Code` rather than `External` relocations. Whole-layout, selected-VCode, invalid-contract, and code-object snapshots cover context-first entry placement, internal call arguments/results, safepoints, and code-symbol relocation. Indirect calls, return areas, and tail calls remain open.
- 2026-07-17: Added internal indirect calls without introducing a target-union fallback. The semantic callee remains outside the logical call signature, while target VCode verifies the leading `Ptr64` operand and the same derived internal call plan used by direct calls. Emission resolves the callee move to reserved `x17` together with register arguments in one parallel-copy graph, removes `x17` from the cycle-scratch set, stores stack arguments first, and emits `BLR x17` with no relocation. Selected-VCode and whole-code-object snapshots lock operand order, context placement, the `BLR` encoding, LR preservation, and empty relocation metadata. Return areas and true internal tail calls remain open.
- 2026-07-17: Implemented true internal AArch64 tail calls as terminators rather than degrading them to call-plus-return. Target VCode accepts only Internal caller/callee protocols, proves that the callee stack-argument area fits the caller's incoming area, requires result-layout equality, and rejects precise roots until post-epilogue stack maps exist. Emission forwards overflow arguments above the current frame, resolves direct or indirect argument moves, tears the frame down, and emits either `B` with a typed `AArch64Jump26` code relocation or `BR x17` without a relocation. Whole-object snapshots cover direct, indirect, and compatible stack-argument forwarding; a negative snapshot locks rejection of oversized tail layouts. Extra return areas and post-epilogue tail-root maps remain open.
- 2026-07-17: Added the non-atomic scalar memory vertical slice. Semantic little-endian loads and stores select to typed AArch64 VCode whose verifier independently checks integer extension, pointer/GC-reference width, FP width, operand shape, and result shape. Emission covers byte, halfword, word, doubleword, F32, and F64 encodings; unencodable unsigned offsets are materialized through reserved `x16` before the actual memory instruction. Trap and source metadata are attached to the faulting `LDR/STR`, not to address setup. Whole-VCode and whole-code-object snapshots cover signed and zero-extending loads, narrow and FP stores, large offsets, and multiple trap sites; valid non-native-endian memory remains a structured unsupported operation. Atomic and vector memory remain open.
