## Description

Implement the complete AArch64 vertical pipeline from verified semantic MachV through selection, legalization, allocation, frame planning, emission, and metadata production while production still uses the legacy AArch64 path.

## Design

- Mechanically reuse known-good AArch64 behavior where possible, but express it in the final target seams.
- Keep target sequences, temporary registers, addressing modes, conditions, ABI details, and encodings inside AArch64 packages.
- Use shadow comparison only in tests and diagnostics.

## Acceptance Criteria

- [ ] AArch64 lowers every production semantic MachV operation into verified AArch64 VCode or a structured unsupported-operation error.
- [ ] Selection, legalization, regalloc constraints, frame planning, emission, relocations, fixups, traps, GC metadata, stack maps, and unwind data use the final seams.
- [ ] Tests compare normalized VCode, metadata, disassembly, and executed JIT behavior with the legacy path.
- [ ] JIT/interpreter differential coverage includes arithmetic, calls, memory, SIMD, GC, exceptions, tail calls, and stack arguments.
- [ ] The complete macOS AArch64 native, WAST, component, and relevant WASI gates from ISS-193 pass in shadow mode.
- [ ] Production AArch64 remains on the legacy path until ISS-199.
- [ ] The common ISS-192 quality gates pass.

## Notes

- This issue expands the new implementation; ISS-199 performs the cutover and contraction.
- 2026-07-17: Claimed on `milky/improve-machv`. Implementation starts with a shadow-only vertical slice that copies proven AArch64 selection and encoding behavior into the final typed VCode, Allocation, FrameLayout, and emission seams. Unsupported semantic operations must be returned as structured errors rather than falling through to legacy code.
- 2026-07-17: Replaced the placeholder VCode metadata ids and string symbol with semantic `SourceLocation`, `TrapReason`, and a closed code/external/data symbol reference. Whole-function snapshots now expose these facts together with safepoints and live roots, so target lowering and later code-object comparison cannot silently erase or reinterpret metadata.
- 2026-07-17: Added the first real semantic MachV-to-AArch64 selector. It reconstructs independent typed blocks, values, edge arguments, and signatures; selects integer constants, copies, nontrapping integer unary/binary operations, comparisons, pointer offsets, jumps, branches, and ABI-constrained returns; preserves source metadata; and verifies the complete target VCode before success. Valid but unsupported operations return a typed error with the MachV block and instruction site. Division remains deliberately unsupported until its zero/overflow trap legalization is emitted rather than incorrectly relying on AArch64 hardware behavior.
- 2026-07-17: Established the first complete executable vertical slice. AArch64 now owns ABI parameter/result materialization, a target register environment, allocation verification, aligned spill/callee-save frame planning, scalar instruction encoding, stack edits, prologue/epilogue emission, and checked local-branch fixups. The final output is a verified unlinked code object with typed relocation/trap/safepoint seams. Floating-point and SIMD allocation now share one `FpVector` bank to model the architectural register alias instead of permitting impossible simultaneous assignments. Whole-object snapshots cover allocated integer arithmetic and conditional control flow. Production coverage, metadata emission, edge-move resolution, calls, memory, SIMD, GC, exceptions, tail calls, shadow comparison, and gate closure remain open under this issue.
- 2026-07-17: Completed the final-seam CFG copy and metadata slice. Generic VCode now resolves typed parallel copies, stack-to-stack transfers, register cycles, and mixed scalar-float/SIMD cycles without aborting; AArch64 supplies reserved scratch registers, full-width FP/SIMD moves, stack encodings, and isolated conditional-edge stubs. Emission now records general source sites, typed safepoints, and allocated register/stack GC roots in the verified code object. Whole-object tests cover jump-edge copies, conditional copies, explicit register cycles, source maps, and precise GC roots. Trap-site production awaits the corresponding trapping instruction families rather than attaching false traps to nontrapping scalar instructions.
