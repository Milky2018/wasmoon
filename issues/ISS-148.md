# ISS-148: Make floating constants explicitly typed by bits

## Metadata
- Type: bug
- Status: closed
- Priority: 0
- Labels: milkir, constants, float, verifier, lowering, correctness, agent
- Assignee: codex
- Created: 2026-07-13
- Updated: 2026-07-13
- External ref: PR #421

## Description
The public `FunctionBuilder::fconst(Type, Double)` API accepts `F32` with an ordinary numeric `Double`, but the IR and backend secretly interpret the low 32 bits of the `Double` payload as packed `Float` bits. Consequently `fconst(F32, 1.0)` produces zero while still passing verification. The same opcode payload has different meanings based on its result value type.

## Design
Replace the ambiguous `FloatConst(Double)` opcode with `FloatConst32(UInt)` and `FloatConst64(UInt64)`. Keep only numeric `fconst_f32(Float)` and `fconst_f64(Double)` builder helpers, which convert values to explicit bit patterns. Make verification bind each opcode to its exact result type, and update optimization, printing, pattern matching, call lowering, and machine lowering to consume the typed payload directly.

## Acceptance Criteria
- [x] The public generic `fconst(Type, Double)` API is removed.
- [x] F32 and F64 constants have distinct opcode variants with explicit bit payloads.
- [x] `1.0`, positive/negative zero, and NaN payloads round-trip without bit changes.
- [x] The verifier rejects an F32 opcode producing F64 and an F64 opcode producing F32.
- [x] MilkIR, lowering, full native, WAST, warning, and module-boundary gates pass.

## Close Notes
Closed on 2026-07-13. MilkIR now represents floating constants as `FloatConst32(UInt)` and `FloatConst64(UInt64)`, and the builder exposes only `fconst_f32(Float)` and `fconst_f64(Double)`. Verification binds each opcode to its exact result type; optimization, printing, pattern matching, call argument collection, and MachV lowering consume explicit bit patterns without consulting result types. Regression coverage preserves positive/negative zero, 1.0, and NaN payloads through IR identity and lowering. Verified with `moon check --target native --deny-warn`, MilkIR and lowering tests, `MACHV_REGALLOC_VALIDATION=1 moon test --target native` (1798/1798), the module-boundary audit, and the full spec matrix (258/258 files and 62563 assertions in both interpreter and JIT modes).
