## Description
MilkIR independently classifies trapping behavior, observable effects, and memory access in several optimization passes. Adding an opcode can therefore leave one classifier stale and silently make an optimization unsound.

## Design
Introduce one package-local semantic summary for built-in `Opcode` values. The summary records memory behavior, trapping behavior, and other observable effects. Each opcode family must be classified through an exhaustive match. Keep verifier contracts, textual formatting, target lowering, and e-graph encodability in their owning adapters because those are not shared semantic facts. Treat dialect extensions conservatively in MilkIR Core.

## Acceptance Criteria
- [x] Tests lock the semantic summaries of trapping scalar operations, memory operations, calls, vector memory operations, and dialect extensions.
- [x] Built-in opcode families have one exhaustive semantic classifier.
- [x] The semantic summary derives preservation and memory-query behavior without duplicating opcode lists.
- [x] No new public MilkIR interface is introduced.
- [x] Targeted MilkIR tests and warning checks pass.
