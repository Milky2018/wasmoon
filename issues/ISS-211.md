# ISS-211: Eliminate the large-CFG compile-time blowup

## Description

The AArch64 paired cutover report compiles the 512-branch `large_cfg.wast` workload in roughly 16-18 seconds with the final MachV pipeline versus roughly 49-64 milliseconds with the fixed legacy pipeline. Across 21 pairs the compile-time geometric-mean ratio is about 282.54x and its upper 95% bound is about 295.53x. This is a compiler scalability defect, not ordinary benchmark noise.

## Design

Build a minimized, parameterized large-CFG differential loop and use existing per-phase metrics plus targeted profiling to identify the superlinear stage. Fix the responsible algorithm or representation without bypassing verification, weakening allocation constraints, or adding a size cliff that disables required compilation stages.

## Acceptance Criteria

- [x] A deterministic legacy/current reproducer reports total and per-phase compile time over a range of CFG sizes.
- [x] The responsible stage and complexity mechanism are demonstrated with measurements.
- [x] `LiveRangeSet` lookup is constant-time by virtual-register identity; no live-range construction path scans all ranges for each lookup.
- [x] The minimized regression is locked by a deterministic scalability or work-budget test at the regalloc seam, without a wall-clock-only assertion.
- [x] Doubling the parameterized workload no longer exhibits the observed near-cubic compile-time growth.
- [x] `large_cfg.wast` compiles within the ISS-193 per-workload compile threshold on real AArch64 hardware.
- [x] Native, WAST, regalloc-validation, and target verifier gates remain green.

## Notes
- 2026-07-20: Run 29716402331 measured a 282.537973 geometric-mean ratio and 295.526284 upper 95% ratio over 21 AArch64 pairs. Candidate code size was also 36,880 bytes versus 14,352 legacy bytes, but code-size remediation is tracked separately in ISS-213.
- 2026-07-20: Phase timing on the 512-branch workload attributed about 12.884 seconds of a 13.447-second compilation to allocation. An 8-second native sample placed all 6,710 samples in `machv_regalloc.allocate_vcode`; raw allocation spent 4,655 of 4,679 samples in `build_live_ranges`, and allocation verification rebuilt the same analysis and spent 1,976 of 2,031 samples there.
- 2026-07-20: The dominant path is `extend_ranges_for_block_liveness -> find_or_create_live_range -> LiveRangeSet::get_by_vreg`. `get_by_vreg` linearly scans every existing range for each operand and live-in/live-out lookup. Parameterized 32/64/128/256/512-branch runs took 13.9/39.2/255.6/1,999.8/13,081.0 milliseconds, with doubling ratios converging near 8x and therefore near-cubic growth.
- 2026-07-20: A diagnostic-only direct `Map[(reg_class, vreg), LiveRange]` index reduced allocation from about 12.884 seconds to 331 milliseconds and total compile time from about 13.447 seconds to 917 milliseconds without changing the 36,880-byte output. Indexed runs scaled at 9.9/24.8/76.9/268.8/1,033.5 milliseconds, exposing a remaining roughly quadratic cost in dense block-by-vreg liveness and repeated verification. The experiment was reverted; the constant-time range index belongs to this issue, while residual shared and quadratic pipeline costs remain in ISS-212.
- 2026-07-20: Split reusable regalloc remediation into ISS-216 through ISS-220 and reserved ISS-221 for a jointly designed MachV production cutover after the core is stable.
- 2026-07-20: Closed ISS-216 through ISS-219 after adding direct live-range indexes, sparse liveness, disjoint fragments, and independent symbolic allocation verification. Final 32/64/128/256/512 whole-pipeline measurements are about 10.7/25.7/72.6/247/892 milliseconds: the former near-cubic regalloc defect is gone, while residual end-to-end cost remains open here and in ISS-212.
- 2026-07-20: Independent verification exposed 13 call/call-indirect allocations that crossed caller-saved clobbers. The range model represented a single-instruction live-through block as `[0, 0]`, so strict point containment missed the call. Block fragments now use explicit before-entry `-1` and after-exit `instruction_count` boundaries. The focused regression and all 2,271 native tests pass.
- 2026-07-20: After the direct production backtracking cutover, a release-mode local AArch64 run of the 512-branch workload completed correctly with `module_compile_us=1,302,346` and 30,756 emitted bytes. This is far below the original 13-18 second failure but still does not meet the fixed-legacy 1.10 per-workload threshold, so ISS-211 remains in progress; the remaining lower/allocation cost must be addressed without a size cliff.
- 2026-07-20: Final 21-pair AArch64 evidence after removing redundant liveness scans, caching the direct VCode view, using bitset verification, and restoring indexed conflict queries measured `large_cfg.wast` at 0.973788x compile time with a 1.008850 upper 95% bound. Emitted size is 14,340 bytes versus 14,352 legacy. The full native suite passes 2,271/2,271 tests, and interpreter and JIT each pass 258/258 WAST files and 62,563/62,563 assertions.

## Close Notes

The near-cubic large-CFG defect is removed and the fixed 512-branch workload now meets the conservative per-workload compile threshold. Remaining ordinary-workload fixed costs and target instruction-selection gaps are tracked by ISS-212 and ISS-213.
