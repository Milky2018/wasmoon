# ISS-326: Move native fiber probes out of the production runtime

## Metadata

## Description
The production `wasmoon_jit` native fiber implementation contains test-only
trampolines, lifecycle counters, register probes, and a fork-based guard-page
self-test. Two self-tests are also exposed through the public MoonBit API.
This mixes test instrumentation with the runtime binary and makes test helpers
look like supported embedding contracts.

## Design
Create a test-only native support package that links against the real runtime
ABI and owns the probe trampolines, register-preservation assembly, and
fork-based guard-page test. Import that package only from `test` and `wbtest`
targets. Remove lifecycle counters rather than retaining production test hooks;
keep the interleaving stress test and sanitizer coverage as the lifecycle
regression boundary.

## Acceptance Criteria
- [x] Production fiber C and stack-switch assembly contain no test probes,
      self-tests, fork logic, or test-only counters.
- [x] `wasmoon_jit` no longer exposes fiber self-test functions.
- [x] Native fiber and continuation regressions use a test-only support package.
- [x] Register preservation, guard-page rejection, hostcall suspension, nested
      traps, and parked GC roots remain covered.
- [x] Native checks, focused tests, and sanitizer builds pass on supported hosts.

## Close Notes
The production fiber runtime now contains only runtime behavior and its
embedding ABI. Guard-page, register-preservation, hostcall, nested-trap, and GC
root probes live behind a package imported exclusively by MoonBit test targets;
the supported `wasmoon_jit` interface no longer exposes executable self-tests.
