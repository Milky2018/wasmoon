## Description
Complete the native execution path for WASI 0.3 components. Component Async
Canonical ABI scheduling, host futures, streams, waitables, callbacks, and
explicit interpreter continuations already exist, but suspendable component
core calls still fall back to the interpreter. Preview 3 host operations also
need a Wasmoon-owned single-threaded async runtime instead of depending on an
external async library that cannot own Wasm continuations or Store access.

## Design
Keep Component Async semantics in `component/runtime_impl`, host readiness in a
new Wasmoon-owned async module, and native stack preservation in `wasmoon_jit`.
The existing `CoreExecutionEngine` remains the seam. Support ordinary native
callback steps separately from stackful native continuations. Initial platform
scope is macOS AArch64 and Linux AMD64. Windows, multi-threaded Store access,
cross-thread continuation migration, continuation serialization, and
arbitrary-instruction preemption are non-goals.

## Acceptance Criteria
- [x] Callback-driven Component Async functions execute through native JIT.
- [x] Stackful suspension resumes the original native activation without replay.
- [x] Preview 3 host operations use the Wasmoon-owned event loop.
- [x] Parked native stacks participate in precise GC and cancellation.
- [x] Official stable, async 0.3, and future-gated matrices pass in JIT and interpreter modes.
- [x] Tests prove that required JIT cases did not silently fall back to the interpreter.
