# ISS-128: Accept I64 pointer carriers in CallPtr verification

## Metadata

- Status: closed

## Description
The `CallPtr` verifier requires the function pointer and callee context operands to have the exact MilkIR type `Ptr`. Existing production entry trampolines represent both values as `I64`, which is already accepted by raw pointer memory operations and by MilkIR-to-MachV lowering. Calling `verify()` or `FunctionBuilder::finalize()` on this valid trampoline IR therefore raises `TypeMismatch(message="call_ptr operand 0 has type i64, expected ptr")`.

## Design
Keep the established raw-pointer carrier contract in which both `Ptr` and `I64` are valid. Reuse the existing `require_pointer_value` helper for the two `CallPtr` prefix operands while retaining the current count checks and rejecting unrelated types. Do not migrate producers or alter the call ABI in this focused fix.

## Acceptance Criteria
- [x] `CallPtr` verification accepts `Ptr` and `I64` for both the function pointer and callee context operands.
- [x] `CallPtr` verification continues to reject non-pointer carriers.
- [x] Production entry trampoline IR passes `verify()`.
- [x] Native, wasm-gc, and register-allocation validation gates remain green.
