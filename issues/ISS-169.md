## Description
The black-box test `public CFG discovers a natural loop and its preheader` intermittently observes loop blocks as `[2, 1]` on the JavaScript backend instead of the expected `[1, 2]`. The semantic loop contents are unchanged, but unstable collection iteration makes the full all-target test gate flaky.

## Design
Identify the unordered collection boundary in natural-loop discovery and define a deterministic block-order contract without weakening the whole-object snapshot. Keep the fix independent of unrelated IR or dialect changes.

## Acceptance Criteria
- [x] Natural-loop block order is deterministic on every backend.
- [x] The existing whole-object CFG snapshot passes repeatedly on JavaScript without sorting inside the test.
- [x] CFG, MilkIR, and all-target test suites pass.

## Notes
- 2026-07-14: Reproduced on the current branch after two passing targeted JavaScript runs followed by a failure. A detached `origin/main` worktree reproduced the same failure after four passing runs, confirming that ISS-154 did not introduce the instability.
- 2026-07-14: Root cause confirmed in both MilkIR and MachV CFG discovery: unordered `HashMap` iteration directly determines the public loop and loop-body arrays. The fix is limited to the four order-observable maps, using the built-in insertion-ordered `Map`; lookup-only hash maps remain unchanged.
