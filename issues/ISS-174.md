# ISS-174: Validate poll clock identifiers before the fast path

## Metadata

## Description
The single-relative-clock fast path in both WASIp1 `poll_oneoff` implementations validates `subclockflags` but does not read or validate the clock identifier. A subscription with `clock_id=99`, relative timeout zero, and otherwise valid memory therefore returns success and emits a clock event. Wasmtime 40 returns `EINVAL` for the same public ABI input.

The general multi-subscription path does validate clock identifiers, so behavior also changes solely with subscription count.

## Design
Validate the decoded clock subscription before entering the fast path. Preserve intentional Wasmtime-compatible behavior for defined CPU clock identifiers in the single-relative-clock case while rejecting unknown identifiers. Decide during implementation whether validation should be factored into a shared subscription decoder or kept as a minimal common predicate; do not duplicate another independent clock-id table.

## Acceptance Criteria
- [x] A single relative clock subscription with `clock_id=99` returns `EINVAL` in interpreter and JIT modes.
- [x] Defined clock identifiers retain their documented behavior, including the existing single-relative CPU-clock compatibility case.
- [x] Fast and general paths use the same authoritative clock-id validation rule where their accepted domains overlap.
- [x] `myspec/wasip1/poll.wast` and targeted interpreter/JIT WASI tests pass.

## Notes
- 2026-07-15: Differential probe: Wasmtime 40 exited with `EINVAL(28)` for `clock_id=99`; Wasmoon interpreter and JIT returned success. The regression is recorded as Test 10 in `myspec/wasip1/poll.wast`.
- 2026-07-15: Implementation started on `milky/fix-poll-oneoff`; the fix will validate a typed subscription plan before any fast path and share semantics between interpreter and JIT.

## Close Notes
Closed on 2026-07-15. `poll_oneoff` now decodes every subscription into a validated typed plan before selecting any wait path, and interpreter/JIT execution share that implementation. Unknown clock identifiers return `EINVAL`, while the defined single-relative CPU-clock compatibility behavior is preserved. Verified by 9 targeted interpreter poll tests, 7 targeted JIT poll tests, `moon test --target native` (1895/1895), and `scripts/run_all_wast.py --dir myspec/wasip1 --rec` (117/117 in both interpreter and JIT modes).
