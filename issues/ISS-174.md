# ISS-174: Validate poll clock identifiers before the fast path

## Metadata

- Status: open

## Description
The single-relative-clock fast path in both WASIp1 `poll_oneoff` implementations validates `subclockflags` but does not read or validate the clock identifier. A subscription with `clock_id=99`, relative timeout zero, and otherwise valid memory therefore returns success and emits a clock event. Wasmtime 40 returns `EINVAL` for the same public ABI input.

The general multi-subscription path does validate clock identifiers, so behavior also changes solely with subscription count.

## Design
Validate the decoded clock subscription before entering the fast path. Preserve intentional Wasmtime-compatible behavior for defined CPU clock identifiers in the single-relative-clock case while rejecting unknown identifiers. Decide during implementation whether validation should be factored into a shared subscription decoder or kept as a minimal common predicate; do not duplicate another independent clock-id table.

## Acceptance Criteria
- [ ] A single relative clock subscription with `clock_id=99` returns `EINVAL` in interpreter and JIT modes.
- [ ] Defined clock identifiers retain their documented behavior, including the existing single-relative CPU-clock compatibility case.
- [ ] Fast and general paths use the same authoritative clock-id validation rule where their accepted domains overlap.
- [ ] `myspec/wasip1/poll.wast` and targeted interpreter/JIT WASI tests pass.
