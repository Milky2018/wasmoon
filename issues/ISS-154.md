# ISS-154: Return typed Wasm dialect lowering errors

## Description
`wasm_isa_lower` decodes extension operations with `decode_or_abort`. Unknown or malformed public `ExtOp` values can therefore terminate the process instead of returning a validation error at the Wasm adapter seam.

## Design
Let a MilkIR function carry embedding-neutral dialect validators registered by its typed dialect builders. Core verification rejects unregistered extensions and turns dialect validation failures into `VerifyError::UnverifiableInstruction`; the Wasm validator delegates to the schema-derived codec rather than duplicating opcode knowledge. Validate again at the public Wasm lowering boundary and propagate the structured verification error. The private lowering callback may rely on that validated invariant, and the aborting decoder must not remain public.

## Acceptance Criteria
- [x] Unknown and malformed Wasm extension operations return typed errors from the public lowering interface.
- [x] `FunctionBuilder::finalize()` rejects unknown and malformed Wasm extension operations through a structured verification error.
- [x] Typed Wasm builders register schema-derived validation without introducing a MilkIR-to-Wasm dependency.
- [x] Removed legacy memory and table opcode names return typed errors rather than aborting.
- [x] `decode_or_abort` is no longer public.
- [x] Valid frontend-produced Wasm MilkIR continues to lower unchanged.
- [x] Generated interfaces, relevant tests, full native tests, warning checks, and module-boundary audit pass.
