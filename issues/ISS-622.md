## Description
The Windows Clang CI job passes release builds but fails debug native test compilation under MoonBit stable 0.1.20261012. Direct object builds ignore `MOON_CC=clang` and discover `cl.exe`, which lacks the `/experimental:c11atomics` option supplied by the separate MSVC driver.

## Design
Select `clang-cl.exe` for the Clang job so generated C and direct object builds use the intended compiler. Preserve the MSVC driver and MASM setup. Verify the actual compiler in native test build logs.

## Acceptance Criteria
- [ ] Clang native test builds use clang-cl without falling back to cl.exe.
- [ ] Both Windows compiler jobs pass strict C, native tests and existing corpus gates.

## Notes
- The failure at head `1227372c` is documented by CI run 38519898799. The new direct object backend has a different compiler-driver contract from release generated-C builds.
- Local validation: strict native checking and all 2620 native tests pass. The script suite passes 172 tests with 54 platform skips after updating its existing Windows compiler expectation to clang-cl. Both Windows jobs must still be verified on the new CI head.
- Run 38530331309 showed that a bare `clang-cl.exe` override is resolved to the automatically discovered `cl.exe` toolchain even for release compilation. Moon's `resolve_msvc_toolchain_override` replaces bare compiler paths with the discovered path. Configure Clang with the absolute executable path from `Get-Command`, and retain verbose native build commands as evidence of the selected driver.
