## Description
Move the real `.cwasm` artifact implementation, `jit_ffi` C/assembly glue, executable memory integration, runtime helper resolution, traps, GC helpers, WASI native glue, stack switching, and JIT engine integration into `modules/wasmoon_jit`.

## Design
`wasmoon_jit` is Wasmoon-specific and may depend on Wasmoon runtime concepts where necessary, but reusable compiler infrastructure must not depend on it. It consumes `machv_emit` outputs, resolves runtime helper relocations, owns executable-memory allocation, and wraps output in Wasmoon-owned `.cwasm` metadata. Do not create a generic `exec_mem` module in this migration unless a separate issue justifies it.

## Acceptance Criteria
- [x] `modules/wasmoon_jit` physically owns the real `jit_ffi` native sources and MoonBit bindings.
- [x] `.cwasm` reader/writer tests move from `modules/wasmoon/cwasm` to `modules/wasmoon_jit` or an explicit Wasmoon-owned subpackage.
- [ ] JIT engine code consumes MilkIR/MachV/machv_emit/regalloc modules through stable interfaces instead of the legacy `wasmoon/ir` and `wasmoon/vcode` pipeline.
- [ ] `machv_emit` remains free of Wasmoon runtime helper resolution and native glue.
- [ ] JIT WAST correctness gates pass or failures have explicit follow-up issues.

## Notes
- 2026-07-04: This is not satisfied by the current manifest-only `wasmoon_jit` boundary.
- 2026-07-04: The real `.cwasm` reader/writer moved from `modules/wasmoon/cwasm` to `modules/wasmoon_jit/cwasm`. The moved package now owns neutral artifact metadata (`FuncAddrFixup`, `CallFixup`, `GcSafepoint`) instead of importing legacy `wasmoon/vcode` or `wasmoon/vcode/emit`; `wasmoon/vcode` provides explicit adapter functions for the remaining legacy JIT pipeline. The old `modules/wasmoon/cwasm` package was deleted, and `moon check --target native --warn-list +73 --diagnostic-limit=200` plus `moon test --target native --warn-list +73 --diagnostic-limit=200` passed with 1972 tests.
- 2026-07-04: The real `jit_ffi` package, including C sources, headers, assembly stubs, native-stub configuration, and MoonBit FFI declarations, moved from `modules/wasmoon/jit/jit_ffi` to `modules/wasmoon_jit/jit_ffi`. Existing wasmoon runtime/JIT/emitter packages now import the moved package instead of retaining a duplicate native glue implementation.
- 2026-07-04: `wasmoon_jit.plan_integration_for_target` now takes an explicit `machv_emit.EmitTarget`, records it in `JitIntegrationPlan`, and calls `machv_emit.emit_function_for_target`. The legacy `plan_integration` wrapper remains as an AArch64 compatibility shim with a TODO to source the target from the configured JIT ISA.
- 2026-07-04: Added `wasmoon_jit.plan_milkir_integration_for_target`, which lowers MilkIR through `x64_target`/`aarch64_target`, applies `machv_regalloc.allocate_and_apply`, and emits with `machv_emit.emit_function_for_target`. This is the first Wasmoon JIT-facing pipeline entry that consumes the reusable compiler-infrastructure modules instead of requiring a prebuilt legacy VCode function. Full native gate passed with 1999 tests. Remaining work: encode MachV terminators and switch the production JIT execution path off legacy `wasmoon/ir`/`wasmoon/vcode`.
- 2026-07-04: After `machv_emit` gained basic terminator emission, the MilkIR JIT integration test now produces both X64 arithmetic bytes and a real `ret` byte from a MilkIR `Return` terminator. Full native gate passed with 2000 tests.
- 2026-07-04: Wasmoon root now exposes `plan_wasm_function_with_compiler_infra`, a Wasmoon-owned planning path that lowers a real Wasm function through `wasm_frontend`, runs MilkIR optimization, and calls `wasmoon_jit.plan_milkir_integration_for_target`. This is a callable bridge from Wasmoon module data into the reusable compiler infrastructure; executable-memory installation and replacing the legacy CLI/JIT compile loop remain to be migrated.
- 2026-07-04: `wasmoon_jit` can now wrap a reusable `JitIntegrationPlan` as a moved `.cwasm` artifact via `CwasmArtifact::from_jit_plan`, linking `machv_emit.CodeObject` metadata through `link_code_object` instead of requiring the old VCode artifact path.
- 2026-07-04: `modules/wasmoon/preflight` no longer imports legacy `wasmoon/ir`, `wasmoon/vcode/lower`, or `wasmoon/vcode/regalloc`. Its JIT preflight check now lowers real Wasm functions through `wasm_frontend`, optimizes MilkIR, and verifies the `wasmoon_jit.plan_milkir_integration_for_target` path without installing or executing machine code. Full native gate passed with 2009 tests.
