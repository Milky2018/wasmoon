## Description
Keep the product-facing Wasmoon runtime, CLI, interpreter executor, WASI glue, instantiation logic, host integration, and JIT selection in `modules/wasmoon`.

## Design
Do not create a first-stage `wasmoon_runtime` package. Treat Wasmoon Runtime as a concept, not a module name. The interpreter stays in `wasmoon` because it depends on store layout, host imports, WASI, traps, instance state, and runtime object model.

## Acceptance Criteria
- [ ] CLI entry points and runtime execution APIs live under `modules/wasmoon`.
- [ ] Interpreter executor remains part of `wasmoon`.
- [ ] `wasmoon` depends on reusable infrastructure modules rather than the reverse.
- [ ] Existing CLI and interpreter correctness tests pass or have follow-up issues.
