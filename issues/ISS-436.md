## Description

The versioned Wasm-Smith differential corpus deterministically finds one trap
classification mismatch at seed `193200201`, case 70. The interpreter reports
`out of bounds table access`, while the AArch64 JIT reports `out of bounds
memory access` with `brk_imm=1`. Both executions trap, but the structured trap
reason is observably different.

The same JIT diagnosis reproduces at `d5e692d6`, `7516a11b`, and the then-current
tree, so this is not a regression from ISS-433 or ISS-434. The fixed corpus
runner correctly records 99 passes and one failure; callers must preserve its
non-zero exit status rather than masking it with a later shell command.

## Design

Trace table bounds checks from Wasm frontend trap construction through target
lowering, machine trap immediates, native signal transport, and public runtime
error mapping. Assign or preserve a distinct structured trap code for table
out-of-bounds without changing guarded-memory fault handling. Keep the fix in
the shared trap representation where possible and use target-specific encoding
only at the final machine-instruction boundary.

## Acceptance Criteria
- [x] A minimized public CLI reproduction reports table out of bounds in interpreter and JIT modes.
