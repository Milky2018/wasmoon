## Description
File families such as `parser_*`, `translator_*`, and `component_*` encode subsystem boundaries only in filenames. Give independent subsystems real package boundaries while preserving existing public imports and behavior.

## Design
- Move WAT/WAST parsing, parser-owned types, and white-box tests into `wasm_core/wat/parser`; keep rendering and compatibility tests in `wat`.
- Move Wasm-to-MilkIR translation into `wasm_milkir/frontend/ir/translator` and preserve the `ir` entry points.
- Move component CLI commands and HTTP serving into `commands/component`. Extract shared argument parsing into `commands/options` to avoid parent-child dependency cycles.
- Move portable component types and binary readers into `wasm_component/model`, with canonical ABI calculations in `wasm_component/canonical`. Keep root reexports.
- Record the package organization convention in `AGENTS.md`.

## Acceptance Criteria

- [x] Formatting, generated interfaces, strict checking, and module boundary audit pass.

## Notes
Target-specific `wasmoon_jit/perf/clock_*` files implement the same API selected by `moon.pkg`; an extra package per target adds no boundary. `executor/instr_*` methods operate on the package-owned execution context and dispatch stack; moving handlers alone would expose implementation state. These are concrete exceptions, not a blanket exemption for every prefixed family.

The remaining large JIT, emitter, optimizer, and component runtime families need a separate ownership/dependency analysis; ISS-576 tracks them rather than marking them as resolved by this change.
