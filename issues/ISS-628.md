## Description
Function-level lowering is shared, but CLI Core compilation and Component core
compilation separately build translation contexts, import identities, optimizer
invocations, compiled function arrays, and artifact manifests. Module-level
policy and failure handling therefore have multiple owners.

At `25381fc7`, compare `cmd/wasmoon/commands/run.mbt::compile_module_to_jit` and
`component_native/compiler.mbt::compile_component_artifact`. Their intentional
differences include alias rewriting, memory overrides, cancellation, NaN policy,
function selection, and diagnostics. The duplicate orchestration makes these
differences harder to reason about and keep synchronized.

## Scope and Evidence
- Inventory CLI run/compile, WAST, Component core, embedding, explore, and
  preflight paths; identify shared policy and intentional differences.
- Keep the already shared target/function compiler from ISS-617. This issue
  concerns the remaining module-level assembly, not a claim that its repaired
  production-versus-diagnostics comparison is broken again.

## Design
Move reusable module compilation behind a product-owned interface with explicit
policy and structured results. Keep CLI logging/output and component alias or
ownership adaptations with their callers. Reuse actual compilation results for
diagnostics; avoid a second graph or pipeline. Preserve generic compiler
dependency direction and avoid configuration for hypothetical callers.

## Acceptance Criteria
- [ ] Record the entry-path/policy matrix, including context shape, identities, target/ABI, memory overrides, optimization, NaNs, cancellation, and selected functions.
- [ ] Common translation/optimization/compilation/artifact assembly has one authoritative implementation; intentional adaptations remain explicit.
- [ ] Equivalent configurations produce matching code and relocation/trap/safepoint/unwind metadata; intentional differences receive behavioral tests.
- [ ] CLI, Component, WAST, embedding, and diagnostic failures preserve their appropriate public presentation without duplicated compiler decisions.
- [ ] Required native, external, strict verification, and module-boundary checks pass; compilation costs are measured to exclude a material regression.
