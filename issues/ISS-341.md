## Description
The stable `Milky2018/wasmoon/component` facade always constructs the portable
interpreter and exposes only a blocking `ComponentFunction::call`. Native JIT
construction remains duplicated in CLI-owned code, while Component Async tasks,
continuations, cancellation, and runtime shutdown are unavailable through the
stable interface.

## Design
Make `ComponentRuntime` the deep module that owns execution selection, component
task scheduling, invocation lifetime, and shutdown. Keep Store, core engine,
fiber, reactor, GC, and JIT contexts private. Provide explicit interpreter and
strict native adapters, an opaque `ComponentCall` lifecycle, blocking and
nonblocking driving, and a real MoonBit async join operation without creating a
second guest scheduler.

## Acceptance Criteria
- [x] Stable callers explicitly select an interpreter or native execution engine.
- [x] CLI and library execution share the same stable runtime path.
- [x] `ComponentCall` supports nonblocking poll, blocking wait, async join, and idempotent cancellation.
- [x] Runtime close terminates outstanding calls and releases native resources exactly once.
- [x] Public interfaces expose no Store, core engine, fiber, reactor, GC, or JIT implementation types.
- [x] Black-box tests and component conformance matrices verify interpreter and native behavior.

## Close Notes

The stable component package now exposes opaque reusable engine configuration,
independent runtime sessions, explicit host installation, and an owned
`ComponentCall` lifecycle. Ordinary CLI invocation and WASI command execution
share that facade. Nonblocking polling, blocking reactor waiting, and MoonBit
async joining drive one continuation state machine; runtime close cancels calls
and host operations before releasing the native session and Store.

Validation includes 17 stable facade black-box tests, one internal
host-lifecycle regression, 8 host invocation black-box tests, 23 CLI error
tests, typed native JIT evidence, stable Component Model 0.2 at 23/23 files and
845 commands, and Component Model 0.3 async at 24/24 files and 153 commands.
ISS-348 subsequently replaced the reexported engine, event, and host-installer
types with facade-owned opaque types and hardened the interface audit.
