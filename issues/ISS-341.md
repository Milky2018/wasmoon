## Description
The stable `Milky2018/wasmoon/component` facade always constructs the portable
interpreter and exposes only a blocking `ComponentFunction::call`. Native JIT
construction remains duplicated in CLI-owned code, while Component Async tasks,
continuations, cancellation, and runtime shutdown are unavailable through the
stable interface.

## Design
Make `ComponentRuntime` the deep module that owns execution selection, component
task scheduling, invocation lifetime, and shutdown. Keep Store, core engine,
fiber, reactor, GC, and JIT contexts private. Provide explicit interpreter and
strict native adapters, an opaque `ComponentCall` lifecycle, blocking and
nonblocking driving, and a real MoonBit async join operation without creating a
second guest scheduler.

## Acceptance Criteria
- [ ] Stable callers explicitly select an interpreter or native execution engine.
- [ ] CLI and library execution share the same stable runtime path.
- [ ] `ComponentCall` supports nonblocking poll, blocking wait, async join, and idempotent cancellation.
- [ ] Runtime close terminates outstanding calls and releases native resources exactly once.
- [ ] Public interfaces expose no Store, core engine, fiber, reactor, GC, or JIT implementation types.
- [ ] Black-box tests and component conformance matrices verify interpreter and native behavior.
