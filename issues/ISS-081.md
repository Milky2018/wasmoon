## Description
`regalloc` and `machv_regalloc` are intended to be reusable allocation infrastructure, but comments and some policy descriptions still refer to Wasmoon, VCode, Wasmoon ABI roles, and VMContext-specific register behavior.

Some of this is only vocabulary debt, but it makes reusable modules look product-owned and can hide real policy coupling.

## Design
Audit these modules for Wasmoon-specific vocabulary. Reword pure comments to generic MachV/embedding ABI terminology. If any behavior truly depends on Wasmoon VMContext roles, replace it with explicit generic parameters or move the policy to `wasmoon_jit`/adapter code.

Non-goals: do not change allocation behavior unless required to remove real coupling.

## Acceptance Criteria
- [ ] `regalloc` and `machv_regalloc` no longer contain product-specific Wasmoon/VCode vocabulary except documented historical references that are still justified.
- [ ] Any VMContext/pinned-register behavior is generic, parameterized, or owned by an embedding adapter.
- [ ] Register allocation tests and WAST correctness gates pass.
