# ISS-059: Remove MilkIR types from machv_regalloc machine data

## Description
`machv_regalloc` still stores `Array[@milkir.Type]` in its machine-function
model. A register-allocation adapter should not depend upward on MilkIR's type
system. Return-value and ABI details should be represented in MachV ABI
metadata or kept in target/JIT planning code.

Evidence:
- `modules/machv_regalloc/function.mbt` has `result_types : Array[@milkir.Type]`.
- `modules/isa_target/lower/lower.mbt` fills the regalloc-side machine function with MilkIR result types.

## Design
After the production path is moved to `@machv.Function`, represent any needed
return ABI information in MachV-owned terms. Keep MilkIR types at the
MilkIR-to-MachV lowering boundary and avoid exposing them through regalloc
adapter APIs.

Non-goal: change the Wasm multi-value return semantics.

## Close Notes
Closed on 2026-07-06 as part of the `@machv.Function` production cutover.
The old regalloc-owned `VCodeFunction` carrying `Array[@milkir.Type]` was
removed, `machv_regalloc` APIs now use `@machv.Function`, and return-result
metadata is represented by `@machv.ValueKind`. The stale `Milky2018/milkir`
module dependency was removed from `modules/machv_regalloc/moon.mod`.
