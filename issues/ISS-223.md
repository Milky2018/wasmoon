# ISS-223: Add soft physical-register preferences to regalloc

## Description

Call ABI registers are currently represented as hard fixed constraints. That can eliminate moves, but allocator-generated edits may run before emitter-owned stack stores and overwrite their sources. Introduce an independent soft preference that improves placement without changing operand validity.

## Design

Keep `OperandConstraint` as a correctness contract. Add an optional same-class physical-register preference to VCode and regalloc operands. Use it only to order otherwise legal allocation candidates; never add spills, live-range splits, or constraint failures solely to satisfy a preference.

## Acceptance Criteria
- [x] VCode and regalloc operands represent constraints and preferences independently.
- [x] Allocation prefers the requested register when it is legal and no more costly.
- [x] Allocation ignores an unavailable preference without adding a move or failing verification.
- [x] Class-invalid and non-allocatable preferences are rejected structurally.

## Close Notes

Closed after adding an optional physical-register preference to Target VCode and regalloc operands. The backtracking allocator uses it only in candidate ordering; `AnyLocation` assignment and edit behavior remain unchanged. VCode checks register classes and regalloc rejects preferences outside the target's allocatable set.
