# ISS-646: Share native interpreter and JIT table storage

## Metadata
- Type: bug
- Status: in_progress
- Priority: 1
- Labels: runtime, jit, performance, tables
- Assignee: unassigned
- Created: 2026-10-20
- Updated: 2026-10-20
- External ref: https://github.com/Milky2018/wasmoon/issues/553

## Description
A cooperative integer loop resynchronizes every table entry at each suspension.
Repeated function-reference encoding also structurally compares an already
registered immutable type graph on every lookup. The current million-iteration
reproduction yields 976 times: an unused 1000-entry function table changes
execution from 3–4 ms to 1658–1887 ms on local macOS ARM64 release builds.

## Design
Cache registered instance mappings by live object identity. On native Store
admission, replace managed table construction state with one shared native
backing for interpreter, host and JIT accesses. Preserve stable Store function
identity through callable registration views; remove upload/download checkpoints
and full-table synchronization. Keep instruction execution, bounds, kinds,
limits, growth checks and lifecycle semantics common to native and wasm, with
only backing operations target-specific. Keep GC roots, cancellation, quotas,
rollback and terminal alias invalidation intact.

## Acceptance Criteria
- [x] Native Store tables have one authoritative backing; no execution-boundary copies remain.
- [x] Runtime and native writes, growth, aliases and parked shared-table calls remain visible.
- [x] Type identities survive imports and reject foreign, rolled-back and closed handles.
- [x] Re-run the million-iteration workload with unchanged return values and yield counts.
- [x] Relevant native/wasm regressions, common Table semantics, full gates and fresh sanitizers pass.
- [ ] Cross-platform CI passes on the submitted final head.
