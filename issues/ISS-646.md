# ISS-646: Avoid unchanged JIT continuation table synchronization

## Metadata
- Type: bug
- Status: in_progress

## Description
A cooperative integer loop resynchronizes every table entry at each suspension.
Repeated function-reference encoding also structurally compares an already
registered immutable type graph on every lookup. The current million-iteration
reproduction yields 976 times: an unused 1000-entry function table changes
execution from 3–4 ms to 1658–1887 ms on local macOS ARM64 release builds.

## Design
Cache registered instance mappings by live object identity. Track mutations of
both table representations at their shared logical owner, including native bulk
writes and growth. Acknowledge completed copies without creating synchronization
ping-pong. Invalidate native encodings when their module or function bindings
change. Preserve suspension admission, GC roots, cancellation and synchronization
at host boundaries; do not change scheduling frequency or deadlines.

## Acceptance Criteria
- [x] Unchanged tables are not copied after the initial synchronization.
- [x] Runtime and native writes, growth, aliases and parked shared-table calls remain visible.
- [x] Type identities survive imports and reject foreign, rolled-back and closed handles.
- [x] Re-run the million-iteration workload with unchanged return values and yield counts.
- [x] Relevant native/wasm regressions, full gates and fresh sanitizers pass.
- [ ] Cross-platform CI passes on the submitted final head.
