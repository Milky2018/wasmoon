## Description
The validate-before-instantiate audit compares effective-code source
positions, but does not account for nested control-flow blocks. Validation in
an unreachable or conditional block can therefore appear lexically before an
unconditional linker instantiation and make the gate pass.

## Design
Keep the scanner conservative. Only a validation call at function-body brace
depth zero establishes validation evidence. Every linker instantiation,
including calls in nested blocks, must occur lexically after such an
unconditional validation. This models structured dominance without requiring
an incomplete MoonBit CFG implementation.

## Acceptance Criteria
- [x] Validation inside a conditional block cannot satisfy the gate.
- [x] Validation and instantiation in the current facade continue to pass.
- [x] Comment, string, and source-order counterexamples remain rejected.
- [x] Security audit and Python gate tests pass.

## Close Notes

The audit now computes brace depth over the effective target function body.
Only a depth-zero validation establishes evidence; every linker instantiation,
including nested calls, must occur after that unconditional validation.
Unbalanced source fails closed.

The reported `if false { validate }` fixture failed before the implementation
change and now passes as a negative regression. A positive regression confirms
that a top-level validation correctly dominates a later nested instantiation.
The focused audit suite passed 22/22, the full Python suite passed 62/62, the
live component security audit passed, and native `moon check` completed
without errors.
