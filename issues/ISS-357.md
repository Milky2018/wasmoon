# ISS-357: Require dominating component validation in the audit

## Description
The validate-before-instantiate audit compares effective-code source
positions, but does not account for nested control-flow blocks. Validation in
an unreachable or conditional block can therefore appear lexically before an
unconditional linker instantiation and make the gate pass.

## Design
Do not approximate control-flow dominance with source-text ordering. Make
successful component validation part of the instantiation boundary so an
unchecked `Component` cannot be passed to `ComponentLinker::instantiate`.
Keep the source audit as a boundary regression check, not as the source of the
safety guarantee.

## Acceptance Criteria
- [x] Validation failure cannot be swallowed before component instantiation.
- [x] Every public linker instantiation path requires evidence produced by
      successful component validation.
- [x] The security audit rejects reintroduction of an unchecked instantiation
      boundary instead of attempting to infer MoonBit control flow.
- [x] Existing component runtime callers migrate to the checked boundary.
- [x] Component tests, security audit, and Python gate tests pass.

## Close Notes

Reopened on 2026-07-30. The previous lexical brace-depth check rejected known
conditional cases but did not prove that validation completed successfully on
every path reaching instantiation. In particular, a nested `catch` can consume
the `raise` that the scanner treated as propagation.

The final implementation removes source-order inference entirely.
`ValidatedComponent` is an abstract validator-owned type whose only producers
perform full validation. `ComponentLinker::instantiate` now accepts that
evidence instead of a raw component, so MoonBit type checking rejects every
unchecked call path. The facade, component-spec runner, and low-level runtime
tests now pass the validation result explicitly.

The generated-interface audit rejects a raw-component linker signature, a
missing evidence producer, or a constructible evidence struct. A public
black-box facade regression verifies that a parsed but invalid component
returns structured `ValidationFailed` before instantiation. Validation passed:
the component security audit, all 59 Python gate tests, 5 validator tests, and
all 540 tests in `Milky2018/wasmoon/testsuite`.
