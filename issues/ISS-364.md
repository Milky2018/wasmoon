## Description

The final 70-workload single-run matrix for ISS-266 retained two diagnostic
threshold exceedances. `aead_aegis128l` measured 1.3498 for the direct
guest-value ratio and 1.3434 for wall time; `aead_aegis256` measured 1.3640 and
1.3579 respectively. Both are Wasmoon divided by Wasmtime.

Earlier AEGIS work removed the pathological allocator and target-lowering
gaps, but these current-version results remain above the matrix thresholds of
1.15 for guest value and 1.20 for wall time.

## Design

Reproduce the residual gap with cache-isolated current-version measurements,
then attribute it across guest instruction count, allocation edits, memory-base
loads, code layout, and fixed process overhead. Implement only target-neutral
or generally profitable target changes; do not add workload-name checks,
reserved physical registers, or AEGIS-specific opcode patterns.

## Acceptance Criteria

- [x] Current-version AEGIS128L and AEGIS256 measurements separate guest value,
      wall time, compilation, and cache state.
- [x] Remaining hot-function differences are attributed with assembly and
      allocation evidence.
- [x] Any implementation has focused regression coverage and no workload
      special case.
- [x] The final report records direct ratios and any remaining limitation
      without treating a single pair as a statistical estimate.

## Notes

- 2026-07-30: Created as the explicit follow-up required by ISS-266. It does not
  block closing the independently accepted `pwhash_scrypt_ll` optimization.
- 2026-08-03: Current allocation evidence identified bundle eviction cost as
  the dominant residual gap. Fragment-local density correctly ranks individual
  ranges, but averaging that density over a small same-value bundle diluted the
  repeated cost of its loop-active fragments. A global sum and an unbounded
  two-hottest-fragment rule were both rejected: the former broke the
  `pwhash_scrypt_ll` hot loop, while the latter increased `codecs::func_51` from
  15 to 45 reloads and slowed the workload by about 13 percent.
- 2026-08-03: The accepted rule is target-neutral and shape-based. A bundle of
  three or four fragments belonging to one SSA value protects its two hottest
  active fragments. Two-fragment ranges, longer bundles, coalesced SSA values,
  and values with an interior cold live-through gap retain the existing density
  price so the allocator can still split cold regions. Focused tests lock all
  five cases.

## Close Notes

Closed after cache-isolated, same-host measurements and full correctness gates.

- The old current-version three-pair corpus baseline measured AEGIS128L at
  `1.362722` value / `1.354231` wall and AEGIS256 at `1.347917` /
  `1.340456`. One warmup plus five measured pairs on the final implementation
  measured AEGIS128L at `1.130525` / `1.126506` and AEGIS256 at `1.067383` /
  `1.064902`. Each workload used an isolated JIT cache; the warmup performed
  the fresh compilation and all measured pairs were cache hits.
- `func_30` fell from 19 slots / 17 spills / 19 reloads / 1356 bytes to
  10 / 8 / 11 / 1288 bytes in both workloads. Wasmtime still emits a
  1132-byte function with no stack allocation edits and retains the stable
  memory base, so target-level base reuse and residual register pressure remain
  the explicit limitation rather than being hidden as parity.
- Three alternating fresh compilations showed no material compile-time cost.
  AEGIS128L new/old medians were `0.9915` for module compile time and `0.9932`
  for register allocation; AEGIS256 was `1.0166` and `1.0176` respectively.
- The scrypt guard retained 19 slots / 18 spills / 28 reloads in `func_42` and
  measured `1.082046` value / `1.084130` wall over five pairs. After rejecting
  the over-broad candidate, 11 alternating old/new `codecs` runs measured
  new/old `0.9913` value and `0.9947` wall.
- Verification passed `moon check --warn-list +73`, 73 focused regalloc tests,
  all 2548 native tests, 986 wasm-gc plus 1562 native tests, and all 258 WAST
  files with 62,563 assertions in both interpreter and JIT modes.
