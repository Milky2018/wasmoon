## Description
`BumpAllocRecordFromStackInline` and `BumpAllocArrayFromStackInline` remain in
MachV instruction core as generic-looking pseudo-ops, but they still encode an
embedding-owned Wasm GC allocation protocol. Their emitter implementations know
about object headers, type indices, allocation cursor/limit slots, outgoing
stack buffers, safepoint metadata, registration helpers, slow allocation helper
ABI, and AArch64/AMD64-specific fast/slow control flow.

This is a remaining abstraction leak after ISS-072. ISS-072 removed the
Wasmoon-named opcodes, but the remaining pseudo-ops still keep too much runtime
and GC lowering behavior hidden inside `machv_emit`.

## Design
Move inline Wasm GC allocation lowering into `wasm_isa_lower` by expanding the
current emitter behavior into explicit MachV CFG before register allocation.
Use the current AArch64 and AMD64 emitter branches as the behavioral source of
truth; do not design a new allocator or change object layout.

The intended shape is:

1. `wasm_isa_lower/gc_lower.mbt` materializes the outgoing value buffer with
   `StoreToStack`, computes object size/header values, and emits explicit
   fast/slow/done blocks.
2. The fast path uses generic MachV loads, stores, arithmetic, comparisons,
   branches, and `CallExternal` for the registration helper.
3. The slow path uses `LoadSP`, `LoadSafepointId`, and `CallExternal` for the
   existing slow helper ABI.
4. Result merging is represented with ordinary MachV block parameters or the
   nearest existing MachV phi/block-param mechanism.
5. `machv_emit` only emits the resulting generic instructions; it no longer
   owns allocation control flow or helper ABI construction.

Non-goals:

- Do not replace the Wasmoon GC object layout.
- Do not change helper symbol names or native helper signatures.
- Do not hand-write a new GC allocation algorithm.
- Do not close this by renaming the pseudo-ops.

## Acceptance Criteria
- [x] `BumpAllocRecordFromStackInline` is removed from `modules/machv` and `modules/machv_emit`.
- [x] `BumpAllocArrayFromStackInline` is removed from `modules/machv` and `modules/machv_emit`.
- [x] `machv_emit` no longer contains Wasm GC allocation layout knowledge such as `type_idx`, `num_fields`, `gc.register_*_inline`, or `gc.alloc_*_slow` handling.
- [x] Inline struct allocation preserves the current fast path, registration call, slow fallback, safepoint metadata, and result value behavior on AArch64 and AMD64.
- [x] Inline fixed-array allocation preserves the current fast path, registration call, slow fallback, safepoint metadata, and result value behavior on AArch64 and AMD64.
- [x] Slow allocation fallback uses generic `LoadSP`, `LoadSafepointId`, and `CallExternal` instructions.
- [x] Relevant GC-focused WAST tests pass locally before the full suite.
- [x] AMD64 JIT correctness is verified with Docker before closing.
- [x] `moon info`, `moon fmt`, `moon check --target native --warn-list +73 --diagnostic-limit=200`, `moon test --target native --warn-list +73 --diagnostic-limit=200`, `python3 scripts/audit_module_boundaries.py`, and `git diff --check` pass.
- [x] `./install.sh` and `python3 scripts/run_all_wast.py --rec` pass with interpreter and JIT modes.
