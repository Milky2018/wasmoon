## Description

The unchanged Wasmtime `p1_poll_oneoff_stdio` program fails in both Wasmoon
interpreter and JIT modes at `1a33cb08` on macOS ARM64. The same guest binaries
and fixtures pass with Wasmtime 40.0.0.

With stdin inherited from `/dev/null`, the guest receives a `BADF` event where
it expects `SUCCESS` at guest line 64. With an open, unreadable stdin pipe,
the subsequent writable stdout/stderr polling returns `BADF` from the syscall
at guest line 116. stdout/stderr are valid writable regular files used to
capture guest output. Both cases include a 200ms clock subscription.

## Design

Minimize the probes and determine whether the problem is host readiness
registration for `/dev/null`/regular files, descriptor mapping, or another
cause. Do not infer the cause solely from the returned errno. Preserve mixed
clock/fd subscriptions and distinguish syscall failure from per-event errors.

## Close Notes

The fd payload was decoded at byte 12 instead of the aligned union offset 16;
several old hand-written tests repeated the same ABI error. A poisoned-padding
guest now guards the layout. Darwin `poll` independently reports `POLLNVAL`
for valid `/dev/null` descriptors; the extracted native readiness backend uses
`select` for these devices while retaining native error/hangup flags.

Both EOF and pending-stdin upstream scenarios pass in interpreter and JIT on
macOS ARM64 (`tmp/p1-poll-fixed/summary.json`). Native tests cover real pipes,
hangup, timeouts, regular files, invalid/negative fds, duplicate subscriptions
and descriptors above `FD_SETSIZE`. Linux verification is tracked separately
in the platform workflow; it is not inferred from the macOS result.
