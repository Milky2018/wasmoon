# ISS-093: Replace stringly typed ExtOp with a stronger extension contract

## Description
MilkIR extension operations are currently represented as `ExtOp` with
`dialect : String`, `opcode : String`, and untyped integer immediates. This
keeps MilkIR generic, but it gives frontend authors weak discoverability and
weak validation. Typos or mismatched immediate layouts are only caught later by
lowering adapters.

`wasm_milkir` demonstrates that dialect-specific helpers are useful, but the
core extension contract still needs clearer structure.

## Design
Design a stronger extension boundary that preserves MilkIR's generic ownership
while giving dialect adapters typed constructors, decoding, validation, and
documentation. Avoid moving Wasm semantics back into `milkir`.

Possible solutions include dialect-owned typed wrappers over `ExtOp`, a
validated descriptor format, or a trait-like lowering contract if MoonBit's
current package model supports it cleanly.

## Acceptance Criteria
- [x] MilkIR core remains free of Wasm-specific opcodes and imports.
- [x] Dialect adapters can expose typed constructors and validate immediate layouts.
- [x] `wasm_milkir` uses the stronger contract for its public helpers.
- [x] Unknown or malformed extension operations fail with clear diagnostics at the adapter boundary.
- [x] README examples show the intended extension workflow.
- [x] Native checks and relevant README tests pass.
