## Description

`compile_validated_module_to_jit` translates, optimizes, lowers, allocates,
frames, and emits every local function in one sequential loop. The functions
produce independent unlinked code objects, so this leaves available host cores
idle during cold compilation.

On the checked-in AEGIS-128L module, Wasmoon compilation is about 205 ms.
Wasmtime 40.0.0 takes 36.2 ms with parallel compilation disabled and 19.0 ms
with it enabled, a 1.91x wall-time improvement. Wasmtime materializes all
per-function results and then collects them in input order so both artifact
layout and the selected error remain deterministic.

Parallelism must follow the major single-function fixes rather than mask them.
Wasmoon function 56 currently takes 68.0 ms and `_start` takes 29.1 ms; together
they account for about half of attributed function compile time and set a hard
lower bound on parallel wall time.

## Design

Extract a function-local compilation job that returns the function index,
unlinked code, optional debug data, structured error, and function-local
metrics. Run those jobs through a bounded native worker pool when parallel
compilation is enabled.

- Treat translation and validation contexts as immutable shared inputs or
  create explicit worker-local state where mutation is required.
- Replace the process-global MilkIR metrics sink with job-local collection
  before enabling concurrent optimization.
- Serialize progress callbacks on the coordinating thread.
- Collect results in function-index order and report the first error in that
  same deterministic order, independent of worker completion order.
- Preserve a sequential mode for debugging, constrained hosts, and parity
  checks.
- Link, lay out, serialize, and install the final artifact only after ordered
  function results have been collected.

Do not parallelize through shared mutable compiler objects, JIT installation,
or cache publication.

## Acceptance Criteria
- [ ] Sequential and parallel compilation produce byte-identical artifacts for the same target, options, and source module.
- [ ] A module with multiple failing function jobs reports the same structured first error in sequential and parallel modes.
- [ ] Detailed metrics contain every function exactly once and are presented in function-index order.
- [ ] Progress callbacks remain serialized and monotonic even when worker completion is out of order.
- [ ] The worker count is bounded and parallel compilation can be disabled explicitly.
- [ ] A same-host paired AEGIS-128L benchmark demonstrates at least a 1.5x compilation wall-time improvement after ISS-371 and ISS-434 close.
- [ ] Native tests with allocation validation, WAST suites, component suites, corpus sweeps, cache round trips, and artifact loading pass in both sequential and parallel modes.
