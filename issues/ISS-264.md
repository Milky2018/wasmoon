## Description

The accepted ISS-259 policy reuses a stable environment field only once within
sixteen instructions. That bounded policy protected AEGIS from longer live
ranges, but `pwhash_scrypt_ll` demonstrates that the fixed global budget is too
coarse. Final AArch64 code loads the same stable linear-memory base 76 times in
`func_37`, 72 times in `func_41`, 24 times in the call-free `func_42`, and 66
times in `func_43`. Wasmtime loads it once in each function.

In `func_42`, the current one-reuse limit pairs nearby accesses but still
rematerializes the base throughout the initial read and final writeback phases.
Because this leaf kernel is called approximately 111 million times by the
workload, even loads outside the arithmetic loop become material.

## Design

Keep semantic legality and physical materialization separate. MilkIR remains
the source of context-field identity and stability. MilkIR-to-MachV lowering
preserves those facts as semantic MachV `EnvironmentField` operations. A small
MachV analysis derives target-neutral occurrence groups, call-free use regions,
context use counts, and whether one field value can replace the context carrier
without extending pressure.

AArch64 lowering consumes those facts and owns the profitability decision. It
may reuse one stable value across a complete reachable function when that value
replaces the context carrier, or within a call-free region when target register
pressure permits. Rejected candidates retain bounded rematerialization.
Mutable fields are never reused. Calls remain physical-pressure barriers even
when the semantic stability contract permits reuse across them.

Do not reserve an allocatable physical register. Reuse must remain ordinary
virtual-value allocation so other functions can choose rematerialization when
that is cheaper.

## Acceptance Criteria

- [x] `func_42` emits one linear-memory-base load for the complete call-free
      function.
- [x] `func_41` emits at most one base load per call-free dominance region
      instead of the current 72 loads.
- [x] The selected reuse does not reintroduce spill/reload traffic into the
      `func_42` arithmetic loop.
- [x] Tests cover stable leaf regions, calls, mutable fields, and a
      pressure-driven rematerialization case.
- [x] MachV analysis reports target-neutral environment-field groups and
      call-free regions without deciding a target allocation policy.
- [x] MilkIR-to-MachV tests lock preservation of field identity and stability.
- [x] No physical register is globally reserved for an environment field.

## Close Notes

Closed with a target-neutral MachV environment-field analysis and two AArch64
reuse paths. Stable values that replace an exclusive context carrier may span
dominated blocks and calls; other stable values use call-free regions guarded
by a conservative post-selection semantic integer-pressure estimate. Rejected
regions retain the ISS-259 short-window policy, and mutable fields remain
unconditionally rematerialized.

Against an independent worktree at commit `3be0cef8`, `func_41` drops from 72
memory-base loads to 4 and its allocation edits improve from 13 spills/56
reloads to 12/55. `func_42` drops from 24 loads to 1; total allocation edits
improve from 47 to 46, with no edits inside the arithmetic loop. AEGIS
`func_30` remains byte-for-byte identical at 30 loads, 17 spills, 19 reloads,
and 1,368 bytes.

Validation passed all 69 AArch64 lowering tests, both focused MachV analysis
tests, the MilkIR-to-MachV field-preservation test, `moon check --target all
--warn-list +73`, all 973 wasm-gc and 1,344 native tests, the reusable-module
boundary audit, and `git diff --check`.
