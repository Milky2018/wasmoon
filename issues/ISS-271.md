## Description
Wasmoon can parse, validate, instantiate, and execute Component Model binaries,
but it does not provide the `wasi:cli/command` host imports used by WASI
Preview 2 components or the current Preview 3 async command world. Component
programs therefore cannot use command arguments, standard I/O, clocks, random
data, files, polling, or sockets through the component ABI.

## Design
Keep the Component Model runtime embedding-neutral. Add a typed host-instance
construction seam there, then implement WASI policy and state in a
Wasmoon-owned module. A single host context, resource table, stream table, and
async state must be shared by all interfaces registered for one linker.

Implement stable Preview 2 before layering the current Preview 3 async
interfaces over the same capability model. Preview 3 remains explicitly
versioned and experimental.

## Acceptance Criteria
- [x] A stable Preview 2 `wasi:cli/command` component can run through the CLI.
- [x] Preview 2 CLI, clocks, random, I/O, filesystem, and sockets imports are
      registered with their exact component signatures and resource identities.
- [x] The pinned Preview 3 async command world can run cross-task stream,
      future, polling, and exit behavior without adapter aborts.
- [x] Filesystem and network access are capability-based and deny access that
      the embedding did not configure.
- [x] Focused host tests, component tests, WASI tests, formatting, interfaces,
      and the full MoonBit suite pass.
