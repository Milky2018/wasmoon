## Description
The HTTPS trust test and HTTP timeout tests shared one whitebox executable and
its cooperative event loop. The pinned async library's Windows TLS server
helper calls PFXImportCertStore synchronously; natural imports exceeding 500ms
were observed on both Clang and MSVC. A ready HTTP producer can lose its read
budget while an unrelated TLS test occupies that thread.

The recorded diagnosis is in
[HTTP timing interference](../docs/evidence/portable-interpreter-2026-10-19/http-timing-diagnosis.md).
The exact blocking operation in the original uninstrumented three-second CI
failure remains unproven. A controlled synchronous stall reproduces its two
error signatures. Upstream issue #669 reports the measured library behavior;
this issue owns the downstream test isolation, not an async-library repair.

## Design
Move the HTTPS trust test to the blackbox executable and exercise the existing
public HTTP/component interfaces. Keep HTTP timeout tests in the whitebox
executable; add no production API for test access. Retain successful custom
trust and rejected system-root verification, consume the complete request,
and preserve the existing HTTP deadlines and TLS outer deadline.

Use --no-parallelize for all native CI platforms to serialize executable
execution. This complements process isolation; the flag alone does not
serialize async tests within an executable.
