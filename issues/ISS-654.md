# ISS-654: Expose owned interpreter failure frames

## Description
Capture live guest frames before error unwind consumes a resumable context.
Keep diagnostics owned and preserve host/guest error provenance.

## Acceptance Criteria
- [x] Initial/resumed traps report owned module/function/position snapshots.
- [x] Existing APIs can avoid frame capture and retain typed RuntimeError.
- [x] Host failures remain distinct from guest traps; runtime causes stay typed.
- [x] Repeated suspensions, start traps, unnamed and cross-module functions work.
- [x] Handled guest exceptions cannot leave stale frames for later traps.
- [x] Snapshots remain readable after continuation consumption and Store close.

## Close Notes
- Add opt-in diagnostic entry/resume and start-instantiation APIs. The single
  owned failure value contains only a runtime cause, kind and immutable frames.
- Capture at the dispatch error boundary before unwind; transport owned indices,
  names and nested instruction paths, not native PCs or guest object references.
- Copy validated function names into instance debug metadata. Default calls do
  not allocate frame snapshots. A consumed continuation remains one-shot.
- Preserve Core publication/enclosing transaction behavior on start failure.
- Seven public regressions run on both native and wasm; disabling capture fails
  the frame assertions. No native backtrace or JIT diagnostic claim is made.
- Final full native 2898/2898 with GC/register-allocation verification and wasm
  1366/1366 pass locally; strict both targets and info/fmt pass.

## Review Follow-up
- 2026-10-21: Reproduced comment 6311145468: a guest continuation body trapped
  at function 0/path [0], but diagnostics contained only its caller's resume.
  Transport owned child snapshots across initial and resumed body callbacks,
  prepend them to the current caller chain, then rethrow the original error so
  guest exception handling and host/execution provenance remain unchanged.
- Share the opt-in flag with child execution contexts so enabling diagnostics on
  a parked parent also enables its existing body. Snapshots retain no live context.
- Five public regressions cover initial traps, repeated/late opt-in resumes,
  guest-effect resumes across calls, caught exceptions and host errors. Reverting
  the repair fails all four frame cases; the caught-exception control still passes.
- Full native 2903/2903 with GC/register-allocation verification and wasm
  1371/1371 pass, along with strict both targets, info/fmt and module boundaries.
  These are local results; current-head CI acceptance remains separate.
