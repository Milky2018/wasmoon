## Description
The old `compare_jit_interp` and WASI JIT tests manually constructed partial JIT runtime state. After deleting legacy fallbacks, those helpers were converted to interpreter-backed compatibility shims to avoid duplicating private runtime integration logic. Unit-level JIT execution coverage should be restored through the production runtime path.

## Design
Build the test harness around the same Store/Instance and JIT setup used by the CLI/WAST path. It should install hostcall and interpcall dispatchers, support captured WASI stdio/preopens, and exercise production-loaded JIT code without local copies of runtime initialization.

## Acceptance Criteria
- [ ] `compare_jit_interp` executes production-loaded JIT code for supported cases.
- [ ] WASI JIT tests execute production-loaded JIT code with captured stdout/stderr, stdin callbacks, and preopens.
- [ ] Unsupported signatures or bodies use the production interpcall fallback path, not a test-only interpreter shortcut.
- [ ] The harness does not duplicate VMContext layout or legacy setup logic.
- [ ] `moon test --target native --warn-list +73 --diagnostic-limit=200` passes.
