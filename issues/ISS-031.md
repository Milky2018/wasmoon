## Description
The old `compare_jit_interp` and WASI JIT tests manually constructed partial JIT runtime state. Unit-level JIT execution coverage should use the production runtime path and must not pass by routing through interpreter fallback.

## Design
Build the test harness around the same Store/Instance and JIT setup used by the CLI/WAST path. It should install the hostcall dispatcher, support captured WASI stdio/preopens, initialize memory/global/table/segment/GC state, and exercise production-loaded JIT code without local interpreter shortcuts.

## Acceptance Criteria
- [x] `compare_jit_interp` executes production-loaded JIT code for supported cases.
- [x] WASI JIT tests execute production-loaded JIT code with captured stdout/stderr, stdin callbacks, and preopens.
- [x] The harness does not use test-only interpreter shortcuts or interpcall fallback.
- [x] The harness does not duplicate VMContext layout or legacy setup logic.
- [x] `moon test --target native --warn-list +73 --diagnostic-limit=200` passes.
