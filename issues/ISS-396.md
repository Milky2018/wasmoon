# ISS-396: A type index of the wrong kind kills every command, during parsing

## Metadata
- Type: bug
- Status: closed
- Priority: 1
- Labels: parser, types, cli, robustness, breaking-change, agent
- Assignee: unassigned
- Created: 2026-08-05
- Updated: 2026-08-05
- External ref: none

## Description
Four lines of WAT killed every command in both binaries:

```wat
(module
  (type $s (struct (field i32)))
  (func (export "go") (type $s)))
```

| Command | Result |
| --- | --- |
| `wasmoon run`, `run --no-jit`, `disasm`, `explore`, `test` | exit 134 (SIGABRT) |
| `wasmoon-tools validate`, `wat2wasm` | exit 134 (SIGABRT) |

The message went to stdout, stderr was empty, and there was no usable exit
code, so none of the CLI's stream or status contracts applied.

Backtrace:

```
abort[FuncType]                     types.mbt:1339
  Module::get_func_type
  Parser::parse_func_def            parser_types_and_instr.mbt:865
  Parser::parse_module
  wat.parse                         api.mbt:20
  load_module_with_binary_from_path path.mbt:12
  run_wasm                          run.mbt:468
```

`run.mbt:468` is the load; validation is at `run.mbt:478`. **The abort ran
upstream of validation**, so no amount of validating could have caught it —
which is why ISS-395, which fixed the validator's own copy of this, did not
help here. Every command parses, so every command died.

The call site had a bounds check and no kind check:

```moonbit
let param_count = if type_idx >= 0 && type_idx < mod_.types.length() {
  mod_.get_func_type(type_idx).params.length()
```

Not an oversight. `get_func_type` returned `FuncType`, so "out of range" was
expressible as a guard and "names a struct" was not.

WAT only: the binary parser does not use these accessors.

## Design
Same root as ISS-395 — a total signature over a partial operation — but the
fix cannot be the same, because the callers are different. The three
accessors have ~116 call sites across eight packages, each with its own
error vocabulary: `WatError` in the parser, `ValidationError` in the
validator, traps in the executor, `ComponentRuntimeError`, the JIT frontend's
`LowerError`. An error type declared in `wasm_core` would force all eight to
catch and translate it.

`Option` instead, so each caller reports the failure in its own terms.

The deeper move is splitting one function into two, because the call sites
were doing two different things and nothing distinguished them:

```moonbit
pub fn Module::func_type_at(Self, Int) -> FuncType?           // decide
pub fn Module::validated_func_type_at(Self, Int) -> FuncType  // rely
```

`validated_` still aborts. That is correct for it: reaching it means a
module passed validation and then turned out to be wrong-kind anyway, which
is a defect here rather than in the input. What changed is that the claim is
now made where it is relied upon, in a name that says so, instead of being
hidden inside an accessor that unvalidated callers also used.

The old names are deleted rather than kept as aliases, so no caller can hold
the old behaviour by accident. `ModuleInstance` had a third copy of the same
three accessors and got the same treatment.

## Acceptance Criteria
- [x] The reproducer is rejected, not fatal, on every command in both

- [x] No accessor that aborts is reachable from a caller that has not
      validated its module.
- [x] Callers that rely on validation say so at the call site.
- [x] Covered by tests that run the built binary.

## Close Notes

58 call sites on each side of the split — that ratio is the finding. Half
the uses had proved nothing and half were relying on validation, and one
signature served both.

Two call sites turned out to have been written correctly all along:
`Store::get_func_type` and the local `get_func_type` in
`wasm_frontend/lower.mbt` both bounds-check and raise a specific error.
Neither was touched. The right shape existed in the repository; the three
accessor families had not caught up with it.

Public interface change, which is the point:

```diff
-pub fn Module::get_func_type(Self, Int) -> FuncType
+pub fn Module::func_type_at(Self, Int) -> FuncType?
+pub fn Module::validated_func_type_at(Self, Int) -> FuncType
```

Every command now reports the reproducer with a source location, for example
`Error: parse wat file error: at 3:32: type 0 is not a function type`.

Verified by running both binaries across all seven entry points, plus
ISS-395's three reproducers to confirm they stayed fixed. Regression tests
run the built CLI over five subcommands, since breadth was the defect. The
new `Option` accessors have their own tests for both halves of the
partiality — wrong kind and no such index, in both directions.

Full native suite 2571/2571, spec corpus 258/258 files and 62563 tests in
both interpreter and JIT modes.
