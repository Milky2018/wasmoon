# ISS-432: Unwind JIT exception handlers on structured control-flow exits

## Description
The JIT links each active `try_table` handler into the runtime exception chain,
but plain `return` and structured branches can leave the handler's lexical
scope without emitting the matching `try_table_end`. A later throw in the same
top-level invocation can then `siglongjmp` through a stale handler whose JIT
frame has already returned. The interpreter is correct; the minimized external
reproduction traps in the JIT on both macOS AArch64 and Linux AMD64, where
fortified glibc may reject the stale jump.

## Design
Treat handler cleanup as a property of every non-local control-flow edge. Record
the active handler depth on each structured control-flow target and emit cleanup
for precisely the handlers crossed by a taken edge. Route plain returns, tail
calls, unconditional and conditional branches, branch tables, and `br_on_*`
through the same depth-based unwind operation. Preserve handlers on fallthrough
and on branches whose target remains inside their lexical scope.

Make a mismatched runtime `try_table_end` an explicit JIT invariant failure
instead of silently retaining the handler chain. Do not weaken glibc
fortification or change the native-fiber trap transport fixed by ISS-431.

- [x] The external Issue #507 return reproduction matches the interpreter.

- [x] Branches that remain inside a `try_table` and untaken conditional edges preserve their active handlers.
- [x] A mismatched `try_table_end` fails explicitly instead of leaving a stale chain.
