## Description
WASI 0.3 needs a single-threaded runtime that can own host operation readiness,
cancellation, task wakeups, and the exclusive Store execution discipline.
`moonbitlang/async` is not the foundation for Wasm continuations and must not
define Wasmoon's runtime contract.

## Design
Create a small deep module for `Poll`, wakers, cancellable operations, a ready
queue, timers, and a reactor adapter. It must not import Component Model or WASI
packages. Component Async remains responsible for guest-visible tasks,
waitables, streams, and backpressure. No threads are introduced.

## Acceptance Criteria
- [ ] A deterministic test reactor drives tasks, timers, wakeups, and cancellation.
- [ ] Pending operations cannot retain mutable Store access.
- [ ] The interface does not expose platform file descriptors or Component Model types.
- [ ] The module has focused black-box tests and documented invariants.
