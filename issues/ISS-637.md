# ISS-637: Move native exception logical ownership into MoonBit

## Metadata
- Type: task
- Status: in_progress
- Priority: 1
- Labels: runtime, exceptions, ffi, ownership
- Assignee: unassigned
- Created: 2026-10-16
- Updated: 2026-10-19
- External ref: none

## Description
Review exception identities, payloads, tracing and activation state. Move logical registry and lifecycle decisions to MoonBit-owned data; retain only machine-code-facing views and native control-transfer primitives.

## Design
Start from complete executable paths and explicit ownership. Reuse the existing hostcall and root-visitor conventions; preserve machine layout and direct access where required. Move decisions with their state and delete old implementations. Do not equate wrapping C in more FFI functions with migration, or claim the complete architecture is repaired after one slice.

## Acceptance Criteria
- [x] Inventory exception payload/identity/activation/root ownership and the native operations required by compiled code.
- [x] Give logical exception state a single MoonBit owner, remove the corresponding C registry/policy and avoid copied mutable mirrors.
- [ ] Preserve throw/rethrow, cross-instance identity, reentry, GC, quota failures and terminal reclamation.
- [ ] Pass both-engine exceptions/GC regressions and sanitizer/platform acceptance; measure relevant overhead.
