## Description

Before fused shift selection, AEGIS `func_30` uses 19 stack slots, 17 spills,
and 22 reloads. Some pressure may disappear with fewer shift temporaries; the
remaining edits must be reclassified before changing allocator policy.

## Design

Re-run allocation after ISS-257, classify each remaining spill by live-range and
constraint cause, and fix only demonstrated avoidable pressure or coalescing
failures. Prefer shortening/rematerializing target temporaries before adding
allocator heuristics.

## Acceptance Criteria

- [x] AEGIS hot-function stack traffic decreases without increasing code size or

- [x] Full regalloc verification remains green.

### Post-ISS-257 allocation classification

| Value class | Slots | Spills | Reloads | Cause | Action |
| --- | ---: | ---: | ---: | --- | --- |
| Encodable address constants | 2 | 2 | 4 | Reused constants lived across the complete loop | Fold into `AddAddressImmediate` |
| Function parameters | 2 | 0 | 2 | Values are used again after the loop | Keep stack homes |
| Mutable state loaded before the loop | 1 | 1 | 1 | The pre-loop value is needed by the final update | Keep spill |
| Loop-invariant lookup indices | 7 | 7 | 7 | More long-lived indices than free registers at the loop header | Keep spills |

## Close Notes

The only avoidable class was the pair of encodable address constants.
`PointerOffset` now selects a typed `AddAddressImmediate` target operation,
with lowering and malformed-VCode regression tests. AEGIS `func_30` fell from
12 slots / 10 spills / 14 reloads to 10 slots / 8 spills / 10 reloads, and code
size fell from `1372` to `1340` bytes.

The three-pair cache-isolated median value ratio improved from `1.215873` to
`1.202732`; wall ratio improved from `1.211529` to `1.197873`. Regalloc,
MachV-regalloc, and AArch64 target suites passed `65/65`, `6/6`, and `201/201`;
the full native suite passed `2307/2307`.
