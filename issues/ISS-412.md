# ISS-412: Preserve spillsets across real live-range splits

## Metadata
- Type: task
- Status: closed

- Assignee: codex
- Created: 2026-08-11
- Updated: 2026-08-11
- External ref: none

## Description

Current bundle splitting partitions existing block-local segments at most
twice and then explodes the bundle into singleton segments. A singleton that
conflicts is immediately spilled, and split pieces lose their common spill
identity.

## Design

Introduce spillsets shared by every descendant of an original bundle. Split
inside live ranges at the selected program point, trim use-free carry regions
into a spill bundle, and give spillable bundles a non-evicting second-chance
register allocation before assigning overlap-aware spill slots.

## Acceptance Criteria
- [x] A split point inside a range produces two valid ranges with preserved
      uses and non-overlapping endpoints.
- [x] Split descendants retain one spillset and register hint lineage.
- [x] Use-free carry ranges move to the spill bundle.
- [x] Second-chance allocation runs before mandatory stack placement.
- [x] Focused pressure, loop, fixed-register, and differential tests pass.
- [x] Native warning check passes and allocation-quality evidence is recorded.
- [x] Deferred spill bundles preserve segment order when earlier ranges are
      appended after later ranges.
- [x] Conflict probes and the Linux x64 GC regression reject overlapping
      physical-register assignments.

## Close Notes

- Spillsets now own eviction weight, register-hint lineage, and their deferred
  spill bundle. Split descendants cannot increase their eviction authority by
  becoming shorter and denser.
- A singleton range splits around the maximal use-free gap containing the
  conflict point. The two useful sides and the gap have disjoint endpoints;
  independent pre-existing fragments remain separately allocatable.
- Deferred carry and failed bundles run through a spillset-priority,
  non-evicting second-chance queue before stack placement.
- Spill-home grouping now consumes spillset lineage directly rather than
  reconstructing it from the pre-split bundle plan.
- `moon check modules/regalloc --target native --warn-list +73` passed.
- `moon test modules/regalloc --target native --warn-list +73` passed: 83/83.
- On the 12,993-instruction spilling workload, output improved from 78,372 to
  78,264 bytes, spills from 5,356 to 5,355, and reloads from 9,029 to 9,003.
  The richer Backtracking path increased median regalloc time from 31,927 us
  to 39,275 us; this tradeoff is recorded rather than hidden and motivates the
  independent fast allocator in ISS-413.
- Regression closure: deferred spill bundles now insert segments in the same
  live-range order required by conflict probing, and bundle validation rejects
  any future ordering violation.
- The focused reverse-append probe passed, as did all 86 regalloc tests, 103
  x64 target tests, 223 AArch64 target tests, and all 13 `gc_v128` tests on
  Linux x64 with `MACHV_REGALLOC_VALIDATION=1`.
