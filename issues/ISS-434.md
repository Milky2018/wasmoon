# ISS-434: Eliminate empty and repeated target move planning

## Description

Target frame planning and emission repeatedly invoke the shared parallel-move
planner at instruction points that have no allocation edits. The planner still
allocates integer and FP/vector move arrays and runs both bank linearizers for
an empty move set. AArch64 frame planning walks every before/after point to
discover whether an emergency slot is needed, and target-frame verification
repeats the same complete discovery. Emission then plans the same points again.

Edge moves have a second avoidable cost. `Allocation::add_edit` already indexes
them by `(source block, successor index)`, but both target edge emitters rebuild
an edge move set by scanning all allocation edits.

On current AEGIS-128L metrics, frame planning takes 20.5 ms and emission takes
13.6 ms. Function 56 alone spends 10.3 ms in frame planning and 7.2 ms in
emission, despite most instruction points having no move work.

## Design

- After validating the concrete scratch roles required by the production
  planner contract, return an empty resolved plan before bank partitioning or
  temporary-array allocation when the move set is empty.
- Let frame planners and emitters skip the resolver when the indexed edit view
  for an instruction point is empty.
- Expose a read-only `Allocation::edge_edits_at` view backed by the existing
  edge index and stop scanning `Allocation::edits()` per CFG edge.
- Compute emergency-area necessity once during frame planning and carry the
  result as validated frame evidence instead of resolving every move set again
  in target-frame verification.
- Apply the shared data-structure and resolver improvements symmetrically to
  AArch64 and x64. Preserve the transfer-scratch roles and emergency spill-slot
  protocol for non-empty plans.

Do not cache complete emitted move instruction sequences in the frame unless
measurement shows that the remaining non-empty replanning is material. The
first change should remove empty and duplicate work without adding another
long-lived representation.

## Acceptance Criteria
- [x] Planning an empty move set performs no bank partitioning, cycle linearization, or temporary-array allocation; target callers with empty indexed buckets bypass the planner entirely.
- [x] Empty instruction edit buckets do not call the parallel-move planner in frame planning or emission.
- [x] A public read-only edge-edit lookup uses the existing `(block, successor)` index, and target edge handling no longer scans every allocation edit.
- [x] Emergency-area discovery is performed once per compiled function and target-frame verification does not repeat move resolution.
- [x] Non-empty integer and FP/vector cycles retain the transfer-scratch plus emergency-slot behavior from ISS-419 through ISS-423.
- [x] AArch64 and x64 frame, move, call, edge, allocation-validation, and native tests pass.
- [x] Current AEGIS-128L detail metrics record a material reduction in frame-planning and emission time without changing generated code except for layout-neutral metadata ordering, if any.

## Close Notes

Target move planning now uses the allocation's instruction and edge indexes,
bypasses empty buckets before constructing transfer arrays, and returns an
empty production plan before bank partitioning. Frame planning computes
emergency-slot necessity once and carries private, allocation-versioned
evidence so later verification remains cheap without accepting a mutated
allocation. AArch64 and x64 use the same protocol, retain concrete scratch-role
validation and emergency spill behavior, and emit identical code sizes while
substantially reducing frame and emission time.
