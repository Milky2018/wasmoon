# ISS-347: Isolate the low-level component-spec harness from CLI commands

## Description
The component-spec JSON script harness still lives in the CLI commands package
and directly constructs `runtime_impl` linkers, values, resources, and host
fixtures. Ordinary invoke and WASI command paths now use the stable
`ComponentRuntime`, but this test-only low-level surface keeps the CLI package
coupled to implementation details.

The harness cannot simply use the stable facade: conformance tests
intentionally construct malformed, partially typed, and host-defined runtime
shapes that the stable facade must reject.

## Design
Move the low-level fixture construction and script execution into a dedicated
Wasmoon-owned conformance package. Keep a small CLI adapter that selects the
engine and reports results. Do not broaden the stable component facade with
test-only escape hatches.

## Acceptance Criteria
- [ ] CLI commands contain no low-level component linker or canonical value construction.
- [ ] The conformance package is explicitly documented as unstable and test-only.
- [ ] Stable library and ordinary CLI execution continue to use `ComponentRuntime`.
- [ ] Existing component-script tests retain their exact structured results.
- [ ] No low-level conformance types enter the stable component package interface.
