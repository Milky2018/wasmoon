## Description
Cancellation captures and scheduling budgets are stored on contexts even though their mutable use belongs to invocations. Reconfiguring a context changes parked invocations and nested entries share scheduling progress.

## Design
Contexts retain defaults for subsequent invocations. Each native activation snapshots and retains the configured callback and owns its scheduling budget. Guest continuation entry shares the current caller's controls; reattachment selects the actual resuming caller. Independent reentry and parked root activations keep their own snapshot. Pop and abandonment release retained captures. Captured cancellation signals remain mutable; replacing the default callback does not replace active invocation callbacks. Preserve the generated-code ABI and standalone helper behavior.

## Acceptance Criteria
- [x] Independent entries isolate controls and continuation calls inherit actual caller controls.
- [x] Parked root invocations retain their callbacks despite default replacement/clear.
- [x] Pop and abandonment release captures exactly once.
- [x] Native, sanitizer, atomic-wait and external regressions pass.
