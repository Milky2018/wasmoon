## Question

Which call, return, tail-call, stack-argument, multi-value-result, clobber, context, and frame facts remain semantic in MachV, and which are introduced only when target lowering applies the selected native ABI?

## Acceptance Criteria

- [ ] MachV call semantics are specified without physical registers or host calling conventions.
- [ ] Target VCode ownership of fixed registers, clobbers, outgoing areas, prologues, epilogues, and special registers is explicit.
- [ ] Wasmoon embedding context and runtime-symbol responsibilities remain outside reusable compiler infrastructure.

## Notes
- 2026-07-15: This decision must cover both internal Wasm calls and foreign/helper calls.
- 2026-07-15: Claimed for a HITL Wayfinder decision session using grilling, domain modeling, and deep-module seam analysis. No production implementation will occur while resolving this ticket.
- 2026-07-15: Decided that MachV preserves a complete logical call contract: ordered typed parameters and results, explicit call arguments and SSA results, and an explicit ordinary `Ptr64` execution-environment value when the callee semantically requires one. MachV does not name or describe VMContext. Hidden return-area pointers, register placement, stack offsets, outgoing areas, and sret registers are ABI implementation details introduced only by target lowering.
- 2026-07-15: Decided that each MachV function entry and Semantic Call explicitly selects a small target-neutral `CallProtocol`: `Internal` for the embedding/compiler-defined convention or `Platform` for the host platform C ABI. Protocol is independent of direct, indirect, or external callee identity and contains no placement facts. Target lowering maps the two variants to statically prepared target ABI plans without opaque ids, registries, or runtime lookup.
