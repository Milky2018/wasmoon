# ISS-352: Move WASI command-world assembly behind one host helper

## Description
The stable component facade directly constructs `WasiComponentHost` and calls
seven Preview 2 and Preview 3 installation methods. This makes the facade own
WASI command-world composition and couples it to every host-interface change.

## Design
Keep the facade-owned private installer lifecycle, but move command-world
composition into one `wasi_component` helper. Split engine and host facade
definitions into focused files in the same package without changing the stable
public API.

## Acceptance Criteria
- [x] The stable facade calls one WASI command-world installation helper.
- [x] Preview-specific installation calls live only in `wasi_component`.
- [x] Engine and host facade definitions are in focused same-package files.
- [x] Generated stable interfaces and component tests remain unchanged in behavior.

## Close Notes

Added `wasi_component.install_command_world` as the single owner of Preview 2
and Preview 3 command-world composition. The stable facade retains the private
installer lifecycle but delegates linker population through that one helper.

Moved the stable engine and host installer definitions into focused
`runtime_engine.mbt` and `runtime_host.mbt` files in the same package. The
stable component interface did not change. Verification passed with facade
black-box tests at 17/17, the host lifecycle test, WASI host tests at 19/19,
full native tests at 2496/2496, and both Component 0.2 and 0.3 matrices in JIT
and interpreter modes.
