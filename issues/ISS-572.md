## Description
Command HTTP composition installs a synchronous native WASI reactor alongside moonbitlang/async HTTP tasks. HttpHost.drive calls progress_one_subtask_intrinsic, which can block in the native event loop while asynchronous HTTP work needs the same thread. The current types-only command guests and HTTP service suite do not exercise this mixed-I/O case.

## Acceptance Criteria
- [ ] Add a command guest that waits concurrently on native WASI I/O and HTTP.
- [ ] Integrate readiness without periodic polling or blocking the async scheduler.
- [ ] Verify cancellation and ownership on Linux, macOS and Windows.

Identified during source review, not covered by the 53/55 external result. The public `async.set_external_event_loop` and `ExternalEventLoop` interfaces support host-loop integration. Adapt the native reactor to this contract rather than implementing a separate waiter thread. Related: ISS-565.
