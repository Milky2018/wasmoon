# ISS-348: Seal stable component adapter ownership

## Description
The stable `Milky2018/wasmoon/component` package reexports
`ComponentEngine`, `NativeComponentExecutionEvent`, and
`ComponentHostInstaller` from adapter packages. Although the generated root
interface does not spell `runtime_impl`, callers can resolve the owner
packages' public methods, whose signatures expose `CoreExecutionEngine` and
`ComponentLinker`. The security audit only checks the root interface for the
literal `runtime_impl` string and therefore reports a false pass.

## Design
Make the stable facade own opaque engine and host-installer wrappers plus its
execution event type. Keep adapter values only in private fields, route the
low-level component-spec harness directly through the low-level adapter, and
teach the security audit to reject implementation-package owners in the
generated stable interface. Preserve ordinary engine selection, WASI host
installation, and runtime lifecycle behavior.

## Acceptance Criteria
- [x] The generated stable component interface contains no `runtime_impl`,
  `component_engine`, `component_host`, or `component_native` owner.
- [x] Native and interpreter engine selection remains available through
  facade-owned opaque values.
- [x] WASI host installation and component CLI execution continue to work.
- [x] The audit rejects a fixture which reexports an implementation-owned
  adapter type.
- [x] Focused facade, CLI, security, and full native tests pass.

## Close Notes

The stable facade now owns its opaque engine and host-installer wrappers plus
its native execution event enum. Low-level adapter values remain private, the
component-spec harness explicitly imports the low-level native adapter, and the
WASI command host is wrapped before reaching `ComponentRuntime::install`.

The security audit now rejects generated interfaces that import or reexport
runtime implementation owners. Verification passed with 2494/2494 native
tests, 11/11 audit tests, 15 stable facade black-box tests, the internal
host-lifecycle regression, 23/23 CLI error tests, Component 0.2 at 845 commands
in both JIT and interpreter modes, and Component 0.3 async at 153 commands in
both modes.
