## Description

AArch64 lowering analyzed every semantic instruction twice for definitions,
uses, constants, and folding selections, then scanned the complete instruction
slot domain a third time solely to find `pointer.offset p, 0` aliases. The
alias decision must run after other address folds, but discovering candidates
does not require another whole-function walk.

## Design

Record the dense instruction ids of zero-offset pointer candidates while the
second analysis pass already has their operation, operands, result, and
constant. Keep the final alias decision in its existing late position, but
visit only those candidates so final skip-result and GC-root facts remain
authoritative.

## Acceptance Criteria
- [x] Zero-offset aliasing does not scan unrelated instruction slots.
- [x] Register-offset memory folds retain priority over the late alias rule.
- [x] GC-root-bearing and already-consumed pointer offsets are not forwarded.
- [x] Existing AArch64 lowering and emission regressions pass unchanged.
- [x] Seven alternating cache-isolated AEGIS-128L pairs improve target analysis and complete target lowering.
- [x] AEGIS-128L allocation decisions and generated code remain unchanged.
- [x] Normal and strict native tests, formatting, warning-73 checking, generated interfaces, and module boundaries pass.
