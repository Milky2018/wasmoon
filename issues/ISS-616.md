## Description
The final PR #523 head failed Windows MSVC strict C compilation. In `modules/wasmoon_jit/jit_ffi/jit_context.c:215`, `new_safepoints` passes a `size_t` allocation size to the `uint32_t` parameter of `moonbit_make_external_object`, triggering C4267 and C2220. `git blame` attributes this allocation path to `48b46f00`, after the all-green ownership-migration baseline `de537e14`. Linux, macOS, Windows clang and sanitizer jobs passed on this PR head; these passes do not establish MSVC acceptance.

## Design
Check the allocation-size contract and count range before narrowing. A cast alone must not hide an oversized allocation followed by a larger memset or descriptor write. Preserve the shared RC owner and existing error/cleanup conventions.

## Fix validation
The shared allocation path now checks the count before multiplication and narrows only after bounding the payload to the MoonBit runtime's 30-bit external-object metadata representation. The infallible constructor aborts on an unrepresentable size before allocating or retaining payloads. A non-allocating boundary regression covers negative counts, zero, one, the largest valid count, the next count and INT32_MAX.

Local validation: the original narrowing error reproduces with `clang -fsyntax-only -Werror -Wshorten-64-to-32` before the fix and passes afterward. All 39 C stubs pass strict compilation; `moon info`, `moon fmt`, `moon check --target native --warn-list +73 --deny-warn`, and all 2,631 native tests pass. Windows MSVC CI remains pending.
