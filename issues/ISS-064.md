# ISS-064: Replace wasm_frontend to wasmoon_jit layout dependency

## Description
`modules/wasmoon/wasm_frontend` directly imports `wasmoon_jit` to read concrete
VMContext memory/table/global layout offsets during native lowering. That leaks
the concrete Wasmoon JIT embedding into the frontend layer and makes the
`EmbeddingEnvironment` abstraction too shallow.

Evidence:
- `modules/wasmoon/wasm_frontend/moon.pkg` imports `Milky2018/wasmoon_jit`.
- `modules/wasmoon/wasm_frontend/types.mbt` defines an `EmbeddingEnvironment` with only symbol-prefix and hidden-context-type fields.
- `modules/wasmoon/wasm_frontend/native_linear_lower.mbt` calls `@wasmoon_jit.vmcontext_layout()` and `@wasmoon_jit.memory_descriptor_layout()`.

## Design
Expand `EmbeddingEnvironment` or introduce a Wasm-lowering environment API that
supplies memory/table/global layout facts and helper bindings without importing
the concrete JIT package. Wasmoon JIT should provide an implementation of that
environment. Keep the lowered MilkIR shape behavior-compatible with the current
native frontend.

Non-goal: generalize Wasmoon runtime data structures beyond the fields the
frontend currently needs.

## Acceptance Criteria
- [x] `modules/wasmoon/wasm_frontend` no longer imports `Milky2018/wasmoon_jit`.
- [x] VMContext, memory, table, and global layout facts are supplied through an explicit embedding environment API.
- [x] Wasmoon JIT provides the production environment implementation.
- [x] Existing native lowering for memory/table/global operations is preserved.
