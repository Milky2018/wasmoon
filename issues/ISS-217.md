## Description

The regalloc core allocates three `block_count * virtual_register_count` boolean matrices for block definitions, live-in, and live-out. Large sparse control-flow graphs therefore retain roughly quadratic initialization and memory costs even after virtual-register lookup is indexed.

## Design

Use a sparse word-indexed bitset for each block, with efficient membership, insertion, removal, iteration, cloning, and union. Keep a compact small-set representation and switch to keyed words only when necessary. Compute liveness with a predecessor worklist and touch only words present in successor live-in sets.

## Acceptance Criteria
- [x] Liveness storage is proportional to populated bitset words rather than `blocks * vregs` booleans.
- [x] Sparse union reports whether a predecessor state changed without scanning the entire virtual-register universe.
- [x] Diamond, loop, unreachable-block, and large sparse-CFG tests preserve exact live-in/live-out behavior.
- [x] The indexed parameterized workload no longer converges toward quadratic matrix-initialization growth.

## Notes
- 2026-07-20: With only constant-time range lookup, 32/64/128/256/512-branch workloads took about 9.9/24.8/76.9/268.8/1,033.5 milliseconds, exposing the remaining dense liveness cost.
- 2026-07-20: Replaced the three dense Boolean matrices with adaptive sparse word sets and a predecessor worklist. Exact snapshots cover a diamond, a loop, an unreachable region, and virtual-register id 1,000,000.
- 2026-07-20: Final post-fix whole-pipeline 32/64/128/256/512 measurements were about 10.7/25.7/72.6/247/892 milliseconds. Native sampling no longer attributes the residual work to dense liveness initialization; remaining end-to-end work stays in ISS-211/212.

## Close Notes

Liveness now stores and propagates only populated 64-bit words. The dense `blocks * vregs` matrices and full-universe unions have been removed.
