# ISS-077: Move Wasm runtime-helper lowering out of isa_target

## Metadata
- Type: task
- Status: closed
- Priority: 0
- Labels: isa_target, wasmoon_jit, wasm_frontend, reusable-infra, abstraction-leak, agent
- Assignee: unassigned
- Created: 2026-07-07
- Updated: 2026-07-07
- External ref: none

## Description
`isa_target/lower` is intended to be reusable MilkIR-to-MachV lowering, but it still owns Wasm runtime-helper semantics. Current examples include `runtime_symbols.mbt` emitting `wasm.runtime.*` names and lowerers for Wasm GC, table, exception, and memory helper calls.

This leaks Wasmoon runtime embedding knowledge into a generic target-lowering module.

## Design
Split generic MilkIR lowering from Wasm extension lowering. Keep the existing lowering code behavior-preserving by moving Wasm-specific helper-symbol construction and Wasm extension lowering into Wasmoon-owned integration code or a clearly named Wasm lowering adapter.

Non-goals: do not redesign helper ABIs, do not change generated code behavior, and do not introduce interpreter fallback or workarounds.

## Acceptance Criteria
- [x] Generic `isa_target/lower` no longer constructs `wasm.runtime.*` symbols.
- [x] Wasm GC/table/exception/runtime-helper lowering is owned by Wasmoon or an explicitly Wasm-specific adapter.
- [x] Generic lowering entry points document what extension hooks or pre-lowered operations they accept.
- [x] Wasmoon JIT still lowers and executes supported Wasm operators through the intended MilkIR/MachV path.
- [x] Full native checks and WAST correctness gates pass.
