## Description
Restoring `compare_jit_interp` to the production-loaded native JIT path exposed a runtime mismatch for bulk-memory segment helpers. A simple `memory.init` case executes through the native frontend and `wasmoon.runtime.memory_init`, but the helper traps with `JITTrap("out of bounds memory access")` while the interpreter returns the copied byte.

## Design
Debug the native runtime helper ABI and production JIT context passed to `wasmoon.runtime.memory_init` and `wasmoon.runtime.data_drop`. Confirm whether the segment helper is receiving the correct VMContext pointer, initialized memory descriptor, data segment table, and `dst/src/len` values. The fix should live in shared production code, not in the testsuite harness.

## Acceptance Criteria
- [ ] `JIT: memory.init basic copy` executes through production-loaded native JIT and returns the same byte as the interpreter.
- [ ] `JIT: memory.init second byte` executes through production-loaded native JIT and returns the same byte as the interpreter.
- [ ] `JIT: data.drop and init with zero length` executes through production-loaded native JIT and matches the interpreter.
- [ ] `compare_jit_interp` can remove its `MemoryInit/DataDrop` compatibility guard.
- [ ] `moon test modules/wasmoon/testsuite/bulk_memory_test.mbt --target native --warn-list +73 --diagnostic-limit=200` passes without compatibility fallback.
