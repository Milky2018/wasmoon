## Description
Restoring `compare_jit_interp` to the production-loaded native JIT path exposed a runtime mismatch for bulk-memory segment helpers. A simple `memory.init` case executes through the native frontend and `wasmoon.runtime.memory_init`, but the helper traps with `JITTrap("out of bounds memory access")` while the interpreter returns the copied byte.

## Design
Debug the native runtime helper ABI and production JIT context passed to `wasmoon.runtime.memory_init` and `wasmoon.runtime.data_drop`. Confirm whether the segment helper is receiving the correct VMContext pointer, initialized memory descriptor, data segment table, and `dst/src/len` values. The fix should live in shared production code, not in the testsuite harness.

## Acceptance Criteria
- [x] `JIT: memory.init basic copy` executes through production-loaded native JIT and returns the same byte as the interpreter.
- [x] `JIT: memory.init second byte` executes through production-loaded native JIT and returns the same byte as the interpreter.
- [x] `JIT: data.drop and init with zero length` executes through production-loaded native JIT and matches the interpreter.
- [x] `compare_jit_interp` can remove its `MemoryInit/DataDrop` compatibility guard.
- [x] `moon test modules/wasmoon/testsuite/bulk_memory_test.mbt --target native --warn-list +73 --diagnostic-limit=200` passes without compatibility fallback.

## Notes
- 2026-07-05: Repro before the compatibility guard: temporarily inspect `compare_jit_interp` for `JIT: memory.init basic copy`; JIT returns `JITTrap("out of bounds memory access")`, while the interpreter returns `I32(187)`.
- 2026-07-05: Lowering order matches the helper shape (`ctx, memidx, data_idx, dst, src, len`), so the next investigation should instrument the actual C helper inputs and context state.
- 2026-07-05: After AArch64 call-frame and parallel fixed-move fixes, removing the `MemoryInit/DataDrop` guard no longer hangs. `data.drop` with zero length passes, but `JIT: memory.init basic copy` still mismatches (`JIT: I32(0)`, interpreter `I32(187)`), so the remaining blocker is actual data copy/context state rather than call return.
- 2026-07-05: Compared against `main:jit/jit_ffi/segment_ops.c` and `main:testsuite/compare.mbt`; segment setup/helper semantics already match the original implementation, and the original harness has no `MemoryInit/DataDrop` fallback guard.

## Close Notes
- Removed the `MemoryInit/DataDrop` compatibility guard from production `compare_jit_interp`; no runtime segment helper rewrite was needed after rebuilding the native stub state and fixing the shared fixed-call move path used by helper calls.
- Verification: `moon test modules/wasmoon/testsuite/bulk_memory_test.mbt --target native --warn-list +73 --diagnostic-limit=200` passed with 8 tests; `moon test modules/wasmoon/testsuite --target native --warn-list +73 --diagnostic-limit=200` passed with 487 tests.
