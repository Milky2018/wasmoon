## Description

MilkIR uses one instruction-count budget for two different costs: the cheap
dominator-order availability walk and the more expensive pointer, alias, and
memory-value analysis. Once the 300-instruction budget is exhausted,
`run_global_value_numbering_with_budget_and_analysis` stops the complete walk,
so later pure expressions and stable context globals receive no value
numbering at all.

On the checked-in `examples/algorithms/aead_aegis128l.wasm`, function 30 starts
with 60 occurrences of the same stable memory-base global. O2 reaches
`work_done=300` with `budget_exhausted=true` and leaves 41 occurrences, which
AArch64 lowering turns into 41 `ScalarLoad(W64, None, Ptr64, 8)` instructions.
The current Wasmoon function is 1,344 bytes and 336 instructions; Wasmtime
40.0.0 emits 1,132 bytes and 282 instructions with one memory-base load.

ISS-428 correctly restored bounded memory forwarding inside the analyzed
prefix, but deliberately retained the rule that no optimization happens after
the work budget. That rule is too broad for cheap, non-memory value numbering.

## Design

Separate the traversal and expensive-analysis budgets:

- visit the complete dominator tree for cheap pure-expression and
  `GlobalValue` availability;
- charge pointer-base inference, load forwarding, and cross-block memory-state
  work to a separate bounded memory-analysis budget;
- after that budget is exhausted, disable precise memory forwarding but keep
  cheap value numbering active;
- keep stable context-field reuse outside the memory prefix in short,
  target-neutral availability ranges so a single canonical value does not
  become live across an entire high-pressure function;
- conservatively invalidate mutable context globals at calls and unknown
  writes even when precise pointer analysis is unavailable;
- keep the implementation target-neutral and do not add an AEGIS peephole or
  reserve a physical heap-base register.

Reconcile the documented ownership with production behavior. If ordinary GVN
owns stable-field reuse, document that policy and remove any unused analysis
that claims target lowering owns a second pressure-based reuse decision. Do
not restore the deleted AArch64-only environment-field heuristic.

## Acceptance Criteria
- [x] A whitebox function with more than 300 instructions reuses eligible pure expressions and stable context globals both before and after the memory-analysis budget boundary.
- [x] Memory forwarding remains bounded and conservative after precise pointer analysis stops.
- [x] Mutable context globals are invalidated by calls and unknown writes outside the analyzed memory prefix.
- [x] AEGIS-128L function 30 emits at most 23 memory-base loads on AArch64 without adding more than one spill or reload relative to the 41-load baseline, and no target-specific special case is introduced.
- [x] The same shared policy is covered on x64.
- [x] The MilkIR and MachV documentation, tests, and production implementation name one owner for stable environment-field reuse.
- [x] AEGIS code size and guest execution improve without materially regressing the checked-in BLAKE2b and Salsa20 allocation/code-quality controls.
- [ ] Strict native tests, the WAST suites, the module-boundary audit, and the algorithms parity sweep pass.

  AArch64 AEGIS function 30 changes from 41 base loads, 1,344 bytes, and 11/12
  spills/reloads to 23 loads, 1,272 bytes, and 12/12. x64 changes from 41
  loads and 5,572 bytes to 23 and 5,457 with allocation edits unchanged at

  bytes and 15/42 to 3,980 and 15/44, while its guest median improves from
  0.678 to 0.650.
- 2026-08-28: Unbounded stable-global reuse was rejected by measurement. It
  reduced AEGIS-128L function 30 from 41 base loads to one and from 1,344 to
  1,236 bytes, but lengthened the base live range across the complete function,
  increasing spills/reloads from 11/12 to 17/19. Across seven cold-cache pairs,
  median guest ratio versus Wasmtime regressed from 1.248 to 1.634. A
  target-neutral 16-instruction, one-reuse range instead emits 23 base loads,
  1,272 bytes, and 12/12 spills/reloads; its seven-pair median is 1.093. The
  revised acceptance criterion records the empirically valid pressure bound
  rather than requiring a harmful one-load result.
- 2026-08-28: Seven current-version cold/warm pairs attribute about 172 ms of the AEGIS warm gap to execution/startup. The redundant hot-loop base loads are the concrete generated-code defect; residual runtime cost must be re-profiled after this issue closes.
- 2026-08-28: Current GVN spends about 75 us processing its 300-instruction prefix in function 30, so completing the cheap linear availability walk is expected to be negligible compared with the module's 205 ms compilation time. This is a hypothesis to verify, not a reason to remove the memory-analysis budget.
