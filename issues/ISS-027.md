## Description
The modules `milkir`, `machv`, `regalloc`, `machv_regalloc`, `machv_emit`, `aarch64_target`, `x64_target`, `wasm_core`, and `wasmoon_jit` are now split out, but their public surfaces still mostly reflect the migration path. External compiler authors need smaller, intentional APIs with clear ownership, names, and minimal Wasmoon-specific leakage.

## Design
Audit exported declarations and package interfaces. Keep API names that describe reusable compiler concepts, hide migration-only helpers, and document which packages are intended for external use. Do not remove behavior needed by Wasmoon; introduce compatibility wrappers only when necessary and with explicit deprecation notes.

## Acceptance Criteria
- [ ] Public `.mbti` surfaces for reusable modules are reviewed and unnecessary exports are removed or made private.
- [ ] Reusable modules expose documented entry points for IR construction, machine IR construction, register allocation, emission, and target selection.
- [ ] Wasmoon-specific runtime glue remains in `wasmoon` or `wasmoon_jit`, not in generic modules.
- [ ] `moon info` reflects the intended public API changes.
- [ ] `moon check --target native --warn-list +73 --diagnostic-limit=200` passes.
