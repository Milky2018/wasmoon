## Description

Migrate the Wasmoon-owned JIT compiler, unlinked code objects, installation, serialization, loading, and Cwasm format to the final MachV architecture, and move the standard WebAssembly binary encoder to `wasm_core`.

## Design

- Keep native runtime address resolution and executable-memory ownership in Wasmoon-owned packages.
- Treat the new Cwasm layout as a direct version break; reject v8 and every older version structurally.
- Use bounded decoding, an explicit compatibility manifest, and code-object verification before installation.
- Do not retain legacy artifact conversion or forwarding encoder APIs.

## Acceptance Criteria

- [ ] The JIT compiler produces verified unlinked code objects containing code, symbolic relocations and fixups, traps, GC metadata, stack maps, unwind data, and compatibility requirements.
- [ ] Installation resolves product runtime symbols, applies validated fixups, and exposes a structured failure path with no partially installed executable.
- [ ] The new Cwasm version round-trips valid artifacts and rejects old versions, malformed sections, invalid manifests, oversized inputs, and inconsistent metadata.
- [ ] Live JIT and loaded Cwasm artifacts have equivalent observable behavior across required regression suites.
- [ ] Artifact tests cover relocation, trap, GC, stack-map, unwind, resource-limit, compatibility, and installer-rollback contracts.
- [ ] The standard Wasm binary encoder moves to `wasm_core/encoder` with its tests, and no forwarding entry remains under retired `cwasm` APIs.
- [ ] Reusable compiler modules do not import Wasmoon-owned runtime or FFI packages.
- [ ] The common ISS-192 quality gates pass.
