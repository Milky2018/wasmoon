## Description

The initial asynchronous core host-function implementation proves the basic
park/wait/resume path but leaves invocation lifecycle state at the wrong
ownership boundaries. A parked interpreter continuation does not contribute
its operand-stack and frame-local references to Store GC roots. Core module
instantiation has no asynchronous start-function path. JIT async host drivers
and errors are stored once per module context rather than once per native
invocation, so nested or concurrently parked calls can observe another
invocation's state.

The public tests also use a white-box file despite exercising only embedding
APIs, and the runtime driver represents its state with independently mutable
integer fields.

## Design

Pin a snapshot of interpreter roots for exactly the lifetime in which an
execution continuation is parked, releasing it before resume and on every
terminal path. Split allocation/initialization from start-function execution
so synchronous and asynchronous instantiation share one implementation and
execute start exactly once. Key JIT async host state by the Store-owned native
invocation id, which is already the lifecycle identity used by stackful
continuations. Represent the host task driver with one explicit state enum.

MoonBit async functions do not expose a synchronously pollable Future object to
the JIT callback. Consequently the first encounter with an async import starts
a structured child task and parks Wasm once; this backend contract must be
documented instead of relying on scheduler-dependent `Task::try_wait` behavior.

## Acceptance Criteria
- [x] A parked interpreter continuation keeps all operand-stack and frame-local GC references alive and releases them after resume, cancellation, or failure.
- [x] Async instantiation executes an async-importing start function exactly once and synchronous instantiation rejects it with a structured runtime error.
- [x] Nested and multiple parked JIT invocations select async host state by native invocation identity, with no context-global driver or error slot.
- [x] Async host driver state has no invalid phase/field combinations and preserves cancellation and runtime-error identity.
- [x] Public async host APIs are covered by black-box tests, including GC, start, errors, repeated calls, cancellation, and JIT invocation isolation.
- [x] Documentation states the MoonBit backend's first-call parking contract.
- [x] Warning 73, strict native tests, module-boundary audit, formatting, and generated interfaces pass.
- [x] JIT calls through imported Wasm propagate async suspension and structured errors without flattening them to an unknown trap.
- [x] Async host reference results remain Store GC roots until consumed or cancelled, and the lease is released on every terminal path.

## Previous Close Notes

Interpreter continuations now hold a Store-owned GC root lease while parked,
including operand-stack values, frame locals, and hostcall arguments captured by
the retry action. Resume, cancellation, errors, and Store closure release the
lease. Async module/linker instantiation shares one allocation path with sync
instantiation and runs start exactly once; this also removed the old linker's
duplicate Store registration and segment/start initialization.

JIT async drivers and structured host errors are keyed by Store-owned native
invocation id. Concurrent parked calls and synchronous nested entry therefore
cannot observe another invocation's driver or error. The dispatcher is now a
method on `JITModuleContext`, and the host driver uses one explicit enum state.
Runtime-error recovery and host-function allocation/registration each have one
shared implementation.

Public black-box interpreter tests cover frame and argument roots, cancellation,
failure cleanup, repeated calls, sync rejection, async start, and exact-once
start. The strict JIT regression covers overlapping parked calls, sync entry
while another invocation is parked, structured host errors, cancellation, and
reuse. `moon info`, `moon fmt`, `moon check --target native --warn-list +73`,
`MACHV_REGALLOC_VALIDATION=1 moon test --target native` (2373/2373), the module
boundary audit, and `git diff --check` pass.

## Close Notes

The async host driver now transfers completed reference results through a
Store-owned GC root lease. The lease remains active after polling returns the
values and is released only when the next call site takes ownership or the
invocation terminates. Cancellation also withdraws ownership before stopping a
host task, so a host function that handles cancellation and still returns a
reference cannot leak a pinned root.

The JIT imported-Wasm dispatcher now enters the callee through an explicit
resumable interpreter seam using the native invocation's async driver. Parked
interpreter continuations are keyed by native invocation identity and preserve
normal return, repeated suspension, uncaught Wasm exceptions, and host-error
provenance separately. Native completion, error, and cancellation paths cancel
any retained interpreter continuation before discarding invocation state.

Black-box regressions cover GC between host-task completion and result
consumption, cancellation suppressed by the host function, two consecutive
async host calls through `JIT A -> interpreted B`, structured synchronous and
asynchronous errors, cancellation, and context reuse. `moon info`, `moon fmt`,
`moon check --target native --warn-list +73`, the module-boundary audit,
`git diff --check`, and `MACHV_REGALLOC_VALIDATION=1 moon test --target native`
(2377/2377) pass.
