# ISS-325: Preserve trailing-slash directory semantics in WASI component paths

## Metadata

- Assignee: codex

## Description
The shared component filesystem path splitter discards empty path segments.
Consequently, a path such as `regular-file/` becomes `regular-file`, losing
the requirement that the final resolved object be a directory. Preview 2 and
Preview 3 can therefore accept a regular file where the guest supplied a
trailing slash.

## Design
Represent the trailing-slash requirement explicitly at the capability-path
boundary and apply it before filesystem operations can erase the distinction.
Keep component-by-component beneath resolution and terminal `.`/`..`
semantics unchanged. Add public-host-interface regression tests for both
Preview 2 and Preview 3.

## Acceptance Criteria
- [x] `stat-at("regular-file/")` rejects a regular file in Preview 2 and Preview 3.
- [x] `open-at("regular-file/")` rejects a regular file in Preview 2 and Preview 3.
- [x] Equivalent paths ending at a directory remain valid.
- [x] Capability escape and terminal `.`/`..` regressions remain green.
- [x] No public API changes are introduced.

## Notes
- 2026-07-29: Initial issue.
- 2026-07-29: The initial black-box regression failed because both Preview 2
  and Preview 3 returned regular-file metadata and a live descriptor for
  `not-dir/`. The same test passes after preserving the trailing separator
  through the component and native capability-resolution seams.

## Close Notes
- Preserved the trailing-slash directory requirement in the shared
  `capability_parent_and_leaf` result instead of normalizing it away.
- Taught the native beneath resolver to apply `O_DIRECTORY` to the final
  component and to accept only trailing separators in its leaf argument.
- Added Preview 2 and Preview 3 black-box coverage for rejecting
  `not-dir/`, accepting `inside/`, and retaining the existing capability
  escape and terminal `.`/`..` behavior.
- Verified 42/42 WASI component package tests, 2473/2473 native tests, native
  warning 73 checks, strict C compilation with `-Wall -Wextra -Werror`, and
  all three pinned Component Model suites in JIT and interpreter modes:
  stable 845/845, async 153/153, and future-gated 387/387.
