## Description
`IRBuilder` currently allows some invalid construction states to fail silently.
For example, emitting an instruction without a current block can create and
return a `Value` without inserting the corresponding instruction into any
block. External users can accidentally build malformed functions and only see
the problem later during verification or lowering.

For a reusable compiler IR, builder misuse should be caught at the builder seam
with clear diagnostics.

## Design
Make builder operations that require a current block report failure explicitly.
Prefer a small, typed MilkIR builder error over silent no-op behavior or
late-stage aborts. Keep the common happy-path ergonomic for examples and
Wasmoon frontend lowering.

Do not redesign SSA construction wholesale in this issue.

## Acceptance Criteria
- [ ] Emitting instructions without a current block cannot silently create orphan values.
- [ ] Builder misuse has a clear error mode documented in README or API docs.
- [ ] Existing valid builder examples remain concise.
- [ ] Tests cover at least one missing-current-block misuse case.
- [ ] `moon check --target native --warn-list +73 --diagnostic-limit=200` and `moon test modules/milkir --target native --warn-list +73 --diagnostic-limit=200` pass.
