## Description
The old `IRBuilder` API allowed some invalid construction states to fail
silently. For example, emitting an instruction without a current block could
create and return a `Value` without inserting the corresponding instruction
into any block. External users could accidentally build malformed functions and
only see the problem later during verification or lowering.

For a reusable compiler IR, builder misuse should be caught at the builder seam
with clear diagnostics.

## Design
Replace `IRBuilder` with a Cranelift-style `FunctionBuilder`: create blocks,
`switch_to_block`, emit instructions directly on the builder, and `finalize`
the function. A new builder creates an entry block immediately, so the current
block is always present and straight-line functions can emit without an explicit
initial `create_block` / `switch_to_block` pair.

Do not redesign SSA construction wholesale in this issue.

## Acceptance Criteria
- [x] `IRBuilder` is removed from the public MilkIR API; `FunctionBuilder` is the builder entry point.
- [x] `FunctionBuilder` has no empty-current-block state that can silently create orphan values.
- [x] The default entry block behavior is documented in README or API docs.
- [x] Existing valid builder examples remain concise.
- [x] Tests cover direct emission into the default entry block.
- [x] `moon check --target native --warn-list +73 --diagnostic-limit=200` and `moon test -p Milky2018/milkir --target native --warn-list +73 --diagnostic-limit=200` pass.

## Close Notes
Closed by replacing MilkIR's `IRBuilder` public API with `FunctionBuilder`, keeping the Cranelift-style `create_block` / `switch_to_block` flow while emitting instructions directly on the builder. `FunctionBuilder::new` now creates the entry block immediately, so `current_block` is a total `Block` field rather than `Block?`, and straight-line builders can emit without a separate initial block setup. Added `finalize`, block-parameter helpers, README documentation, and tests that emit directly into the default entry block. Validation passed: `moon check --target native --warn-list +73 --diagnostic-limit=200`; `moon test -p Milky2018/milkir --target native --warn-list +73 --diagnostic-limit=200`; `moon test modules/milkir/README.mbt.md --target native --warn-list +73 --diagnostic-limit=200`; `moon test --target native --warn-list +73 --diagnostic-limit=200`; `python3 scripts/audit_module_boundaries.py`.
