## Description
The user requires invocation at most 1.05x V8 and compilation at most 1.5x
V8 for the same pinned asserted 20000-iteration property, after ISS-670 still
leaves a 2.98x invocation ratio. Preserve cold caches, serial compilation,
assertions, precise roots, quotas and the real runtime contract. Do not claim
completion from a subset, a single timing sample or unsafe admission hints.

## Design
Measure current invocation and compiler phases first. Rank and independently
control repeated checked-view admission, root/allocation boundary work and
repeated compiler analysis. Implement measured changes with failing semantic
or work-count regressions, both target selection and full platform-appropriate
local gates. Keep reusable modules product-neutral and preserve raw-entry,
legacy layout, reentry, alias, GC and rollback safety.

### Current implementation: internal views and generated allocation
- 2026-10-23: The user authorized prioritizing internal admission reuse and a
  machine-code allocation success path. The prior source-hashed checkpoint is
  preserved as historical evidence; its numerical targets remain unmet.
- Reproduced retained reservation-helper calls on both targets. Untimed original
  workload counters also found 84,061,688 struct-view helper calls, including
  repeated admission of the same exact canonical object.
- Implemented an embedding-supplied heap layout, derived from native declarations.
  Generated allocation rejects before mutation for missing capacity/layout/identity
  pages, verification, failure injection and bound quota reservations. Budgeted
  Stores retain shared atomic admission; collection/retry retain precise roots.
- The retained admission cache belongs to the heap, uses exact reference,
  canonical identity, shape and field count, and never roots or owns the object.
  Retirement, runtime-type changes, payload growth, compaction and close invalidate
  it. Current context type mappings are still read on every lookup; raw-entry,
  subtype, legacy and verification checks retain their original fallback.
- Rejected the constructor-result physical-view prototype: semantic regressions
  passed, but it eliminated no helper calls on the actual guest. It was removed
  rather than credited as an execution improvement.
- Unbounded generated allocation made cold initializers and register allocation
  much larger. A per-function expansion budget of 512 and a runtime-prepared
  identity/live-list capacity window bound this cost without precharging objects
  or quotas. Collection and rollback invalidate the window. Codegen revision 20
  invalidates prior generated artifacts; the JIT ABI remains 8.
