## Description

ISS-459 completed the authoritative DFG and bounded acyclic optimizer
architecture, but it intentionally migrated only the compact integer rewrite
set. The deleted matcher described 276 rules, while the current direct
dispatcher implements only the core identities, limited reassociation,
conversion folding, simple comparisons, and select folding.

Complete the useful semantic migration without restoring the deleted e-graph,
schema, generator, generic matcher, or saturation loop. The old rules are an
inventory, not a specification: several are insufficiently guarded or can
increase live ranges, so every migrated rule needs a fresh legality and
profitability argument.

## Design

Keep rules as handwritten, root-opcode-specific MoonBit in the existing
acyclic optimizer. Prefer in-place canonicalization or a strictly cheaper
staged candidate. Do not introduce target costs into MilkIR or duplicate rules
owned by target address and instruction selection.

Migrate in evidence-backed groups:

1. Boolean/integer comparison normalization and safe extend/reduce rules.
2. Bitwise, mask, shift, and rotate rules.
3. Select, min/max, and integer absolute-value canonicalization.
4. Vector splat and exact constant rules.
5. Deep reassociation only where use counts and measured allocation pressure
   prove it profitable.

Classify rejected legacy rules explicitly as obsolete, target-owned, unsafe,
or unprofitable. In particular, do not migrate narrowing arithmetic through
extensions without an overflow proof, trapping division/remainder rewrites
without definedness facts, or floating-point identities that relax exact Wasm
semantics.

## Acceptance Criteria
- [ ] Every deleted rule family is classified as migrated, obsolete, target-owned, unsafe, or pending.
- [ ] Safe comparison and extend/reduce rules use direct root-opcode dispatch and have exact IR regressions.
- [ ] Safe bitwise, mask, shift, and rotate rules have exact IR regressions.
- [ ] Safe select and vector rules have exact IR regressions.
- [ ] No migrated rule expands a shared definition or worsens the representative corpus materially.
- [ ] Strict native validation, warning-73, generated interfaces, formatting, and module-boundary checks pass.
- [ ] Optimizer documentation describes the bounded directional aegraph rather than the deleted union-find implementation.

## Notes
- 2026-09-03: Created after auditing the post-ISS-459 optimizer. Architecture migration is complete, but only roughly one fifth of the deleted rule declarations have direct equivalents. The useful remaining set is expected to be substantially smaller than the raw legacy count because the old catalog contains unsafe and target-owned transforms.
- 2026-09-03: The first comparison batch added boolean-test elimination, one-bit comparison mask elimination, modular common-addend cancellation, unsigned-zero canonicalization, sign facts for zero extension, and profitable comparison narrowing through single-use extensions. Nine exact IR tests include constant-left normalization, extended booleans, and a shared-extension non-expansion control. A ten-pair alternating cold AEGIS-128L comparison against `93188c08` measured 56,322.5 us versus 55,969.5 us compile medians (+0.63%, within noise) while generated code fell from 58,576 to 58,300 bytes (-276 bytes); all twenty runs exited successfully. Capture: `/tmp/wasmoon-iss461.iCMzmL`.
- 2026-09-03: The legacy extend catalog is not treated as authoritative. In particular, pushing addition through unsigned extension is invalid when the narrow addition overflows, and replacing wide subtraction of unsigned-extended operands with a sign-extended narrow subtraction is invalid for positive differences above the narrow signed maximum. Those rules remain rejected until a range proof can establish legality.
- 2026-09-03: The bitwise/shift batch added complement identities, absorption and nested-idempotence, XOR cancellation, opposite-rotation cancellation, constant-rotation combination, shift-overflow folding, saturating arithmetic-shift combination, and constant shift-pair masks. Nine exact IR tests and four multi-input JIT/interpreter differential tests cover edge values and masked rotation amounts.
- 2026-09-03: The first bitwise/shift implementation repeated definition lookup through small matcher helpers. Ten alternating AEGIS pairs showed no code-size change and a +4.49% compile median, so that implementation was rejected. The retained direct dispatcher resolves each bitwise child once and folds shift-pair matching into the existing nested-shift path. Twenty alternating cold pairs against the comparison-only binary measured 56,401.5 us versus 56,074.5 us (+0.58%, within noise), with identical 58,300-byte generated code and all forty runs successful. Capture: `/tmp/wasmoon-iss461.iCMzmL`.
- 2026-09-03: The first two retained batches pass 2,237/2,237 native tests with `VCODE_REGALLOC_VALIDATION=1`, warning-73 checking, generated-interface refresh, formatting, and the reusable-module boundary audit. ISS-461 remains open for the remaining rule-family inventory, select/vector work, and documentation correction.
