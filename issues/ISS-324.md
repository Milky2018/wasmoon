# ISS-324: Keep synchronous Component JIT traps on their native fiber

## Description
Linux AMD64 rejects two valid Component Model 0.3 async trap tests with:

```text
*** longjmp causes uninitialized stack frame ***
```

The component adapter sends resumable calls through native continuations, but
still sends `RunToReturn` calls through the older dedicated Wasm-stack entry.
A nested synchronous core call can therefore save its trap target on one
native fiber and trap from another stack. glibc's fortified `siglongjmp`
correctly rejects that cross-stack transfer before Wasmoon can report the
structured Wasm trap.

## Design
Use the native continuation entry for all Component JIT core calls. A
`RunToReturn` request immediately drives the continuation to completion and
rejects any unexpected suspension. This keeps each trap activation and its
jump buffer on the same retained native stack without weakening glibc
fortification or introducing an uninstrumented longjmp shim.

## Acceptance Criteria
- [x] Component JIT `RunToReturn` calls use native continuation entry.
- [x] Unexpected suspension in a `RunToReturn` call is cancelled and rejected.
- [ ] Linux async-0.3 JIT passes `drop-stream.wast`.
- [ ] Linux async-0.3 JIT passes `futures-must-write.wast`.
- [ ] The full Linux AMD64 and macOS ARM64 workflows pass.
