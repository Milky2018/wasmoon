# ISS-450: Allocate directly into VCode allocation tables

## Metadata

- Status: open

## Description

`machv_regalloc` still flattens every VCode function into an owned
`VCodeFunctionView`, asks generic regalloc to build an `AllocationPlan`, and
then walks all values, operands, edits, spill slots, and GC roots again to build
target `Allocation` tables. AEGIS-128L spends about 1,055 us constructing the
view and 3,393 us translating the plan, in addition to allocator work.

## Design

Make VCode satisfy the allocator's read interface through non-owning indexed
access and let an injected allocation sink receive dense value, operand, edit,
spill-slot, and safepoint results in target table shape. Standalone regalloc
tests use an in-memory sink adapter. Production uses the VCode allocation-table
adapter. Keep allocation policy and target-independent tests inside `regalloc`.

Do not merge target instruction semantics into generic regalloc, weaken strict
validation, or retain the old copy path as a second production implementation.

## Acceptance Criteria
- [x] Production regalloc does not construct owned copies of VCode layout, operands, clobbers, successors, or edge arguments.
- [x] Production regalloc does not materialize a generic `AllocationPlan` and then translate every result into another allocation object.
- [ ] The generic allocator remains target-independent and is testable through one non-owning function interface and one result-sink interface.
- [x] Allocation decisions, spills, reloads, moves, scratch roles, safepoint roots, frame layout, and generated code remain unchanged.
- [ ] Seven cache-isolated AEGIS-128L runs remove the measured view and plan-translation costs and improve complete regalloc materially.
- [x] Normal and `MACHV_REGALLOC_VALIDATION=1` native tests, both targets, formatting, warning-73, generated interfaces, and module boundaries pass.

The prototype was rejected rather than hiding the displaced cost. Captures: `_build/aegis-iss450-indexed-view.lb8yQD4n`, `_build/aegis-iss450-dense-index.5X8AzmkB`, and `_build/aegis-iss450-index-scratch.bZm7G88n`.

The builder preserves the old path's location-class, slot-owner/type, and index validation even when the final expensive verifier is disabled. Seven isolated AEGIS runs reduced plan translation from 3,553 us to 3,063 us, total regalloc from 32,016 us to 30,701 us, and module compilation from 86,412 us to 83,738 us. Capture: `_build/aegis-iss450-sink-prelim.xufRl8tR`.

- 2026-08-30: The generic plan's finalized value and operand location arrays are now adopted directly as the VCode allocation tables. Spill ids retain identity across the boundary and carry their owning value separately so VCode reconstructs typed stack-slot metadata without remapping every location. Local shape, location-class, slot-owner, size, and alignment checks remain active even when final allocation validation is disabled. This removes copied layout/body/metadata/root collections and repeated owner-handle index recovery from the adapter while retaining root ownership and assigned-location checks. Seven alternating cache-isolated AEGIS-128L pairs against `0aa8ec30` reduced median plan translation from 1,589 us to 1,249 us. All 14 runs preserved the exact code and allocation vector. Remaining translation is dominated by edit conversion and indexing. Capture: `_build/aegis-iss450-dense-safepoints-paired.Dufbyh`.
