## Description

`machv_regalloc` still flattens every VCode function into an owned
`VCodeFunctionView`, asks generic regalloc to build an `AllocationPlan`, and
then walks all values, operands, edits, spill slots, and GC roots again to build
target `Allocation` tables. AEGIS-128L spends about 1,055 us constructing the
view and 3,393 us translating the plan, in addition to allocator work.

## Design

Make VCode satisfy the allocator's read interface through non-owning indexed
access and let an injected allocation sink receive dense value, operand, edit,
spill-slot, and safepoint results in target table shape. Standalone regalloc
tests use an in-memory sink adapter. Production uses the VCode allocation-table
adapter. Keep allocation policy and target-independent tests inside `regalloc`.

Do not merge target instruction semantics into generic regalloc, weaken strict
validation, or retain the old copy path as a second production implementation.

## Acceptance Criteria
- [ ] Production regalloc does not construct owned copies of VCode layout, operands, clobbers, successors, or edge arguments.
- [ ] Production regalloc does not materialize a generic `AllocationPlan` and then translate every result into another allocation object.
- [ ] The generic allocator remains target-independent and is testable through one non-owning function interface and one result-sink interface.
- [ ] Allocation decisions, spills, reloads, moves, scratch roles, safepoint roots, frame layout, and generated code remain unchanged.
- [ ] Seven cache-isolated AEGIS-128L runs remove the measured view and plan-translation costs and improve complete regalloc materially.
- [ ] Normal and `MACHV_REGALLOC_VALIDATION=1` native tests, both targets, formatting, warning-73, generated interfaces, and module boundaries pass.

## Notes
- 2026-08-29: ISS-443 removed nested copied collections but retained one complete flattened copy and a second allocation result representation. This issue closes that remaining seam mismatch.
- 2026-08-29: Work started after ISS-449 closed. A partial view change that removed cached value/type tables reduced the measured view phase from 1,067 us to 967 us, but repeated type lookup shifted cost into allocator work and regalloc rose from 32,016 us to 32,599 us. It was rejected. The retained design must change the collection interface to indexed access and remove the whole view atomically. Rejected capture: `_build/aegis-iss450-direct-values.QWjGDkLM`.
- 2026-08-29: A complete indexed input prototype removed the owned view and reduced its phase to 32 us, but the VCode and regalloc operand vocabularies still require conversion on every phase read. Even after caching each instruction's operands inside multipass hot loops, three isolated runs measured 34,267 us total regalloc versus the 32,016 us baseline. The prototype was rejected rather than hiding the displaced cost. Captures: `_build/aegis-iss450-indexed-view.lb8yQD4n`, `_build/aegis-iss450-dense-index.5X8AzmkB`, and `_build/aegis-iss450-index-scratch.bZm7G88n`.
- 2026-08-29: Work continues on the output boundary first. Removing the 3,553 us generic-plan translation does not impose repeated hot-loop reads; a later input change must either use one canonical allocation operand vocabulary or prove a faster non-owning representation end to end.
- 2026-08-29: The first retained output step adds a dense VCode `AllocationBuilder` for an already verified plan and reads plan operands/edits by index instead of allocating snapshot arrays. The builder preserves the old path's location-class, slot-owner/type, and index validation even when the final expensive verifier is disabled. Seven isolated AEGIS runs reduced plan translation from 3,553 us to 3,063 us, total regalloc from 32,016 us to 30,701 us, and module compilation from 86,412 us to 83,738 us. All runs retained 57,396 code bytes, func_56 at 15,256 bytes, 350 spills, 1,023 reloads, and 83 register moves. The generic plan still exists, so the issue remains open. Captures: `_build/aegis-iss450-checked-builder.eJxJJZy4`.
