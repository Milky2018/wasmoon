# ISS-329: Invalidate shared memories when their owning store closes

## Metadata
- Type: bug
- Status: closed
- Priority: 1
- Labels: runtime, memory, ownership, safety, asan, agent
- Assignee: codex
- Created: 2026-07-30
- Updated: 2026-07-30
- External ref: none

## Description
`Memory` copies currently retain an immutable native descriptor pointer.
`Store::close` frees that descriptor without invalidating aliases held by the
caller or another Store. Such aliases can access freed memory, and closing two
Stores containing the same Memory can free the descriptor twice.

## Design
Replace the copied descriptor pointer with a shared, invalidatable handle.
Store closure must invalidate the handle before freeing the descriptor, making
all aliases observe the closed state. Raising Memory operations report a
structured closed-memory error; non-raising compatibility helpers return their
existing failure sentinel without calling native code. Do not expose ownership
internals through the public API.

## Acceptance Criteria
- [x] Public black-box tests reproduce close-after-access and cross-Store aliasing.
- [x] Closing a Store invalidates every alias of each registered Memory.
- [x] Closing multiple Stores containing the same Memory frees its descriptor once.
- [x] Raising Memory operations report a structured closed-memory error.
- [x] Non-raising Memory operations do not call native code after invalidation.
- [x] Native and isolated ASan/UBSan regressions pass.

## Close Notes
- Replaced the copied descriptor pointer with a shared invalidatable state.
  Store closure marks it closed before freeing, so every Memory alias observes
  invalidation and repeated closure cannot double-free the descriptor.
- Added structured `MemoryClosed` failures for raising operations while keeping
  the existing sentinel behavior of non-raising compatibility operations.
- Added public API black-box coverage for retained aliases, cross-Store aliases,
  exact-once closure, sentinel operations, and structured errors.
- Validation: focused black-box tests 3/3, runtime package tests 40/40, full
  native suite 2478/2478, module-boundary audit, 49 script tests, and isolated
  ASan/UBSan black-box/internal/white-box binaries all passed.
