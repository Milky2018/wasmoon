# ISS-179: Interpret poll subscription counts as unsigned size values

## Metadata
- Type: bug
- Status: closed
- Priority: 2
- Labels: wasi, wasip1, poll, abi, memory-safety, interpreter, jit, tests, agent
- Assignee: codex
- Created: 2026-07-15
- Updated: 2026-07-15
- External ref: none

## Description
WASIp1 defines `nsubscriptions` as the unsigned 32-bit `size` type, but the MoonBit host boundary receives it as `Int` and currently treats every value with the high bit set as a negative count. Those values return `EINVAL` as though the caller supplied zero subscriptions instead of being interpreted as large counts whose input and output arrays fail memory validation.

## Design
Reinterpret the incoming i32 bits as `UInt`, distinguish only zero as the empty-subscription case, validate array byte lengths with widened unsigned arithmetic, and convert to `Int` only after proving that the count is representable and the guest ranges are valid.

## Acceptance Criteria
- [x] Zero subscriptions continue to return `EINVAL`.
- [x] Counts with the i32 high bit set are treated as unsigned and fail with the repository's structured memory-range error when their arrays do not fit.
- [x] Count-times-element-size arithmetic cannot wrap into a small accepted range.
- [x] Interpreter and JIT public ABI tests cover `0x80000000` and `0xffffffff`.

## Notes
- 2026-07-15: A public ABI probe returned `EINVAL` in both engines for `0x80000000`; the value is an unsigned WASIp1 `size`, not a negative count.

## Close Notes

- 2026-07-15: `nsubscriptions` is reinterpreted as `UInt`; array byte lengths and endpoints are checked with widened unsigned arithmetic before conversion back to `Int`.
- 2026-07-15: Public WAST regressions cover both high-bit count boundaries in interpreter and JIT modes.
