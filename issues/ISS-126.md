## Description
MilkIR now verifies definition uniqueness, dominance, use types, CFG targets, block-edge arguments, and return signatures, but instruction verification remains incomplete. Many opcode families validate only operand arity or fall through without checking operand types, result counts, or result types. `CallIndirect`, `CallPtr`, SIMD operations, and untyped `Custom` instructions can therefore pass verification with malformed contracts. `FunctionBuilder::finalize()` also returns an invalid function without validation.

## Design
Define complete, conservative instruction contracts at the MilkIR boundary and make the builder finalization boundary reject invalid IR. Keep structural SSA validation independent from opcode validation, avoid a permissive catch-all opcode branch, and require custom or dialect operations to provide a verifiable contract or be rejected. Preserve the existing dependency boundary: reusable MilkIR must not import Wasmoon product packages.

## Acceptance Criteria
- [ ] Scalar, comparison, select, conversion, memory, SIMD, and control-related instruction families validate operand and result arity and types.
- [ ] `CallIndirect` validates operands and results against its `Signature`; `CallPtr` validates its declared argument and result counts.
- [ ] `Custom` and extension instructions cannot bypass verification without an explicit contract.
- [ ] `FunctionBuilder::finalize()` cannot return structurally invalid, unverified IR.
- [ ] Every test in `modules/milkir/verify_contract_wbtest.mbt` passes without weakening its assertions.
- [ ] Existing verifier, native, and wasm-gc test gates remain green.
