## Description
`Milky2018/regalloc` currently exposes allocator implementation details and lacks one small canonical entry point that represents the intended user-facing API. Users see `allocate_linear_scan`, live-range builders, backtracking helpers, CFG utilities, and planner internals at the same level, so it is unclear which surface is stable compiler infrastructure and which surface is allocator implementation.

## Design
Introduce a canonical public facade for the root package: a compact program model, allocator configuration, allocation result queries, and verifier entry points. The facade should make the normal use case obvious without exposing linear-scan or backtracking engine internals as the main API. Keep the implementation target-independent and do not introduce MachV or Wasmoon concepts.
