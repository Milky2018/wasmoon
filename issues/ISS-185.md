## Question

What is the smallest concrete MoonBit API sketch that demonstrates one shared Target VCode function, block, control-flow, and allocation shell parameterized by closed `AArch64Inst` and `AMD64Inst` types without reintroducing a union opcode?

## Design

Use one generic shared shell—`VCodeFunction[Inst]`, `VCodeBlock[Inst]`, and `Terminator[Inst]`—parameterized by a closed target instruction type. AArch64 and AMD64 compilation select `AArch64Inst` or `AMD64Inst` and then remain separate statically typed pipelines. The shell owns CFG structure, block/instruction identity, body-versus-terminator position, and traversal. Register allocation depends on a one-method static `AllocatableInst` interface that projects operands and constraints; it does not see a target opcode union, target name, or printer data.

Wasmoon supports AArch64 and AMD64 as the required native targets. The architecture may admit one later `RISCVInst` adapter without changing the shell, but it does not provide an open-ended runtime ISA plugin mechanism. Target selection therefore branches at orchestration into a finite set of statically typed pipelines rather than erasing them behind an existential or union opcode.
