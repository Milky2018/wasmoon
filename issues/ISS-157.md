## Description
GVN separately maintains memory-read, memory-write, and candidate opcode matches. The candidate check repeats trapping and store cases already rejected by the effect classifier, while the load-CSE comment does not match the current behavior because all memory operations are rejected first.

## Design
Derive memory reads, writes, and conservative GVN safety from ISS-155 semantic facts. Keep result arity, dominance, value numbering, and e-graph representation policy in their owning passes. Preserve current load-CSE behavior during this refactor; enabling additional load CSE requires a separate correctness change.

## Acceptance Criteria
- [x] GVN memory reads and writes are derived from the centralized semantic summary.
- [x] GVN candidate selection contains no repeated div, remainder, conversion, or store opcode lists.
- [x] Current candidate behavior is locked by regression tests before migration.
- [x] Comments accurately describe the implemented load behavior.
- [x] Targeted MilkIR tests and warning checks pass.
