## Description
The opcode-semantics regression test samples only one representative from each non-pure category. Exhaustive implementation matches force new variants to be classified, but they do not prevent an existing trapping, memory, vector-memory, or call variant from being moved accidentally into a pure branch.

## Design
Use a table-driven snapshot with an independent expected semantic summary for every non-pure built-in opcode constructor. Cover constructors rather than every payload combination, since payloads do not affect these semantic categories. Keep a pure scalar sentinel and retain conservative extension coverage.

## Acceptance Criteria
- [x] All non-pure integer binary and conversion constructors have explicit expected summaries.
- [x] All generic memory constructors have explicit expected summaries.
- [x] All vector-memory constructors have explicit expected summaries.
- [x] Both call constructors and dialect extensions have explicit expected summaries.
- [x] No production API or semantic implementation changes are required.
- [x] Targeted MilkIR tests, full native tests, warning checks, and module-boundary audit pass.
