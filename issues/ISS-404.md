# ISS-404: Add a materialization-cost predicate for cheap pure values

## Description

Rematerialization needs to know what rebuilding a value actually costs.
Without that, the choice between rebuilding and spilling is a guess.

Measured cost of materializing a constant on AArch64, against a reload
from a spill slot at one instruction:

| value | instructions |
| --- | ---: |
| 5, 1020, 65535, 65536 | 1 |
| 4294967295, 305419896 | 2 |
| 81985529216486895 | 4 |
| `f64.const 3.14159` | 5 |

At one instruction, rebuilding matches the reload and additionally saves
the spill store, the stack slot, and the cross-block live range, so it
strictly wins. At four or five it is several times the reload and is
likely a loss. The interesting middle is two instructions, which should
be measured rather than assumed.

This is the piece Cranelift structurally lacks: its remat rules live in
the target-independent mid-end, so they cannot consult a cost, and the
result is a blanket rule over every `iconst`, `f32const` and `f64const`
regardless of what materializing one costs on the target. See ISS-403.

## Design

Add a predicate over an instruction that answers whether the value it
defines is cheap enough to rebuild at a use site. Requirements:

- Pure and side-effect free, single result, and either operand-free or
  depending only on values that are live at the use anyway.
- Conservative first cut, target-independent: integer constants whose
  value is a 16-bit immediate shifted by 0, 16, 32 or 48. That is exactly
  the single-`movz` form on AArch64 and is also one instruction on x64,
  so it needs no target knowledge to be correct on either.
- Exclude float and vector constants. Measured at five instructions on
  AArch64, so they lose to a four-byte reload.

`milkir` is a leaf module with no Milky2018 imports and no target
knowledge, which is the same position Cranelift's mid-end is in. Rather
than give it a target dependency, leave a seam: an optional cost callback
on the optimizer entry point, supplied by the caller that already knows
the target. `compile_wasm_body_diagnostics_for_target` has that
information today. The seam is added here and left unused; the
conservative predicate above is what ships first.

Non-goals: the ALU-with-one-constant-operand forms. Rematerializing
`y = a + k` swaps which value is live rather than reducing the count, and
without recursive remat it can move the long live range onto `a` instead.
Revisit only with measurements.

## Acceptance Criteria
- [ ] A predicate identifies single-`movz`-form integer constants as
      cheap to rebuild.
- [ ] Float and vector constants are excluded.
- [ ] The optimizer entry point accepts an optional target cost callback,
      defaulting to the conservative predicate.
- [ ] Unit tests pin the boundary cases, including 65536 as cheap and
      4294967295 as not.
