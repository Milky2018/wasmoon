## Description
`machv`, `milkir_machv`, and `machv_emit` no longer import Wasmoon-owned modules, but they still encode a fixed embedding runtime-context schema. The reusable infrastructure currently knows about fields such as function table, table0 base, globals, memory directory, debug current function, and GC allocation cursor/limit. Those fields are Wasm/Wasmoon embedding concepts and should be owned by `wasm_isa_lower` and `wasmoon_jit`.

## Design
Replace the fixed `EmbeddingContextLayout` field schema with generic context access metadata and symbolic/fact-based lowering. Move Wasm/Wasmoon interpretation of context offsets into Wasm-owned adapters. Preserve behavior by mechanically moving existing lowering/emission logic where possible, not rewriting algorithms.

## Acceptance Criteria
- [x] Reusable infrastructure no longer exposes fixed runtime-context fields such as function table, table0, globals, memory directory, debug function, or GC cursor/limit.
- [x] Wasm/Wasmoon-owned code still provides the concrete VMContext layout and maps it into generic lowering/emission inputs.
- [x] Generic peepholes reason from facts/capabilities, not from Wasm/Wasmoon offset names.
- [x] Direct code-symbol emission does not require generic emitters to know the Wasmoon function table layout.
- [x] Native checks, tests, boundary audit, and rebuilt full WAST gates pass.
