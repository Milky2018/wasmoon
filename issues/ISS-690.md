# ISS-690: Keep segment-created arrays in canonical native layouts

## Description
JIT `array.new_data` and `array.new_elem` bypass the canonical typed allocator
and create legacy 16-byte slots, even when the complete layout is registered.
Besides wasting payload space, these allocations prevent a typed-only young
collector from admitting the heap. The interpreter already uses typed layouts.

## Acceptance Criteria
- [x] Reproduce missing canonical metadata in the original JIT path.
- [x] Reuse the shared typed allocator when the context supplies a known array
  layout, preserving the single non-collecting attempt and all caller checks.
- [x] Check canonical identity, compact allocation size, values and subsequent
  collection for packed integers, i32/i64, f32/f64 and reference elements in
  both engines at optimization levels 0, 2 and 3.
- [ ] Pass the full runtime, integration, sanitizer and exact-head CI gates.

## Notes
- 2026-10-25: A temporary first-untyped-allocation probe identifies
  `gc_heap_alloc_array_wide` in the regex fixture. The new public regression
  passes its interpreter control and fails JIT canonical identity before the
  change. All seven element-kind cases pass after using the shared allocator;
  their eight-byte payloads occupy 48 bytes including headers/alignment.
  Unknown low-level embeddings retain their existing wide representation.
  Diagnostic source and binary are removed; timing uses uninstrumented builds.
