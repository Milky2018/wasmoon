# ISS-440: Preserve SysV stack alignment across expanded x64 tail calls

## Metadata
- Type: bug
- Status: in_progress
- Priority: 1
- Labels: x64, jit, abi, tests
- Assignee: agent
- Created: 2026-08-28
- Updated: 2026-08-28
- External ref: https://github.com/Milky2018/wasmoon/issues/508

## Description
Expanded x64 internal tail calls synthesize a return thunk when the callee
requires a larger stack-argument area than the caller received. The current
emitter subtracts an aligned argument area plus one eight-byte return slot,
which enters the callee with `%rsp % 16 == 0` instead of the SysV-required
`%rsp % 16 == 8`. A later call from that callee into a native runtime helper
therefore violates the platform ABI and can fault in otherwise unrelated C
code.

## Design
Make x64 frame planning own a complete expanded-tail-call transfer plan: the
synthetic return slot, stack-argument area, alignment padding, pre-jump stack
adjustment, and return-thunk cleanup. Argument placement and emission must
consume this plan rather than reconstructing offsets independently. Verify the
callee-entry alignment invariant in the frame verifier. Add both an
architecture-independent emission regression and an x86-64 native helper that
reports the actual entry-stack alignment.

## Acceptance Criteria
- [x] Expanded tail-call frame planning explicitly represents the synthetic return slot, stack arguments, and alignment padding.
- [x] Every x64 internal callee enters with `%rsp % 16 == 8` for normal, size-preserving, and expanded tail-call edges.
- [ ] An expanded tail-call callee can invoke a native helper without violating SysV stack alignment.
- [x] Deterministic emitter and native x86-64 regressions cover the expanded path directly.
- [x] Strict native tests pass with and without `MACHV_REGALLOC_VALIDATION=1`.

## Notes
- 2026-08-28: Created from GitHub issue #508. Current emission subtracts `callee_args_size + 8` before jumping to the callee and the return thunk restores only `callee_args_size`.
- 2026-08-28: The architecture-independent emitter regression failed before the fix with `(false, false)` for the aligned transfer and cleanup byte sequences, then passed after emission consumed the complete frame plan.
- 2026-08-28: The corrected 32-byte expanded layout uses an 8-byte synthetic return slot, 32-byte stack-argument area, 8-byte alignment padding, 48-byte transfer adjustment, and 40-byte thunk cleanup. This preserves the SysV 8-mod-16 callee-entry invariant without overwriting the caller's return address.
- 2026-08-28: `moon test --target native` and `MACHV_REGALLOC_VALIDATION=1 moon test --target native` both passed 2673/2673 on Darwin arm64. The native x86-64 helper regression compiles but skips on this host; Linux x64 execution remains the close gate.
