# ISS-062: Remove Wasm runtime pseudo-ops from MachV instruction core

## Metadata
- Type: task
- Status: open

- Assignee: unassigned

- Updated: 2026-07-06

## Description
MachV instruction definitions still include Wasm/runtime-specific concepts such
as `CallConv::Wasm`, VMContext memory-base loads, Wasm function indices, GC
allocation helpers, and type-check helper operations. This prevents MachV from
being a generic machine IR.

Evidence:
- `modules/machv/instr/instr.mbt` defines `CallConv { Wasm, C }`.
- The same file contains instructions such as `LoadMemBase`, `LoadFuncAddr`, `CallDirect(Int, ...)`, GC allocation pseudo-ops, and subtype-check pseudo-ops.
- `modules/machv/instr/moon.pkg` imports `Milky2018/wasm_core/types` for display support.

## Design
Replace Wasm/runtime pseudo-ops with generic MachV operations, relocation
records, external-symbol references, target pseudo-ops, or Wasmoon-owned
lowering hooks. Move any Wasm-specific display or type logic out of MachV core.
Preserve behavior by migrating each existing pseudo-op to an equivalent
target/JIT lowering path one group at a time.

Non-goal: remove all pseudo-ops. Generic target pseudo-ops are acceptable when
their semantics are not Wasm-specific.

## Acceptance Criteria
- [ ] `modules/machv/instr` does not import `wasm_core`.
- [ ] MachV core instruction names and payloads no longer encode Wasm function indices, VMContext layout, or Wasmoon runtime helper semantics.
- [ ] Wasmoon JIT or ISA target lowering owns the replacement logic for calls, memory-base access, GC helpers, and subtype checks.
- [ ] Existing generated code behavior is preserved.
- [ ] Completeness TODO comments are added where a Wasm-specific pseudo-op cannot be fully generalized in one change.
- [ ] `moon info --target native` is run and generated `.mbti` diffs are reviewed.
- [ ] `git diff --check` passes.
- [ ] `moon check --target native --warn-list +73 --diagnostic-limit=200` passes.
- [ ] `moon test --target native --warn-list +73 --diagnostic-limit=200` passes.
- [ ] `python3 scripts/run_all_wast.py --rec --dump-failures --timeout-sec 20` passes.
