## Description
`Milky2018/milkir` is usable today, but its generated public interface exposes
too much implementation detail: many individual optimization passes, CFG
utilities, e-graph internals, mutable IR fields, and low-level helper types all
appear next to the intended user-facing `Function`, `IRBuilder`, `verify`,
`print`, and optimization entry points.

This makes the package hard for external compiler authors to learn and makes it
unclear which APIs are stable.

## Design
Define and document a small stable facade for normal users. Keep internal
debugging and advanced optimization hooks available only when they are
intentionally public, or move them behind clearly named subpackages.

Preserve current behavior and existing Wasmoon use. Do not remove a public entry
point until there is either a stable replacement or a clear compatibility plan.

## Acceptance Criteria
- [x] `modules/milkir/README.mbt.md` identifies the stable user-facing entry points.
- [x] Public APIs that are intended only for internals, experiments, or debugging are moved, hidden, or explicitly documented as advanced/unstable.
- [x] Normal examples use the facade path rather than direct internal helpers.
- [x] `moon info` reflects the intended public surface.
- [x] `moon check --target native --warn-list +73 --diagnostic-limit=200` and relevant README tests pass.
