# ISS-305: Introduce Store-scoped native execution state

## Description
The current native Wasm stack belongs to one JIT context and is reset for every
call. A Store may have multiple parked component tasks and nested JIT entries,
so continuation state cannot live in one context-global stack or TLS singleton.

## Design
Add Store-scoped native execution state owning the active activation stack,
parked invocation leases, and resource-release lifecycle. Each invocation gets
an exclusive resource identity. ISS-306 materializes that resource identity as
a guarded native fiber; ISS-307/308 attach trap and GC registrations.

## Acceptance Criteria
- [x] Multiple native invocations can be parked with distinct resource leases.
- [x] Nested native entries restore the previous activation.
- [x] A retained release closure can pin code, instance, and buffers.
- [x] Cancel and return release execution state exactly once.
- [x] Ordinary native entry is registered under the owning Store.
