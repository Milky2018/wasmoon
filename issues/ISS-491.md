# ISS-491: Isolate WAST component instances in separate runtime stores

## Metadata

## Description
The pinned Wasmtime WAST runner creates a fresh Store for each component instantiation. Wasmoon's script runner shares one ComponentLinker/Store across the entire file, incorrectly sharing trap state, host resources and task state between independent top-level instances. Correcting store-wide trap poisoning in ISS-490 exposed this mismatch.

## Acceptance Criteria
- [x] Host registration is reusable and every top-level component instantiation receives its own linker/store.
- [x] Named instance invocations retain their original live store; rebinding creates a fresh instance.
- [x] All retained stores are closed after the script.
- [x] Original component suites and misc component lane pass without new exclusions.

## Close Notes

- Moved host registration into script_host.mbt and store/instance ownership into ComponentScriptRuntime. Each successful instance retains its own linker; failed instantiations close their linker immediately. Named invocations retain the original ComponentInstance rather than rebinding its store.
- Reflected only core module definitions and resource types, matching the pinned Wasmtime adapter. Resource origins survive re-export through another store and aliases map to one receiving-store resource type; distinct origins remain distinct. Host fixture resources now use the linker's allocator instead of hard-coded IDs.
- The resource-type-identity WAST independently verifies aliases, re-export and inequality against the pinned oracle. Instance-store-isolation verifies that a fresh top-level component does not inherit an earlier trap.
- Verified component gate: local 119, stable 845, async 153 and future-gated 387 commands per engine. Native validation pending.
