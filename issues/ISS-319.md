# ISS-319: Encode Preview 3 output error futures correctly

## Metadata

## Description
Preview 3 stdout and stderr futures currently return
`Variant(1, Some(Variant(0, None)))` after a real write failure. The future
element is `result<_, error-code>`, where `error-code` is an enum represented
by `U32` or `S32` at the component-value seam. Consuming the malformed future
therefore traps with `result type mismatch` instead of returning
`error(error-code::io)`.

## Design
Add a red-capable regression that forces output failure and consumes the
result through canonical lowering. Encode the error payload as
`Variant(1, Some(U32(0)))` in both the initial-write and resumed partial-write
failure branches. Do not change the public builder or runtime interfaces.

## Acceptance Criteria
- [x] A forced stdout write failure is returned as `error(error-code::io)` without a canonical type mismatch.
- [x] The resumed output branch uses the same valid value shape.
- [x] Stdout and stderr share the corrected output-future implementation.
- [x] Targeted WASI component and complete native tests pass.
