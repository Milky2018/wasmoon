## Description
Remove or reduce the old `modules/wasmoon/ir`, `modules/wasmoon/vcode`, `modules/wasmoon/cwasm`, and old JIT integration paths after the real implementations have moved into reusable modules.

## Design
Wasmoon should remain the product runtime, CLI, interpreter, validator, parser integration, and host integration package. It should consume compiler infrastructure modules instead of carrying duplicate internal compiler implementations. Temporary compatibility shims are allowed only when they are thin, documented, and scheduled for deletion.

## Acceptance Criteria
- [ ] `modules/wasmoon/ir` and `modules/wasmoon/vcode` are deleted, reduced to compatibility shims, or explicitly justified by follow-up issues.
- [ ] Wasmoon CLI, testsuite, explorer, and JIT paths use `milkir`, `machv`, targets, `regalloc`, `machv_regalloc`, `machv_emit`, and `wasmoon_jit` as the implementation path.
- [ ] No compiler-infrastructure module imports `Milky2018/wasmoon` or legacy `Milky2018/wasmoon/ir` / `Milky2018/wasmoon/vcode` packages.
- [ ] User-facing CLI behavior and correctness tests remain stable.
- [ ] Any remaining legacy code has a concrete issue ID and deletion condition.
