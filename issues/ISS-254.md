## Description

`benchmark_algorithms_parity.py` builds every Wasmtime sample before running
Wasmoon samples. Order, thermal state, and stale Wasmoon JIT artifacts can move
the reported AEGIS ratio from about 1.26x to about 1.60x.

## Design

Measure paired samples per workload, alternate engine order, and give Wasmoon an
isolated cache rooted in the benchmark output area. Report paired value and wall
ratios rather than ratios of two independently collected medians. Keep the tool
manual and do not restore Wasmtime as a blocking CI dependency.

## Acceptance Criteria

- [x] Each measured pair runs both engines under an alternating deterministic
      order.
- [x] Wasmoon uses an isolated cache and records whether the measured artifact
      was freshly compiled.
- [x] Summary JSON records raw pairs plus paired median and geometric-mean ratios.
- [x] Unit tests cover order, ratio aggregation, and cache isolation without
      requiring Wasmtime.

## Close Notes

Closed with five Wasmtime-free unit tests and a real two-pair AEGIS run.
Measured order alternated Wasmoon/Wasmtime then Wasmtime/Wasmoon. The isolated
cache recorded one warmup compilation and zero measured compilations, and kept
the revision-tagged v9 artifact identity. Paired value ratio was `1.270317`
median / `1.270314` geometric mean; paired wall ratio was `1.264638` median /
`1.264636` geometric mean.

The Python gate now discovers all tests under `scripts/tests`; no Wasmtime
binary is invoked by those unit tests.
