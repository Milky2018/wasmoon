# ISS-254: Make engine parity benchmarks paired and cache-isolated

## Metadata

- Updated: 2026-08-11

## Description

`benchmark_algorithms_parity.py` isolated only the Wasmoon cache. Wasmtime still
used its process-global cache, so disabling warmups compared cold Wasmoon
compilation with cached Wasmtime execution. Warmups avoided that asymmetry but
excluded compilation from both measured paths. Neither shape satisfies the
current corpus-sweep contract.

## Design

For each workload, create empty output-local caches for both engines, point
Wasmtime at its cache with `cache-config`, then invoke each engine exactly once.
Alternate engine order across workloads and report the direct value and wall
ratios without warmups, repetitions, medians, or averages. Keep the tool manual
and do not restore Wasmtime as a blocking CI dependency.

## Acceptance Criteria

- [x] Each workload invokes Wasmoon once and Wasmtime once under an alternating
      deterministic order.
- [x] Both engines start from separate empty output-local caches; Wasmtime does
      not use its global cache.
- [x] Summary JSON records the raw pair and direct ratios without statistical
      aggregation fields.
- [x] Unit tests and a real-engine smoke cover double cache isolation and the
      single-pair contract.

## Close Notes

Closed with five Wasmtime-free unit tests and a real two-pair AEGIS run.
Measured order alternated Wasmoon/Wasmtime then Wasmtime/Wasmoon. The isolated
cache recorded one warmup compilation and zero measured compilations, and kept
the revision-tagged v9 artifact identity. Paired value ratio was `1.270317`
median / `1.270314` geometric mean; paired wall ratio was `1.264638` median /
`1.264636` geometric mean.

The Python gate now discovers all tests under `scripts/tests`; no Wasmtime
binary is invoked by those unit tests. This 2026-07-23 closure evidence is
historical and is superseded by the 2026-08-11 acceptance criteria above.

The 2026-08-11 revision removes warmup and iteration controls, emits one raw
pair per workload, and gives Wasmoon and Wasmtime separate empty output-local
caches. A real `auth2.wasm` smoke recorded empty pre-run snapshots and fresh
artifacts for both engines; the user-level Wasmtime cache had no modified files.
`python3 -m unittest discover -s scripts/tests -p 'test_*.py'` passed 67 tests.
