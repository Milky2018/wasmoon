# ISS-320: Isolate concurrent macOS descriptor registrations

## Metadata
- Type: bug
- Status: closed
- Priority: 1
- Labels: async, reactor, macos, kqueue, ffi, wasi, preview3, agent
- Assignee: codex
- Created: 2026-07-29
- Updated: 2026-07-29
- External ref: none

## Description
The macOS reactor registers the caller's original descriptor directly with
kqueue. Since a kqueue registration is identified by `(ident, filter)`, a
second operation for the same descriptor and direction replaces the first
operation's token. Cancelling either operation also deletes the one shared
kernel event. WIT permits multiple standard-input streams to remain active, so
one of their futures can remain pending forever.

Linux already avoids this collision by duplicating every registered descriptor.

## Design
Give every macOS descriptor registration its own close-on-exec duplicate, as
the Linux backend does. Track the actual kernel descriptor and filter in the C
reactor by monotonic token. Completion, cancellation, registration failure, and
reactor finalization must each release exactly the descriptor owned by that
registration. Make cancellation token-based so the MoonBit layer does not
retain stale platform identifiers.

## Acceptance Criteria
- [x] Multiple read registrations for the same descriptor complete independently.
- [x] Cancelling one registration does not cancel another registration for the same descriptor and filter.
- [x] Registration descriptors are released after completion, cancellation, failure, and reactor finalization.
- [x] Targeted reactor tests, strict C warnings, sanitizers, and complete native tests pass.

## Notes
- 2026-07-29: Reported after the standalone scheduling layer was removed; the
  defect is in the macOS kernel-registration identity and ownership seam.

## Close Notes
- 2026-07-29: Reproduced both failure modes on macOS. Two read
  registrations produced only the second token and left the first pending;
  cancelling one of two registrations then prevented the peer from completing.
- 2026-07-29: Made macOS duplicate every registered descriptor with
  `F_DUPFD_CLOEXEC`. The C reactor now owns the actual kernel identifier,
  filter, and optional descriptor by token, and releases each registration on
  installation failure, completion, cancellation, or reactor finalization.
  The MoonBit registration no longer stores platform identifiers.
- 2026-07-29: Verified reactor tests at 7/7 with `-Wall -Wextra -Werror` and
  ASan/UBSan, WASI component tests at 37/37, complete native tests at
  2464/2464, and the official async 0.3 matrix in JIT and interpreter modes at
  24/24 files and 153/153 commands each.
