## Description

At Wasmoon `1a33cb08` on macOS ARM64, 42 of the newly imported Wasmtime P1
programs fail in each of interpreter and JIT modes with `NOTCAPABLE` before
reaching most of their intended file-operation assertions. The unchanged
upstream `open_scratch_directory` opens `.` using zero base and inheriting
rights. Wasmoon records those requested rights, whereas the Wasmtime tests
expect subsequent operations on the directory to work.

This is a confirmed model/compatibility difference, not yet a finding that
Wasmoon's rights enforcement violates the WASIp1 contract. Do not silently
grant additional rights or edit upstream assertions merely to make the suite
green. The older `docs/wasip1-issue-tracker.md` describes Wasmtime parity goals
and does not represent the current implementation's rights behavior.

## Design

Compare the legacy WASIp1 rights contract with both implementations and record
an explicit compatibility decision. If independent standards-oriented tests
need a scratch directory with rights, add separately attributed tests rather
than altering the upstream snapshot. Preserve the strict upstream run and
its failure count so its actual coverage remains visible.

## Acceptance Criteria
- [x] Explain the normative rights contract and the deliberate Wasmtime deviation, if any.
- [x] Record the intended Wasmoon policy and its compatibility implications.
- [x] Add an independent minimal rights probe and test the chosen policy.
- [x] Recover useful file-operation coverage without claiming unchanged upstream conformance when tests were adapted.

## Close Notes

Resolved in favor of the legacy requested-rights contract; the runtime does not
implicitly expand zero rights. See `docs/wasip1-rights.md` for primary sources
and the policy decision. The independent public-ABI rights probe passes in
both engines. The separate `explicit-rights` source profile recovers operation
coverage without changing upstream sources or assertions. Its two remaining
rights-errno incompatibilities stay visible as failures.
