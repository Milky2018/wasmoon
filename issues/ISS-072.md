## Description
MachV instruction core currently contains Wasmoon GC allocation pseudo-ops:
`GCAllocStructInline`, `GCAllocStructSlowPrecise`,
`GCAllocArrayFixedInline`, and `GCAllocArraySlowPrecise`. These opcodes encode
Wasmoon GC object layout, allocation cursor/limit layout, helper symbols,
outgoing stack buffer conventions, and safepoint metadata behavior.

## Design
Move the existing allocation behavior out of MachV instruction core one opcode
family at a time. Preserve behavior by mechanically migrating current emitter
logic into Wasmoon-owned lowering, target hooks, or generic MachV instruction
sequences.

The migration order inside this issue should be:
1. slow precise struct allocation.
2. slow precise array allocation.
3. inline struct allocation fast path plus slow path.
4. inline fixed-array allocation fast path plus slow path.

Do not hand-write a new allocator. Copy the current AArch64 and AMD64 emission
logic as the behavioral source of truth, then generalize names and ownership.
