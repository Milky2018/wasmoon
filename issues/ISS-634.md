# ISS-634: Invalidate native objects when shared C headers change

## Description
An incremental build during ISS-625 linked native objects compiled against two
sizes of the same private struct. Adding the pending-hostcall-exception field
in `wasmoon_jit/jit_ffi/jit_context.h` changed `jit_trap_activation_t` from 1088
to 1096 bytes on macOS ARM64. `trap.c` used the new size, while the unchanged
`native_test_support/context_test_support.c` allocated the old stack size.
Two native tests crashed. ASan independently reported a 1096-byte initialization
into the 1088-byte `outer` allocation.

Fresh native and sanitizer builds passed, with no change to those test
implementations. This establishes stale/mismatched build artifacts, but does
not yet distinguish a MoonBit transitive-header invalidation defect from missing
supported build configuration. The current toolchain is stable
`0.1.20261012 (748b63c)`.

## Scope and Evidence
- Review dependency tracking for C stubs including shared private headers across
  packages, including ordinary native, release installation and sanitizer builds.
- Preserve [the ASan observation](../docs/evidence/runtime-failures-2026-10-15/abi-cache-before.log).
- Create a small two-package header/layout change reproduction before selecting
  a tooling/configuration fix or reporting an upstream defect.

## Design
Use supported native dependency tracking or an upstream build-tool repair.
Object invalidation must follow transitive header content, not manually touched
C files or duplicated struct declarations. Clean builds remain a diagnostic
control; silently accepting incremental ABI mismatches is not the final fix.

## Acceptance Criteria
- [ ] Reproduce a header-only layout change with a small fixture and identify the missing dependency or cache input.
- [ ] A normal incremental build recompiles affected native objects and executes correctly after the shared header changes.
- [ ] Ordinary native, release and sanitizer paths use consistent struct layouts; compare with clean-build controls.
- [ ] Document any verified upstream limitation and the supported temporary workaround without inventing an ad hoc style audit.
