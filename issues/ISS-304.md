## Description
Preview 3 host adapters currently expose poll closures and a blocking Boolean
event-loop hook. They must register concrete operations with the Wasmoon-owned
async runtime so readiness and cancellation have one owner.

## Design
Migrate clocks, standard I/O, filesystem streams, and sockets incrementally.
Host operations report readiness only; Component Async converts completion
into guest-visible subtask, future, stream, and waitable events. Regular file
operations remain honestly synchronous where the host offers no useful
nonblocking primitive.

## Acceptance Criteria
- [x] Preview 3 host operations use registered cancellable async operations.
- [x] No host operation busy-polls.
- [x] Cancellation releases native registrations and component resources.
- [x] Preview 3 CLI and conformance tests pass on macOS and Linux.

## Close Notes
- Replaced the Preview 3 deadline and descriptor polling tables with
  generation-safe `wasmoon_async` tasks backed by the native reactor.
- Migrated clocks, inherited stdio, TCP, UDP, and resolver operations to
  opaque cancellable registrations. The host event loop now blocks in kqueue
  or epoll and dispatches only completed task IDs.
- Kept regular-file input synchronous because epoll does not accept regular
  files, while pipe and socket input follows real readiness. Inherited stdio
  descriptors are duplicated before reactor allocation so later kernel
  objects cannot reuse ambient descriptor numbers.
- Added native timer, cancellation, regular-file stdin, pipe readiness, EOF,
  and invalid-stdin regressions. Verified 35/35 WASI component tests and 31/31
  component command tests on macOS and Ubuntu Linux, with ASan/UBSan on both.
- The separate official Component Async semantic matrix remains tracked by
  ISS-310; its pre-existing 15/24 baseline is not counted as host I/O
  conformance evidence here.
