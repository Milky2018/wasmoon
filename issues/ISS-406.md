## Description

Wasmoon rematerializes exactly one class of value today, and it does it
in AArch64 lowering: `EnvironmentField` values, covered by the
`AArch64 lowering rematerializes stable fields under integer pressure`
test. GVN cooperates by deliberately not merging
`GlobalValue(ContextField(_, Stable, _))`, so the IR does not create the
long-lived value in the first place. Those two decisions are one coherent
policy, and the `Stable` skip in `opt_passes_cse_gvn.mbt` is correct
rather than the inverted condition it first looks like.

Once ISS-405 lands there are two mechanisms doing the same job, one
target-independent and one AArch64-only. Every future target would have
to reimplement the second.

## Design

Move `EnvironmentField` into the ISS-404 marked set and delete the
lowering-level special case, so context fields and constants take one
path.

Keep the GVN skip. It is what stops the IR from merging these into a
single long-lived value before elaboration ever sees them, which is the
same outcome the shared mechanism produces.

This is the reason the work belongs in elaboration rather than in the
register allocator. An allocator that rematerializes has to emit target
instructions for every value it declines to spill, which pushes the
policy back down into each target's lowering — exactly the duplication
this issue removes.

## Acceptance Criteria
- [ ] `EnvironmentField` values go through the shared remat path.
- [ ] The AArch64-only remat special case in lowering is gone.
- [ ] The existing lowering pressure test still passes, or is replaced by
      an equivalent test against the shared mechanism.
- [ ] x64 gets the same behavior without target-specific code.
