## Description

Wasmoon rematerializes exactly one class of value today, and it does it
in AArch64 lowering: `EnvironmentField` values, covered by the
`AArch64 lowering rematerializes stable fields under integer pressure`
test. GVN cooperates by deliberately not merging
`GlobalValue(ContextField(_, Stable, _))`, so the IR does not create the
long-lived value in the first place. Those two decisions are one coherent
policy, and the `Stable` skip in `opt_passes_cse_gvn.mbt` is correct
rather than the inverted condition it first looks like.

Once ISS-405 lands there are two mechanisms doing the same job, one late in
MilkIR and one AArch64-only. Every future target would otherwise have to
reimplement the second.

## Design

Keep stable `ContextField` definitions separate in MilkIR GVN, as it already
does for semantic correctness and local materialization. Delete AArch64's
second policy layer: context-carrier replacement, regional aliasing, distance
limits, and target-local pressure estimation. Both targets then materialize
each semantic MachV occurrence directly.

This is the reason the work belongs in elaboration rather than in the
register allocator. An allocator that rematerializes has to emit target
instructions for every value it declines to spill, which pushes the
policy back down into each target's lowering — exactly the duplication
this issue removes.

## Acceptance Criteria
- [x] `EnvironmentField` values go through the shared remat path.
- [x] The AArch64-only remat special case in lowering is gone.
- [x] Existing pressure coverage is replaced by an equivalent test against
      the shared mechanism.
- [x] x64 gets the same behavior without target-specific code.

## Notes
- 2026-08-07: Removing the GVN `Stable` skip was tested and changes the
  emitted code by zero bytes, because lowering already remats these
  values. Recorded in ISS-403 so it is not retried.
- 2026-08-12: AArch64 lowering still owns the stable environment-field
  rematerialization path, while the shared per-block mechanism in ISS-405 does
  not exist. This remains correctly blocked on ISS-405.
- 2026-08-12: ISS-405's corrected design is source-local rather than a late
  pass. The existing stable-field GVN exclusion already provides that shared
  policy. Removed AArch64's 355-line alias/pressure layer and 237 lines of
  heuristic-specific tests. Focused shared, AArch64, and x64 tests pass
  187/187, 219/219, and 104/104; workspace gates remain before closure.
- 2026-08-12: Follow-up profiling showed that the exclusion became harmful
  after the AArch64 policy was removed. Stable fields now use ordinary,
  budgeted GVN. On `aead_aegis256` this halves the hot loop's context-base
  loads without adding a target rule or a performance gate.
