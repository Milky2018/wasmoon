# ISS-636: Move native GC slow-path decisions into MoonBit

## Metadata
- Type: task
- Status: in_progress
- Priority: 1
- Labels: runtime, gc, ffi, performance
- Assignee: unassigned
- Created: 2026-10-16
- Updated: 2026-10-19
- External ref: none

## Description
Use a synchronous, call-scoped native request to expose allocation and root-safe collection primitives. A closed MoonBit callback owns retry and failure decisions; it returns before native trap or stack transfer. Keep machine layout and fast paths stable, then review collection coordination for the same ownership rule.

## Design
Start from complete executable paths and explicit ownership. Reuse the existing hostcall and root-visitor conventions; preserve machine layout and direct access where required. Move decisions with their state and delete old implementations. Do not equate wrapping C in more FFI functions with migration, or claim the complete architecture is repaired after one slice.

## Acceptance Criteria
- [x] Record exact ABI, callback ownership, root pinning, reentry and non-suspension contracts.
- [x] Move all native word/wide allocation retry decisions to a shared MoonBit owner and delete the old C policy.
- [x] Preserve precise-root failures separately from quota/allocation exhaustion and clean up native request storage before any trap.
- [x] Exercise GC-heavy allocation, wide values, quota denial, callback failure, reentry and live/parked roots through public behavior.
- [x] Move visitor ownership, collection/rollback prepare/finish/abort and same-heap reentry decisions into one MoonBit coordinator; preserve native physical scans.
- [ ] Measure before/after fast and slow paths; pass required native, strict C, sanitizer and external suites with documented platform acceptance.
