## Description
Restoring `compare_jit_interp` to the production-loaded native JIT path exposed hangs in `memory.grow`. Memory64 load/store and both memory32/memory64 `memory.size` tests return, but the grow helper does not return through the production JIT call path.

## Design
Debug the native `memory.grow` runtime helper ABI for memory32 and memory64 memories. Confirm how the helper receives the memory descriptor, page delta, maximum page limit, and return value, and make the CLI/WAST path and testsuite use the same production setup.

## Acceptance Criteria
- [x] `memory64: memory.grow takes and returns i64` returns through production-loaded native JIT.
- [x] `memory32: memory.grow takes and returns i32` returns through production-loaded native JIT.
- [x] `compare_jit_interp` can remove its `MemoryGrow` compatibility guard.
- [x] Add or keep focused regression tests for memory32 and memory64 grow.
- [x] `moon test modules/wasmoon/testsuite/memory64_test.mbt --target native --warn-list +73 --diagnostic-limit=200` passes without compatibility fallback.

- 2026-07-05: Reopened after full `moon test --target native --warn-list +73 --diagnostic-limit=200` showed `memory64: memory.grow takes and returns i64` still traps when the compatibility guard is removed. Correctness gates pass again only after restoring the `MemoryGrow` guard in `compare_jit_interp`.
- 2026-07-05: Compared against `main:jit/jit_ffi/jit.c`; the original `wasmoon_jit_get_memory_grow_ptr` returned `memory_grow_indexed_internal`, matching the new multi-memory helper ABI.
