# ISS-431: Unify JIT trap exit through native fiber returns

## Description
The legacy synchronous JIT entry saves a `sigjmp_buf` in a host-stack
`jit_trap_activation_t`, switches the machine stack in `stack_switch_call`,
and lets generated traps and runtime helpers `siglongjmp` directly from the
Wasm stack to that host activation. Fortified glibc diagnoses some of these
cross-stack transfers as an invalid jump instead of returning a structured
Wasm trap. Disabling `_FORTIFY_SOURCE` or calling an unchecked longjmp would
only hide the diagnostic and would not establish a portable stack-switch ABI.

ISS-324 fixed this class of failure for synchronous Component Model calls by
routing them through a retained native continuation. Ordinary core calls still
use the older dedicated Wasm-stack entry when a context stack is allocated, so
the repository retains two stack owners and two trap-exit models.

## Design
Make the native fiber protocol the only owner of host/fiber stack transfer for
JIT execution. Route ordinary synchronous core calls through the same native
continuation entry used by resumable calls, drive them once to a terminal
result, and reject and cancel an unexpected suspension. Preserve the configured
Wasm stack size when creating the fiber so the migration does not reduce the
CLI recursion budget. Represent normal return, trap, and suspension as distinct
protocol outcomes instead of making callers reinterpret one bare integer.

Keep trap payload and cleanup state invocation-local in
`jit_trap_activation_t`; do not move mutable trap state into the shared,
long-lived `jit_context_t`. A caught WebAssembly exception may continue to
`siglongjmp` to a handler in an active frame on the same fiber stack. An
uncaught exception, explicit runtime trap, or hardware fault must terminate the
current JIT invocation on its own fiber and then let the fiber protocol restore
the caller stack and return a typed terminal outcome.

Signal handlers must record only the information required to identify the
fault before transferring to a valid activation or signal-safe landing stub.
Any frame walking, formatting, allocation, exception cleanup, or GC cleanup
must run after control has left the signal handler. Do not weaken fortification
or add an unchecked longjmp shim. After all production callers use native
fibers, delete `stack_switch_call`, the legacy `call_with_stack_switch` FFI, and
the duplicate context-owned Wasm stack transport.

## Acceptance Criteria
- [x] Ordinary synchronous core JIT calls and resumable calls use one native-fiber entry and a protocol that distinguishes normal return, trap, and suspension.
- [x] Trap payload, nesting, exception state, and GC cleanup remain owned by the current `jit_trap_activation_t`, not shared mutable fields in `jit_context_t`.
- [x] Caught WebAssembly exceptions still transfer to a live handler on the same fiber stack.
- [x] Uncaught exceptions, runtime-helper traps, `SIGTRAP`, and guarded-memory or stack `SIGSEGV`/`SIGBUS` faults return structured trap results through a normal fiber-to-host transfer.
- [x] Synchronous entry preserves the caller-configured native Wasm stack size and rejects unexpected suspension without leaking a fiber, activation, GC frame, root scope, or exception handler.
- [x] Signal handlers defer non-signal-safe diagnostics and cleanup until after the trap reaches a safe execution context.
- [x] `stack_switch_call`, `wasmoon_jit_call_with_stack_switch`, their MoonBit FFI declarations, and the duplicate context-owned stack call path are removed after caller migration.
- [x] No build configuration disables `_FORTIFY_SOURCE`, and no unchecked or private longjmp entry point is introduced.
- [x] Focused regressions cover nested same-context calls, trap after hostcall resume, repeated trap cleanup, all trap origins above, and both caught and uncaught WebAssembly exceptions.
- [x] macOS AArch64, strict full native, core WAST interpreter/JIT, component WAST, and module-boundary gates pass.
- [ ] Fortified Linux AMD64 passes.
- [ ] The sanitizer gate passes when the repository provides a supported sanitizer runner.
