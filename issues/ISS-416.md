# ISS-416: Remove repeated compiler analysis and allocation work

## Metadata

- Status: closed

## Description

MilkIR and regalloc still repeated whole-function analyses, copied growing
collections, allocated maps for dense IDs, and used per-instruction or
per-segment scratch storage. On `box_seed`, these costs accumulated across many
large generated functions even though MoonBit compiles the functions
sequentially.

Remove the repeated work at its source. Preserve optimization semantics and the
single verified allocator rather than hiding the cost behind size-specific
heuristics or another allocation strategy.

## Acceptance Criteria
- [x] MilkIR reuses CFG and dominance facts across instruction-only O2 passes.
- [x] DCE, alias canonicalization, pointer-base inference, and GVN use dense
      value storage and bounded work where value IDs are dense.
- [x] E-graph extraction and pointer-base inference are dependency worklists,
      not repeated whole-graph scans.
- [x] Regalloc collects liveness in one operand scan and avoids per-block maps.
- [x] Operand assignment has one stored representation and reuses scratch
      arrays.
- [x] Transitive bundle construction does not repeatedly copy the full merged
      span prefix.
- [x] Full native tests pass with and without allocator validation.
- [x] A cold `box_seed` compile records phase-level before/after evidence.

## Notes
- 2026-08-12: The initial cold diagnostic run reported 613,435 us module
  compile time, including 377,834 us in regalloc. Bundle allocation alone used
  246,292 us; MilkIR e-graph, DCE, GVN, and alias passes used 76,442 us.
- 2026-08-12: The post-change cold diagnostic run reported 314,886 us module
  compile time and 126,085 us in regalloc. Bundle allocation fell to 67,279 us;
  the same MilkIR passes used 67,171 us. These are single-run diagnostic values,
  not a statistical benchmark.
- 2026-08-12: A post-close regression in `df3a8aae` showed that operand scratch
  reuse treated the public, potentially sparse `tie_id` as an array index.
  Operand assignment now maps instruction-local tie labels to dense scratch
  slots, and a public API regression test covers `tie_id = 7`. The full native
  suite passed 2650/2650 with and without `MACHV_REGALLOC_VALIDATION=1`.

## Close Notes

- Shared one CFG/dominance analysis across e-graph, GVN, and final alias
  cleanup; replaced dense-ID hash maps and temporary terminator arrays.
- Fused use-position collection with block liveness, reused dense open-range
  storage, and stopped copying VCode block parameters.
- Reused operand-assignment scratch arrays, removed the duplicate assignment
  log, and replaced chain-growing bundle span copies with logarithmic merge
  levels.
- `moon check --target native --warn-list +73` passed without warnings.
- `moon test --target native` passed 2648/2648; the same full suite passed with
  `MACHV_REGALLOC_VALIDATION=1`.
