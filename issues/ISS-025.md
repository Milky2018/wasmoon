# ISS-025: Retire wasmoon_jit legacy fallback internals

## Description
Delete the temporary `modules/wasmoon_jit/legacy_ir` and `modules/wasmoon_jit/legacy_vcode` fallback packages without hiding unsupported cases behind interpreter fallback.

## Design
The accepted correction is copy-first: keep the old `origin/main` production IR/VCode pipeline, but rehome it under `modules/wasmoon_jit/ir` and `modules/wasmoon_jit/vcode` so Wasmoon no longer owns duplicate compiler implementation directories. Reusable MilkIR/MachV work remains separate compiler-infrastructure polish; it must not replace production semantics until it reaches parity.

## Acceptance Criteria
- [x] `modules/wasmoon_jit/legacy_ir` and `modules/wasmoon_jit/legacy_vcode` are deleted.
- [x] The old production IR/VCode implementation lives under `modules/wasmoon_jit/ir` and `modules/wasmoon_jit/vcode`, not under `modules/wasmoon`.
- [x] Production JIT compilation has no interpreter fallback trampoline or interpcall dispatcher.
- [x] Wasmoon product packages consume the rehomed JIT compiler through explicit module imports.
- [x] Full correctness gates pass after deletion.

## Notes
- 2026-07-05: Deferred because deleting the fallback now would reduce correctness coverage. The fallback is no longer owned by `wasmoon`; it is quarantined under `wasmoon_jit/legacy_*` with TODO markers on unsupported native paths.
- 2026-07-05: Removed `legacy_perf` from the fallback set by renaming it to `modules/wasmoon_jit/perf`. The remaining legacy cleanup scope is now only `legacy_ir` and `legacy_vcode`.
- 2026-07-05: Removed the `wasm_frontend.lower_function` bridge through `wasmoon_jit/legacy_ir`. The public lowering entry is now native-only and raises `UnsupportedNativeLowering` when the native frontend cannot lower a function. `preflight.validate_jit` now mirrors the production reusable-pipeline behavior by validating only `try_lower_native_function` successes and warning on unsupported functions instead of silently using legacy IR.
- 2026-07-05: Replaced the production hostcall import-trampoline generation path with `wasmoon_jit.build_hostcall_import_trampoline_for_target`. The new generator emits target-specific scalar/no-overflow trampolines directly in `wasmoon_jit`, carries AArch64 runtime function-address fixups through the existing loader patch API, and leaves V128, stack-passed import args, and overflow result areas as explicit `TODO(ISS-026)` unsupported cases instead of falling back to `legacy_vcode/emit`. Local validation passed with `moon check modules/wasmoon_jit modules/wasmoon/jit --target native --warn-list +73 --diagnostic-limit=200`, `moon test modules/wasmoon_jit modules/wasmoon/jit --target native --warn-list +73 --diagnostic-limit=200`, `./install.sh`, and `python3 scripts/run_all_wast.py --rec --only-jit --dump-failures --timeout-sec 20`.
- 2026-07-05: Correction: the `build_interpreter_fallback_trampoline_for_target` plus interpcall dispatcher approach was rejected and removed. The production compile loop now uses the restored old IR/VCode path under `wasmoon_jit/ir` and `wasmoon_jit/vcode` for real machine-code generation.
- 2026-07-05: Removed the interpcall dispatcher, interpreter fallback trampoline generator, runtime symbol, MoonBit wrappers, C FFI exports, and tests that treated fallback as a supported path.
- 2026-07-05: Restored testsuite JIT helpers to production-loaded JIT execution without interpreter-backed compatibility shims, including GC setup/teardown copied from the old main-branch harness.
