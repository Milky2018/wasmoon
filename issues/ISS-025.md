## Description
Delete the temporary `modules/wasmoon_jit/legacy_ir` and `modules/wasmoon_jit/legacy_vcode` fallback packages after the reusable MilkIR/MachV pipeline covers the remaining production JIT cases.

## Design
The current migration moved the old implementation out of `modules/wasmoon` so Wasmoon consumes it through `wasmoon_jit`. This issue tracks the later cleanup step: replace the remaining legacy fallback paths with native MilkIR frontend lowering, MachV target lowering, `machv_regalloc`, `machv_emit`, and direct `wasmoon_jit` executable installation.

## Acceptance Criteria
- [ ] `modules/wasmoon_jit/legacy_ir` and `modules/wasmoon_jit/legacy_vcode` are deleted.
- [ ] Entry trampolines no longer fall back to the legacy emitter for unproven signatures.
- [ ] `wasm_frontend.lower_function` no longer bridges through `legacy_ir` for unsupported Wasm operators or structured control-flow cases.
- [ ] Production JIT compilation has no `legacy_vcode` fallback for function bodies or import trampolines.
- [ ] Full correctness gates pass after deletion.

## Notes
- 2026-07-05: Deferred because deleting the fallback now would reduce correctness coverage. The fallback is no longer owned by `wasmoon`; it is quarantined under `wasmoon_jit/legacy_*` with TODO markers on unsupported native paths.
- 2026-07-05: Removed `legacy_perf` from the fallback set by renaming it to `modules/wasmoon_jit/perf`. The remaining legacy cleanup scope is now only `legacy_ir` and `legacy_vcode`.
- 2026-07-05: Removed the `wasm_frontend.lower_function` bridge through `wasmoon_jit/legacy_ir`. The public lowering entry is now native-only and raises `UnsupportedNativeLowering` when the native frontend cannot lower a function. `preflight.validate_jit` now mirrors the production reusable-pipeline behavior by validating only `try_lower_native_function` successes and warning on unsupported functions instead of silently using legacy IR.
