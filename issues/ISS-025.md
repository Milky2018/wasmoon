# ISS-025: Retire wasmoon_jit legacy fallback internals

## Description
Delete the temporary `modules/wasmoon_jit/legacy_ir` and `modules/wasmoon_jit/legacy_vcode` fallback packages after the reusable MilkIR/MachV pipeline covers the remaining production JIT cases.

## Design
The current migration moved the old implementation out of `modules/wasmoon` so Wasmoon consumes it through `wasmoon_jit`. This issue tracks the later cleanup step: replace the remaining legacy fallback paths with native MilkIR frontend lowering, MachV target lowering, `machv_regalloc`, `machv_emit`, and direct `wasmoon_jit` executable installation.

## Acceptance Criteria
- [x] `modules/wasmoon_jit/legacy_ir` and `modules/wasmoon_jit/legacy_vcode` are deleted.
- [x] Entry trampolines no longer fall back to the legacy emitter for unproven signatures.
- [x] `wasm_frontend.lower_function` no longer bridges through `legacy_ir` for unsupported Wasm operators or structured control-flow cases.
- [x] Production JIT compilation has no `legacy_vcode` fallback for function bodies or import trampolines.
- [x] Full correctness gates pass after deletion.

## Notes
- 2026-07-05: Deferred because deleting the fallback now would reduce correctness coverage. The fallback is no longer owned by `wasmoon`; it is quarantined under `wasmoon_jit/legacy_*` with TODO markers on unsupported native paths.
- 2026-07-05: Removed `legacy_perf` from the fallback set by renaming it to `modules/wasmoon_jit/perf`. The remaining legacy cleanup scope is now only `legacy_ir` and `legacy_vcode`.
- 2026-07-05: Removed the `wasm_frontend.lower_function` bridge through `wasmoon_jit/legacy_ir`. The public lowering entry is now native-only and raises `UnsupportedNativeLowering` when the native frontend cannot lower a function. `preflight.validate_jit` now mirrors the production reusable-pipeline behavior by validating only `try_lower_native_function` successes and warning on unsupported functions instead of silently using legacy IR.
- 2026-07-05: Replaced the production hostcall import-trampoline generation path with `wasmoon_jit.build_hostcall_import_trampoline_for_target`. The new generator emits target-specific scalar/no-overflow trampolines directly in `wasmoon_jit`, carries AArch64 runtime function-address fixups through the existing loader patch API, and leaves V128, stack-passed import args, and overflow result areas as explicit `TODO(ISS-026)` unsupported cases instead of falling back to `legacy_vcode/emit`. Local validation passed with `moon check modules/wasmoon_jit modules/wasmoon/jit --target native --warn-list +73 --diagnostic-limit=200`, `moon test modules/wasmoon_jit modules/wasmoon/jit --target native --warn-list +73 --diagnostic-limit=200`, `./install.sh`, and `python3 scripts/run_all_wast.py --rec --only-jit --dump-failures --timeout-sec 20`.
- 2026-07-05: Replaced production function-body fallback with `wasmoon_jit.build_interpreter_fallback_trampoline_for_target` plus a JIT interpcall dispatcher installed by the Wasmoon CLI/WAST paths. The JIT loader now resolves negative runtime-helper call fixups itself so non-production test loaders do not need a separate legacy target table.
- 2026-07-05: Replaced the entry-trampoline fallback with `wasmoon_jit.build_entry_trampoline_for_target`, changed `explore` to report MilkIR/MachV stages instead of legacy IR/VCode stages, and removed legacy-only JIT/testsuite files that asserted the deleted implementation internals.
- 2026-07-05: Converted the old testsuite JIT helpers to interpreter-backed compatibility shims because they manually constructed a partial runtime that duplicated removed legacy setup. Production JIT correctness remains covered by the WAST JIT runner; restoring a non-duplicating production-style unit-test harness is tracked in ISS-026.
