# ISS-699: Materialize only the live-out arrays consumed by range construction

## Description
After bounded word stores, a valid 8192-object initializer still spends 11.970s
building live ranges out of 16.694s compilation. An effective 3856-sample CPU trace
includes repeated SparseVRegSet::to_sorted_array and integer sorting under live-set
propagation. It enumerates bits and then sorts every register, even when dense
words already establish the order.

## Design
Propagate the same caller-owned live-in sets and return only sorted live-out
arrays. Production range construction never consumes serialized live-in; copying
it is unused work and extends array lifetime. Tests inspect the owned input sets
explicitly. Remove the now-unused opaque DenseLiveSets Debug snapshot, which has
no public constructor or producer. Its name and Debug method disappear from the
generated interface; document that cleanup explicitly. Do not change CFG,
liveness, allocation, runtime contracts or cache ABI; require exact artifacts.
