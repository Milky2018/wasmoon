## Description
The Linux AMD64 and macOS ARM64 sanitizer steps build only the CLI in an
isolated target directory. Their six subsequent `moon test` commands omit
`--target-dir`, so a preceding ordinary native suite can satisfy them from
the default `_build` cache.

The current toolchain also does not consume the generic `CC`, `CFLAGS`,
`CXXFLAGS`, or `LDFLAGS` environment variables used by the workflow. A cold
isolated test build therefore still uses Moon's default compiler command and
does not link ASan or UBSan. The recorded sanitizer evidence in ISS-302,
ISS-303, and ISS-311 is not valid.

## Design
Use a repository-owned compiler-driver wrapper that injects ASan and UBSan
into every C compilation and link command selected by Moon. Force the C
native backend for the sanitizer step and select the wrapper through Moon's
supported `MOON_CC` override. The override also disables the incompatible
`tcc -run` test path, so the CLI and all six targeted tests produce standalone
executables in one isolated target directory.

Annotate Wasmoon's custom native fiber switches with the sanitizer fiber
interface. A real ASan build otherwise aborts when a suspended JIT continuation
moves between the host stack and its guarded fiber stack. Preserve ASan's
alternate signal stack instead of replacing it with Wasmoon's normal trap
stack in sanitizer builds.

MoonBit's C backend gives each `FuncRef` closure signature a generated nominal
struct tag which a separately compiled native stub cannot name. Route the four
C-to-MoonBit callback families through narrowly annotated call bridges that
disable only Clang's `function` sanitizer at that erased ABI seam. Keep ASan
and every other UBSan check enabled for both the bridge and its callers.

After building, verify every produced CLI/test executable actually references
the ASan runtime and UBSan handlers. Add a static workflow regression test so
future edits cannot drop target-directory isolation, compiler wrapping, or
binary verification while retaining the sanitizer label.

## Acceptance Criteria
- [x] The sanitizer CLI and all six targeted test commands use one isolated target directory.
- [x] A warm ordinary `_build` cache cannot satisfy a sanitizer test command.
- [x] Native stubs and C-backend generated code compile through the sanitizer wrapper.
- [x] Native fiber switches complete the ASan start/finish handshake.
- [x] C-to-MoonBit `FuncRef` calls suppress only the unrepresentable nominal function-type check.
- [ ] Linux binaries link ASan and UBSan; macOS binaries link ASan and contain UBSan handlers.
- [x] CI fails when sanitizer instrumentation is absent.
- [x] Static workflow tests and local macOS sanitizer execution pass.
- [ ] ISS-302, ISS-303, and ISS-311 record corrected sanitizer evidence.

## Notes
- 2026-07-29: Reproduction after a warm ordinary native test left the default
  white-box executable's mtime and SHA-256 unchanged under the workflow's
  sanitizer environment. `otool -L` listed only `libSystem`.
- 2026-07-29: A cold build in a separate target directory still emitted
  `/usr/bin/cc` commands without sanitizer flags, proving that the workflow's
  generic compiler environment variables are ignored by this Moon toolchain.
- 2026-07-29: The corrected macOS ARM64 run passed all 57 selected tests and
  verified sanitizer evidence in one release CLI plus 15 standalone test
  executables.
- 2026-07-29: Real ASan execution exposed a last-use lifetime bug in
  `gc_clear_heap(context.ptr())`: the managed context could be finalized before
  the C call consumed its raw address. `NativeJITContext::clear_gc_heap` now
  borrows the managed object across that call.
- 2026-07-29: Workflow run 30423984731 confirmed that all ordinary suites pass
  and that sanitizer builds no longer reuse the default cache. Linux stopped
  in the pre-existing GC differential before reaching the six targeted tests,
  while macOS timed out during their cold instrumented compilation. The GC
  differential remains in the platform jobs but now runs with the ordinary
  release CLI; sanitizer steps have a 40-minute cold-build budget and are
  dedicated to the six lifecycle files plus binary instrumentation checks.
- 2026-07-29: Workflow run 30426237189 completed the macOS ARM64 sanitizer
  step and binary verifier. Linux reached the first instrumented lifecycle
  test and exposed Clang UBSan's nominal function-pointer mismatch at the
  erased MoonBit `FuncRef` callback seam. The native callback bridges now
  disable only `-fsanitize=function` for their indirect calls rather than
  weakening the sanitizer build globally.
- 2026-07-29: A fresh local macOS ARM64 sanitizer target passes all six
  lifecycle files (57 tests) and the binary verifier reports ASan and UBSan
  instrumentation in one release CLI plus 15 standalone test executables.
- 2026-07-29: Workflow run 30428964319 passes the complete macOS ARM64 job.
  Linux passes every ordinary suite and no longer reports the `FuncRef`
  function-type mismatch, then LeakSanitizer exposes two test-owned C heaps
  and two context-capturing callback cycles in
  `native_continuation_wbtest.mbt`. The tests now clear native callbacks at
  their ownership boundary and explicitly free detached C heaps instead of
  weakening leak detection.
- 2026-07-29: Workflow run 30430978553 passes the complete macOS ARM64 job.
  Linux passes every ordinary suite and the prior leaks are gone, but ASan's
  fake stack moves a fixed-size local out of the native-fiber mapping in the
  test-only active-stack probe. The probe now obtains an address from the
  registered fiber mapping directly, preserving the production range check.
  A local isolated ASan/UBSan run with
  `detect_stack_use_after_return=1` passes all 12 continuation tests.
