# ISS-529: Support developer-mode Windows symlinks within directory capabilities

## Metadata

- Status: in_progress

- Updated: 2026-09-15
- External ref: none

## Description
Capability-relative symlink creation currently requires a token with the symlink privilege even when Windows Developer Mode permits unprivileged creation through CreateSymbolicLinkW.

## Design
Retain handle-relative reparse creation when permitted. After a privilege failure and successful placeholder cleanup, use CreateSymbolicLinkW with unprivileged creation enabled. Pin the normalized volume-GUID path from its root with handles denying write/delete sharing, reject reparse points, and verify the final directory identity against the capability. Release all locks after the operation. Unsupported paths and conflicting handles fail safely. Do not change ordinary directory sharing or Unix behavior.

## Acceptance Criteria
- [ ] Developer Mode permits creation using a token without the symlink privilege.
- [ ] Without Developer Mode or privilege, creation fails with a permission error and leaves no placeholder.
- [ ] Concurrent ancestor/parent replacement cannot redirect creation outside the held directory.
- [ ] Existing privilege handling, relative targets, duplicates, and renamed parents retain their behavior.
- [ ] Clang/MSVC CI and full native gates pass; document tested boundaries.
