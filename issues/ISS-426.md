## Description
The legacy `resolve_parallel_moves` adapter eagerly selects both integer and
FP/vector transfer scratches before planning. As a result, resolving an empty
move set with empty scratch lists raises `MissingScratch(Int)` instead of
returning an empty move sequence as it did before the emergency-spill refactor.

## Design
Keep the new `plan_parallel_moves` scratch contract unchanged. Restore the
legacy adapter's empty-input compatibility contract by returning before scratch
selection, and lock the behavior with a focused whitebox regression test.
