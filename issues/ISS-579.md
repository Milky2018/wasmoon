# ISS-579: Make resolver ownership safe and retire unused native WASI state

## Description
The retained JIT WASI compatibility context duplicates the shared host configuration and contains unchecked argument/environment allocations. Resolver APIs expose pointer-valued integers, and cancellation can close a pipe before the worker writes its completion notification.

## Design
Remove unused native WASI configuration and its public configuration APIs; retain host exit status transport. Shared MoonBit WASI builders already configure all production callers. Preserve the fixed machine-code VMContext prefix. Replace resolver pointer integers with managed opaque handles and idempotent close; serialize completion notification with cancellation under the worker mutex. Workers never access MoonBit reference counts.

## Acceptance Criteria
- [x] No duplicate C WASI argument, descriptor, preopen, or stdio state remains.
- [x] Resolver close, finalization, failed creation, and next-after-close are safe.
- [x] Cancellation before and after completion works with default SIGPIPE disposition.
- [x] Native fault injection and sanitizer checks cover resolver ownership.
- [x] Strict C/MoonBit checks, native tests, package installation, and API migration documentation pass.

## Notes
This intentionally removes obsolete native WASI configuration APIs rather than retaining misleading no-op compatibility methods. Guest configuration remains in WasiContextBuilder and register_wasi.

## Close Notes

Removed the unused C WASI context and all redundant CLI/JIT initialization, eliminating the unchecked argument/environment allocation paths rather than preserving dead state. Retained exit transport and the machine-code ABI prefix. Resolver handles now use MoonBit external objects, idempotent explicit close, and worker-owned cleanup; completion notification stays serialized with cancellation. Documented the intentional API migration.

Validation: `moon info`, `moon fmt`, strict native `moon check --warn-list +73 --deny-warn`, all 2558 native tests, all 35 strict C compilation units, and 167 script tests (53 platform skips) pass on macOS ARM64. ASan/UBSan passes 41 tests, resolver allocation/cancellation schedules, and both positive controls. Isolated packaged installation passes argument, environment, preopen, and stdout assertions on both engines. An initial incremental native test used stale C objects after the private context layout changed; a clean rebuild and the subsequent full rerun passed. The dev branch does not trigger CI on push. The full Check and Test workflow was manually dispatched for code commit c9d286ae; its cross-platform results are pending. No registry release is included.
