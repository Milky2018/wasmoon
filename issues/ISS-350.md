# ISS-350: Seal component session and host installation ownership

## Metadata

- Status: closed

- Assignee: codex

- Updated: 2026-07-30

## Description
The public `component_engine` adapter accepts an arbitrary
`from_session_factory` closure. A producer can return the same mutable
`CoreExecutionEngine` repeatedly, so two stable `ComponentRuntime` values may
share one Store-scoped session and closing one can invalidate the other.
Likewise, `component_host` publicly exposes a generic installer callback and an
`install` method carrying `ComponentLinker`, leaking the private execution
boundary.

## Design
Make the stable component facade directly own the immutable engine factory and
host-installer closures. Expose only the concrete interpreter, native, and
WASI constructors; remove the generic public adapter packages. Keep the
low-level native session entry solely for the component-spec harness until
ISS-347 migrates that harness to the stable facade.

## Acceptance Criteria
- [x] No public generic session-factory API can inject a reused mutable engine
  into `ComponentRuntime`.
- [x] `ComponentHostInstaller` has no public API mentioning
  `ComponentLinker` or `runtime_impl`.
- [x] Reusing one stable engine configuration across runtimes creates
  independent sessions, and closing one runtime leaves the other operational.
- [x] Interface auditing rejects reintroduced generic adapter boundaries.
- [x] Focused facade, audit, full native, and Component 0.3 async tests pass.

## Close Notes

Removed the generic `component_engine` and `component_host` packages. The
stable facade now privately owns the only closures that create execution
sessions or populate component linkers, while its public API offers only
concrete interpreter, native, and WASI constructors. The low-level native
session entry remains isolated to the conformance harness pending ISS-347.

Added public black-box regressions which reuse one interpreter or native engine
configuration, close the first runtime, and then successfully invoke through
the second. The security audit now rejects restoration of either obsolete
generic adapter package.

Verification passed with 17/17 stable facade black-box tests, 1/1 internal
lifecycle test, 52/52 Python tests, 2496/2496 native tests, and Component Model
0.3 async at 24/24 files and 153 commands in both JIT and interpreter modes.
