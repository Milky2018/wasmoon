## Reverification (2026-09-30)

Keep open. Downloaded raw MSVC evidence from [CI 36679855167](https://github.com/Milky2018/wasmoon/actions/runs/36679855167) still contains the same four failures (two guests times two engines), with 106 passes. The pinned guest sources at `609c446139956ff30239f87cb18af1dc6128bed2` are byte-identical to those fetched from current testsuite main (`5f3c702bee1cde4362b018d1b3b1d99592af99e6`). No upstream expectation repair was found in those files.

- Fields: both the vendored WIT and [current WASI HTTP WIT](https://github.com/WebAssembly/WASI/blob/39c11a76958d015ace3f1bf68500057a28c7837f/proposals/http/wit/types.wit#L259-L267) require copy-all to return original casing. The guest appends `foo` and `FOO` but expects both returned names to be `foo`. This is a concrete expectation/contract conflict, not a reason to lowercase Wasmoon's stored names.
- Empty path: the WIT describes an optional path/query but does not explicitly require the getter to normalize `Some("")` to `Some("/")`. Wasmoon retains the value and uses `/` when sending the request. The guest expects normalization. The WIT text alone does not resolve that accessor policy; neither implementation correctness nor a test defect is established by this mismatch alone.
- Additional Wasmoon boundary problem: the authority setter calls the transport helper `authority_host_port`, which rejects userinfo, an empty host and ports outside u16. The WIT setter instead specifies syntactically valid URI authority. [RFC 3986 section 3.2](https://www.rfc-editor.org/rfc/rfc3986#section-3.2) includes optional userinfo in authority syntax. The guest later expects `user@localhost:80` to be accepted. Transport restrictions should be evaluated separately from the resource setter's syntax contract; accepting a resource value need not permit sending it over HTTP.
- Further guest assertions accept raw non-ASCII path characters and bare percent signs, while our URI parser rejects them. These need their own URI/IRI contract decision, not a blanket relaxation to make the entire guest pass.

`moon test modules/wasmoon/wasi_http --target native --filter '*URI setters*'` passed its one existing test on merged main. That test explicitly expects `user@host` and `host:65536` to be rejected; its success confirms current behavior, not correctness of those expectations. No guest assertions were patched or skipped. No upstream messages were posted. Follow-up should separate setter syntax validation from transport policy, add independent contract tests, and resolve the remaining upstream expectations before claiming full conformance.
