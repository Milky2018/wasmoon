# ISS-361: Guard complete component scheduling rounds against reentrancy

## Metadata
- Type: bug
- Status: closed
- Priority: 1
- Labels: component-model, native-jit, continuation, cancellation, reentrancy, lifecycle, tests, agent
- Assignee: codex
- Created: 2026-07-30
- Updated: 2026-07-30
- External ref: none

## Description
The deferred-cancellation guard on `ComponentInvocation` covers only the root
`step_task_once` call. It is cleared before the same scheduling round advances
a background subtask or polls host events. A native execution callback reached
from a side task can therefore close the runtime while that side task's
continuation is not yet stored, allowing teardown to close the JIT engine
before the continuation becomes runtime-owned.

The stable `ComponentCall` facade also enters `poll`, `wait`, and `join`
without checking whether its runtime is closed or the same invocation is
already driving. A callback can recursively activate the same call.

Finally, linker teardown does not cancel continuations retained by background
subtasks, sync-lower state, or explicit guest threads before closing the core
execution engine.

## Design
Treat one complete `drive_once` call, including bounded side-task and host-event
progress, as the non-reentrant activation boundary. Defer cancellation until
that boundary exits, then consume any continuation published during the round.
Reject closed or recursively active facade calls before entering the low-level
driver, while retaining a low-level guard as the authoritative boundary.

Before closing the core engine, drain all continuations owned by the shared
component runtime state. Cancellation must remain idempotent and must precede
JIT-context and code-mapping teardown.

## Acceptance Criteria
- [x] The invocation driving guard covers root, side-task, and host-event
      progress for the entire scheduling round.
- [x] Recursive `poll`, `wait`, or `join` on the same call is rejected before a
      second native activation.
- [x] Calls observed after runtime close report structured cancellation without
      entering the low-level driver.
- [x] Linker teardown cancels runtime-owned subtask, sync-lower, and explicit
      thread continuations before closing the core engine.
- [x] Public black-box regressions cover root and side-task callback-driven
      close, including attempted same-call reentry.
- [x] Fresh ASan/UBSan-instrumented callback tests complete without findings in
      the changed paths, and native and Component Model regressions pass.

## Close Notes

Closed on 2026-07-30.

- `ComponentInvocation::drive_once` now keeps its non-reentrant driving guard
  active across root execution, bounded side-task progress, and host-event
  polling, and consumes deferred cancellation before returning.
- `ComponentCall` now shares one active-operation token across aliases and
  rejects closed or overlapping `poll`, `wait`, and `join` operations before
  entering the low-level driver.
- Linker close drains subtask, sync-lower, and explicit-thread continuations
  before closing the core execution engine.
- Public black-box tests cover root and side-task callback close, side-task
  reentry, and overlapping asynchronous joins.
- Validation passed: runtime-implementation tests 33/33; facade tests 24/24;
  native tests 2504/2504; stable Component Model 0.2 matrix 23/23 files and 845
  commands; async 0.3 matrix 24/24 files and 153 commands.
