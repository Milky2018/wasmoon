# ISS-176: Enforce descriptor rights across WASIp1 operations

## Metadata
- Type: bug
- Status: in_progress
- Priority: 1
- Labels: wasi, wasip1, capabilities, security, descriptors, interpreter, jit, agent
- Assignee: codex
- Created: 2026-07-15
- Updated: 2026-07-15
- External ref: none

## Description
The interpreter and JIT descriptor tables retain native descriptors and basic file metadata, but they do not retain the effective WASIp1 base and inheriting rights selected by `path_open`. Operations therefore cannot consistently enforce rights after a descriptor is created. For `poll_oneoff`, this means a descriptor can be subscribed for read or write readiness without proving that it carries `RIGHT_POLL_FD_READWRITE` and the corresponding read or write capability.

This is a broader descriptor-model defect rather than a second `poll_oneoff` implementation detail. Adding a poll-only rights table would create another source of truth and leave other fd operations inconsistent.

## Design
Store effective base and inheriting rights in the authoritative descriptor entry for both interpreter and JIT modes. Centralize capability checks at descriptor lookup boundaries, migrate existing fd operations to those checks, and make `poll_oneoff` request the appropriate poll/read or poll/write capability through the same interface.

## Acceptance Criteria
- [x] Interpreter and JIT descriptor entries retain effective base and inheriting rights.
- [x] `path_open` rejects rights escalation and records the granted rights on success.
- [x] `poll_oneoff` returns the specified capability error for descriptors lacking poll/read or poll/write rights.
- [ ] Existing fd operations use the same descriptor-rights source of truth.
- [x] Differential WASIp1 tests cover allowed and denied operations in interpreter and JIT modes.
