# ISS-176: Enforce descriptor rights across WASIp1 operations

## Metadata
- Type: bug
- Status: in_progress
- Priority: 1
- Labels: wasi, wasip1, capabilities, security, descriptors, interpreter, jit, agent
- Assignee: codex
- Created: 2026-07-15
- Updated: 2026-07-20
- External ref: none

## Description
The interpreter and JIT descriptor tables retain effective WASIp1 base and inheriting rights, but most descriptor, path, and socket operations do not consume them. A guest can successfully attenuate a descriptor with `fd_fdstat_set_rights` and then continue to perform host operations that the reported rights no longer permit.

The current rights model also omits the Preview1 `SOCK_ACCEPT` bit, silently masks unknown rights in `path_open`, and does not enforce `PATH_OPEN` or the conditional create/truncate rights. This is a capability-boundary defect rather than a `poll_oneoff` implementation detail.

## Design
Keep effective base and inheriting rights in the authoritative descriptor entry for both interpreter and JIT modes. Centralize capability checks at descriptor lookup boundaries, reject invalid rights at ABI boundaries, and migrate descriptor, path, and socket operations to those checks. Verify the contract through one shared interpreter/JIT behavioral matrix.

## Acceptance Criteria
- [x] Interpreter and JIT descriptor entries retain effective base and inheriting rights.
- [x] `path_open` rejects rights escalation and records the granted rights on success.
- [x] `poll_oneoff` returns the specified capability error for descriptors lacking poll/read or poll/write rights.
- [ ] Existing fd operations use the same descriptor-rights source of truth.
- [ ] All Preview1 rights, including `SOCK_ACCEPT`, have the correct bit representation and invalid rights are rejected.
- [ ] Path and socket operations enforce base, inheriting, conditional, and two-descriptor rights before host side effects.
- [ ] Differential WASIp1 tests cover allowed, denied, attenuated, and unrelated-right cases in interpreter and JIT modes.

## Notes
- 2026-07-15: The shared poll implementation deliberately consumes the existing descriptor model instead of introducing a poll-specific rights shadow table.
- 2026-07-15: Interpreter `OpenFile` entries and JIT fd metadata now retain effective rights. `path_open`, `fd_fdstat_get`, `fd_fdstat_set_rights`, and `poll_oneoff` consume that state; remaining fd operations still need migration before this issue can close.
- 2026-07-20: Re-audit confirmed that stored rights are not consumed by most operations. Split implementation into ISS-206 through ISS-209 so the rights model, descriptor operations, contextual path/socket operations, and differential closure can be verified independently.
