## Description
`isa_target/lower/peephole_licm` currently identifies immutable context-derived loads by checking fixed offsets such as function table and global storage. This encodes Wasm/Wasmoon runtime-layout knowledge in generic optimization code.

## Design
Represent load invariance and aliasing through generic facts on MachV memory operations or context-slot metadata. Peepholes should use those facts rather than matching concrete runtime-layout fields.

## Acceptance Criteria
- [x] LICM/CSE no longer checks `function_table_offset`, `global_storage_offset`, or other fixed runtime-context field names.
- [x] Equivalent invariant loads are still hoisted/CSE'd when supplied with generic facts.
- [x] Conservative behavior is used when facts are absent.
- [x] Existing optimization and correctness tests pass.
