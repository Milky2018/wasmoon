# ISS-405: Keep cheap materialization recipes out of global CSE

## Metadata

- Status: closed

## Description

Global CSE merged repeated address constants and their `uextend` recipes into
function-long SSA values. Once the 256-address fixture began reusing an
address, regalloc spilled those values and reloaded them at every later use.

The initially proposed once-per-block late pass did not solve the real input:
all 300 operations occupy one MilkIR block. The end-to-end probe still had 21
spills and 32 reloads, so that implementation was removed rather than layered
with a distance heuristic.

## Design

Treat a cheap materialization recipe as an alternative representation, not as
a globally reusable SSA computation:

- use the ISS-404 cost predicate for one-instruction integer constants;
- include the direct `uextend` of such a constant because both targets lower
  that address recipe without an additional materialization instruction;
- do not bind those values as dominating e-graph representatives;
- do not rewrite a local recipe operand to an older equivalent value;
- exclude the constants from global GVN.

This preserves ordinary CSE, avoids distance and pressure thresholds, and
keeps the policy in MilkIR. A cheap recipe is emitted near each source use;
ISS-407 separately owns folding its constant offset into memory operands.

## Acceptance Criteria
- [x] Repeated cheap constants and direct `uextend` recipes are not replaced
      by function-long dominating definitions.
- [x] Ordinary non-materialization CSE remains enabled.
- [x] The 256-address fixture has no spill/reload cliff between 280 and 300
      operations.
- [x] The 400- and 800-operation fixtures allocate with zero spill and reload
      edits.
- [x] Focused tests pin both the cost boundary and repeated-recipe behavior.

## Notes
- 2026-08-07: The fixture is `scripts/gen_wide_branch_wat.py`, which cycles
  through 256 distinct addresses. A variant with every address distinct was
  the no-spill control.
- 2026-08-12: A late once-per-block pass was implemented first, then rejected
  by the end-to-end probe because the hot sequence is a single large block.
- 2026-08-12: After the corrected CSE policy, 280/300/400/800 operations emit
  5,624/6,024/8,024/16,024 bytes with zero spill and reload edits. The stable
  20 B/op includes two local address materializations per load/store pair;
  ISS-407 tracks folding those offsets and reports that effect separately.
