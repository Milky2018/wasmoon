# ISS-405: Rebuild marked values once per using block during elaboration

## Metadata

## Description

This is the change that fixes the doubling measured in ISS-403.

Elaboration currently reuses any dominating definition of an e-class for
free. For a constant used across many blocks, that single definition is
live for the whole function, so the register allocator gives it a stack
slot and reloads it at every use. In the measured fixture 64.5% of the
emitted bytes are spill and reload traffic and the marginal cost per wasm
op doubles from 16 to 32 bytes.

## Design

In `collect_elaboration_steps`, the fast path returns `Existing(value)`
whenever `class_to_value` holds a dominating value for the key. Narrow
it: return `Existing` only when the value is defined in the block being
elaborated, or when the value is not marked cheap by ISS-404. Otherwise
plan a fresh build.

Memoise the rebuild on `(block, key)` so repeated uses inside one block
still share a single definition. The granularity is deliberately once per
block rather than once per use: inside a block one register serves every
use, and only the cross-block live range needs cutting. This is the
middle ground between full CSE and full duplication, and matches what
Cranelift's `maybe_remat_arg` does with its `(insert_block, value)` key.

`class_to_value` is already walked over the dominator tree with entries
undone on exit, so the scoped-reuse structure this needs is in place. The
change is the marked set and the per-block rebuild, not the machinery
around them.

Do not recurse into the rebuilt value's own operands. Cranelift leaves
this open as their TODO #7313 to avoid a second fixpoint loop; the same
reasoning applies, and the conservative predicate from ISS-404 admits
only operand-free values anyway.

## Acceptance Criteria
- [ ] A constant used in several blocks is rebuilt in each using block
      rather than reused from a dominating definition.
- [ ] Repeated uses within one block still share one definition.
- [ ] The 256-distinct-address fixture holds at 16 B/op at 400 and 800
      ops, with no cliff between 280 and 300.
- [ ] Spill and reload traffic drops well below the measured 64.5% share
      on the 20,000-op fixture.
- [ ] A regression test pins the marginal byte cost. It must be cheap:
      the 400-op case is a few hundred milliseconds, unlike the megabyte
      fixture rejected on cost in ISS-402.
- [ ] Workspace tests and the WAST corpus pass in both modes.
