# ISS-267: Preserve deferred homes across ABI definitions and CFG edges

## Description

The loop-aware allocator introduced two ways to use a value before its stable
home had ever been initialized.

First, an `AnyLocation` definition could be assigned to a hot segment register
even though target ABI materialization writes directly to the value's stable
home. The allocator then treated the uninitialized segment register as
resident. This made AEGIS enter `_start` with a corrupt VMContext and trap.

Second, a value that was both an edge argument and independently live through
the same edge only received the block-parameter transfer. Its own deferred home
transfer was skipped. `core3.wasm` later reloaded that original value from an
uninitialized spill slot, and independent allocation verification rejected the
plan.

## Design

Keep the target-neutral allocator contract explicit:

- a pure `AnyLocation` definition materializes directly in its stable home;
  `AnyLocation` uses may still consume a resident register or spill slot;
- edge-argument transfer and live-through preservation are independent facts,
  even when they refer to the same source value.

Do not reserve a target register, disable allocation verification, or special
case AEGIS/core3 opcodes.

## Acceptance Criteria

- [x] A focused red test requires an `AnyLocation` definition to use its stable

- [x] A focused red test requires both the parameter copy and the original
      live-through home transfer on the same edge.
- [x] AEGIS and core3 execute successfully through the production AArch64 JIT.
- [x] Regalloc, target, native, and WAST correctness gates pass.
