## Description
A comparison passed as a jump argument was incorrectly classified as absorbed
by branch lowering. A shared constant could then be deferred into one sibling
block and reused from a block it did not dominate.

## Acceptance Criteria
- [x] Reproduce invalid SSA and the two-loop execution mismatch before repair.
- [x] Distinguish absorbable branch conditions from other terminator operands.
- [x] Preserve existing shared immediate and addressing-mode optimizations.
- [x] Always verify both target selectors for shared sibling constants.
- [x] Execute the two-loop regression at optimization levels 0 through 3.

## Close Notes
- Record actual Branch/Brz/Brnz conditions separately from general use counts.
  A comparison is deferred for branch fusion only when its sole use is one of
  those conditions. Jump/return arguments and br_table indices remain values.
- The cross-target regression explicitly calls finish_selected with its default
  SSA verification enabled, independently of the production environment flag.
  Restoring the old selector fails DefinitionDoesNotDominate before allocation.
- The existing VCode verifier already checks dominance; no duplicate verifier
  or blanket disabling of shared-constant selection was added.
- Native execution is verified on the local ARM64 host; x64 execution is a CI
  requirement, while both target VCode shapes are checked locally.
