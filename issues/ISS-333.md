# ISS-333: Consume owned callback closures exactly once

## Metadata

## Description
The cancellation and WASI stdin callback setters receive their closure
parameters through `#owned` FFI declarations, then increment the closures again
before storing them. Replacement, clear, and context destruction only decrement
once, so captured values remain retained. Both setters also return from a null
context without consuming the transferred closure.

## Design
Match the adjacent hostcall callback ownership protocol: store an owned closure
without incrementing it, decrement the previous stored closure on replacement
or clear, and decrement the incoming closure on every failure path. Add
black-box lifecycle tests backed by a test-only external object finalizer; do
not add counters or probes to release artifacts.

## Acceptance Criteria
- [x] Cancellation callback replacement and clear release each capture exactly
  once.
- [x] WASI stdin callback replacement and clear release each capture exactly
  once.
- [x] Null-context setters consume transferred closures.
- [x] Native tests and sanitizer-relevant callback tests pass.
