## Description
`x64_target` and `aarch64_target` expose functions and tests named around Wasm body lowering. Target modules should own x64/AArch64 ABI and lowering policy, not WebAssembly product semantics.

The target modules can support arbitrary call-convention layouts, but Wasm-specific naming and wrappers should live in Wasmoon-owned code.

## Design
Rename or replace `lower_wasm_body_function`-style APIs with generic call-convention-based APIs. Provide Wasmoon-owned wrappers in `wasmoon_jit` if needed for compatibility inside the product.

Non-goals: do not change AArch64/x64 ABI behavior, and do not remove convenience helpers unless equivalent Wasmoon-owned wrappers exist.

## Acceptance Criteria
- [x] Target modules no longer expose public APIs named around Wasm body lowering.
- [x] Wasmoon JIT still has a clear wrapper for compiling Wasm bodies with the Wasmoon call convention.
- [x] Target README examples and tests use generic call-convention terminology.
- [x] Target module checks and native tests pass.
