## Description

The `pwhash_scrypt_ll` SMix driver (`func_43`) currently contains 965 AArch64
instructions and 128 branch instructions, compared with 840 instructions and 80
branches in Wasmtime. Its code is 3,860 bytes versus 3,360 bytes for Wasmtime.
The Target VCode layout follows block creation order even though lowering visits
semantic blocks in CFG order, so otherwise free fallthrough edges survive as
explicit branches.

This is secondary to the BlockMix and Salsa allocator defects, but it adds
front-end pressure and recurring control-flow overhead around the two
memory-hard SMix phases.

## Design

Choose a deterministic, target-neutral CFG layout after semantic lowering and
before register allocation. Apply it to both AArch64 and AMD64 Target VCode so
the existing fallthrough-aware emitters can omit avoidable branches. Preserve
CFG edges, explicit traps, block arguments, and edge transfers; do not recognize
Scrypt-specific control flow. Only introduce block threading as separately
tracked work if layout alone leaves a demonstrated forwarding-block problem.

## Acceptance Criteria

- [x] A focused CFG/layout test covers deterministic fallthrough selection with
      block arguments and loops.
- [x] Both AArch64 and AMD64 apply the selected layout before register
      allocation.
- [x] Its final AArch64 branch count falls from 128 to at most 90 without
      increasing code size.
- [x] Trap, loop, and structured-control semantics remain unchanged.
- [x] Native and recursive WAST suites pass.
